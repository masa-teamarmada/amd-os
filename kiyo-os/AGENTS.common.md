## 1. これは何か

**きよOS** = きよ専用の個人OS。きよの毎日・仕事・お金・記録・考えごとを 1 か所に集めて、
AI（えいみ）が横から手伝えるようにするための Web アプリ。

雛形の発想元は、まさ専用に作った **えいみOSスイート**（個人の資産・家計・生活ログ・道のり・
目標・外部脳・週次操縦席・対話ログを 1 つのアプリに束ねたもの）。

**ただし、中身は「えいみOSスイートのコピー」ではない。**
きよが実際に欲しいものは、まさが欲しかったものとは違う。
だから **画面の中身はまだ決まっていない**。決めるのはきよ本人であって、AI ではない。

- 骨組み（ログイン、レイアウト、ナビ、ダッシュボード、モジュールの追加口）→ **できている**
- 中身（どんなモジュールを何個、何を表示するか）→ **これから、きよと決める**
- 中身の決め方 → [`docs/INTAKE.md`](docs/INTAKE.md) に沿ってヒアリングして積む

## 4. 絶対に守ること

### 4.1 きよOS は AMD OS ではない

- **会社の本番データ（AMD OS / Supabase `nbnhrhybjslbawdukvvk`）に、このリポジトリから書き込まない。**
- 会社の経理・PJ・請求のデータが必要になったら、コピーせず、まさに相談してから
  read-only の手段を設計する。
- `amd-os` リポジトリのファイルをこのリポジトリへ丸ごとコピーしない。参考にするのは構造だけ。

### 4.2 秘密の値をリポジトリに書かない

- API キー、パスワード、トークン、`SERVICE_ROLE_KEY` の類を
  **ファイル・commit・チャット・スクショに出さない**。
- 置き場所は `.env.local`（git 管理外）と、Vercel / Supabase の管理画面だけ。
- 必要な変数が足りなくてエラーになったら、**変数の「名前」だけ**を報告する。値を要求しない。

### 4.3 きよの中身を AI が勝手に決めない

- 「たぶんこういうのが欲しいだろう」で画面を増やさない。
- 思いついた案は実装せず、`docs/INTAKE.md` に候補として書いて、きよに選んでもらう。
- 決まったものだけ `docs/DESIGN.md` に昇格させて実装する。

### 4.4 壊さない

- 相手（もう一人）の未 push の作業を、`reset` / `checkout` / `force push` で消さない。
- 見慣れない変更を見つけたら、消す前に「これは誰の作業か」を確認する。

## 5. Git の運用

### 5.1 main 一本。ブランチを作らない

- 正本リポ: `github.com/masa-teamarmada/kiyo-os`（唯一）
- **ブランチは作らない。main に直接 commit して push する。**
- 理由: まさときよ 2 人 + AI が別々の場所で動く。枝が増えると
  「どっちが本物か分からない」事故が必ず起きる（AMD OS で実際に起きた）。
- 例外は、まさがそのセッションで明示的に「ブランチ切って」と言った時だけ。

### 5.2 作業開始時に必ず実行（同期の 4 ステップ）

もう一人が先に進めているかもしれないので、**触る前に必ず**:

```sh
git fetch --all --prune
git rev-list --count HEAD..origin/main   # 0 でなければ自分が古い
git log --branches --not --remotes --oneline   # 空でなければ push し忘れがある
git status -s
```

`HEAD..origin/main` が 0 でないまま編集を始めない。まず `git pull --ff-only origin main`。

### 5.3 commit したら即 push

- 機能が完成するまで push を待たない。**1 まとまり = 1 commit = 即 push。**
- 「今日の終わりに必ず push」が最低ライン。手元に残したまま寝ない。
- 理由: 手元にしかない作業は、もう一人からは**存在しないのと同じ**。

### 5.4 2 人が同じアカウントで push する前提

まさときよは同じ GitHub アカウント（`masa-teamarmada`）を共有している。
このままだと **commit の履歴で誰の作業か分からなくなる**ので、必ず:

- commit message の末尾に、その作業をした人を 1 行入れる:

  ```
  Worked-by: kiyo
  ```
  または
  ```
  Worked-by: masa
  ```

- push 直前に必ず `git fetch origin main` して、相手の新しい commit がないか見る。
  あったら先に取り込む（`git pull --rebase origin main`）。

同時に同じファイルを触りそうなときは、先にチャットで「今どこ触ってる」を言う。

# 組織の状態を、案件ごとの入力として受け取る

まさ 2026-08-28「組織がめちゃくちゃ重要なのは、みんながもう認識してるところなのに、そこをスコアに入れないとかはあり得ない」。

## いま何が起きているか

参照実装 `model/tools/bzm30_forward.cjs` が案件ごとに受け取る組織の入力は、**担い手 $e$ の1つだけ**である。
八機能（§6.B-1）のうち $e$ が表すのは機能1（エバンジェリスト）だけで、残り7つは案件ごとに指定できない。

| 機能 | いまの扱い | 案件ごとに入れられるか |
|---|---|---|
| 1 エバンジェリスト | $e$（探索過程・$\kappa_e = 1/18$ が乗る） | **入れられる** |
| 2 技術の核 | **「空席にならない」と規約で固定**（§6.I-3-1） | **入れられない** |
| 3 用途と需要家 | AMD の供給過程で月 $\kappa_{\mathrm{sup}} = 1/12$ の率で埋まる | **入れられない** |
| 4 意思決定 | 同上 | **入れられない** |
| 5 資金調達 | 同上 | **入れられない** |
| 6 対外交渉 | 同上 | **入れられない** |
| 7 組織 | 同上 | **入れられない** |

空席の期待値は `vacancyProbs` が機能 1・3・4・5・6・7 の**64通り**にわたって厳密に計算するが、
機能2 は常に充足として数えられる。技術の核の恒久喪失は $\lambda^{\mathrm{core}} = 0.008$（年率0.8%）という
**全案件共通の係数**で、案件ごとに受け取る口が無い。

## これが実害になっている案件

**p16 ORLIB（プレドープシリコン負極の高容量リチウムイオン電池、東京大学 西原研発）。**

- 技術の鍵を握るメンバーを追い出し、経営者の息子を正社員にしていた
- 現状は経営者の息子・営業1名・佐藤社長の3名で、**誰も電池を作れない**
- 興味を示していたリベラウェアから「早く納品してくれ」と言われながら引き伸ばしている
- 株主の多くは経営者の交代を望むが、経営者が67%を持っていて交代できない
- 出資したトヨタ紡織CVCは株主間契約を締結しておらず、株を回収できない
- 差別化要因の中心だった負極材のプロセス装置をタイの大学へ販売しようとしていた

**この状態は「機能2（技術の核）の恒久喪失」そのものだが、モデルに入れる口が無い。**
担い手 $e$ を範囲の下端 0.20 まで下げても、$v$ は 0.507 → 0.281 にしか落ちなかった。
評価日に主張できる証拠水準を段階3から段階1へ下げて、はじめて $v$ が 0.023 になった。

証拠水準で代用したのは「越えたゲート」ではなく「評価日に外部から検証できる水準」という読み方に基づくもので、
それ自体は §6.I-1-4 の定義と矛盾しないが、**本来は機能2の空席として入るべきものを別の入力で代用している**。
代用しているあいだ、次の3つが起きる。

1. 同じ状態の案件を、評価する人ごとに違う入力で表す（再現しない）
2. 「技術の担い手が戻った」ときに元へ戻す手続きが決まらない
3. 機能3〜7 が抜けている案件（例: 資金調達の担い手がいない）を表す手段が何も無い

## 提案

### 1. 八機能の充足を、案件ごとの入力として受け取る

`init` に `funcs` を足す。八機能それぞれについて、評価日の充足を 0〜1 で受け取る。

```
init.funcs = { f1: 0.25, f2: 0.0, f3: 0.5, f4: 0.5, f5: 0.3, f6: 0.4, f7: 0.5 }
```

- 省略した機能は、いまと同じ扱い（機能1 は $e$、機能3〜7 は供給過程、機能2 は充足）にする。**後方互換を保つ**
- `vacancyProbs` の 64通りを 128通り（機能2 を含む7機能）へ広げる。計算量は2倍で、いまの1件2〜3分が5〜6分になる
- $e$ は `funcs.f1` の別名として残す（既存の入力を壊さない）

### 2. §6.I-3-1 の「機能2 は空席にならない」という規約を、条件つきへ改める

いまの規約は「研究者本人が担い、一時的な不在は扱わない。恒久喪失（異動・定年で戻らない）は $\lambda^{\mathrm{core}}$ で扱う」。
これを次へ改める。

> 機能2 は既定では空席にならない。ただし**評価日に技術の核の担い手が案件から失われていることが観測された場合**は、
> 案件ごとの入力として空席を指定できる。指定した案件では $\lambda^{\mathrm{core}}$ を重ねて適用しない（二重計上を避ける）。

観測の条件は §6.B-2（充足の判定 — 直近性・証拠の下限・失効）の様式をそのまま使う。
ORLIB の場合は「引き合いに対して製品を出せていない」が証拠になる。

### 3. $d_{2,g} = 1.00$ を較正の対象へ戻す

§6.I-3-1 は「この規約の帰結として $d_{2,g}=1.00$ は Tier 0 の計算では発火せず、較正の対象から外す」としている。
機能2 の空席を受け取るようになれば発火するので、較正の対象へ戻す。
$d_{2,g}=1.00$（前進しない）が強すぎるかどうかは、発火する案件が出てから測る。

## 影響

- **計算量が2倍**（64通り → 128通り）。1件あたり2〜3分が5〜6分になる。21件の全件再計算で並列6なら約20分
- 既存の入力（$e$ だけを渡す形）は動き続ける。後方互換
- 案件ごとの入力を持つ `seed_bzm30_inputs` に列を8つ足す必要がある（migration）
- **いま証拠水準で代用している案件（p16 ORLIB）は、機能2の空席へ移して証拠水準を戻す**

## 採らない案

- **$\lambda^{\mathrm{core}}$ を案件ごとに受け取る。** 恒久喪失は率ではなく状態なので、率で表すと
  「いつ失われたか」で答えが変わる。すでに失われている案件を率で表すのは無理がある
- **担い手 $e$ の範囲を 0〜1 へ広げる。** $e$ は機能1 の量であって、機能2 の代わりにはならない。
  範囲を広げても「技術の核が無い」は表せない
- **変換能力 $c$ を実現の申し出の到来率にも乗せる。** 試算では「これ以上ゲートを越えない」を表せた
  （ティエム 2.9億）が、まさ 2026-08-28 が棄却——「ライセンスやM&Aの話を取れるかどうかは戦略余力に
  かかってるわけで、待ってれば話が来る状態なら、それは戦略余力が高いよ」。
  申し出の側は戦略余力の鮮度（提案9 の無風期間）で持つ

## 決めてほしいこと

1. この提案を採るか
2. 計算量が2倍になることを受け入れるか（1件5〜6分）
3. 八機能の充足を、誰がどの様式で埋めるか（§6.B-2 の様式をそのまま使うか、簡略化するか）

### 提案4: 機能の補完性を表す

いまの担い手乗数は $\eta_t = \prod_f (1 - d_f \mathbb 1[\text{空席}])$ で、**空席どうしを代替的に扱う**
（空席が増えるほど追加の空席の害が小さくなる）。正本自身が §6.I-3-1 と I-13 で
「創業チーム研究が示すのは逆の補完性なので、この形は補完性を表現できない」と認めている。

**噛み合わせ係数 $\chi \in [0.5, 1.5]$ を案件ごとに受け取り、$\eta_t$ に掛ける。**
1.0 が中立。チームが噛み合っている案件は 1.0 超、対立している案件は 1.0 未満。
積の形そのものを直すのは較正の材料が無いので、**乗数で外から補正する**のが現実的。

観測の条件は「同じ機能を担う二人以上の間で、意思決定が滞った記録があるか」。
p20 CryoX は 1.2、p21 SolvioraX は 0.9 が候補。

### 提案5: 権利・承認の残件に、資本の種類を足す

いま $R_0$ が数えるのは 職務発明の帰属 / 共同出願の同意 / ライセンス条件の合意 / 利益相反の承認 の4種
（§6.I-6）。**資本の側の未処理を足す。**

| 追加する種類 | 発火条件 | 効き方 |
|---|---|---|
| 株主間契約（SHA）の未締結 | 外部投資家が入っているのにSHAが無い | 経営陣の交代・株の回収ができないので、**撤退の四経路のうち②M&A・③知財売却の到達確率を下げる** |
| 創業者間契約の未締結 | 創業者が複数いるのに契約が無い | 同上 |
| 支配権の集中 | 一人が過半（例: 67%）を持ち、株主の多数が交代を望んでも実現できない | 意思決定（機能4）の空席と同じ効き |

p16 ORLIB は3つとも該当する。**これは「残件が解決されれば消える」ものではなく、
出資時点で決まって後から直せない**ので、残件（時間が経てば解ける）ではなく
**状態（解けない）**として持つほうが正しいかもしれない。ここは設計の判断が要る。

### 提案6: 案件ごとのバーンレートを受け取る

既に `seed_bzm30_inputs.burn_rate_yen_month` に値は入っているが、参照実装が受け取らない。
実績は型別の既定値の**2〜37倍**ずれている（p22 OptQC が月1.5億円に対し既定400万円で約37倍）。

**`init.burnMan`（万円／月）を受け取り、$\mu$ を差し替える。**
「TRLが低い段階で高級オフィスを借りている」のような、身の丈に合わない固定費はここに現れる。
省略した案件はいまと同じ既定値。

### 提案7: 変換能力 $c$ を案件ごとに受け取る

**$c$ が測るもの**（§5.3）: 「変換能力。**投入資源あたりに前進を生む速さの乗数**」。
要件1（§3）では「技術と資本金を戦略余力に変える能力」。
まさ 2026-08-28「設立後の資金や、資金以外も戦略余力があると思うけど、**それをどのくらい変換できるかの指標**」。

つまり **$c$ は、案件が持っている戦略余力（設立後の資金と、資金以外の余力）を、
どれだけ前進へ変換できるかを表す量**である。同じ資金と同じ月数を使っても、
越えるゲートの数は案件によって違う。その差が $c$。

**参照実装は $c$ を案件ごとに受け取らない。**
`cfgL.cNodes = [[0.55, 0.25], [1.00, 0.50], [1.82, 0.25]]`（対数正規 GSD 1.65 の3点）を
全案件共通で回すだけで、`init` に $c$ の口が無い。**要件1に挙げた量が、案件ごとに入らないまま計算されている。**

#### 直し方

`init.c` を受け取る。渡された案件は `cNodes` を $c$ を中心とした3点へ置き換える
（幅は GSD 1.65 のまま。点推定にすると不確かさが消える）。

#### 測り方（v2。まさ 2026-08-28 の設計で置き換え）

まさ 2026-08-28「変換能力については、何かアクションをするたびに、そこにかかった費用と得られた戦略余力を推定して、
その比率の移動平均を取るのがいいと思う」。

- **アクションごとに、掛かった費用と、得られた戦略余力の増分を推定し、その比率を分野の基準と比べる。**
  戦略余力の増分に数えるのは: 獲得した資金／越えたゲート（証拠水準の上昇）／知財／需要家との関係／人
- **直近に重みを置いた移動平均で持つ。** 昔は変換できていた案件が、いまも変換できているとは限らない。
  実務は評価版の期間ごとに区切って更新する（アクションと費用の記帳は §6.C の登録簿の様式がそのまま使える）
- 設立前資金の扱い（下の拡張）はこの測り方の特別な場合——設立前に使った資金が案件の資産へ
  どれだけ変わったかは、まさにこの比率

正本 §5.3 のいまの文（「これまでに投入した資金と月数に対して越えたゲートの数の比」）は
**累積の一括比**なので、移動平均へ書き換える。累積比だと、過去に速かった案件の失速が薄まって見えない。

#### 観測できない案件の概算（提案9 の無風期間を使う）

AMD が関与しておらず、費用とアクションの記録が取れない案件は、
**外から見えるポジティブな動き（調達・製品化・提携・受賞などの公開情報）**で概算する。
まさ 2026-08-28「ネット記事とかでポジティブなニュースが出ていれば、ある程度高いと推定することはできると思う」。
最後の動きからの経過月数（無風期間。提案9）が長いほど低く置く。

#### 設立前の資金への拡張（まさ 2026-08-28）

まさ「**ただしそれを設立前の資金にも拡張できると考えた**」。

> 設立前の獲得資金については、設立後の残高と同等に考えたらダメ。
> その資金がどの程度設立後SUの資産に変換されたかを評価する必要がある。
> ダメなPJだと、SUと無関係な、自分の研究のために使われることもある。
> 一方でいいPJだと、よくその費用でそこまで知財を創出したね、みたいなのもある。

**設立前に獲得した公的資金（科研費・GAP・PSI など）は、そのままの額を戦略余力として数えない。**
その資金がどれだけ**案件の資産**へ変わったかを見て、$c$ の推定に使う。残った資産は次の4つ。

| 残った資産 | 何で見るか |
|---|---|
| 知財 | 出願・登録の件数と、権利が案件へ帰属しているか |
| 試作・実証 | 越えたゲートの数（T1〜T3・M2〜M4） |
| データ | 再現できる形で残っているか |
| 人 | その資金で採用・育成した人が案件に残っているか |

同じ額を使っても、**研究者個人の研究に使われて案件の資産が増えていない場合**と、
**少ない費用で知財と実証を積んだ場合**とで $c$ は大きく違う。いまはどちらも同じ中央値1.0で計算されている。

#### 「これ以上ゲートを越えない」は、$c$ と無風期間（提案9）の組で表す

試算で分かったこと（2026-08-28）: **$c$ を下げるだけでは、伸びが止まった案件の価値は落ちない。**
p03 ティエムファクトリ（天井を SAM 本来の 66.5億／年へ戻して試算）で $c$ を 0.2 まで下げても、
中央値は 12.6億 → 11.9億 にしか動かなかった（自力で量産へ届く確率は 1.5%→0.5% に落ちるのに）。
価値の大半が「留まっていても外から来るライセンス・M&A の申し出」の経路から立っていて、
$c$ は前進確率にしか乗らないため。

まさ 2026-08-28 の整理: **申し出（ライセンス・M&A）の話を取れるかどうかは戦略余力の役割**——
「待ってれば話が来る状態なら、それは戦略余力が高いよ」。
だから申し出の側は $c$ ではなく、戦略余力の鮮度の観測量（提案9 の無風期間）で落とす。

| 置き方 | ティエムの中央値 |
|---|---:|
| いまの代用（天井を13.3億へ絞る。$c$ は全案件共通） | 2.5億 |
| 天井66.5億へ戻す ＋ $c=0.2$（前進のみ。元の提案7） | 11.9億 |
| 天井66.5億へ戻す ＋ $c=0.2$ ＋ 無風期間36か月以上（申し出 ×0.2） | **2.9億** |

役割分担が正しくなる——$c$ は「投じた資源が前進へ変わるか」、無風期間は「外から見て動きがあるか＝
引き合いを呼べる状態か」。承認されたら、ティエムの天井は 66.5億へ戻して絞りの代用をやめる。

$c$ の目盛りの案（根拠レベルは C）:

| $c$ | 状態 |
|---:|---|
| 1.8 | 少ない資源で知財と実証を積み上げている |
| 1.0 | 分野の基準どおり |
| 0.5 | 資源を使ったわりに越えたゲートが少ない |
| 0.2 | 資源を使っても案件の資産に変わっていない／伸びが止まっている |

### 提案8: 戦略余力の、資金以外の部分を持つ

要件2（§3）は「戦略余力 = 次の行動を起こすための資金。**金だけではない**。減ってゼロと交差したら清算するしかない」。
まさ 2026-08-28 も「設立後の資金や、**資金以外も戦略余力がある**」と言っている。

**参照実装の戦略余力は、資金の残高 $s$（万円）だけである。** 資金以外の余力を持つ場所が無い。
資金以外の余力にあたるのは、たとえば次のもの。

- 大学の設備・装置を使える権利（設立前の案件はここが大きい）
- 共同研究先が負担してくれる工数
- 引き当てられる人（採用しなくても動いてくれる関係者）
- 使える公的支援プログラムの枠（採択ではなく、応募できる資格）

これらは**減っていく**（設備の利用期限、共同研究契約の期間、関係者の離脱）ので、
資金と同じ「減ってゼロと交差したら清算」の構造に乗る。

#### 直し方（2案）

- **案A: 資金へ換算して足す。** 資金以外の余力を「同じことを金で買ったらいくらか」に直して $s$ へ足す。
  実装が要らない。**設立前の案件で効く**——大学の設備を使えることは、その分の資金を持っているのと同じ
- **案B: 別の状態として持つ。** 資金と別の軸で持ち、減り方も別にする。表現は正しくなるが、格子の次元が増えて計算量が跳ねる

**案Aを推す。** 要件2 が「金だけではない」と言っているのは量の話であって、
資金と別の力学を要求しているわけではない（「減ってゼロと交差したら清算」という同じ構造で書かれている）。
換算のしかたを `model/cases/README.md` の規約として決めれば、いまの実装のまま入る。

**2026-08-28 追記**: 「会社化前は資金が前進の速度を変えるだけ」（2026-08-27 提案の書き直し版）が
承認されると、設立前の案件では残高の感度がほぼ消えるので、案A（資金へ換算して残高に足す）の効き先が
ほぼ無くなる。戦略余力の非資金の側は、まさ 2026-08-28 の整理（申し出を取れるかは戦略余力の役割）に
沿って、**過程の側の観測量として持つ**方向へ変える——その最初の実装が提案9 の無風期間。
この提案8 は承認を求めず、後回しにする。

### 提案9: 無風期間 — ポジティブな動きが出ていない月数を、案件ごとの入力として受け取る

まさ 2026-08-28「ポジティブなニュースがどのくらいの期間出ていないかは重要な情報かもしれない。
これが長くなっていくに連れて戦略余力は下がっていってるわけだし、変換能力も高くないと推定される」。

**無風期間** = 外から見えるポジティブな動きが最後に観測されてからの月数。
ポジティブな動き = 資金調達の成立・製品化・提携・受賞・大型の採択などの公開情報。
AMD が関与している案件では、登録簿のゲート通過（種類9）・採択（種類1）・民間調達（種類5）・
受託契約（種類13）・用途の拡張（種類19）の事象がそのまま使える。

使い先は二つ。

1. **変換能力 $c$ の概算**（提案7 の測り方が使えない、記録の無い案件）: 無風期間が長いほど低く置く
2. **実現の申し出の到来率の乗数**（戦略余力の鮮度）: 動きが見えない案件には引き合いも来ない。
   §6.I-5-1 の $\nu_k$ と、§5.7-2 の撤退の四経路の引き受け手の現れやすさ（②出口クラスの転換・
   ③ライセンスへの畳み込み）に掛ける

目盛り（根拠レベル C。較正対象）:

| 無風期間 | $c$ の概算 | 申し出到来率の乗数 |
|---|---:|---:|
| 12か月未満 | 1.0 | 1.0 |
| 12〜24か月 | 0.7 | 0.7 |
| 24〜36か月 | 0.45 | 0.45 |
| 36か月以上 | 0.2 | 0.2 |

- 効き先が資金の残高と独立なので、「会社化前は資金が速度を変えるだけ」が承認されて残高の感度が
  消えても、伸びの停止はこちらで表せる
- **二重計上の防止**: 無風期間から $c$ を概算した案件では、同じ無進捗を種類23（経過報告）から
  もう一度 $c$ に効かせない。提案7 の測り方（移動平均）で $c$ を推定できる案件では、
  無風期間は乗数（使い先2）にだけ使う
- 試算（p01 OPTMASS。$c=0.3$〈履歴推定: 約7年・2.2億円で段階2〉・無風27か月で乗数0.45）:
  現行 5.3億 → **2.1億**。2024-05 の協調融資を最後に公開の動きが無い、という読みを直接に反映できる

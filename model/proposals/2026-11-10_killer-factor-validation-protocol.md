# キラー要素の検証手順

状態: proposal / 未承認

## 目的

キラー要素カタログを、工程失敗や資金切れでは拾えない新情報の監視台帳として使えるか検証する。

現行の七分類、予防統制と常時監視の区分、四段階表示、件数によるPJ全体判定は暫定実装である。
この提案は、それらを正しい尺度として承認するものではない。

## 現行モデルで確定している範囲

- キラー要素は、それ自体を数値化した予測因子ではなく、影響工程の入力を聞き直す契機として扱う。
- 発生証拠と、工程の確率・所要時間・費用・分岐の変更を分けて記録する。
- 一律の減衰係数を置かない。
- 記録と文書を主要な証拠とし、CEO本人の自己申告だけで発生を確定しない。
- 情報締切と版を保存し、後から得た結果で過去の判定を書き換えない。

## 検証する問い

1. 各候補は、工程失敗、資金切れ、他の候補と区別して定義できるか。
2. 同じ証拠を見た複数の評価者が、該当有無、観測日、影響工程を同じように判定できるか。
3. その候補を観測すると、既存の工程入力だけでは起きなかった再測定が生じるか。
4. 再測定後の入力は、後の事実と照合できる形で保存できるか。
5. AMDの予防作業、PJの観測事実、BZMの再測定結果を別々に運用できるか。

## 候補ごとの定義票

候補ごとに次を作る。

| 項目 | 記載内容 |
|---|---|
| 名称 | 観測対象を直接表す短い名称 |
| 定義 | 該当する状態または事象 |
| 含む例 | 定義に含める具体例 |
| 含まない例 | 工程失敗、症状、予防作業など、別の場所で扱う例 |
| 観測単位 | 文書上の有無、事象、回数、期間、連続値など |
| 証拠 | 利用できる記録と文書 |
| 事象時点 | 状態または事象が生じた時点 |
| 認識時点 | AMDが証拠から確認できた時点 |
| 影響工程 | 聞き直す工程入力と作用の理由 |
| 既存入力との差 | 既存工程へすでに織り込まれていない理由 |
| 予防作業 | AMDが事前に行う仕事。観測事実とは別に管理する |
| 反証条件 | 候補を棄却、統合、別の工程入力へ移す条件 |

## 過去事例による定義検査

ORB、tiem、r3ktだけに結論を合わせず、当時の記録を確保できる過去PJを対象にする。

1. PJごとに複数の情報締切を置き、その日までに存在した資料だけを評価者へ渡す。
2. 結果と現在の評価を伏せた状態で、二人以上が独立して定義票を適用する。
3. 該当有無、分類、事象時点、認識時点、影響工程、再測定の要否を記録する。
4. 不一致は多数決で消さず、定義の曖昧さ、証拠不足、複数分類の重複として原因を残す。
5. 評価者間一致の指標は、標本数と該当率を確認した後、データを見る前に固定する。

少数事例の段階では、予測精度や減衰量を確定しない。
まず、同じ資料から同じ判定を再現できるかを確認する。

## 既存モデルへの追加価値の検査

各判定について、キラー要素を使わない基準版と、証拠を受けて工程入力を再測定した版を残す。

- 基準版だけで同じ入力変更が生じる候補は、独立キラー要素から外し、既存工程の証拠へ移す。
- AMDの作業進捗だけを表す候補は、予防作業の台帳へ移す。
- 別の原因の結果として現れる候補は、症状として原因候補へ統合する。
- 既存工程では拾えず、証拠によって影響工程の再測定が必要になる候補だけを監視項目として残す。

前向き運用では、観測前の版、証拠、再測定対象、質問文、評価者、変更前後の入力幅、変更後の版、後の結果を保存する。
十分な外部標本が貯まるまで、候補の件数や段階を減衰係数へ変換しない。

## 測定方法の選択

全候補へ同じ四段階を当てない。
定義票と実例から、候補ごとに次のいずれかを選ぶ。

- 文書上の有無や適用状態を記録するカテゴリ
- 発生回数
- 継続期間や遅延日数
- 金額や比率などの連続値
- 順序に観測可能な境界を置ける段階
- 発生順と証拠を残す事象履歴

順序段階を使う場合は、隣接する段階を記録と文書で区別できることを条件とする。
段階番号の加算、平均、異なる候補間の比較には、別途の妥当性確認が必要である。

## 候補の状態

候補は要素ごとに次の状態を持つ。

`候補 → 定義済み → 過去事例検査済み → 前向き検証中 → 運用採用 / 統合 / 棄却`

採用はカタログ全体ではなく要素単位で判断する。

## 画面とデータの扱い

検証が終わるまでは、現在の四段階と全体判定をBZMの確定尺度として説明しない。
次の改修案は、検証設計の承認後に別途決める。

- PJの観測事実
- AMDの予防作業
- 再測定待ちと再測定済み
- 影響を受けた工程入力と版

これらを別の情報として表示し、候補件数だけからPJ全体の危険度を導かない。

## 承認後の最初の作業

「経営陣の意思疎通」「プロジェクト管理」「経理体制」の三候補について定義票を作る。
ORB、tiem、r3ktと、当時資料を確保できる追加PJへ適用し、独立キラー要素、既存工程の入力、AMDの予防作業、症状、重複のどこへ属するかを判定する。

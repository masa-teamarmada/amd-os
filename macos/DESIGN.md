# AMD OS macOS 設計正本

最終更新: 2026-07-17

## 1. 位置づけ

macOS版はPWAの表示を包む殻ではなく、AMD OSの同じ正本データと権限境界を使う独立したネイティブクライアント。
Macでの仕事は画面の横幅を活かし、常設ナビ・一覧・詳細・キーボード操作を中心に組み立てる。

## 2. 全体構成

| 層 | 正本 / 実装 |
|---|---|
| 認証 | `AMDOSCore` のSupabase Google OAuth + PKCE。callbackは `amdos-macos-auth://oauth/callback` |
| データ | `AMDOSCore` のRLS付きSupabase REST読み取り。既存PWA API / Edge Functionを安全な書込み先として扱う |
| 表示 | `AMDOSDesign` の色・文字・状態・カード・アクセシビリティ |
| ナビ | `NavigationSplitView`: 仕事 / 探索 / 管理 / 設定 |
| アプリアイコン | `SupportingFiles/Assets.xcassets/AppIcon.appiconset`: AMD三連中空六角形 |
| 追跡 | `PARITY.md`: 全機能の対応、権限、回帰確認を開発用台帳として管理する。画面には渡さない |

## 3. ナビゲーション

### 3.1 仕事

「今日」「プロジェクト」「お知らせ」「立替」「名刺」「月初の確認」を置く。
今日とプロジェクトはMacで実データを読み、お知らせは認可済みの配送結果だけを表示する。名刺はファイル・ドロップ・貼付を共通の確認待ち状態へ送る。

### 3.2 探索

「Atlas」「材料」「Seeds」「PoC」「VC」「研究動向」「研究機関」「AMD Score」を置く。
Atlas・材料・研究機関・研究シーズ・PoC候補・投資候補・研究動向・プロジェクトの見立てを、業務の読み取り画面として同じ情報設計で扱う。開発上の進み具合や内部の対応表は画面へ出さない。

### 3.3 管理

admin権限がある場合だけ「管理ホーム」「請求書」「財務」「支払」「契約」「メンバー」「会社概要・ガバナンス」「裏wiki」「経営ノウハウ」「運営カレンダー」「MS一覧」「シーズン予実」「週次活動」を表示する。
管理画面の表示権限はMac側の見た目ではなく `members.is_admin` と既存API/RLSで判定する。

### 3.4 設定

「状況モニター」「使い方」「設計書」「教科書」「アカウント」を置く。
教科書と状況モニターは読み取り専用。旧タスク画面や旧月次ルーティンの導線は持たない。

## 4. 画面品質契約

- 主役は各画面1つ。ラベルは値より弱く、状態は色だけに依存させない。
- 余白は4 / 8 / 12 / 16 / 24 / 32pxのスケールを基本にする。
- 横長一覧は列を潰さず、詳細は右側または別ペインへ出す。
- 文字・ボタン・カードは狭いウィンドウでも重ならない。必要なら縦積みへ切り替える。
- フォーカスリング、キーボードでのサイドバー移動、Enter / Spaceでの操作を維持する。
- 名刺のドラッグ&ドロップ領域、ファイル選択、クリップボード貼付は同じ確認待ち状態へ入れる。

## 5. 主要画面の契約

- ログイン画面は白背景に透過AMDロゴmarkを主役として置き、名称・説明・Google認証の順序を保つ。仮の記号、ロゴ入り背景、別形状のシステム画像は使わない。
- 今日の画面は「今日やる判断」「プロジェクト」「お知らせ」を主役にし、内部の進捗ラベルやデータ構造を表示しない。
- プロジェクトは一覧から選択して詳細を開く。Macの横幅を活かし、ツールバー更新、キーボードフォーカス、Enter/Spaceでの選択を保つ。
- お知らせは通知配送用Edge Functionの結果だけを読み、直接のテーブルREST取得は行わない。取得できない場合は権限エラーを画面へ見せず、自然な空状態を出す。
- 名刺はファイル選択、ドラッグ&ドロップ、クリップボード貼付を主導線とし、OCR候補は人が確認してから既存の認可済みAPIへ渡す。非公開の画像・個人情報をPJ知識へ自動複製しない。
- 月初の確認は担当内容・予定額・合意履歴を確認する入口とし、管理上の安全な書込みは既存の認可済み経路へ委譲する。
- 管理領域はadmin権限のときだけ表示し、権限のないユーザーへ内部の拒否理由やデータ境界を見せない。
- 外部確認導線はSwiftUI `Link`を使う。Commandキーを押しながらクリックしたときの既定ブラウザの新規タブ動作を妨げない。
- `PARITY.md` は開発用台帳であり、ユーザー向け画面・空状態・エラー文言には表示しない。残りの対応は台帳から削除せず、実装の事実と回帰確認を更新する。

## 6. アプリアイコン仕様

- 完成マスターは `SupportingFiles/Brand/AMDLogo-master.png` に原寸のまま保存し、元画像を上書き・再圧縮しない。
- マスターは深いネイビー地に高コントラストの青でAMDの三連中空六角形を置いた正方形画像。
- `AppIcon.appiconset` にはmacOSの16 / 32 / 128 / 256 / 512ポイントを1倍・2倍で収録し、最大1024pxの派生画像を使う。
- ログイン画面の主役は `AMDLogoMark.imageset` の同じAMDロゴmarkを128ptで表示し、仮の記号や別形状のシステム画像を使わない。
- ログイン用markは背景を透過し、白いログイン画面にはmarkだけを置く。深いネイビー地のAppIconとは表示用途を分ける。
- ログイン画面は白背景、ロゴ、`AMD OS`の名称、説明文、既存のGoogle認証導線の順序を保ち、ブランド表示の変更で認証本文や権限説明を壊さない。
- Google OAuthは`ASWebAuthenticationSession`で開き、Mac専用の`amdos-macos-auth://oauth/callback`をcallback schemeとして受け取る。SwiftUIの`onOpenURL`も同じschemeだけを受理し、受け取るのはPKCE codeだけに固定して交換する。iOS・Kagamiと共有するGoogle callback schemeは使わない。
- PWAの安全な確認経路へ委譲する外部導線はSwiftUI `Link`として実装し、通常クリックは既定ブラウザ、Commandクリックは既定ブラウザの新しいタブで開く。
- XcodeGenの `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` と `Assets.xcassets` を通じて、実アプリの `CFBundleIconName` に結び付ける。
- 配布用サイズはマスターから機械的に縮小生成する。ロゴの再描画・色変更・自動トリミングはしない。

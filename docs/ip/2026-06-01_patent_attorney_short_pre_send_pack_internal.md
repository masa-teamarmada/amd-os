- 作成日: 2026-06-01
- 位置づけ: まさ / 特許出願司令塔レビュー用の内部ドラフト
- 共有制限: 外部送付禁止。弁理士送付禁止。このまま添付・Drive共有・チャット共有しない。
- 目的: 初回打診後、弁理士から事前資料を求められた場合に、送付候補として使える1〜2ページ相当の短縮版を準備する。

## 0. 使い方

これは「送付候補版」であり、「送付版」ではない。

実際に外部へ送る前に、送付先、守秘義務又はNDA、添付要否、料金条件、ファイル名、PDF化範囲を確認し、まさ / 特許出願司令塔が最終レビューする。明細書たたき台、内部相談パック、営業秘密境界メモ、worker報告を丸ごと送る前提にしない。

## 1. 相談目的

研究シーズの事業化判断を支援する社内OSについて、国内特許出願へ進める前の初回相談をしたい。

弁理士に確認したい中心は、発明をゼロから作ることではなく、以下である。

- 既存の内部ドラフトを、出願可能な明細書・請求項・図面へ整えるための論点確認。
- 請求項を、広いAI経営支援ではなく、証拠付き候補生成、人間承認、正本反映、feedback、protocol化、outcome観測の閉ループとして書けるかの確認。
- 秘匿すべき実データ、prompt、score条件、内部運用を出さずに、実施可能要件・サポート要件を満たせるかの確認。
- 発明者、出願人、権利承継、共同発明者確認の進め方。
- 国内ミニマム出願までの費用、期間、追加サーチ要否、PCTや分割の判断時期。

## 2. 発明概要

対象は、研究機関、大学、企業研究所、又はスタートアップスタジオ等で、研究シーズの事業化判断を支援する情報処理方法、装置、及びプログラムである。

発明候補の要点は、複数種類の業務データ源から事業化判断候補を生成し、根拠となる証拠メタデータとともに人間の確認インターフェースへ提示し、承認済み候補のみを正本へ反映し、却下又はコメントを後続処理へ反映する点にある。さらに、承認済み情報から固有情報を除いた判断protocolを生成又は更新し、後日の結果観測を複数期間でappend-onlyに保持する構成を相談したい。

実データ、個別案件、内部prompt、score条件、導入運用ノウハウは、特許出願に出しすぎず、営業秘密として残す。

## 3. 請求項A/B二段構え

### A. HITL正本化ループ

主請求項候補Aは、一般的なAI抽出との差分を、証拠メタデータ、人間承認、承認済みのみの正本反映、却下・コメントfeedbackの永続化に置く。

- 複数業務データ源から事業化判断候補を生成する。
- 候補に証拠メタデータを関連付ける。
- 候補と証拠を確認インターフェースへ提示する。
- 承認済み候補のみ正本へ反映する。
- 却下又はコメントを後続候補生成へ反映する。

### B. protocol / outcome閉ループ

主請求項候補Bは、Aより狭くなる可能性がある一方、事業化判断OSらしさを強く出す候補である。

- 承認済み正本レコードから、固有情報を除いた判断protocolを生成又は更新する。
- 1つのprotocolに複数の事例を関連付ける。
- protocol又は事例に紐づくaction後のoutcomeを、複数期間でappend-onlyに保存する。
- 矛盾する観測を上書きせず、異なるhorizon又はvalenceの観測として提示する。
- outcomeに複数種類の証拠参照を関連付ける。

相談では、Aを独立請求項の中心にし、Bを独立候補、従属項、又は分割候補のどこに置くべきかを確認したい。

## 4. 送付資料候補

初回打診後に資料を求められた場合も、送る候補は次に絞る。

| 候補 | 初回扱い | 目的 |
|---|---|---|
| このショート版 | 最有力 | 相談対象と質問範囲を短く共有する |
| 請求項ツリー要約 | 必要なら送付候補 | A/B二段構え、従属項、分割候補の相談 |
| 公開済み資料確認候補の要約 | 必要なら送付候補 | 新規性喪失リスクの確認範囲を相談 |
| 発明者 / 出願人要約 | 必要なら送付候補 | 発明者、出願人、承継書面の確認 |

初回では、明細書たたき台、内部パック、現OS乖離チェック、合成実施例の裏取り、営業秘密境界メモは丸ごと送らない。必要性を弁理士に確認したあと、別途削除版を作る。

## 5. 弁理士に聞きたい5問

1. 主請求項は、A: HITL正本化ループと、B: protocol / outcome閉ループの二段構えで相談するのが妥当か。
2. 実データ、prompt、score条件、個別案件名を出さず、抽象テーブル、フロー、匿名合成例で実施可能要件・サポート要件を満たせるか。
3. outcome ledger、矛盾観測表示、複数証拠参照、system parameter governanceは、基幹出願に入れるべきか、従属項又は分割候補へ下げるべきか。
4. 法人設立前研究シーズの設立時期推奨は、従属項・補強に留めるべきか、別独立請求項も検討すべきか。
5. 発明者を代表者単独、出願人を会社とする場合、承継書面、職務発明整理、共同発明者確認として何を用意すべきか。

## 6. 送付可 / 口頭 / 送らない

### 送付可候補

- 抽象化済みの発明概要。
- 請求項A/B二段構えの要約。
- 公開済み資料の確認候補を抽象化した棚卸し。
- 発明者 / 出願人 / 承継確認の要約。
- 国内出願までの相談目的と、費用・期間・追加サーチの質問。

### 初回は送らず口頭

- 現OSとの差分、部分実装、retrofit候補。
- 匿名合成実施例の裏取り方針。
- moat、ROI、価格維持、後出し出願防止などの事業背景。
- 画面共有や追加資料を出す場合の開示制御方針。

### 送らない

- prompt、few-shot、comment変換ロジック。
- score条件、weight、threshold、calibration、正解ラベル。
- 実データ、実PJ本文、実source所在、production DB row。
- 顧客名、研究機関名、個人名、契約条件、価格、商談ログ。
- 内部source、connector認証、監視、復旧、watch対象、運用PC、抽出スケジュール細部。
- 未公開知財詳細や導入先別の実運用ノウハウ。

## 7. まさ判断事項（5個以内）

1. 初回は資料なしで打診し、求められた場合だけこのショート版候補を整えるか。
2. 事前送付する場合、資料をこのショート版 + 請求項ツリー要約までに絞るか。
3. 初回相談の予算上限を15〜30万円に置くか、30〜50万円まで許容するか。
4. 資料送付前にNDAを求めるか、弁理士の通常守秘義務を確認して進めるか。
5. WS-5 / WS-6 / outcome系を基幹出願へ残すか、従属項・分割候補寄りで相談するか。

# AMD OS / AMDプロトコル 弁理士事前送付資料セット案・送付前チェックリスト（内部版）

- 作成日: 2026-06-01
- 位置づけ: まさ / 特許出願司令塔レビュー用の内部チェックリスト
- 共有制限: 外部送付禁止。弁理士送付禁止。このまま添付・Drive共有・チャット共有しない。
- 目的: 弁理士初回相談の前に、送る候補、初回は送らず口頭にするもの、送らないものを分け、営業秘密混入と公開リスクを確認する。

## 0. 基本方針

外部相談用削除版パックをそのまま送らない。

事前送付する場合も、さらに短い送付版を別途作る。初回打診では、相談可否、料金、守秘義務又はNDA、見積もりに必要な資料範囲を先に確認し、必要最小限だけ送る。

## 1. 事前送付する資料セット案

### 送る候補

送る場合でも、以下は新しく短縮版を作る。

| 資料候補 | 初回送付での扱い | 目的 | 送付前に削るもの |
|---|---|---|---|
| 1〜2ページの発明概要 | 最有力 | 相談対象、技術分野、出願目的を伝える | 実案件名、実source、prompt、score条件、実DB、内部運用細部 |
| 請求項案の要約 | 必要なら送る | 主請求項の軸と従属項の候補を見てもらう | 内部コメント、実装固有名、狭すぎるID、営業秘密メモ |
| 明細書たたき台の抜粋 | 初回は慎重 | 発明の名称、技術分野、課題、手段、図面案だけ確認 | 実施例の内部裏取り、営業秘密境界、retrofit生メモ |
| 発明者・出願人整理の短縮版 | 必要なら送る | 発明者、出願人、承継書面の要否確認 | AI/Codex会話ログ、worker詳細、内部判断ログ |
| 公開済み資料棚卸しの短縮版 | 必要なら送る | 新規性喪失リスクの確認候補を共有 | 未確認事項の断定、具体URL、実source所在、相手名 |

### 初回は送らず口頭にするもの

| 資料 / 論点 | 扱い | 理由 |
|---|---|---|
| 開示制御版パック本文 | 口頭の進行メモとして使う | 開示ランク自体が内部運用情報だから |
| 現OS乖離チェック | 安全要点だけ口頭 | 実装パス、管理画面、DB構造、未実装箇所の詳細を残さないため |
| 合成実施例の裏取り | 要点だけ口頭 | 実案件や内部資料の所在を連想させないため |
| 図面清書指示メモ | 必要箇所だけ口頭 | 図面作成者向け内部ブリーフで、実装との距離感を含むため |
| 予算・交渉目的 | 口頭中心 | 価格維持、提携、営業上の狙いを資料に残しすぎないため |

### 送らないもの

| 資料 / 情報 | 扱い | 理由 |
|---|---|---|
| 内部版パック一式の丸ごと送付 | 送らない | 内部判断、営業秘密、worker文脈が混ざるため |
| 実データ、実PJ本文、実source所在 | 送らない | 営業秘密かつ発明説明に不要なため |
| prompt全文、few-shot、変換ロジック | 送らない | 競争優位の中核で、出願書類にも入れないため |
| score weight、threshold、calibration | 送らない | 特許化対象外かつ営業秘密として残すため |
| production DB行、実ログ、connector運用情報 | 送らない | セキュリティ・運用上の機密で、相談目的に不要なため |
| 顧客名、研究機関名、個人名、契約条件、価格 | 送らない | 初回相談の技術論点に不要で、開示リスクが大きいため |

## 2. 送付前チェックリスト

### A. 営業秘密混入チェック

- [ ] 実案件名、顧客名、研究機関名、個人名が入っていない。
- [ ] 実メール、議事録、チャット、クラウド文書、月次レポート本文が入っていない。
- [ ] 実source所在、source permalink、内部source id、長いsnippetが入っていない。
- [ ] prompt全文、few-shot、negative examples、comment-to-guidance変換ロジックが入っていない。
- [ ] score weight、threshold、calibration、正解ラベル、教師データが入っていない。
- [ ] production DB行、実ログ、connector認証、監視、復旧、watch pathが入っていない。
- [ ] 契約条件、価格、商談ログ、導入先別運用ルールが入っていない。
- [ ] 「秘匿したい情報がある」という抽象表現に留め、秘匿情報の中身を説明しすぎていない。

### B. 新規性喪失 / 公開済み資料チェック

- [ ] 公開済み資料棚卸しは、リスク断定ではなく「弁理士へ確認したい候補」として書いている。
- [ ] イベント登壇、営業資料、Web、note、公開予定原稿、外部説明資料の存在・日付・外部性・資料配布有無を確認した。
- [ ] 未確認の公開物を「公開していない」「問題ない」と断定していない。
- [ ] 発明コアの具体処理フロー、WS-1〜WS-5/WS-6のAND結合、実施例を公開資料へ出しすぎていないか確認した。
- [ ] 特許法30条例外や外国出願への影響は、内部判断で断定せず弁理士確認事項にしている。

### C. 発明者 / 出願人 / 承継書面チェック

- [ ] 発明者、出願人、AI/Codexの位置づけを短く整理している。
- [ ] 共同発明者候補の有無を、請求項の中核構成への具体的寄与ベースで確認した。
- [ ] 出願人を会社にする場合、特許を受ける権利の承継書面が必要かを質問に入れている。
- [ ] 職務発明規程、個別譲渡書、今後の共同研究契約条項は弁理士確認事項にしている。

### D. 予算上限 / 依頼範囲チェック

- [ ] 初回相談の予算上限を決めた。
- [ ] 弁理士へ頼む範囲を、出願可能化、請求項レビュー、明細書・図面整備、出しすぎ防止、手続き代理に絞っている。
- [ ] 発明設計、prompt設計、score設計、事業戦略、営業戦略を依頼範囲に入れていない。
- [ ] 15〜30万円、30〜50万円、100万円超のどの粒度で何ができるかを聞く。
- [ ] 国内出願後、PCTや分割をいつ判断するかを聞く。

### E. NDA / 守秘義務チェック

- [ ] 事前送付前に、弁理士側の守秘義務又はNDAの扱いを確認する。
- [ ] NDA締結前に送る資料は、営業秘密を含まない短縮版だけにする。
- [ ] 画面共有する場合は、実名、実データ、案件本文、内部URL、管理画面詳細が見えない状態にする。
- [ ] 相談後に追加資料を求められた場合も、内部版を丸ごと送らず、追加削除版を作る。

## 3. 送付直前の最終ゲート

1. 送付先、宛名、相談形式、料金条件を確認する。
2. 添付ファイル名に `internal` や内部管理名を残さない送付版を別途作る。
3. PDF化又は共有設定前に、本文検索で禁止語・実名・内部IDを確認する。
4. まさ / 特許出願司令塔が最終レビューする。
5. 送付後は、送付日時、送付先区分、添付資料名、NDA/守秘義務の扱い、返信待ち事項を台帳に残す。

## 4. まさ判断事項

1. 初回は資料なしで打診するか、短縮版概要だけ添付するか。
2. 初回相談の予算上限を15〜30万円にするか、30〜50万円まで許容するか。
3. 送付候補を、1〜2ページ概要、請求項要約、公開済み資料棚卸し要約に絞るか。
4. 守秘義務だけで進めるか、資料送付前にNDAを求めるか。
5. 弁理士候補の実名調査workerを別途切るか。

## 5. 残課題

- このチェックリストは送付前の内部ゲートであり、送付版資料そのものではない。
- 弁理士候補の実名リストは今回作らない。必要なら候補調査workerへ分ける。
- 別workerで批判的弁理士レビューが進んでいる場合、その結果に応じて、送付候補、送らない情報、まさ判断事項を再調整する。

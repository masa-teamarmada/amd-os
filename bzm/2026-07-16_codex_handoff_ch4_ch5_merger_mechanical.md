## slug 規律(繰り上げ時の必読事項)

Ch14 挿入時と同じ規律を踏襲する:

- **slug は原則不変**。既存 slug(`book-a-ch-1` 〜 `book-a-ch-15`、および `book-a-ch-13-5`)を新しい章番号に合わせて renumbering はしない。理由=起草中の各章ワーカー worktree のファイルパスを保護するため、および過去の commit・PR・ハンドオフドキュメントで slug 参照している箇所の互換性を維持するため。
- 統合章の slug は **`book-a-ch-4-5`**(新規採番)を推奨。既存の `book-a-ch-4` と `book-a-ch-5` の slug は**廃止扱い**(bzm-chapters.ts から削除するのではなく、status を deprecated 相当にするか、レコード自体を削除するかは、bzm-chapters.ts の実装スキーマを読んで判断する — 現状のスキーマで自然に表現できる方を選ぶ)。既存 slug を保持したい理由(過去 URL)がある場合は、統合章の slug を暫定的に `book-a-ch-4`(旧 slug 再利用)とする選択肢もあるが、意味論の混乱を避けるため `book-a-ch-4-5` を優先する。この判断は Codex の裁量でよい(判断根拠を Changelog に明記すること)。
- **繰り上げ後の章番号と slug の対応表**(結論):

## 確立済み運用ルール(必読・厳守)

### 【全面禁止】ブランチ作成

- このリポは main 一本。**あなたがブランチを切ることは絶対に禁止**。`main` 上で直接 commit する。
- 過去、Codex や AI エージェントが「ブランチを切る」デフォルト挙動でリポの整合を壊した事故があり、その反省で全面禁止となっている(詳細は `/Users/masa/projects/AMD/amd-os/CLAUDE.md` の「ブランチ作成は全面禁止」節)。
- 唯一の例外はまさが明示的に「ブランチ切って」と言った場合のみだが、本プロンプトではその例外は該当しない。

### コミット・プッシュ規律

- 論理単位ごとに小刻みに commit する(全変更を1つの巨大 commit にまとめない — 例: §1 の MASTER_PLAN、§2 の STORY_WORLD、§3 の NARRATIVE_DESIGN、§7 の本文前方参照、§8 の bzm-chapters.ts は別 commit にする)。
- commit の直前に必ず `git fetch origin main` を実行し、他セッションが並行して push している可能性を検知する。rejected なら `git pull --rebase --autostash` で取り込んでから push。パイプで一発化せず、fetch → pull → push を単独コマンドで実行して各ステップの成否を確認。
- **他の未追跡ファイル(例: `pwa/bzm/2026-07-14_frontmatter_gairei_draft_v1.md` などの他セッションの未完成下書き)を絶対に stage しない・commit しない・touch しない**。`git add` は必ず対象ファイルをフルパスで明示指定し、`git add .` や `git add -A` は絶対に使わない。
- コミットメッセージは日本語、`docs(bzm): ...` 形式、以下の Co-Authored-By 行を必ず含める:
  ```
  Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
  ```
- push は origin main へ直接。
- 破壊的操作(`git reset --hard`・`git checkout --`・`rm -rf`・`git push --force`・`git commit --amend`)は絶対に使わない。pre-commit hook の失敗時も `--no-verify` は使わず、hook のエラー内容に従って修正してから新規 commit を作る。

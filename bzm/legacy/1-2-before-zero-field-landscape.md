# Before Zero とは何か — 会社になる前に勝負が決まる場所

> この章は何か: BZM の数式へ入る前に、Before Zero の現場で何がまだ不確実なのかを読むための入口です。ここではモデルを説明するのではなく、研究・技術・知財・人・制度・顧客がまだ形になりきっていない段階を、AMD がどう観察するかを整理します。

## 1. Before Zero は「法人設立前」だけではない

Before Zero は、単に法人登記の前という意味ではありません。研究成果が会社・事業・市場の形を取る前に、勝負の大半が決まっていく領域です。

この段階では、次のものが同時に未確定です。

- 研究成果が、事業で使える技術になるか
- 技術を守る知財と、論文・発表の順序を両立できるか
- 誰が事業化の責任を引き受けるか
- 大学・研究機関・企業・VC・行政の期待値が揃うか
- 顧客が本当に困っていて、対価を払うか
- いま会社化してよいのか、まだ待つべきか

BZM はこの混ざった不確実性を、あとから `σ_SU`、XRL、FRL、AMD Score、ERS として測れる形に分解します。ただし読む順番は逆です。まず現場で何が起きるかを見て、その後で「それが理論上どの変数に入るのか」を確認します。

## 2. 会社化の前に決まるもの

Before Zero では、資本金や登記より先に、次のような「後から変えにくい初期条件」が決まります。

| 初期条件 | 現場での問い | 後半の理論で接続する章 |
|---|---|---|
| マクロの追い風 | この領域はいま社会・産業・政策・研究の流れに乗っているか | [マクロ環境 σ_SU](2-1-sigma-su-triple-helix.md) |
| 技術の芯 | 研究成果はどこまで再現でき、どこから開発課題になるか | [XRL 群](3-1-xrl-group.md) |
| 顧客・用途 | 誰のどの課題に効き、検証順序は何か | [XRL 群](3-1-xrl-group.md) |
| 制度・規制 | 出せない情報、踏むべき認証、標準化の道筋は何か | [XRL 群](3-1-xrl-group.md) |
| チーム | 研究者、候補 CEO、AMD、大学側が何を担うか | [XRL 群](3-1-xrl-group.md) / [FRL](4-1-frl-founder-readiness.md) |
| 創業者 | この人は不確実性の中で前に進めるか | [FRL](4-1-frl-founder-readiness.md) |
| 苗床 | 研究機関側に、案件を継続的に生む仕組みがあるか | [ERS](7-1-ers-ecosystem-readiness.md) |

## 3. Before Zero の典型フェーズ

厳密なフェーズ名は PJ ごとに変わりますが、AMD が見る現場はだいたい次の順に進みます。

| フェーズ | 起きること | 典型的な鬼門 |
|---|---|---|
| 探索 | 研究シーズ、研究者、制度、周辺市場を広く見る | 良い技術と良い事業を混同する |
| 事業化仮説 | 用途、顧客、知財、担い手を仮に置く | 研究者の期待と顧客の困りごとがズレる |
| 外部接触 | 企業、VC、行政、大学本部と話し始める | 出してよい情報と出してはいけない情報を間違える |
| 設立準備 | CEO 候補、共同研究、PoC、資本政策を組む | 会社化が早すぎる、または遅すぎる |
| Zero | 法人・事業として外に出る | 初期条件の歪みが一気に表面化する |

このフェーズ表は、後半の理論を置き換えるものではありません。むしろ理論章を読むための地図です。例えば「会社化が早すぎる」は、後半では TRL、BRL、HRL、FRL、`σ_SU`、律速軸の組み合わせとして説明されます。

## 4. この先の読み方

次章からは、Before Zero の現場で実際に起きるズレ、判断分岐、関係構築、失敗学習を順に見ます。その後で、BZM を構成する現場要素を一度すべて棚卸しし、最後に理論章で数式・rubric・検証へ入ります。

読者はまず「この場面、見たことがある」と感じることを優先してください。数式は、その現場感覚を後から再現できるようにするための道具として出てきます。

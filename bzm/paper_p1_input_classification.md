（`bzm/tools/dual_scoring.cjs` も `model/tools/bzm30_score_seeds.cjs` も実行していない。DBへの書き込みもしていない）。

## 0. このやり直しの理由

前回の分類（`bzm/paper_p1_dual_scoring.md`、`bzm/tools/dual_scoring.cjs` の `CLASSIFICATION.maskedB`）には
査読で方法上の欠陥が指摘された。「まさへの聞き取り由来」と判定した項目を一律に参照実装の既定値へ戻していたが、
**記録が値そのものを持っている項目や、値を制約する境界を与えている項目まで、区別せずに既定へ戻していた**。
本タスクは分類のみをやり直し、計算は行わない（計算は別セッションが本ファイル確定後に行う）。

## 1. 分類の規則（全項目へ一様に適用した3条件）

各案件・各パラメータについて、AMD OS のデータベースの記録だけで何が言えるかを判定する。

- **(a) 記録が値を持つ** → 記録にある値をそのまま使う。
- **(b) 記録は境界だけ与える** → 境界の内側で最も情報の少ない点（＝境界の値そのもの）を使う。
- **(c) 記録が完全に沈黙している** → 参照実装の既定値（モデルページ§6.I-9-3「Tier 0 の代表案件の前提」）へ戻す。
  真に聞き取りでしか得られない値だけがここに入る。

判定の際に適用した原則:

1. 「まさが把握している」と reason に書いてあっても、その内容が議事録・資金繰り表・契約書・特許庁データベース・
   経営シグナル（project_strategy_signals）・project_knowledge など**文書として存在する**なら (a) か (b)。
2. 公開情報（特許公報・公募の採択結果・報道・業界の周知の逆風など）で同じ結論に届くなら (a)。
3. 「まさに聞かなかったら、この値は何になっていたか」を毎回自問する。記録が値も境界も与えないときだけ (c)。
4. 迷った場合は (a)/(b) 側に倒す——(c) を過剰に取ると効果を水増しするため。
5. 順序尺度（証拠水準など）は、記録が単独で立証する下限と、まさの情報が否定する上限を分けて考える。
   下限が記録だけで成立するなら (a)。
6. 値の導出が「中立値からの加減算」のように明示的に複数項へ分解されている場合、記録で説明できる項と
   まさの情報でしか説明できない項を分け、記録だけで説明できる部分の値を (b) の境界として使う
   （本タスクで新たに確立した運用。詳細は §4）。

## 2. 実際の判定方法（監査可能性のために明記）

DB の `seed_bzm30_inputs` の `*_reason` 系欄（`self_revenue` のみ `self_revenue_note`）を21件・全パラメータ
読んだうえで、各項目に「まさ (日付) `発言引用`」という帰属表現があるかを機械的に走査し、該当した項目だけを
個別に精査した（帰属が無い項目は、汎用の書式・定型句を除けば案件固有の私的情報に依存しないため、原則 (a)）。
精査では以下を裏取りに使った。

- **`project_org_observations`**（組織状況の観測。`source_tag` 列で情報源を機械可読に記録）。全5件を確認し、
  すべて `source_tag='masa'`・`created_at=2026-08-28T08:04:33`（本評価と同時期に一括作成）であることを確認した。
- **`project_knowledge`**（21件対象PJで計1,744行）。`source` 列の値で標準記録（`drive:*`・`meeting:*`・
  `codex_clg_review_*`・`j-platpat:*`・`manual`・`pj_basic_facts_sync` など、評価期間より前の日付を持つもの）と、
  `masa_direct_2026082[6-9]*`（本評価期間中にまさへの聞き取りを直接書き起こしたもの）を区別した。
- **`project_strategy_signals`**（経営シグナル。日付とconfidenceを持つ構造化レコード）。
- **`project_valuation_rounds`**（資金調達ラウンドの実績記録）。reason 欄が引用するラウンドが実際にこの表へ
  入っているかを確認した。
- 一般的な業界動向・特定の資金調達の実在については、可能な範囲でWeb検索により裏取りを試みた。

この裏取りにより、**「ヒアリング」「聞き取り」という語が reason に出てくること自体は (b)/(c) の根拠にならない**
ことが分かった。誰への聞き取りか（まさ本人か、大学・投資家など第三者との商談記録か）、いつの情報か
（本評価期間中に新規に得たものか、それ以前からOSに立っていた記録か）で判定が変わる。

（＝既定へ全戻しにはしない）。確信度は4.1・4.2より低いことを明記する（§6でも「迷った項目」として再掲）。

## 1. 推奨アーキテクチャ — 「読者のジョブ」で切る3層 + 共通基盤

```
[学術層]  940p モノグラフ (Cambridge UP / Before Zero Studies)   ← 理論の正本・引用アンカー
    ▲ 「発展」ポインタ                          読者: 研究者・査読者
[教育層]  Book A 教科書 (15章セメスター型 + 演習パッケージ)      ← 講義・研修採用で売る
    ▲ 「さらに学ぶには」ポインタ                 読者: MBA/MOT院生・学部上級・教員・研修
[現場層]  Book B 解説書 (実戦書17章の統合改修 + RT部)            ← 現場の緊急ニーズで売る
                                               読者: URA/産連/EIR/研究者 (主)、VC/事業会社 (従)
共通基盤: BOOKS_PORTFOLIO.md (新設) / terminology_glossary 3冊共通正本化 /
          冊子横断ケース露出台帳 / 共通図版ファミリー
```

書き分けは「同じ理論の解像度違い」ではなく**読者のジョブの違い**で切る:
- **B = ツールと台本** (診断シート・チェックリスト・面談スクリプト・順序ロック)
- **A = 体系と演習** (15回シラバス・ケース討議・採点課題・Instructor's Manual)
- **モノグラフ = 導出と定理** (証明・識別・事前登録)

カニバリ回避の数値規律 (提案): 概念フレームワークは100%共有 / 散文の重複15%未満 / **章頭ストーリーは冊子間0%共有** (public-manuscript の別場面から採る) / 主要ケースは冊子間で主戦場排他 / A と B の刊行は12ヶ月以上離す。

判定テスト: 「URA が書店で A と B を両方手に取ったとき、迷わず B を選ぶか」— 迷うなら設計が悪い。**A の個人購買は期待しない** (A は講義・研修採用の B2B 商品として設計する)。

## 2. Book A (教科書) 設計案

### 2-1. 主対象 — ⚠️ 元の依頼からの変更提案

依頼は「MBA 1年生 or 経営学部1年生」だったが、**学部1年は明示的に捨てる**ことを推奨する。

- 理由: (a) 学部1年入門の棚は忽那ら『アントレプレナーシップ入門』(有斐閣ストゥディア、262p・2,200円) の牙城で正面衝突して勝てない。(b) BZM は readiness 概念・確率×期待値・知財制度の前提知識を要求し、薄めると評価装置としての独自性 (=採用動機) が死ぬ。(c) 学部1年の入口は Book B が担える。
- 推奨主対象: **MBA/MOT 大学院1年 (主) + 大学院共通アントレ科目 + 学部3-4年ゼミ + URA/EIR/VC 研修市場**。本文の読解水準は学部上級に合わせ、深さは Box と発展演習で出す。

### 2-2. 体裁・構成

- A5判 / 320-360p / 本体3,200-3,600円 / **15章 = 半期15回に1:1対応** (採用の絶対条件)
- 章型 (全章統一): 章頭ミニケース (意思決定直前で切る) → **標準理論 (was) → deep-tech Before Zero での破綻点 (but) → BZM の拡張 (therefore)** → ツール → 章頭ケースに戻って答え合わせ → 演習 → 章末の問い + モノグラフ読書案内
  - この3拍子構造は「自社フレームワーク宣伝本に見える」という無名著者最大の致命傷への唯一の構造的解毒剤。全章に適用。
- 部構成: 第I部 Before Zero という時間帯 (1-4章) / 第II部 案件を測る PRS (5-9章) / 第III部 苗床を測る ERS (10-11章) / 第IV部 動かす — RT・チーム・知財還流 (12-14章) / 終章 総合演習 (15章)
  - 「**観測二層 (PRS/ERS) + 行動一層 (RT)**」の三部構成が教科書としての BZM の背骨。
- 15回シラバス詳細案・標準理論の配置マップ (Timmons→PRS、Klepper→タイミング、Triple Helix→σ_SU、リーン→BRL、実物オプション→GO、エフェクチュエーション crazy quilt→RT 等) はワークフロー出力に完成版あり (ダイジェスト: scratchpad/workflow_digest.md 視点2)。

### 2-3. 数式の見せ方 — 4層 one-way dependency (3冊共通規律に昇格提案)

| 層 | 内容 |
|---|---|
| 本文 | 直感・グラフ・数値例のみ。式は各章2本まで。記号より日本語名 (「追い風指数」「創業者資質」) を主 |
| Box「式で見る」 | 式1本 + 記号読み下し表。飛ばしても本文が読める旨を毎回明記 |
| 章末 | Excel で完結する計算ワークシート |
| 巻末 | 導出は載せずモノグラフ章番号への参照のみ |

個別裁定: Cobb-Douglas 乗法と ERS 加重和は本文OK (掛け算の性質と GPA アナロジーで高校数学完結)。CES は「弱い方に引っ張られる補完性」の直感まで。**first-passage・状態空間モデル・不可能性定理・Kmenta 識別は教科書に登場させない** (「τx と τy のタイマーレース」メタファー + Excel シミュレーション演習で置換)。

⚠️ 批判レビューで潰された教え方: 「掛け算=一つゼロなら全部ゼロ」を看板にする案は**確定モデルと矛盾** (実装は +1 シフトでゼロ落ちしない / S 内部は明示的に代替的 — JC 自走型が反例)。正しくは3層で教える: **P×R×S トップ層 = 乗法の直感 / S 内部 = 代替的 (σ_SU 低くても F で補える) / F 内部のみ CES 補完的 (両方必須)**。この3層対応表を terminology_glossary に正本化し、A/B の Box はそこからだけ引く。

### 2-4. 差別化資産 = 演習パッケージ

- 架空シーズカード20枚 (PRS 採点演習)、RT 役割カード7種 (組成ロールプレイ)、ERS セルフ評価課題、PRS/ERS 採点ワークシート (Excel + AMD OS 画面の教育開放も検討価値)
- Instructor's Manual (章別スライド・解答・teaching note・試験バンク) は**執筆と同等の工数**。ただし初版1,500-2,500部の教科書に出版社は付属物制作費を出さない → **AMD の持ち出し = 営業装置・研修商材への投資として損益を切り分ける**。
- YD (即落 NO_GO)・TIEM (ゾンビ型 WAIT) による survivorship bias の解毒 = 「やめる判断・待つ判断を教えられる教科書」は日本に存在しない。A/B ケース分割 (A=あなたは GO を出すか、で討議 / B=実際の帰結) で運用。
- 必須図版: **PRS≠GO の1ページ図解** (PRS は優先順位スコア、GO は2軸ゲート。「PRS 高だが WAIT」の設問を演習に必ず1問) — 誤読誘発の最大ポイントを塞ぐ。

### 2-5. チャネル戦略 — 教科書は属人ネットワークで採用される

教員は「タイトルが科目名に合う本」ではなく「知っている著者・使った経験・学会で回ってきた本」を採用する。現時点で教員ポスト・採用ネットワークがゼロという最大の欠落への処方:

1. **二段ロケット化**: 初版は「履修証明プログラム/URA研修/EIR育成の指定教材」として B2B・機関一括販売 (オンデマンド印刷可) → 採用実績と改訂フィードバックを持って第2版で版元流通 (中央経済社等が第一候補)。
2. **共著者戦略**: アントレ科目担当経験のある実名教員を共著者/監修に迎える (チャネル・信用・改訂体制を同時に解く。AMD の差別化は rubric とワークシートに宿るので本文共著で失われない)。学会報告実績づくり (研究・イノベーション学会、日本ベンチャー学会) と並行。
3. **講義実績の先行確保**: まさ自身の非常勤/集中講義/寄附講座を2027年度に1件確保する活動を執筆より先に開始。
4. **go/no-go 基準の明文化**: チャネル (講義 or 研修採用先) が1件も確定しないなら商業教科書としては見送り、研修テキストに縮小 — BZM 自身の GO/WAIT/NO_GO 論理を出版計画に適用する。

タイトル戦略: 主タイトルは科目名に載る語 (案: 『ディープテック起業の経営学 — 会社設立前 (Before Zero) から設計する大学発スタートアップ』)。「Before Zero」は副題で育て、シリーズ冠は Before Zero に統一 (商標調査を先に)。

## 3. Book B (解説書) 設計案

### 3-1. 骨格 — URA 視点案を本体に採択 (推奨)

ワークフローで URA 案 (大学側主語・4部16章) と VC 案 (読者レーン型・5部26章) が並立したが、**URA 案を本体に採択**を推奨: 購買チャネルが実在し (RA協議会・UNITT・JST/NEDO 研修 = 機関経費購買で価格弾力性低)、著者の一次経験と主語が一致し、匿名ケースへの許容度も高い。VC/事業会社向けは「既存VC評価軸→PRS変換表」と「RT参加判断チェックリスト12項目」を章内ツール + 巻末付録に圧縮吸収。フル展開は B の実売を見て第2弾 (別書/ホワイトペーパー) で判断。

**推奨骨格** (A5判 260-300p、序章+4部16章+付録。各章型 = 痛点ストーリー → 道具 → チェックリスト/rubric → 「明日やること3つ」):

- **序章** 会社設立前がすべてを決める (public-manuscript/00-prologue「強すぎた一文」を昇格) + 読者別ナビゲーション
- **第I部 物差しを持つ** (4章): PRS 言葉版 / GO 判定 =「まだ作らないでください」を言う技術 / 社長は誰か (F_char×F_cap 言葉版・EIR実務) / 自機関を測る ERS 8軸セルフ診断
- **第II部 機関を整える** (3章): 規程整備の順序 (軸7 ロードマップ: 認定制度→COI→株式保有→IP-equity→ファンド) / GAP+URA+EIR を一本の導線に / 「ベンチャー数」の罠 (Goodhart)
- **第III部 ラウンドテーブルを組む** (4章、本書の目玉): 協定はなぜ動かないのか (RT成立条件と「中身ゼロ連携」の分水嶺) / 地域型RT (地銀・自治体・地元企業) / 用途横断型RT (非独占 field-of-use・take-or-pay) / 8フェーズ・順序ロック・CRL
- **第IV部 先生が一歩を踏み出すとき** (5章、研究者本人向け): 早すぎ起業の解剖 / 退路・お金・家族 / 株・学生・COI / 社長にならない起業 (創業科学者という選択) / やらかし図鑑ダイジェスト
- **付録 = ツール集** (DL特典): ERS 28サブ軸診断シート / 認定規程チェックリスト / RT組成チェックリスト / GAP審査 rubric 雛形 / 研究者面談スクリプト集
  - 「本文より付録で売る」のが制度実務書の定石 — 機関一括購入の稟議を通すのは付録。

### 3-2. 主語の転換 (Book B の信頼性を決める最重要判断)

RT 理論は AMD=keystone 経営当事者の視点で書かれているが、そのまま書くと**大学読者には「AMD の営業資料」に見えて死ぬ**。主語を「研究機関ノード (⑥ = 知財の源泉かつ還流先・代替不可)」に転換する。ただし理論の中核区別を守る:

> **RT の主宰者は定義上、中心 DTSU であって大学ではない** (大学・協議会が主宰する多者連携は RT ではなく「多中心の平場」= §4.3 の❌事例)。機関の役割は「主宰」ではなく、**点火を可能にする土壌** (正門・雛形・規程) の整備と、代替不可ノードとしての交渉。

この線引き表を第III部冒頭に明記する。これは理論保全であると同時に、AMD の差別化資産 (RT組成力 = F_cap_amd) の無償公開を自然に回避する。

### 3-3. RT 部の出荷ゲートと二段刊行

RT は v0.1 で、独禁 (§7.3 field-of-use 分割の垂直ライセンス構成) 未確認・実地検証 (SX/EWIR・KENQ) 未了。**目玉 = 最も未検証な部分**という構造をスケジュールに翻訳する:

- **Book B v1 = RT lite**: 概念 + 成立条件 + 呼べる/呼べない線引き + 順序ロック + 点火KPI + 「型化できるのは地雷探知機と順序ロックまで、点火と政治は型化できない」(§9.3) の正直な留保。CRL は判定演習・❌事例集形式で公開 (白紙チェックリストの DL 配布はしない — 攻略ガイド化を防ぐ)。
- **RT 増補 (別冊/増補版)**: 契約粒度 (field-of-use 条項・take-or-pay 設計・二層経済の実装) は「独禁法務確認完了 ∧ 実地点火の事後観測1件以上」を印刷ゲートに。版元とは最初から二段刊行で握る (増補は版元にとって再販機会なので商業的にも正当)。
- 監修クレジット: 弁護士 (独禁・契約)・会計士 (take-or-pay の負債性)・現役URA (実名) の3監修を奥付に — 法的リスク対応と無名著者の信用補完を兼ねる。

### 3-4. フレーミング

「起業を止める本」は研修・政策チャネル (SU創出数を増やす建付けの予算) から敬遠される。公式フレームは「**死なない会社だけ作る**」「成功率を上げるための設立前設計」で統一し、WAIT/NO_GO は成功率向上の手段として語る。

## 4. RT × BZM 理論組み込み設計案 (本丸)

### 4-1. 原理 — 「ストックは軸に、フローはレンズに」の対称適用

BZM には既にこの設計原理が確立している (戦略余力を第10軸にせず S の動学層に / CRL を独立軸にせず P/R/S ドライバーの観測レンズに)。**ERS 側にも対称適用する**:

| | PRS (個体) | ERS (苗床) |
|---|---|---|
| 低速ストック → スコア本体 | XRL/FRL/P rubric | 8軸×サブ軸 rubric (+ 最小サブ軸追加) |
| 高速フロー → 観測レンズ | **CRL L0-L5** (設計済み) | **ICT (新設提案)** — 加重和に足さない |

### 4-4. 三項構造の理論的位置づけ — RT は ERS→PRS 伝達機構の観測可能な実体

まさの洞察「DTSU の RT 形成は出自機関の RT 形成ケイパビリティに依存する」の定式化 (二段):

1. **高速・案件単位 (順方向)**: Ch 8 の S 動学は jump intensity λ_x(σ_SU, ERS) で既に ERS 依存を持つがブラックボックス。RT 事象はこの中身に観測可能な実体を与える。ただし批判レビューの重要な修正: **CRL L2 の典型事象 (予算化・与信・take-or-pay 署名) は「金」なので y 側のジャンプ/μ_y の drift 改善**であり、λ_x (技術完成側) に効くのは実装ノード由来の事象 (実証フィールド・量産能力→TRL/BRL) だけ。「RT 事象は主経路タグに応じて y ジャンプ / μ_y drift / σ_SU / λ_x に振り分けられ、機関ケイパビリティ (ICT) はこれら事象の到来強度全体の共変量」と書くのが正しい配線。
2. **低速・機関単位 (双方向)**: Ch 10.7 Murmann 双方向 coupling の Ψ に機関横断の異質性を与える分解仮説 **Ψ_j = Ψ̄ + β·ICT_j + ε (予測 β>0)**。RT は Ψ の全体ではなく観測可能な一成分。さらに RT は法人化前 (pre-B) に作動する coupling キャリアなので、**Murmann coupling の「法人化前カーネル」という BZM 固有の拡張** = Before Zero Studies の新規性主張に直結する (Murmann 原典は法人設立後の共進化しか観測していない)。
   - ただし Ch 26b への即時事前登録は識別不能 (ICT 当面≈0、機関 N=3-7) なので「ICT 測定開始の事前登録」に格下げし、β 推定の登録はデータが立ってからの追補とする。

### 4-5. 2類型のチャネル写像と計上規則

| | 地域型 (SX/EWIR) | 用途横断型 (KENQ) |
|---|---|---|
| 主に動く因子 | ΔR 大・ΔS 大 (P は弱) | **ΔP 大**・ΔR 中・ΔS 中 |
| 観測変数例 | 与信枠設定額 (→y 月数換算)、自治体予算の議会通過、実証フィールド提供契約 (→TRL/BRL)、行政参画 (→μ_G) | take-or-pay 署名数量・金額、プリペイメント着金 (→y)、field-of-use 条項数、国費採択公知化、コミット済み累積量/次用途採算閾値 (§4.6「数でなく量」) |

**take-or-pay の3分割計上** (R_net の定義保全): (i) プリペイメント入金 → y (現金月数) / (ii) 署名という紙 → P 証拠の質 + BRL / (iii) 将来数量コミット → drift μ_y の期待改善。**実現済みでないコミットを R_net に計上しない**。

**二重計上ガード (組み込みの前提条件)**:
- **単一事象台帳 + 排他的主経路割当**: RT 関連の全事象 (与信・予算通過・take-or-pay・参画) を1つの台帳に持ち、各事象に主経路タグ (y / P証拠 / BRL / μ_G / μ_I / drift) を1つだけ付与。
- **leave-one-out 規則** (批判レビューが特定した最大の抜け穴への処方): 案件 i の S 計算に使う λ_x の ERS 引数は、案件 i 自身の RT 事象由来の寄与を除いた **ERS_{-i}** とする (ICT は「他案件・将来案件への土壌効果」の観測に純化)。σ_SU 控除規則の対称拡張として rt_roundtable_theory.md §13 に1段落追記すれば足りる。
- **点火事象の帰属タグ** (DTSU経営/機関窓口/外部): F_cap_amd への計上と ICT への計上の重複を防ぐ。「RT形成は機関ケイパビリティに依存」と「RT組成力は AMD の中核価値」は両立するが、同一事象を両方の手柄に数えた瞬間に反実仮想 F_cap(全員)−F_cap(AMD抜き) が壊れる。
- UI 禁止事項: ICT×ERS や CRL×PRS の合成単一スコア表示を UI レベルで禁止 (二層非可換性定理の運用形)。

# AMD OS ローカルAI

2026-10-26: Windows PC上で資料検索と出典付き回答を行う、独立した単一利用者向けの試用サービス。
PWA / iOS / macOSの画面や書込み経路から独立して動く。SOLだけは、明示指定を受けた既存DBの構造化情報を一方向に読み取る。
この段階では研究機関向けの本番環境や機関内完結の認定を意味しない。

## 利用方法

1. デスクトップの「AMD OS ローカルAI」を開く。画面は `http://127.0.0.1:17840/`。
2. 「架空資料で試す」で架空の議事録2件を取り込む。
3. 「資料を調べて回答する」で担当と期限の変更を確認する。
4. 回答下の出典本文と行番号を照合する。回答は整理案であり、正式な決定ではない。

対象を「SOL — OSの取得済み情報」へ切り替えると、SOLだけの保存済み情報を検索する。
「SOL情報を更新」で取得し直せる。取得日時と件数を表示する。自動同期や本番への書込みはない。
「SOLの直近の会議で決まったことと、次の対応を整理して」などを質問できる。
架空資料とSOLは別の検索DB・回答ルールを持ち、切替時に前の回答・原文表示を消す。

許可された自分の資料は「このPCから資料を選択」から取り込む。
対応はUTF-8の `.txt` / `.md` / `.csv` / `.tsv` / `.json` / `.jsonl`。1件50万文字、500資料まで。
PDF、画像、音声の取り込み、資料の共有、AMD OSへの書込みは未実装。
資料を削除すると、次回以降の検索対象と本文表示から外れる。端末の物理媒体からの完全消去ではない。
質問と回答はブラウザ表示と処理中のメモリにだけ置き、アプリの履歴DBやログへ保存しない。
ブラウザ拡張、Windows、GPUドライバー等の振る舞いまでは本サービスで制御しない。

## 構成・費用

- Python 3.11以上の標準ライブラリ、SQLite FTS5による日本語2文字単位の検索。
- 公式Ollama **0.40.11** のWindows amd64配布物をSHA-256照合後に展開。
- モデルは **Qwen3 4B Instruct、Q4_K_M**。ダウンロード後のdigestを端末へ記録する。
- ソフト・モデルによる新たな月額契約、外部AIの従量料金は不要。
- PCの電気代、既存回線、既存のAMD OSや開発ツールの契約は別。
- 電気代の計算例: `0.1kW × 8時間 × 30日 × 31円/kWh = 744円/月`。
  100Wと31円は仮定であり、端末の実測値やユーザーの契約単価ではない。既存作業との重複分もある。
- 将来のバックアップ媒体、無停電電源、専用サーバー、保守費用は今回購入していない。

実行先は `%LOCALAPPDATA%\AMDOS\amie-local-ai\`。モデル・検索DBはGitやDriveに入れない。
端末の暗号化やバックアップは別の運用事項。DB自体は平文で、単一Windowsアカウントの信頼境界を使う。
インストール時に実行先フォルダの継承ACLを外し、現在のWindowsユーザーとSYSTEMへアクセスを限定する。

## セットアップ・起動

モノレポのルートから実行する。WSL / Docker / 有料AIのキーは不要。

```powershell
python services/amie-local-ai/setup_runtime.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File services/amie-local-ai/install_app.ps1
python "$env:LOCALAPPDATA\AMDOS\amie-local-ai\app\start.py" --pull
```

`ExecutionPolicy Bypass`はこの1プロセスのローカルスクリプト実行に限定し、Windowsの恒久設定を変更しない。
`setup_runtime.py` は約1.6GBの公式配布物、`--pull` は約2.5GBのモデルをダウンロードする。
このセットアップ通信では、取り込んだ資料や質問を送らない。

通常はデスクトップの入口から起動する。自動起動は既定OFF。
必要な場合だけ `install_app.ps1 -AutoStart` で当該ユーザーのログイン時に起動する。
常駐処理は非表示。スリープ中・PC停止中は使えない。Windowsの電源設定やファイアウォール設定は変更しない。

## 通信・権限の境界

- 画面は `127.0.0.1:17840`、AIは `127.0.0.1:11439` のみ待受け。LAN・外部へ公開しない。
- `OLLAMA_NO_CLOUD=1`、1モデル・1質問の同時処理。外部AIへのfallback、外部検索、ツール実行なし。
- アプリからのAI通信は固定のループバックURLだけ。システムのプロキシとHTTP転送を使わない。
- 許可したHost/Originと、画面にだけ配るランダムな操作tokenを照合。CORS許可なし、埋込み禁止、本文のHTML実行なし。
- 同じPC・ユーザー権限の別プロセスを攻撃者として隔離するものではない。共有端末・複数利用者向け認証は未実装。
- Ollamaのクラウド機能停止はOS全体の外向き通信遮断と異なる。完全な閉域構成にする際は、
  別途ネットワークの送信制御・ブラウザ管理・ログ・バックアップを含めて検証する。
- 資料は指示として実行せず、参考データとしてAIへ渡す。出典番号は存在範囲を検証するが、
  その出典が回答を意味的に裏付けるかは人が確認する。
- 回答ルールはローカルDBで版管理し、画面で全文閲覧・編集可能。旧版は保持する。

## SOLの読取り接続

2026-10-26、まさが最初の対象としてSOLを指定。既存の社内向け保存済み情報を対象に、次だけを取得する。

| 対象 | 初回取得件数 | 条件 |
|---|---:|---|
| 会議要約・決定・進捗・次の対応・課題 | 119 | PJ=`p21`、会議日が取得日以前、upcomingを除外 |
| 工程 | 0 | PJ=`p21`、削除済みを除外 |
| 課題 | 17 | 同上 |
| 対応 | 19 | 同上 |

計155件。対象はSOLの社内情報であり、一般公開・外部共有可能という意味ではない。
全業務面・原本ファイル・DD資料・メール本文・会議全文を網羅する接続ではない。
読み取る表・列・PJと接続先ホストをコードで固定し、全ページを空ページまで取得する。
秘密値は既存のローカル設定から専用の取得処理だけが読み、AIプロセスや新しい設定へコピーしない。
既存の管理者用資格情報を使うため、DB側でp21だけに制限された資格情報ではない。
この試用では固定された読取り処理で範囲を絞る。本番機関別配置では専用の権限へ置き換える。

更新ボタンの取得処理は別プロセスで実行し、任意のURL・PJ・表・設定ファイル・コマンドを画面から指定できない。
本番へ送るのは読取り要求だけ。本文・AI回答・資格情報は作業ログへ出さない。
メールアドレスと外部URLはこの試用に不要なので、ローカル資料から省略する。匿名化を保証する処理ではない。
取得が全件成功してからローカルDBを一括置換し、削除済み・対象外になった前回資料を次回検索から除く。
取得エラー時は前回資料と取得日時を保持する。全件取得に成功して対象0件になった場合は、ローカル側も空にする。

初回の接続先設定は、元からある設定ファイルのパスだけを保護されたLocalAppDataへ登録する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File services/amie-local-ai/install_app.ps1 -SolEnvFile C:\projects\AMD\amd-os\pwa\.env.local
```

CLIで更新する場合は、同じルートから次を実行する。

```powershell
python services/amie-local-ai/import_sol.py --env-file C:\projects\AMD\amd-os\pwa\.env.local
```

## 検証

```powershell
python -m unittest discover -s services/amie-local-ai -p "test_*.py" -v
```

日本語検索、削除後の検索除外、入力拒否、回答ルールの版保存、不正出典拒否、外部HTTP転送拒否、
他サイトからの操作拒否、根拠が無い場合にAIを呼ばないことを確認する。
実機のGPU認識、架空資料での回答、根拠不足時の応答と所要時間は実モデルで別途確認する。

2026-10-26実機確認: 12検査成功。架空議事録2件で担当・期限の変更を正答し、予算未決定も出典付きで回答。
初回はモデル読込みを含め53.3秒、準備済み状態の予算質問0.8秒、資料比較0.9秒。
短い架空資料での単発実測であり、長い実資料の速度や精度を保証しない。
モデル全体のGPU配置（約3.88GB）、context 8192、クラウド機能停止の起動ログ、両ポートのloopback待受けを確認。
端末内の設置済みコピーへ切替後も、Chromeで資料比較と出典表示を確認した。
SOLでは155件から資料を取得し、出典付き回答1件を6.15秒で生成した。実資料の本文・回答は作業ログへ出さず、
回答が存在し、全出典がSOL側だけであることを確認した。実資料の回答内容の正しさは別途、人が根拠と照合する。
Chromeの対象切替・「SOL情報を更新」も操作し、155件と新しい取得日時が表示されることを確認した。

# SPEC.md — Project Share 恒久仕様

正本。PJ別インスタンスの実装詳細は各インスタンスの `README.md`（[`vsx/README.md`](vsx/README.md)、
[`cx/README.md`](cx/README.md)、[`se/README.md`](se/README.md)、[`sx/README.md`](sx/README.md)、
[`zmp/README.md`](zmp/README.md)、[`kute/README.md`](kute/README.md)）を見る。ここには、インスタンス横断で守るべき
恒久仕様だけを置く。

## 目的

PJ関係者・社外協力者へ、AMD OS本体のログイン（Supabase Auth）を要求せずに、
PJごとの許可メールアドレスと共有パスワードで資料・ファイルを共有する。1インスタンス = 1 PJ = 1 独立
Vercelプロジェクトとし、AMD OS PWA 本体の認証・データとは分離する。

## 認証モデル（恒久）

- 環境変数3つ（アクセスパスワード、HMAC署名鍵、許可メール一覧 `<PJ>_ALLOWED_EMAILS`）を
  Vercel環境変数にのみ置く。実値はリポジトリ、HANDOFF、チャットへ書かない。
- `<PJ>_ALLOWED_EMAILS` は、カンマ・セミコロン・改行・空白のいずれでも区切れる完全一致
  メールアドレス一覧として解析する。各値はtrim後に小文字化して正規化し、簡易的な形式検証を
  行い、重複は除外する。未設定・空・不正な値を1件でも含む場合は認証設定不足として`503`を返し、
  認証をバイパスしない（アクセスパスワード・署名鍵が未設定の場合と同じ扱い）。
- ログインフォームはメールアドレスとパスワードの2フィールドを持つ
  （`autocomplete="username"` / `autocomplete="current-password"`）。未認証GETはログイン画面
  のみ返す。
- メールアドレスは許可リスト照合用の識別子であり、メール受信や所有を確認するものではない。
  この方式を多要素認証またはメール認証とは扱わない。
- POST時はメールアドレスの許可判定とパスワード照合を両方評価してから可否を決める
  （どちらが先に不一致だったかで応答を分岐させない）。パスワード照合は引き続き
  `timingSafeEqual` を使う（タイミング攻撃対策）。失敗時は、メールアドレスの存在有無を
  一切示さない共通メッセージ「メールアドレスまたはパスワードが違います。」だけを返す。
- 認証成功で発行するセッションCookieは、HMAC署名付き・`HttpOnly; Secure; SameSite=Lax`・
  有効期限30日（`Max-Age=2592000`）。ペイロードにはログイン時のメールアドレス・有効期限に加え、
  ログイン時点のアクセスパスワードから導出したダイジェスト（パスワード本体は含まない）を
  署名対象として含める。これにより、許可リストからの除外・アクセスパスワードの変更・
  HMAC署名鍵の変更のいずれかが起きた時点で、既存の全セッションが次回リクエストから
  自動的に無効化される（明示的なセッション失効処理を別途持たない）。
  成功したログインPOSTはCookieを発行してから `303 See Other` で `/` に転送し、
  認証済みのBOXをGETで表示する（ブラウザ再読み込み時にフォームの再送信確認を出さない）。
- Cookieの改ざん・不正な形式・署名不一致は、すべて未認証として扱う（fail closed）。
- 変更系エンドポイント（アップロード、署名URL発行、削除、ログアウト等）は、セッション
  Cookieに加えて同一オリジン検証（Origin優先、Refererにフォールバック）を必須にする。
  ログインPOSTのみ、通常ブラウザのフォームPOSTとの互換性のため同一オリジン必須判定の
  対象外にできる（メール・パスワード照合とCookie発行のセキュリティは維持したまま）。
- 権限分離（閲覧者間の権限差）は今回のスコープに含まない。許可リストに載った全メール
  アドレスは同一の閲覧・操作権限を持つ。

## ファイル共有モデル（恒久）

- ストレージは Vercel Blob の private store を使い、PJごとに専用storeを分ける。
- 保管先はPJ専用のprefixで固定する（例: `vsx/files/`）。ファイル名・フォルダ名は
  パストラバーサル防止のバリデーションを通す。
- 全PJインスタンスで、外部の `http` / `https` URLをオンライン資料として追加できる。
  URL本文は取得・複製・中継せず、URL・表示名・保存先フォルダ・更新日時だけをPJ専用の
  private Blob（例: `vsx/links/`）に記録する。元サービスの閲覧権限はそのまま適用される。
- 一覧APIはBlobの生URLや署名付きURLを含まない。
- ダウンロード・閲覧は、短時間（分単位）だけ有効な署名付きURLをサーバー側で都度発行する
  方式に統一し、恒久的な公開URLを発行しない。
- HTMLファイル（`.html` / `.htm`）は通常のダウンロードボタンを表示せず、同じ認証済み
  オリジンからサーバー側で静的PDFへ変換する「PDF化ダウンロード」を表示する。変換時はHTML内の
  JavaScriptと外部ネットワーク通信を実行しない。日本語を含むHTMLには同梱の日本語フォントを
  適用する。変換前HTMLは8MB、返却PDFは4MBまでとし、制限を超える場合は明示的に失敗させる。
- アップロードは大容量ファイルに対応するため、クライアント直PUT（ブラウザから
  `@vercel/blob/client`）方式を使う。サーバーはアップロード許可トークンの発行だけを行う。
- ファイル名変更とフォルダ移動は、private Blobの`rename`を使って保存先の存在確認後に実行する。
  同名ファイルへの上書きは許可しない。名前はフォルダ名と同じ安全な文字列検証を通す。
- ファイルのポインタドラッグ移動中は、ドラッグ対象の行そのものを半透明のプレビューとして、つかんだ
  位置を保ったままポインタに追従させる。移動元の行も薄く残し、移動先フォルダは背景・枠線・
  フォルダアイコンの色で示す。補助文言は表示しない。
- ファイル行は操作ボタン以外のどの位置からでもドラッグ移動を開始できる。フォルダを開くための
  ダブルクリックと、名前変更・削除・ダウンロードの各操作は維持する。
- 全レスポンスに `Cache-Control: no-store` を含む共通セキュリティヘッダーとCSPを付与する。

## デプロイモデル（恒久）

- 各インスタンスは、AMD OS PWA（`pwa/`）とは別の独立Vercelプロジェクトにデプロイする。
  PWAの`main` push自動デプロイ対象とは混同せず、各インスタンスのREADMEに記載した方法で
  反映する。Git連携が未確認なら、`main` pushだけで反映されたと判断しない。
- ビルド生成物（HTML/画像を埋め込んだ module、ブラウザ向けバンドル）はローカルで生成し、
  git管理してデプロイ対象に含める。Vercel cloud build 側ではリモートで生成できない
  前提を維持する（`vercel.json` の `buildCommand` は生成物の存在確認だけを行う）。
- 各インスタンスのcontentは、そのインスタンスディレクトリの `content/` に閉じる。
  リポジトリ外の個人ディレクトリパスへ依存しない。

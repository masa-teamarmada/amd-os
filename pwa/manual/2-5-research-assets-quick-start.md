# 探索・知識アセット — Atlas / Seeds / PoC / VC / Scholar / Knowledge Map の使い方

AMD OS は、既存 PJ を管理するだけでなく、次の PJ 候補を探すための探索系アセットと、AMD 内に溜まったノウハウを眺める知識アセットを持つ。この章は、AMD メンバーが「どの画面を見れば何が分かるか」を最短で掴むための入口。

## 6 つの役割

| 画面 | 一言でいうと | 使う場面 |
|---|---|---|
| `/atlas` | 外部シグナルの地図 | 政策・市場・論文・投資ニュースが、どの領域や PJ に影響しそうかを見る |
| `/seeds` | 研究シーズ候補の棚 | 大学・国研・高専などの技術シーズを、AMD 視点で調査・接触・PJ 化まで追う |
| `/poc` | PoC案件化の棚 | シーズとPoC先を入力し、その掛け合わせからヒアリング、PoC条件、謝礼、契約、収益分配を設計する |
| `/vcs` | 国内 deeptech VC マスタ | どの VC がどの領域・ステージ・ファンド残にいるかを見る |
| `/scholar` | 学術トレンド | OpenAlex 論文数を lane x quarter で見て、AMD Score の M 軸根拠に使う |
| `/knowledge-map` | AMD ノウハウ地図 | OS 内の L2 / manual / spec / BZM 候補を横断して、判断軸・根拠・PJ事例を眺める |

この 6 つは似ているが、混ぜない。

```text
Atlas        = 外部マクロ signal / story / decision
Seeds        = 研究シーズそのもの
PoC          = シーズ x PoC先の案件化設計
VC           = 投資家・ファンド・接点
Scholar      = 学術活動量の時系列
KnowledgeMap = OS 内の L2 / manual / spec / BZM 候補を束ねる内部ノウハウ地図
```

## Atlas を見る

Atlas は、外部環境が AMD の判断にどう効くかを見る場所。

| 画面 | 役割 |
|---|---|
| `/atlas` | signal / story の一覧 |
| `/atlas/inbox` | 自動収集された候補の確認 |
| `/atlas/inbox/submit` | 手動 signal 投入 |
| `/atlas/map` | signal / project / decision の関係地図 |
| `/atlas/macrotrends` | 世界の構造課題と 10-30 年の変化仮説 |
| `/atlas/divergence` | 世界 / 日本差分 |
| `/atlas/decisions` | Atlas 由来の判断ログ |

見方:
1. まず `/atlas/macrotrends` で大きな構造課題を見る
2. 気になるテーマは `/atlas` と `/atlas/map` で根拠 signal を見る
3. PJ や Seeds への影響がありそうなら `/atlas/decisions` に判断ログとして残す

Atlas は VC 個別ニュースや Seeds 本体の棚ではない。VC のファンド動向は `/vcs`、研究シーズ本体は `/seeds` で扱う。

## Seeds を見る

Seeds は、AMD の Before 0 起点となる研究シーズリスト。

Seeds の1行は研究者単位ではなく、**技術 × 用途の1案件**。同じ研究者が複数の事業化候補を持つ場合は、研究者名が同じ複数行として登録する。`discovered` の候補は公開情報等から見つけた未確認項目で、研究者・大学が事業化シーズとして確認したことを意味しない。

```text
candidate -> investigating -> contacted -> discussing
  -> spun_off / declined
```

| 操作 | 何を見る / 何をする |
|---|---|
| 検索 | シーズ名、機関、PI、ラボ、キーワードで探す |
| 一覧の順番 | 研究機関はPJ化済み → PJ化検討中 → その他。シーズはPJ化済み → PJ化検討中 → PJなし・SPS評価済み → その他。区切り見出しではなくPJ状態カラムと行色で確認する |
| カラム | 研究機関、研究者/PI、PJ状態、SPS(億円)・根拠Lv、旧SPSと各軸を1シーズ1行で比較する |
| SPS・根拠Lv (2026-08-15〜) | 一次選別で見積もった「億円レンジ」を中央値主表示・括弧内が範囲 (例: 30.3 (0.5〜60)) で表示し、そのスコアの裏付けの深さを表す根拠Lv (Lv0=ネット情報のみ〜Lv3=月次試算表あり) を並べて表示する。中央値は下限と上限の単純な真ん中を仮に採用したもので、正式な評価額ではない。列見出しをクリックすると中央値で並び替えできる。旧来の9軸ルーブリック (M×P×R×S) は「旧SPS」列に残り、機能・値は変わらない |
| status filter | シーズ自体の候補・調査・接触・協議・スピンアウト・見送りを絞る。AMD PJ状態とは別 |
| domain filter | `gx_energy`, `life`, `materials`, `robo` など lane で絞る |
| 担当 filter | AMD 側 owner ごとに見る |
| 行クリック | 詳細 modal で概要、機関・研究者、AMD 評価、補助金、接触履歴、ニュースを見る。一次選別のスクリーニング帯 (段階仮説・q帯・P帯・SPS中央値・根拠Lv・評価根拠) がある場合は「一次選別スクリーニング帯」セクションにも表示する (2026-08-15〜) |
| 深掘り資料 | 一覧の資料アイコン、または詳細 modal から、確認済みの事業化検討資料をOS内Markdownモーダルで開く。左メニューは表示しない |
| `+ 新規シーズ` | 手入力で候補を追加する |
| `/seeds/inbox` | cron / automation で見つかった未確認 seed を verify / dismiss する |

AMDとのPJ関係は `seed_projects` が正本。`spun_off_project_id` は旧互換で、PJ化判定には使わない。PJ化済みでもシーズ台帳から移動・複製・非表示にせず最上部へ、検討中はその次へ並べる。SXはPJ化済みだが会社未設立なので、シーズ状態は `discussing` のまま扱う。

深掘り資料には、AMD内で確認済みの要約・判断資料だけを紐づける。メール本文、議事録本文、一次ソース本文やその生URLを置く場所ではない。

## PoC 案件化を見る

PoC は、Seeds の下流で「どのシーズをどのPoC先に当てると、ヒアリングや有償PoCになりそうか」を組む場所。一次入力は `シーズ` と `PoC先` の2つ。PoC先候補をタグ付きで整備し、タグ・検索・状態で絞った候補をシーズごとの案件化キューに出して、そこから案件候補を作る。

| 操作 | 何を見る / 何をする |
|---|---|
| 検索 | シーズ、PoC先、相性仮説、ヒアリング論点、次アクションで探す |
| 案件状態 filter | 候補、質問設計、紹介済、ヒアリング済、PoC設計中、PoC実施中、案件化を分ける |
| PoC先状態 filter | 候補、リスト化、接触済、ヒアリング中、PoC設計可を分ける |
| シーズを追加 | シーズ名、機関、研究者、用途・業界タグ、キーワード、概要、次アクションを保存する |
| PoC先を追加 | PoCを受けてくれそうな企業・事業所・組合・施設カテゴリ、業界タグ、過去PoC/紹介経路、謝礼メモを追加する |
| PoC先候補リスト | 候補先を表形式で比較し、業界タグ、地域、規模感、状態などのタグで絞る |
| 案件化キュー | シーズごとに既存案件と上位PoC先候補を見て、`案件化` から仮説・質問・条件の初期案を作る |

PoC 画面は、議事録や外部ソースの全文を保管する場所ではない。保存するのは、次の提案やヒアリングで使う構造化された仮説とメモだけ。

## VC List を見る

VC List は、国内 deeptech VC のファンド・接点・ニュースをまとめる。

| 見るもの | 内容 |
|---|---|
| VC 本体 | `name`, `type`, `thesis`, `amd_rating` |
| ファンド | 号数、サイズ、vintage、status、DPE 残 |
| 接点 | AMD PJ との関係、担当者、最終接触 |
| 投資 | 自社 PJ への出資、ポートフォリオ |
| ニュース | fundraise / fund close / 投資ニュース |

DPE 残は出所を分けて見る。

| `dry_powder_source` | 意味 |
|---|---|
| `estimated` | 公開情報などからの推定 |
| `heard_from_contact` | VC 担当者から直接聞いた情報 |
| `public_disclosure` | 公開資料で確認できる情報 |

`/vcs/inbox` は VC ニュース候補の受信箱。verify すると `vc_news` の確認済み情報として使える。

## Scholar を見る

Scholar は、個別論文の文献管理ではなく、学術活動量の観測画面。

- データソース: OpenAlex -> `papers_log`
- 粒度: lane x quarter
- 指標: `paper_count`
- 用途: AMD Score の M 軸、特に Triple Helix の学術観測量 `N`

読む時は「この論文が良い」ではなく、「この lane で学術活動が増えているか / 鈍っているか」を見る。

## Venture Map との接続

Venture Map は、探索系アセットを使って「どの波にいつ PJ を投入するか」を見る場所。

| 画面 | 役割 |
|---|---|
| `/venture-map` | macro lane、過去 PJ、論文、政策シグナルの統合マップ |
| `/venture-map/amd-score` | PJ / SU 単位の AMD Score 一覧 |
| `/venture-map/timeline-3d` | 過去 PJ と macro wave の 3D timeline |
| `/venture-map/state-space` | Triple Helix 状態空間 |
| `/venture-map/cyberspace` | 実験ビュー |

細かいモデルは [5-2 章 HUD / Venture Map 仕様](5-2-hud-and-venture-map-spec.md)、AMD Score の式は [4-3 章](4-3-amd-score-spec.md) を見る。

## AMD Materials を見る

`/knowledge-map` は、元素・鉱物・鉱石・樹脂・高分子を、特徴だけでなく供給・用途・AMDとの接点まで辿る材料インテリジェンス画面。従来の Obsidian 風 Knowledge Map も `材料マップ` tab に残している。

| tab | 見るもの |
|---|---|
| 全体 | 世界の材料事情を見る5視点を押さえ、元素・鉱物・樹脂を横断した需給の崩れランキングと、4指標合計（20点満点）の上位材料を見る。需給ランキングは不足だけでなく、供給過剰と価格乱高下も区別する。分類カード全面から各一覧へ移動できる |
| 元素 | 全118元素の周期表。注目度 / 需要 / 供給不安 / AMD相性の色を切り替え、枠内の日本語主用途と供給`警戒` / `危機`で全体を読む。評価済み元素を押すと相場・推移・産出国構成が小窓で開く |
| 鉱物・鉱石 | 元素がどの鉱物・鉱石から得られ、精製後にどの用途へ向かうか。項目を押すと要点の小窓が開く |
| 樹脂・高分子 | 4指標合計の高い順に並び、項目を押すと要点の小窓が開く。詳細では原料、作り方、物性、用途、循環性、規制・代替、AMDとの接点を見る |
| 材料マップ | L2 / manual / spec / BZM 候補と正本への入口をマインドマップで見る |
| 比較 | 比較欄へ入れた2〜4材料を共通軸で横に並べる |

使い方:
1. `/knowledge-map` を開き、まず `全体` の需給の崩れランキングを見る。偏りの強さは5点満点で、`不足側`、`供給過剰側`、`価格乱高下`の状態、原因、供給が詰まる工程、評価時点、確からしさを必ず一緒に読む。`元素`では淡黄→黄→橙→赤→深紅ほど注目度が高く、枠上端の`警戒` / `危機`は選択中の色軸に関係なく供給不安を示す
2. 周期表の主用途で候補を絞り、枠を押す。最初の小窓では用途、供給警報、代表品目の直近公表相場、5年価格推移、産出国構成を見る。相場は単位・代表品目・公表時点を確認し、現在価格として扱わない。生産量が非公表の元素では輸入供給元などの代替指標を円グラフ注記で確認する
3. さらに必要なときだけ`詳細を開く`を押し、同じ小窓を拡大して特徴、埋蔵・需給メモ、代替・循環性、AMDとの接点、出典まで読む。`窒化ガリウム製の電力用半導体`や`無線通信用の高周波部品`のように、略語だけでなく用途の意味を日本語で表示する
4. 鉱物・樹脂の一覧は `注目度 + 需要 + 供給不安 + AMD相性` の合計が高い順に読む。樹脂の詳細では「原料」と「作り方」を確認する
5. 候補を `比較に追加` し、最大4件まで同じ軸で比べる。比較列も4指標合計の高い順に並ぶ
6. AMD OS 内のノウハウやPJ事例を探すときだけ `材料マップ` を開き、検索・domain filter・node detailから正本画面へ戻る

色は将来予測の確定値ではなく、評価時点の情報をまとめた初期の定性評価。`未評価` は低評価や需要ゼロを意味しない。精密な市況・埋蔵量・生産量を判断に使うときは、detailのsourceから最新の一次資料を確認する。

AMD Materials は読み取り専用。DB write、LLM 呼び出し、画面内Q&A、外部 NotebookLM への自動同期はしない。質問や追加分析は Codex のえいみに依頼し、画面は探索・比較・根拠確認に集中させる。

## BZM 2.0 理論マップ (`/bzm/map`)

BZM 2.0 の主張・概念・測定・決定・文献・未解決論点を、自分でノードとエッジにして育てる**論証台帳**。「真理マップ」ではなく、ノード数・接続数は真偽・確信度を表さない。

### 新しい理論要素を書く

1. `/bzm/map` を開き、マップの空いている場所をクリックする。ノードが0件なら、中央の案内の周囲が空白。
2. 概念・主張・測定・決定・文献・論点から種別を選ぶ。
3. 見出しと要約を書く。必要なら種別を問わず「参考リンク（任意）」へURL・DOI・書誌情報・OS内参照を残す。リンクは編集フォームだけで扱い、マップ上へ長いURLを掲載しない。
4. 必要なときだけ「詳細を設定」を開き、層・状態・本文を足す。

作成パネルはマップと同じ作業領域に出る。地図を覆う中央モーダルではなく、クリック位置の近くに出る。ヘッダーのグリップを掴むと動かせる。パネルは常に「いま実際に見えている画面の範囲」に収まり、収まりきらない内容はパネル内側をスクロールして読む。

編集できるのはadminだけ。一般メンバーには同じ地図が読み取り専用で見える。

### 選んだノードを育てる

ノードを通常クリックすると、まずそのノードの小型**閲覧**パネルが開く。種別・層・状態、要約、本文、メモを高密度に読み、数式は式のまま表示される。編集したい時だけ「編集する」を押す。パネルはdesktopで幅約360px、本文は内部でスクロールする。閉じる×はなく、**パネルそのもの以外**（地図の空白、フィルタ、ページ余白、別ノード）をクリック・タップすると閉じる。パネル内の入力・ボタン・グリップ操作は閉じない。地図の空白では閉じるだけで、その同じクリックでは下書きを作らない。別ノードを通常クリックすれば確認なしでそのノードへ切り替わる。ノードの場所を普通にドラッグすると位置が保存され、次のリロードでも残る。過去の座標未保存ノードは散らして表示するだけで、読むだけではデータを書き換えない。

- **メモを追加**: 選択ノードの操作帯にあるこの1ボタンから、根拠・異論・論点・検証などのメモを、選択ノードの内側へ記録として積む。まずメモ本文を書き、次にそのメモの役割 (支持・異議・反証・論点・検証の5種類) を選ぶだけで、新しいノードや接続 (エッジ) は一切作らない。保存後もボタンは残るので、同じノードへ何件でもメモを積める。定義する・依存する・上書きする・運用化するの4種は、向きが用途で変わるためメモの役割には出さず、既存の `Cmd`/`Ctrl` を押した2ノード接続から選ぶ。

既にある要素をつなぐ時は、`Cmd` を押したまま始点ノード、接続先ノードの順にクリックする（Mac以外は `Ctrl`）。1つ目には外周のハローと「接続元」案内が出る。必要ならこの接続待ち帯でrelationを変え、2つ目を選んだ瞬間に始点から接続先へ線が出て、そのまま保存される。「つなぐ」確認ボタンや接続パネルは出ない。同じノードを2回選んでも自己接続は作られない。空白クリックかEscapeで接続待ちを解除できる。

種類はノードの塗り色で見分ける。形も併用しているので色だけに依存しない。状態は塗り色ではなく外周線（実線・破線・二重線など）で表し、ノード中心に「概」「主」などの略字は出さない。

### 直す・外す・削除する

- ノードを通常クリックして内容を読み、「編集する」から見出し、要約、分類、本文、文献情報を直す。
- マップの線をクリックし、マップ内の確認パネルからそのエッジだけを削除する (2026-08-02 以降、この線クリックだけが接続解除の入口)。
- 誤記程度なら消さずに編集し、棄却した理論は状態を「反証済み」にして履歴を残す。それでも管理者はノードそのものを削除できる (2026-08-02 追加)。編集パネル下部の控えめな削除ボタンを押すと、同じパネル内でノード名・接続数・メモ件数・削除で何が消えるかの確認に切り替わり、そこで「ノードを削除する」を押すまでは何も消えない。「編集へ戻る」を押せば入力していた内容も残ったまま元の編集に戻れる。削除は物理削除ではなく、まさが後で確認できるよう記録側で保持する運用にしている。

画面はマップ表示と一覧表示を切り替えられる。ノードがある時のスマホは一覧が初期表示だが、0件の時は最初のノードを作れるようマップを出す。検索と層・状態filterはノードを絞り、relation filterはマップ上のエッジだけを絞る。desktopは常設の右読み取りパネルを持たず、マップが画面の横幅いっぱいに広がる (2026-08-02 に撤去)。ノードの詳細を読む・書くのは、通常クリックで開く編集オーバーレイと、選択ノード下の操作帯 (編集・メモを追加) だけ。旧右台帳にあった「外部ソース支持なし」「異議・反証なし」「検証なし」の記録手薄warningは、この撤去にあわせて廃止した。

データの共有正本はDBで、現在は0件からまさ自身が書く。`pwa/bzm/theory-graph/*.md` の旧21ノード / 34関係は検証・復元用の履歴資産で、画面へ自動表示しない。DB障害時も過去データへ切り替えず、編集停止を案内する。

開発者が変更した時は `npm run test:bzm-theory-graph`、`npm run test:bzm-theory-editor`、`npm run test:critical-ui` を実行する。

## 注意

- Atlas 候補、Seeds inbox、VC news inbox は、確認前は正本ではない
- Seeds は外部公開ショーケースではなく、まず AMD 内部の探索台帳
- PoC は Seeds の代替ではない。研究シーズ本体は Seeds、PoC先や条件設計は PoC に分ける

# 書斎で草稿を通読する

## いつ使うか

読む人は管理者（まさ）。書いている途中の本や論文を、Kindleのように1ページずつめくって通読したいときに使う。赤入れの前に全体を読み通す場面を想定している。

**結論**: 書斎は AMD OS とは別のアドレス `https://bookshelf-armada.vercel.app` で開く別アプリ。iPhone のホーム画面か Mac の Dock に「書斎」を入れておくと、AMD OS のアプリとは別の、書斎だけのアプリとして開く（入れ方は下の「書斎アプリを入れる」）。書斎アプリでは初回に1回、Google でログインする。AMD OS の左メニューに書斎の項目は出ない。棚で本のカードの **続きから読む** を押すと、前に読んだ続きから始まる（初めての本は **最初から読む**）。画面の右側を押すと次のページ、左側を押すと前のページ。画面の中央を押すか Escape キーを押すと、上下の帯が出たり隠れたりする。広い画面では、読書画面の左に目次の列が常に出る。目次の章の行を押すと、その章の見出しの一覧がすぐに開く（章を開き直さなくても、どの章にどんな見出しがあるか見られる）。章の行は一覧を開け閉めするだけで、章の最初の文章は、一覧の先頭の **導入** から開く。文字の大きさ・行間・書体・背景は、画面上部の **Aa**（文字の設定）で変える。読んでいた位置、しおり、文字の設定、背景色、目次の列の開け閉めはこの端末だけに残り、別の端末には引き継がれない。

書斎は読むためだけの画面で、原稿は書き換えられない。原稿を直すときは、これまでどおりリポジトリの `bzm` フォルダの原稿を編集する。

## 書斎アプリを入れる

書斎は、AMD OS とは別のアドレス `https://bookshelf-armada.vercel.app` で開く。アドレスが別なので、AMD OS のアプリを入れている端末でも、書斎は AMD OS のアプリの中に入らず、ホーム画面や Dock に「書斎」という単独のアプリとして入る。中身のサーバとデータは AMD OS と同じで、費用は増えない。入れるのは端末ごとに最初の1回だけ。

書斎のアドレスは AMD OS とログインの状態が別になる。そのため、書斎アプリでは初回に1回、AMD OS と同じ Google のアカウントでログインする。ログイン画面には「書斎」の見出しと **AMDメンバーとしてログイン** のボタンだけが出る。

**iPhone**

1. Safari で `https://bookshelf-armada.vercel.app` を開く。ログイン画面が出たときは先にログインし、「書斎」の見出しと本のカードが並ぶ棚が開いてから次へ進む。
2. 共有ボタンを押す。
3. 「ホーム画面に追加」を押す。
4. 名前は「書斎」のまま、「追加」を押す。
5. ホーム画面にできた「書斎」を開く。初回はアプリの中で Google のログインが要る（Safari とは別のログイン）。ログインすると棚に戻る。

**Mac の Chrome**

1. Chrome で同じアドレス `https://bookshelf-armada.vercel.app` を開く。ログイン画面が出たときは先にログインし、棚が開いてから次へ進む。
2. アドレスバーの右端にあるインストールのアイコンを押す。アイコンが見つからないときは、メニュー（︙）の「キャスト、保存、共有」にある「ページをアプリとしてインストール」を押す。
3. Dock の「書斎」から開ける。

**AMD OS のアドレスから入れた「書斎」がある場合**

以前の手順で `https://amd-os-pwa.vercel.app/bzm/read` から入れた「書斎」は、消して、上の手順で入れ直す。iPhone はホーム画面の「書斎」を長押しして削除する。Mac の Chrome は、書斎アプリの窓のメニューからアンインストールする。消し忘れた古い「書斎」を開いても、書斎のアドレスへ移る。

- ログインしていない状態で書斎を開くと、ログイン画面に送られる。ログインすると、開こうとしていた書斎の画面へ戻る。
- 開けるのは管理者のアカウントだけ。
- 書斎のアドレスで開けるのは、書斎の画面とログイン画面だけ。原稿の章どうしのリンクで、同じ本でない章（教科書の作業画面）へ移るときは、AMD OS のアドレスの画面として、書斎アプリの外で開く。書斎へ戻るときは、書斎アプリを開く。
- AMD OS のアドレスで `/bzm/read` を開いても、書斎のアドレスへ移る。古いブックマークはそのまま使える。

## 開き方

1. 専用アプリ「書斎」を開く（ホーム画面のアイコン、または Dock）。アプリを入れていないときは、ブラウザで `https://bookshelf-armada.vercel.app` を開く。
2. 棚に本が6冊並ぶ。読みたい本のカードにある **続きから読む**（初めての本は **最初から読む**）を押す。
3. この端末で前に読んだ位置があれば、その章のその位置から開く。初めての本は、最初の書けている章から開く。
4. 読み始めると、画面いっぱいが本文になる。左上の「書斎へ戻る」で棚へ戻る。棚の画面にも、AMD OS の左メニューや通知は出ない。上に「書斎」の見出しが出る。

前に読んだことのある本のカードには、**続きから読む** と **最初から読む** の2つのボタンが出る。**最初から読む** は、本の最初の章を先頭のページから開く。特定の章から読みたいときは、本を開いてから左の目次（狭い画面では上の目次ボタン）で章を選ぶ。

管理者でない人が書斎を開くと、AMD OS のダッシュボードへ戻される（AMD OS のアドレスの画面に移る）。未投稿の論文や匿名化前の草稿が棚に並ぶため、会員全員には見せていない。

## 棚に並ぶ本

| 本 | 種類 |
|---|---|
| BZM 3.0教科書 | 教科書 |
| ディープテック起業の経営学 | 本 |
| BZM 2.2教科書 | 教科書 |
| BZM 批判的基礎講座 | 講座 |
| The Before Zero Model（第1論文） | 論文（英語） |
| 第1論文 補足資料 | 論文（英語） |

カードには、書けた章の数（「6章中4章を執筆済み」の形）、総文字数、通読にかかる目安の時間、この端末で前に読んだ章と本全体の進み具合（「前回: 章の題・本全体 18%」）が出る。棚の順番は固定で、原稿フォルダにファイルが増えても自動では並ばない。

BZM 3.0教科書の最初の章は「序 — このモデルは何を測るのか」。

総文字数と通読の目安は、画面に見える字数に近づけた**目安**で、正確な文字数ではない。空白、改行、見出しの記号、表の区切り行は数えない。リンクは表示されている文字だけ、図は1字、数式は1つにつき1字で数える。

## めくり方

| 操作 | 動き |
|---|---|
| 画面の右側 3 割を押す、左へスワイプ、右矢印キー、PageDown、Space | 次のページ |
| 画面の左側 3 割を押す、右へスワイプ、左矢印キー、PageUp、Shift+Space | 前のページ |
| 画面の中央を押す | 上下の帯（操作部）を出す／隠す |
| 下矢印キー、上矢印キー | 次のページ／前のページ（スクロール表示では少しずつ下／上へ動く） |
| トラックパッドやマウスのホイールで縦または横に動かす（ページ表示） | 一定の量動かすごとに1ページめくる。めくった直後は少しのあいだ続けてめくらない |
| Escape キー | 上下の帯を出す／隠す。目次などのパネルを開いているときは、パネルが閉じるだけ |
| Home / End | 章の最初／最後 |

- 横書きなので、右が次のページ。
- 章の最後のページでさらに「次」へ進むと、次の書けている章の最初へ移る。章の最初のページで「前」へ戻ると、前の書けている章の最後へ移る。
- 本の最初のページでさらに「前」へ、本の最後のページでさらに「次」へ進もうとすると、移れる章がないので、画面の下に「本の最初」「本の最後」と短く出る。
- リンク、ボタン、表の横スクロール、選択している文字の上を押したときは、めくらない。横に長い表の上でトラックパッドを横へ動かしたときは、めくらず表のほうが動く。
- 上下の帯のボタン（書斎へ戻る、目次、しおり、文字の設定）を押したあとも、続けて Space キーや矢印キーでめくれる。キーボードだけでボタンを選んで操作しているときは、Space はそのボタンの操作になる。
- OSの「視差効果を減らす」を入れている端末では、めくりの動きを付けない。
- 広い画面で「見開き」を入れているときは、2ページを並べて2ページずつめくる。左ページと右ページの間は広く取ってあり、真ん中に細い仕切りの線が引かれる。
- 見開きになるのは、本文の幅が目安 1100px 以上のとき。左の目次の列を出しているあいだは、列を除いた本文の幅で決まる。そのため、画面の幅が 1100〜1380px 前後のときは、目次の列を閉じたときだけ見開きになる（目次の列を開いたままだと1ページ表示になる）。
- 目次の列を開閉して1ページ表示と見開きが切り替わっても、読んでいた段落が見える位置へ戻る。
- 左の目次の列の上を押したり、列の上でホイールを動かしたりしても、本文はめくれない。右 3 割・左 3 割の判定は、目次の列を除いた本文の幅で行う。

画面を開いた直後は上下の帯が出ている。1回めくると帯は隠れる。もう一度出したいときは画面の中央を押すか、Escape キーを押す。

高さの低い画面（スマートフォンの横向きなど）では、本文の上下の余白を詰めて、本文の行を多く出す。帯は出したときだけ本文に重なる。

### 上下の帯

- **上の帯**: 「書斎へ戻る」、本と章の題、「目次」、「しおり」、「文字の設定」。「目次」は、広い画面（1100px 以上）では左の目次の列を開け閉めし、狭い画面では目次のパネルを開く。
- **下の帯**: 章の中の位置を示すつまみ（ドラッグするとそのページへ飛ぶ）、「p. 3 / 41」のようなページ番号、「本全体 18%」の進み具合、「この章の残り 約12分」の目安時間。

## 目次としおり

### 左の目次の列（広い画面）

画面の幅が 1100px 以上のときは、読書画面の左に目次の列が常に出る。幅は、画面の幅の 22% か 280px の小さいほう。

- 列の上のタブで、**目次**と**しおり**を切り替える。
- 目次には、本の章の一覧が並び、いま読んでいる章が強調される。いまの章は、その下に **導入** と見出しが開いて並ぶ。押すと、そのページへ飛ぶ。
- 章の行（章の題と、右端の小さな矢印）を押すと、その章の見出しの一覧がすぐに開く。もう一度押すと閉じる。章の行は一覧を開け閉めするだけで、本文は動かない。画面は切り替わらず、待つこともない。章の行ぜんたいが、指で押しやすい大きさ（高さ 44px 以上）になっている。
- 章の最初の文章（章の題と最初の節のあいだにある、導入の段落や本章の到達目標）は、一覧の先頭の **導入** から開く。いまの章なら章の最初のページへ戻り、別の章ならその章を最初のページから開く。章の題のすぐ後に最初の節が来る章には、**導入** は出ない。見出しが1つも無い章（論文の Abstract など）は、**導入** だけが出る。
- 別の章の見出しを押すと、その章が開いて、その見出しのあるページから始まる。
- 別の章の **導入** や見出しを押すと、その章が届くまでの少しのあいだ、目次の中でその章が強調されて行の右に「開いています…」と出る。画面の一番上には細い帯が動き、本文が薄くなる。章が届くと、元の表示に戻る。
- いま読んでいるページに当たる見出しも強調される。めくるにつれて強調が移る。章の最初のページ（扉と導入のページ。最初の節より前）にいるあいだは **導入** が強調され、最初の節に入ると、その節の見出しへ移る。強調した項目が列の見える範囲から外れたときは、列の中だけが動いて、その項目が見える位置へ寄る。
- 見出しや **導入** を押しても、上下の帯は隠れない。列は出したままになる。
- 開け閉めは、上の帯の **目次** ボタンか、列の先頭の **目次を閉じる** ボタン。閉じた列は、上の帯の **目次** ボタンでもう一度開ける。開けているか閉じているかは、この端末に残る（初めては開いている）。
- 列を閉じると、本文の幅が広がる。
- 色は、背景の設定（白・セピア・黒）に合わせて変わる。

### 目次のパネル（狭い画面）

画面の幅が 1100px 未満のときは、**目次**を押すと、横からパネルが出る。中身は左の目次の列と同じ。

- 本の章の一覧が並び、いま読んでいる章が強調される。
- その下に、いまの章の **導入** と見出しが並ぶ。押すと、そのページへ飛ぶ。
- 章の行を押すと、どの章の見出しの一覧もすぐに開ける（章の行は開け閉めするだけ）。別の章の **導入** や見出しを押すと、その章が届くまでのあいだ、パネルの中でその章が「開いています…」と出る。

### 章を押したときの待ちを短くする仕組み

別の章へ移るとき、章の中身をサーバから受け取るのに時間がかかる（本番の実測で約 2 秒。iPhone ではもっとかかる）。待ちを縮めるため、章を先に読み込んでおく。

- 目次の章の行や、**導入**・見出しの上にポインタを載せる、指で触れる、キーボードで選ぶと、その章を先に読み込み始める。そのまま押すと、サーバを待たずにすぐ開く。目次の上をマウスでなぞって通り過ぎただけのときは、読み込まない。章の行を押して見出しの一覧を開いたときも、その章を先に読み込む。
- 章を開いて少しすると（画面が落ち着いてから）、前の章と次の章も先に読み込む。章の最後のページから次の章へ移るときの待ちが短くなる。
- 先に読み込んだ章は、5 分のあいだ使える。長く同じ章を読んでいたときは、章の終わり近く（最初のほうへ戻ったときは始まり近く）で、前後の章をもう一度読み込み直す。
- 端末で通信量の節約（データセーバー）を入れているときは、前後の章を自動では読み込まない。目次を触ったときの読み込みは行う。
- 先に読み込む分、通信量とサーバの処理は少し増える。1 章あたり 100〜400KB ほどで、章を開くたびに前後の 2 章を読み込む。

### しおり

**しおり**は、いま見ているページを挟む（もう一度押すと外す）。しおりのパネル（広い画面では左の列の「しおり」タブ）には、この本で挟んだしおりが一覧で出る。章の題、本文の冒頭 40 字、挟んだ日が並び、押すとその位置へ移る。外す操作もここにある。

パネルは、閉じるボタン、Escape キー、パネルの外側を押すことのどれかで閉じる。閉じるボタンは指で押しやすい大きさ（44px 四方）にしてある。

**しおりを挟んでいるかどうか**は、いま見ている画面に、しおりを挟んだ場所が含まれているかで決まる。その状態でもう一度しおりのボタンを押すと、いまの画面に当たるしおりが外れる。

## 文字の設定

上の帯の **Aa** を押すと、次の項目を変えられる。

| 項目 | 選べるもの | 初期値 |
|---|---|---|
| 文字の大きさ | 14〜30px（10段階） | 17px |
| 行間 | 1.6 / 1.8 / 2.0 / 2.2 | 1.8 |
| 余白 | 狭い / 標準 / 広い | 標準 |
| 書体 | ゴシック / 明朝 | ゴシック |
| 背景 | 白 / セピア / 黒 | 白 |
| 表示 | ページ / スクロール | ページ |
| 見開き | 広い画面で2ページ並べる | 入 |
| 執筆メモ | 章末に執筆メモを出す | 切 |

- 設定は全部の本で共通。1冊で変えると、ほかの本も同じ設定になる。
- 文字の大きさや余白を変えると、ページを割り直す。読んでいた段落が入っているページへ自動で戻る。
- 書体は、端末に入っている游ゴシック・ヒラギノ角ゴ・游明朝・ヒラギノ明朝を使う。端末にない書体は別の書体で表示される。
- **表示を「スクロール」にする**と、ページをめくらず縦に流して読める。
- **見開き**は、本文の幅が足りないと効かない。目次の列を開いたままだと1ページ表示になる広さのときは、「見開き」の下に「左の目次を閉じると有効」と出る。目次の列を閉じると見開きになる。
- **執筆メモ**は、原稿の中に書いてある注記（HTMLコメント）のこと。入にすると章の最後にまとめて出る。切のときは本文に出ない。

## 位置の記憶は端末ごと

読んでいた章と位置、しおり、文字の設定、目次の列の開け閉めは、使っているブラウザ（端末）の中にだけ保存される。

- 位置は、読んでいた段落と、その段落の中のどのあたりかの両方で覚える。長い段落や長い表の途中で閉じても、開き直すと途中のページに戻る。スクロール表示でも、1つ前の段落へずれずに戻る。
- 背景色（白・セピア・黒）は、ブラウザの別の保存場所（Cookie）にも覚えさせる。章を開き直したり再読み込みしたりしたときに、一瞬だけ白い画面が光るのを防ぐため。Cookie に覚えるのは背景色の名前だけで、位置やしおりは入らない。

- Macで読んだ続きは、iPhoneの書斎には出ない。端末ごとに、その端末で最後に読んだ位置から始まる。
- iPhone のホーム画面に追加した書斎アプリは、Safari とログインが別になる。位置やしおりの保存場所も、Safari とは別になることがある。続きを読みたいときは、いつも同じほう（アプリか Safari）で開く。
- 保存場所はアドレスごとに分かれる。AMD OS のアドレスで読んでいたときに残した位置、しおり、文字の設定は、書斎のアドレスには引き継がれない。書斎のアドレスで開き直すと、その端末では最初の書けている章から始まり、文字の設定は初期値に戻る。
- ブラウザの閲覧データを消すと、位置としおりも消える。
- プライベートブラウズなど、保存が使えない環境でも読書そのものはできる。ただし位置は残らない。
- 端末をまたいで位置を揃える機能は、まだない（下の「まだできないこと」）。

## 未執筆の章の見え方

棚のカードの「N章中M章を執筆済み」は、予定している章の数N章のうち、原稿のファイルがある章の数M章。BZM 3.0教科書のように、章の予定だけが先にある本がある。

- 読書画面の目次には、未執筆の章が予定の題で灰色に出る。押しても開かない。
- 未執筆の章の画面を、アドレスを直接入力するなどして開いたときは、本文の代わりに「この章は未執筆」と出る。そこから「最初の書けている章へ」か「書斎へ戻る」を選べる。
- 「次」へ進むときも、未執筆の章は飛ばして、次の書けている章へ移る。
- 本全体の進み具合（％）と通読の目安時間は、書けている章の文字数だけで数える。章が増えると、同じ位置でも％は下がる。

## 章と節の区切り

教科書とディープテック起業の経営学では、章と節の区切りが目で追えるようにしてある。

- **章の扉**: 章の題が「序章」「第N章」「付録」で始まる章は、章の最初のページに、章の番号（第1章など）が小さな色つきの字で出て、その下に章の題が大きく出る。下には細い線が引かれる。
- **最初の節は新しいページから**: ページ表示のとき、章の最初の節は新しいページから始まる。章の最初のページには、扉（題、導入の段落、本章の到達目標）だけが載る。見開きでは、扉が左のページ、最初の節が右のページに載る。扉の文章が長くて1ページに収まらないときは、扉の続きが次のページに入り、最初の節はその次のページから始まる。縦に流す「スクロール」表示では、新しいページに分けず、続けて読める。
- **節と項**: 節（1.1 など）は大きめの字で、上に広い余白があり、題の下に細い線が引かれる。項（1.1.1 など）は節より小さい字で、線は引かれない。節と項の番号は、色つきの字で出る。
- 論文、補足資料、講座のように、章の題が「序章」「第N章」「付録」で始まらない本は、扉にせず、これまでどおり続けて読む。節と項の番号の色は同じように付く。
- 原稿が書き直し前の書き方（章の題が「BZM 3.0教科書 第2章 — 題」、節が「1. 題」）のままでも、扉と節の番号は同じように出る。
- 背景（白・セピア・黒）のどれでも、文字と背景の色の差は十分に取れる濃さにしてある。白の背景では、リンクや番号の青を、以前より少し濃くした。
- 目次に出る見出しの文字は、原稿に書いてある見出しの文字そのまま（番号を含む）。

## 図・数式・表

- 数式は組版して表示する。インラインの式も、独立した式も読める。原稿で金額のドル記号を書くときは、ドルの前にバックスラッシュを付ける（`\$`）。付けないと、2つのドル記号の間が数式として読まれる。
- 表は列の数で見え方が変わる。列が5つ以上の表は、表の部分だけが横に動く（セルが細くなりすぎないよう、横に動かして読む）。列が4つ以下の表は、本文の幅に収まり、横には動かない。ページをまたいで続くことがある。
- 横に長い数式も、はみ出すときだけその部分が横に動く。ページ全体はめくりのまま。
- 表の罫線は、本文の区切り線より少し濃い色で出る。黒の背景では、透明な図の下に白い地が敷かれる。
- 原稿の中の図は、書斎の中で表示する。管理者でないと図は表示されない。
- 論文の引用番号 `[1]` は、番号ごとに押せる。押すと、文献一覧の章を開いて、その文献のあるページへ移る。引用番号の上にポインタを載せると、その文献の書誌が出る。
- 同じ章に同じ文字の見出しが複数あっても、目次から押したときは、正しい見出しのページへ飛ぶ。

## まだできないこと

- **端末をまたいだ位置・しおりの同期**: 別の端末に引き継ぐには、サーバに保存先の表を作る必要がある。まさの判断待ち。
- **線引きとメモ**: 文字を選んで線を引く、メモを残す機能はない。
- **縦書き**: 横書きだけ。iOSアプリの「教科書」（設定タブ）は縦書きで、PWAの書斎とは別の画面。
- **電波のない場所での読書**: 通信がないと章を開けない。
- **iOS・macOS・Androidのアプリ版**: 書斎はPWA（ブラウザで動く版）だけにある。ホーム画面や Dock に入れる「書斎」アプリも同じPWA（別のアドレスで開くだけ）で、iOS・macOS・Androidのアプリ版は未移植。
- **会員全員への公開**: 管理者だけが読める。広げるかどうかは、まさが決める。
- **原稿の編集**: 書斎から原稿は書き換えられない。

## 困ったとき

| 状況 | 見ること |
|---|---|
| AMD OS の左メニューに書斎が無い | 書斎は別アプリになり、左メニューには項目を置いていない。専用アプリ「書斎」か、`https://bookshelf-armada.vercel.app` から開く |
| AMD OS のアドレスから入れた古い「書斎」が残っている | 古い「書斎」は消して、`https://bookshelf-armada.vercel.app` から入れ直す |
| 開くとダッシュボードに戻る | 管理者のアカウントで開いているか。管理者だけが開ける |
| 書斎アプリを開くとログイン画面が出る | 書斎のアドレスは AMD OS とログインの状態が別。初回はアプリの中で Google のログインをする。iPhone のホーム画面のアプリは Safari ともログインが別。ログインすると書斎へ戻る |
| 「ホーム画面に追加」が見つからない・インストールのアイコンが出ない | iPhone は Safari で開いているか（共有ボタンの中にある）。Mac は Chrome で `https://bookshelf-armada.vercel.app` を開いているか。出ないときは、メニュー（︙）の「キャスト、保存、共有」の「ページをアプリとしてインストール」を見る |
| 見開きにならない | 画面の幅が足りない。左の目次の列を開いていると、列のぶん本文が狭くなる。目次の列を閉じる。設定の「見開き」が入になっているかも見る |
| 左の目次の列が出ない | 画面の幅が 1100px 未満だと列は出ず、「目次」ボタンで横からパネルが出る。広い画面で列が出ないときは、列を閉じている。上の帯の「目次」ボタンを押すと開く |
| 章の中のリンクを押すと、書斎アプリの外の画面が開く | 別の本の章へのリンクは、AMD OS のアドレスの教科書の作業画面へ移る。そこは書斎アプリの外で、AMD OS 側のログインが要ることもある。書斎へ戻るときは書斎アプリを開く |
| 続きから開いたのに最初の章になる | 別の端末で読んだ位置は残らない。AMD OS のアドレスで読んでいた位置も、書斎のアドレスには残らない。ブラウザの閲覧データを消した場合も同じ。iPhone では、アプリと Safari で保存場所が別になることもある |
| 図が表示されない | 管理者のアカウントでログインしているか。原稿の図のパスが `bzm` フォルダの中にあるか |
| 再読み込みのたびに一瞬白く光る | ブラウザが Cookie の保存を止めていると、背景色を最初の描画に反映できない。読み込み後は設定どおりの背景に切り替わる |
| 章の最初のページに題と導入だけが出て、本文が次のページから始まる | 章の扉の仕様。ページ表示のときだけ、最初の節を新しいページから始める。続けて読みたいときは、文字の設定（Aa）の「表示」を「スクロール」にする |
| 目次で別の章を押したあと、すぐには開かない | 「開いています…」が出ているあいだは、章を受け取っている最中。先にポインタを載せる（指で触れる）と先に読み込むので、次からは短くなる。章の行は、読み込み待ちなしに見出しの一覧だけを開け閉めする |
| 目次で章の題を押しても、本文へ移らない | 章の行は、見出しの一覧を開け閉めするだけ。章の最初の文章は、一覧の先頭の **導入** を押すと開く。**導入** や見出しを押すと、本文がそのページへ移る |
| 目次の章に **導入** が出ない | 章の題のすぐ後に最初の節が来る章には、**導入** を出さない。章の題と最初の節のあいだに文章がある章にだけ出る。見出しが1つも無い章は、**導入** だけが出る |
| 開いた章が「この章は未執筆」になる | 原稿のファイルがまだない章。「最初の書けている章へ」を押す |

# OS一覧のデザイン監査

対象はPWAの一覧・比較表と、それを共有するコックピット、ワークスペース、管理画面、DD。実装担当がinterface-design、refactoring-ui、design-review、ui-polish-gateに沿って監査した。別人のデザイナーによる独立監査とは区別する。

## 棚卸しと基準

106ファイル・203個の表を棚卸しし、101ファイル・192個の業務表に共通の階層・桁揃えを適用。原資料表示と印刷の5ファイル・11表は原資料の寸法を維持。数値行列は詰めた比較を保持し、レコード一覧は44px以上、既に成分別比較を持つ実験一覧は専用の約60pxを保持する。表以外も標準Badge、ダッシュボード、関係先・ガント・開発テーマ、権限、変更履歴、資料・会議の既存の分類と状態を点検する。

一覧画面の棚卸し.json、状態表示の棚卸し.json、分類表示の棚卸し.jsonに対象を記録。分類は名称付きラベル、状態は記号＋名称、変化は方向＋値を独立させる。未知を完了やゼロへ変換しない。分類色と増減方向は良悪の判定ではない。既存の保存先・認可・外部公開・採否・通知操作を使い続ける。

## 発見と修正

| 重要度 | 発見 | 修正 |
|---|---|---|
| 高 | 稼働中が完了と同じ緑、未評価が進行色 | 共通定義と状態記号。進行は青、完了は緑、未確認は灰。関係先・開発テーマの共有色も修正 |
| 高 | 分類・状態を同じ重さの文字で読む必要 | 分類は菱形ラベル、状態は▶/✓/!/×/?と文言。標準Badgeにも既知の状態だけ適用 |
| 高 | 多数の設定列が最初の比較を妨げる | PJ・メンバー台帳を比較一覧と全設定に切替。元の全列・セル編集を保持 |
| 高 | 廃液のデータセルから編集できない | 押したデータセルの項目を同じ行の直下で編集、保存/取消、キーボード、戻り先を接続 |
| 中 | 結果と実験状態の名称が目的とずれる | 結果列・凡例・編集欄を「実験結果」へ揃え、済スタンプとの独立表示を保持 |
| 中 | 数値の増減が符号や文章だけに埋まる | 実在する差額・スコア差の方向を同じ位置で表示。増加だけで改善と判定しない |
| 中 | スマホの横移動前に状態が見えない | 識別列にも状態と分類を表示。セル編集欄は画面幅内、入力16px、主要操作44px |

## 開発画面の確認

実装本体のAmieEffluentLedgerとAdminProjectsTableを使用。監査用の一時ページは127.0.0.1だけで提供し、本番の構築前に削除、開発サーバーを停止した。実験49行は既存の照合済み記録。PJ台帳の監査用3行は合成した表示用データで、本番DBへ保存していない。

1440×900：共通の進行・完了・注意・未評価の色と記号を確認。比較行44px以上、PJ台帳の3行は46px。比較一覧は7列、全設定は31列へ切替可能。390×844：ページ幅390px、はみ出しなし。PJ識別列の状態・分類が見え、実験の行内編集幅310px、入力16px。実験の6データ列はクリック、詳細・出典セルはEnterで編集、取消を確認。詳細ボタンは原記録の開閉として保持する。

型検査、意味検証、技術開示、廃液の保存契約、主要UI、構築・配信前検査を使用。VCのpassed=見送りと、技術試験のpassed=合格を表示文言から区別する。必要な合意のpending=未合意は注意、単なる待機は中立。欠測の数値はゼロにしない。

開発時の評価は8.7/10。パソコン・スマホの分類/状態/変化/編集の見通しは基準を満たす。本番の保存済みデータ・主要な一覧群は反映後に追記する。専用のSwift/macOSクライアントの実画面は今回の改修対象に含まない。

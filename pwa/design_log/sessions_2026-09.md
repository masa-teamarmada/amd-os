### 追記 2026-09-05 深夜 「1円入れても計算が変わらない」の原因3つ

上に「次につぶすべき問い」（判断できる→手が止まっている→期限超過→あと少しで閉じる順）、下に木。閉じた問いは同じ並びの末尾へ落とす。

### 確認

型0件、`npm run build` 成功、ローカル本番ビルドを1440pxの実寸＋認証cookieで表示。横スクロールなし、コンソールエラー0。SXは問い27件・未閉じ26・判断できる4・手が止まっている9・期限超過14。

### 手順と残り

- 正規checkoutが36ファイルdirty（別セッションのSlack取り込み作業）かつ25 behindだったので、`amd-os-tree` に使い捨てクリーンクローンを作ってそこで作業した。既存dirtyには触っていない。未pushだった2commit（design_log / institutions data）も別セッター由来なので触っていない。
- `npx supabase db push` は使えない。ローカルにあってリモート履歴に無い migration が20件以上あり（別経路で適用済みのもの）、push すると巻き込む。MCPの `apply_migration` で1本ずつ当てた。

### 追記: まさの指摘8件を反映して形を固め、つくよみの受け皿まで作った（v3.101.0 → v3.104.0）

同じセッションの続き。まさが本番を見るたびに指摘が出て、そのたびに直した。**指摘の順に並べる。**

1. **「次につぶすべき問い」コーナーが使えない。** 「上にピックアップされても、それがどの論点のどの部分なのかが分からん」。上への抜き出しは親子の文脈を切る。コーナーごと撤去し、手を打つべき行を**木の中で**強調する形へ。`pickNextUp` と `bundle.nextUp` も削除。強調される問いへ至る道は初期表示で開いておく（畳まれていたら強調しても見えない）。
2. **詳細はトグルでなくモーダル。** 背景欄は長く積むので、行の下に展開すると木が縦に伸びて上下の文脈が飛ぶ。`createPortal` + `useModalContainment`。**踏んだ罠**: portal で body 直下へ出た `.backdrop` は `.page` の子孫でないためCSS変数の継承が切れ、モーダルが透けた。`.page, .backdrop` の両方で変数を定義して解決。見出しに根からのパンくずを出す。
3. **並び替えを戻す。** 「同じ階層内限定でいいから順番は入れ替えたい。先に解決できるものとか重要なものを上にしたい」「親を変える場合は別の親のところにドラッグアンドドロップ」「ボタンが無駄に増えるとUXがどんどん悪くなる」。上下の縁へ落とせば並び替え、真ん中へ落とせばその子になる。DB関数 `reorder_project_questions` 1回で付け替えと採番を確定。
4. **やることも木の子に出す。** 「TODOがあるなら、その論点の子として追加しないとじゃないの?」— **構造の誤りを突かれた**。やることは論点にぶら下がっているのに、モーダルの別欄へ隔離していた。木の子として出し、子の追加は「子を追加」1つの入口で種類（論点/仮説/決めること/やること2種）を選ぶ形へ。ボタン名も一般語へ（解決にする / 子を追加 / 根拠を追加 / 取り下げ）。画面から「問いの木」の名前を消した。
5. **各項目をクリックで編集。** 値を押すとその位置だけが入力欄へ変わる。導出値は `（自動）` と付けて押せなくする。**一度差し戻された**: 機能は動いていたのに点線の下線が薄く、読み取り専用に見えていた（まさ「まだ編集できないよ」）。読んでいる状態でも入力欄の枠を出す形へ。
6. **入力状態で欄の大きさが変わるのをやめる。** textarea を中身の高さへ合わせ、1行の欄は読みでも折り返さない。実測で担当32px→32px。
7. **やることも押せば詳細が開く。** 14項目をその場で直せる。末尾に「これが答えを出す論点」を出す。
8. **罫線を親のタイトル真下へ。** 「子側の『├』は『バイオディーゼル事業〜』の『バ』の下にないと変」。**ずれの実体は印（代替/決める）がタイトルの前にあって幅が可変だったこと。** 印をタイトルの後ろへ移し、罫線を1階層2枡（罫線の枡＋開閉マークの枡、同じ15px幅）にした。実測で根56px = 子の├ 56px、depth1のタイトル86px = depth2の├ 86px。状態の縦棒は罫線と重なるので8pxの丸へ（まさ「丸の方が信号っぽい」）。

## 2026-09-11 つくよみの「書き漏らし検出」をdailyで動かす

前日の続き。受け皿と承認・却下は本番v3.104.0にあったが、拾う側が無かった。まさ確定は「議事録から全部を作るのではなく、会議中に論点タブへ書き忘れたものだけをdailyで拾う」。

- Codex automation `4-35` を毎日04:35 JSTで追加。前日00:00 JST以降の開催済み `project_meeting_summaries.narrative_md` と、PJごとの `project_questions` / `project_actions` を意味で照合する。
- 出すのは問いとやることだけ。既存・提案中・過去に「いらない」とされた同義候補を除き、PJあたり合計5件まで。acceptedかつ未削除の問いを親候補として必須にし、理由も必須にした。
- 抽出側はGETとoutbox JSON作成だけ。専用LaunchAgent `jp.teamarmada.amd-os-question-tree-outbox-applier` が5分ごとに取り込み、すべて `review_state='proposed'` で止める。既存のL2/Atlas applierはVercel消費事故の停止札で止まっているため、Vercelを呼ばないこの経路は失敗範囲を分けた。
- 取り込みの `on_conflict=project_id,client_token` を廃止。部分unique indexはPostgRESTの競合先にならないため、accepted / proposed / 却下済みを含む既存tokenを先に読み、新規だけPOSTする。同じJSON内の重複も除く。tokenはPJ・議事録・種類・正規化した内容から決定的UUIDにする。
- 安全弁は抽出と取り込みの両方に置いた。空outbox、6件以上、親候補・理由なし、他PJまたは未承認の親候補は反映しない。
- 本番データを触る前の控えは、未削除が問い114件・やること233件・分かったこと11件、提案0件、client_tokenあり0件。並び替え関数は呼ばず、提案は木へつながない形で重複往復だけを試す。

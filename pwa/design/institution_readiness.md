## 何のための機能か

AMD は香川大・KUTE・NIMS など複数の研究機関で **エコシステム構築業務** を請け負っている。
「各機関が何をできていて、何が未整備で、どんな特徴を持つか」を一覧・比較できる資産として OS に持つ。
そのうえで整備度をスコアリングし、**ギャップ（＝AMD が次に売れる支援メニュー）を可視化**する。

### AMD Score との関係（重要・二重計上しない）

- **AMD Score** = 個体レイヤー。1 つのベンチャーが IPO に向けてどれだけ育ったかを見る現行 SPS primary 指標。7 軸 Cobb-Douglas / M-X-F は legacy comparison と evidence chain として残す。
- **ECR** = 苗床／土壌レイヤー。機関が「ベンチャーを生み育てる装置」としてどれだけ整備されているか。
- 両者は **σ_SU（Triple Helix: 学術 μ_A × 産業 μ_I × 政府 μ_G）経由でデータとして自然に連動**する。
  機関の整備が進む → そこ発のベンチャーの μ_I / μ_G が上がる → AMD Score が上がる。
- ⚠️ **ECR を PJ の AMD Score の計算式に直接足し込まない**（σ_SU で既に効いており、二重計上になる）。
  連動は「概念的・データ上の因果」止まりにし、計算式は別々に保つ。

## スコアの構造（AMD Score とは別ロジック）

AMD Score の legacy 乗法（Cobb-Douglas）は「全軸ないと IPO 死ぬ」モデルなので**流用しない**。
ECR は逆で「**何が欠けているか（未整備ギャップ）を見せる**」のが目的なので、欠損が掛け算で消えない**加重和（充足率）**にする。

```
2 階層構造:
  capability 軸 (8)  >  サブ軸 / 評価ポイント (軸ごとに複数)  >  各サブ軸 Lv1–5

サブ軸スコア      lv ∈ {1,2,3,4,5}
サブ軸正規化      s = (lv - 1) / 4          → 0.00 / 0.25 / 0.50 / 0.75 / 1.00
軸スコア          A_k = mean(その軸のサブ軸 s)        ← サブ軸数の偏りで軸間が歪まないよう「平均」
ECR（充足率）     ECR = 100 · Σ_k w_k · A_k  (Σw_k = 1)

重み w_k は当面 等加重（= 1/8）。精度が上がったら軸レベルで調整する。
```

設計判断（2026-05-29 まさ合意）:
- サブ軸数のバラつきで軸が勝手に重くならないよう、**軸スコア＝サブ軸の正規化平均**にして軸を等価値に揃える。
- 重みは軸レベルにだけ持たせる（サブ軸には持たせない）。最初は等加重。

評価尺度（2026-05-29 まさ合意）:
- 3 段階では差がつかない → **各サブ軸 Lv1–5**。
- Lv は「ただの 1–5」ではなく、サブ軸ごとに **到達状態の定義文（rubric）** で固定する。
- 本ドキュメントでは **Lv1 / Lv3 / Lv5 の 3 アンカー**を定義する（Lv2・Lv4 はその中間として補間）。
  例外的に 7-c だけは「5 段階フル」の見本も載せる（まさのガバナンス例）。

機関タイプ（2026-05-29 まさ合意）:
- 研究所（NIMS）／大学（香川大）、国立／私立で性格は違うが、**当面は軸セットを分けない**。
  評価制度の精度が上がってから機関タイプ別チューニングを検討する。

## 制度比較マトリクス（ECR raw evidence レイヤー）

2026-05-31 の香川大 / KUTE / NIMS 本評価と、KUTE 認定規程整備 (`/Users/masa/projects/AMD/kute/output/regulations/`、共有フォルダ `ARMADA/p25_kute`) からの学び:

- **ECR 本体**は 5 段階の成熟度評価として残す。制度の有無だけでなく、実運用・人・成果まで含めて「機関としてどれだけ効くか」を見る。
- **規程・制度整備状況**は、5 段階に無理に押し込まず、別の制度比較マトリクスで持つ。
- **未確認と未整備を混ぜない**。未確認は `unknown`、未整備は `not_started` として別扱いにする。

### 3 段階で持つ制度整備ステータス

| status | 意味 | ECRへの扱い |
|---|---|---|
| `unknown` | 未確認。資料・ヒアリング・DB の裏取りがまだない | スコアには入れず、ヒアリングTODOとして扱う |
| `not_started` | 未整備。検討・草案も確認できない | ECR の該当サブ軸を下げる根拠 |
| `drafting` | 検討中・審議中・草案あり・委員会通過前 | Lv2〜3 相当の根拠 |
| `established` | 規程・制度として整備済み | Lv3〜4 相当の根拠。実運用があれば Lv4〜5 |

### 認定規程の成熟度チェック項目

KUTE で規程整備した時の論点を、大学別に比較できる raw evidence として持つ。

| 領域 | チェック項目 | 例 |
|---|---|---|
| 規程主体 | 学校法人規程 / 大学規程 / ハイブリッド | 学校法人主体だが認定は学長、株式/SOは理事長など |
| 決裁者 | 認定 / 称号授与 / 更新 / 解除 / 取消 / 支援決定 / 改廃 / 株式・SO取得 | 学長、理事長、認定委員会、理事会 |
| 認定対象 | 研究成果型 / 知財型 / 教職員・学生型 / 卒業生・退職者 / 第三者代表会社 | 退職・卒業後 1年/3年/期限なし、実質的関連性 |
| 登記前申請 | 事前相談 / 認定予定通知 / 条件付認定 | 設立前申請を受けるか、正式認定は登記後か |
| 有効期間・更新 | 称号期間 / 更新可否 / 更新審査 / 要件再確認 | 3年、5年、再申請可 |
| 呼称 | 大学発ベンチャー / スタートアップ / 併記 | 公的制度との整合、急成長志向の明示 |
| 称号使用制限 | 品質保証・投資推奨・経営状態保証の否定 | Web/営業資料/採用資料での誤認防止 |
| 大学名・ロゴ | 名称、標章、ロゴ、校章の利用ルール | 別規程接続、個別許可 |
| 知財利用 | 認定とライセンス契約の切り分け / 優遇措置 / 有償性 | 認定だけで自動許諾しない |
| 報告・変更届 | 年次報告 / 決算未了時代替 / 法人形態別書類 / 代表者・所在地・資本構成変更 | 合同会社等も捕捉 |
| 取消・解除 | 取消事由 / 称号返付 / 取消後表示削除 / 営業利用停止 | 社会的信用失墜、虚偽申請、報告義務違反 |
| 支援申請 | 認定とは別の個別申請・審査・契約 | 施設、登記、共有機器、広報、紹介 |
| 支援期間・対価 | 称号期間と支援期間の分離 / 実費・有償負担 | 支援内容ごとに期間・条件を決める |
| 関係規程接続 | 兼業 / COI / 知財 / 共同研究 / 施設利用 / 共有機器 / 研究倫理 / 安全保障貿易管理 | 支援を広げるほど安全弁になる |

## UI 方針（2026-05-29 まさ決定）

**ダッシュボードに表示する**（当初「並べない」案から変更）。縦に 2 ブロック:

```
ダッシュボード
├─ 上ブロック: SU リスト（既存 AMD Score の PJ 一覧）
└─ 下ブロック: 研究機関リスト（ECR）
```

- 上＝SU（ベンチャー個体 / AMD Score）、下＝研究機関（苗床 / ECR）と**縦に積む**。
  個体レイヤーと苗床レイヤーが同じ画面で上下に並ぶことで「どの土壌からどの個体が出るか」が一望できる。
- 各レイヤーで使うスコアは別ロジック（上＝AMD Score SPS primary / 下＝ECR 充足率 0–100%）なので、
  研究機関リスト側に「ECR は整備度（充足率）であり AMD Score とは別指標」と明示する。
- **機関詳細ページ**: 8 軸レーダー／サブ軸 rubric の現在 Lv ＋ 根拠ノート ＋
  **「この機関発の PJ」へのリンク**（σ_SU への概念接続を見せる）。
- 研究機関リストの各行: 機関名 / タイプ / ECR 充足率 / 8 軸ミニヒートマップ / 詳細リンク。
- ナビにも機関一覧（横断ヒートマップ比較）への導線を置く。

- **比較ヒートマップ `/institutions`**: **行 = 8 軸（左ヘッダ列に番号＋軸名＋対応 XRL をフル表示）／列 = 機関**の転置レイアウト。最上部に総合 ECR 行（大フォント太字で強調）、最下部に評価済サブ軸数。セルは **indigo 単色の濃淡（濃いほど高得点）**で、赤→緑のカラフル配色はやめた（色覚的に読みやすく・総合点が一望できる、というまさ判断）。ヘッダ行・列は sticky 固定、下部の軸凡例は行ヘッダに名前が入ったので廃止。
- **評価入力マトリクス `/institutions/assess`（admin）**: 各サブ軸を **Lv1–5 の 5 行に展開し各レベルの rubric をフル表示**、右の各機関列はチェックボックスのみ。1 つにチェック＝そのレベル、**どの Lv にもチェックしなければ N/A**（軸平均から除外）。各サブ軸末尾に根拠メモ行（インライン入力）。変更は 1 セルずつ即保存（楽観更新）、ECR はリアルタイム再計算。チャットで 1 件ずつ伝える運用を置き換える狙い。
  - UX 変遷（捨てた案）: 当初は「列＝機関／行＝サブ軸、各セルに Lv1–5 ボタン＋ rubric ツールチップ」だったが、まさ指摘「ツールチップは UX 悪い／各レベルを行で分けて基準を全部見せたうえでチェックだけ付けたい」で現行の行展開型に刷新。
- **書き込み**: `POST /api/institutions/assess`（admin）→ `institution_assessments` を当日分で `onConflict(institution_id,criterion_id,evaluated_at)` upsert。`fetchErsBundle` が (機関 × サブ軸) ごとに最新 1 件を採用。

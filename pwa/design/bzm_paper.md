## 0. 二本立ての役割分担（教科書 vs 論文）

| | Web 教科書（`pwa/bzm/*.md`） | 学術論文（本 doc が設計） |
|---|---|---|
| 読者 | AMD 内部・実務家・学生（通読性優先） | 査読者・研究者（厳密性・新規性優先） |
| 文体 | 「ねらい」→説明→例題→章末まとめ→練習問題 | IMRaD、主張ごとに文中引用 |
| 引用 | 「著者（年）」で軽く参照、巻末に集約 | 各主張に厳密な文中引用 |
| 数式 | 直感重視、導出は噛み砕く | 定義→仮定→命題、再現可能性を担保 |
| 検証 | 9 PJ retrofit を物語として読ませる | retrofit を方法・限界つきで報告 |
| 正本 | コンテンツは教科書側が正本 | モデル定義は `before-zero/theory/*.md` / `pwa/design/amd_score.md` / `institution_readiness.md` が正本 |

**原則**：モデル定義（数式・重み・rubric）の正本は theory / design md。教科書も論文もそこから派生する二次表現。定義に揺れが出たら正本を直し、両方を同じ更新で揃える。

## 2. 論文骨子（IMRaD・日本語・JASVE 向け）（タスク #6）

仮題：**「Before Zero Model：法人設立前ベンチャーの成熟度を測る 7 軸統合スコアと苗床レイヤーの提案」**

### 要旨（400〜600 字目安）

- 問題：従来の Valuation は「ゼロ（設立・事業開始）」以降を前提とし、設立前（Before Zero）の準備度を測れない。
- 提案：マクロ環境 σ_SU・個体 5 軸（XRL 群）・創業者軸 FRL の 7 軸を Cobb-Douglas で統合する **AMD Score**、および苗床（研究機関）の整備度を加重和で測る **ERS** の二層モデル。
- 検証：結果既知の過去 9 PJ への retrofit で、判定が現実と整合するかを確認。
- 含意：「マクロは揃っていたが TRL ゲート未達で早すぎた」事例（ティエム）を定量的に説明できる。

### 1. はじめに（Introduction）

- 1.1 背景：ディープテック／大学発ベンチャーの増加と、設立前評価の空白。
- 1.2 問題設定：Valuation の限界（キャッシュフロー前提・設立後前提）。「ゼロ」の定義。
- 1.3 本研究の貢献：(a) 設立前を測る 7 軸統合スコア、(b) 創業者を独立軸に立てる FRL、(c) 個体と苗床を分ける二層構造、(d) retrofit による妥当性検証手法。
- 1.4 論文の構成。

### 2. 先行研究（Related Work）

- 2.1 Readiness Level 系：TRL（Mankins 1995）と諸 RL への拡張、EU Horizon SRL、SIP 公募要領の 9 段階。
- 2.2 Triple Helix（Etzkowitz & Leydesdorff 1995, 2000）：学・産・官の共進化。
- 2.3 創業者・リーダーシップ：Authentic Leadership（Walumbwa 2008 / Avolio & Gardner 2005）、Grit（Duckworth 2007）、Resilience（Markman 2005）、創業者経験と資金調達（Hsu 2007 / Bernstein 2017）。
- 2.4 統合関数：Cobb-Douglas（Cobb & Douglas 1928）の代替・補完弾力性。
- 2.5 時系列推定：VAR（Sims 1980）、Bayesian VAR と Minnesota prior（Litterman 1986）、Panel VAR（Canova & Ciccarelli 2013）、主成分による予測（Stock & Watson 2002）。
- 2.6 本研究の位置づけ：上記を設立前評価へ統合した点が新規。

### 3. モデル（Model / Methods）

- 3.1 マクロ環境 σ_SU と Triple Helix：μ_A/μ_I/μ_G のシフト幾何平均、観測量 7 種と C 行列負荷、状態空間定式化（詳細は付録 A）。
- 3.2 個体軸 XRL 群：TRL/BRL/GRL/SRL/HRL の定義と 0–9 化。
- 3.3 創業者軸 FRL：HRL では捉えきれない CEO 個人の質。FRL = 0.6·ALQ_avg + 0.2·Grit + 0.2·Resilience。
- 3.4 統合関数 AMD Score：$S=K\prod(X_i+1)^{\alpha_i}$、シフト方式、IPO=100,000 校正、base case の重み、律速 $\arg\max_i \alpha_i/(X_i+1)$。Cobb-Douglas 採用根拠（完全代替と完全補完の中間）。
- 3.5 苗床レイヤー ERS：加重和（充足率）、8 軸 × サブ軸 × Lv1–5、二層構造（σ_SU 経由の因果に留め計算式に足さない＝二重計上回避）。

### 4. 検証（Results）

- 4.1 retrofit の方法：結果既知の 9 PJ（ティエム、輝翠 TECH、CrestecBio、LiSTie、JOYCLE、BWE、Yellow Duck、CryoX、SolvioraX）に軸評価を遡及付与し AMD Score を算出。
- 4.2 ティエム時系列：「5 年早かった」を約 23 倍のスコア差として定量化。σ_SU は揃っていたが TRL ゲート未達という構造の提示。
- 4.3 他 PJ の試算と判定整合性。

### 5. 考察（Discussion）

- 5.1 含意：設立前 GO/NO 判定への応用、律速軸＝次の打ち手。
- 5.2 二層構造を分ける設計判断（ERS を式に足さない理由）。
- 5.3 AMD OS への実装含意（重みスライダー・K 自動再校正・律速表示）。
- 5.4 **限界（重要・正直に書く）**：
  - retrofit の軸評価は事後の専門家事前情報に依存（後ろ向き／確証バイアス）。
  - 重み α・校正 K は base case の暫定値、データ駆動の推定はこれから。
  - σ_SU の状態空間推定は少標本（識別性を prior で補っている）。
  - サンプルが AMD 関与 PJ に偏る（外部妥当性）。
- 5.5 反証可能性と今後：新規 PJ での前向き検証、L2 抽出（OS 運用ログ）による軸評価の客観化。

### 6. 結論（Conclusion）

- 設立前評価の空白を埋める 7 軸統合 + 苗床二層モデルを提案・retrofit で妥当性を確認。今後は前向き検証と重みのデータ駆動推定。

### 付録

- 付録 A：状態空間モデルの定式化（BVAR / Kalman / 固有値分解と螺旋）。← 教科書 2-2
- 付録 B：記号表。← 教科書 9-2
- 付録 C：ERS 全 8 軸 rubric。← 教科書 9-4

### 参考文献

- 教科書 9-1 の母集合から、論文で実際に文中引用したものを採録。

## 3. 図版方針（タスク #5）

> 🚨 **画像生成 MCP は手元に無い**（2026-05 時点。Drive/Slack/Notion/Calendar/Gmail/DocuSign/Chrome のみ）。
> 本物の図が要るものは **外部（ChatGPT/Imagen/Midjourney 等）で生成 → PNG/SVG を受領 → `pwa/public/bzm/` に配置**する。
> **SVG/CSS/絵文字で「図っぽいもの」を自作してごまかすのは禁止**（AGENTS ルール）。

ただし図には 2 種類あり、扱いを分ける：

### 3-A. データ図（プロット）＝コードで正しく描いてよい

実データ・数式から決まる図は「ごまかし」ではなく正当な可視化。matplotlib 等で生成して `public/bzm/` に置く、または既存の OS 内インタラクティブ可視化（`/venture-map/oscillator`, `/state-space`, `/amd-score/retrofit` 等）のスクショを使う。

| 図 | 内容 | 生成元 |
|---|---|---|
| F1 σ_SU 幾何平均の曲面 | min 律との比較、ゼロ近傍の挙動 | 数式からプロット（matplotlib） |
| F2 状態空間の螺旋軌道 | 複素固有値ペアによる減衰螺旋 | 数式からプロット／OS `/venture-map/oscillator` スクショ |
| F3 retrofit スコア時系列 | ティエムの「5 年早かった」23 倍差 | 9 PJ データからプロット／OS `/amd-score/retrofit` スクショ |
| F4 ERS 8 軸レーダー | ある機関の充足率と支援ギャップ | データからプロット（radar chart） |
| F5 律速バー | $\alpha_i/(X_i+1)$ の軸別 | 数式からプロット |

### 3-B. 概念図（ポンチ絵）＝外部画像生成 or 手描き受領が必要

データではなく「概念の構造」を見せる図。きれいなブランド感のある絵が要るなら外部生成。簡素な構造図なら本文中の ASCII/Mermaid 風で代替してもよい（論文掲載時は清書）。

| 図 | 内容 | 方針 |
|---|---|---|
| G1 二層構造図 | 苗床(ERS)→σ_SU→個体(AMD Score) の因果フロー | 外部生成 or 清書受領。教科書 7-1 §5 に「図版 TODO」あり |
| G2 7 軸の M×X×F 分解 | Macro / XRL 積 / Founder の 3 要素 | 構造図。外部生成 or 清書 |
| G3 Triple Helix 螺旋イメージ | 学・産・官の三重螺旋（アルマダロゴ象徴） | 外部生成（ブランド感が要る） |

**まさへの依頼事項（外部生成が要るもの）**：G1（二層構造の因果フロー）、G3（Triple Helix 螺旋）の 2 枚は、ChatGPT 等で生成して PNG/SVG をもらえれば `pwa/public/bzm/` に配置して教科書・論文に組み込む。データ図（F1〜F5）はえいみが matplotlib で生成 or OS 可視化のスクショで賄えるので、まさの手は要らない。

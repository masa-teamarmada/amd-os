# PoC Matching

`/poc` は、研究シーズとPoC先を一次入力として持ち、その掛け合わせからヒアリング、PoC設計、謝礼、契約、資金、収益分配まで案件化するための台帳。

巨大な `シーズ x PoC先` の全面マトリクスは作らない。シーズが100件、PoC先が500件になった時にほとんど空白の 50,000 セルになり、実務上の選定に向かないため。先に `PoC先候補リスト` をタグ付きで整備し、タグ・検索・状態で候補先を絞ったうえで、シーズごとの `案件化キュー` に上位候補だけを出す。

## 位置づけ

| レイヤー | 役割 |
|---|---|
| `/seeds` | 研究シーズそのものの棚 |
| `/poc` | シーズ x PoC先の案件化設計 |
| `/project/[projectId]/cockpit` | PJ化した後の実行管理 |
| `/admin/management-knowledge` | PoC設計で再利用できる型・座組ノウハウ |

2026-07-09 のPoCサービスMTGを起点に追加。Notion議事録はsourceだが、OSへは全文・URLを入れない。保存するのは短い参照名、構造化された仮説、次アクションだけ。

## データ

| table | 役割 |
|---|---|
| `seeds` | シーズの正本。PoC画面からも追加でき、研究機関、研究者、用途、キーワード、次アクションを持つ |
| `poc_companies` | PoC先の正本。企業、事業所、組合、自治体、施設カテゴリなど、PoCを受ける側の業界タグ、地域、規模感、PoC相性、過去PoC/紹介経路、謝礼メモ、担当、次アクションを持つ |
| `poc_matches` | シーズ x PoC先から生成する案件候補。相性仮説、ヒアリング論点、PoCで確認すること、謝礼、契約、資金、収益分配、状態、優先度を持つ |

`seeds` は研究シーズ側の正本として再利用し、PJ化済み案件は `projects.project_id` に任意で紐づける。PoC先は、過去のAMD接点、かるちゃん側の企業ネットワーク、公開PoC事例の調査結果、既存OS内のPJ資料などから手入力または将来の候補抽出で増やす。案件候補は、シーズとPoC先がそろってから、候補先タグとシーズ側の用途・キーワードを照合して案件化キューから生成する。

## 状態

PoC先:

```text
candidate -> listed -> contacted -> hearing -> poc_ready -> archived
```

案件候補:

```text
candidate -> hearing_design -> introduced -> hearing_done
  -> poc_design -> poc_running -> deal / archived
```

## UI

`/poc` は左ナビの探索グループに置く。

必須要素:

- 上段メトリクス: シーズ、PoC先、進行中の案件候補、PoC設計以降
- 検索と状態フィルタ: シーズ、PoC先、仮説、次アクションを横断検索
- シーズ追加: シーズ名、機関、地域、PI/研究者、領域、用途・業界タグ、キーワード、概要、担当、状態、次アクションを保存
- PoC先追加: PoC先名、規模感、地域、業界タグ、PoC相性、過去PoC/紹介経路、謝礼、担当、状態、次アクションを保存
- PoC先候補リスト: PoC先を比較表で表示し、業界タグ、地域、規模感、状態、PoC相性、謝礼・履歴、案件数、次アクションを横並びで比較できる。業界タグ、地域、規模感、状態などのタグで絞り込む
- 案件化キュー: シーズごとに既存案件と上位PoC先候補を並べ、候補の `案件化` から相性仮説・ヒアリング論点の初期案を生成する
- 一覧: 案件候補とPoC先の状態を画面上で更新できる

## Source Hygiene

- Notion、Gmail、Slack、Drive、Webの本文・URLをこの台帳へ直接保存しない
- `source_ref` / `source_note` は `2026-07-09 PoCサービスMTG` のような短い参照名に留める
- 議事録由来のメモは、相性仮説、質問、契約論点、収益分配メモなど、次に使う構造へ落としてから保存する

## 回帰防止

- route、GlobalNav導線、`seeds` / `poc_companies` / `poc_matches` のdata access、シーズ追加、PoC先追加、PoC先候補リスト、案件化キューを消す変更は `FEATURE_REGISTRY.md` と `pwa/scripts/check_pwa_critical_ui.cjs` も同時に更新する
- `/poc` はSeedsの代替ではない。シーズ情報そのものは引き続き `seeds` が正本で、`/poc` からの追加も同じ正本に入る。PoC固有のPoC先・条件・質問だけを `poc_*` に置く

**日付**: 2026-08-30（v0.2）

## 0. このドキュメントの位置づけ

石原先生から「愛大内の多数の研究シーズの事業化を横断的にマネジメントしたいが、各案件のプロジェクトマネジメント・進捗管理・予算管理がそれぞれカオスになっている」というお話を伺いました。

本書は、**何をどこまで実装するか**を先生と一緒に決めるためのたたき台です。

> **v0.1（2026-06-16）からの変更**: 機能を一覧で並べる構成をやめ、**先生方の作業がどれだけ減るか**から書く構成に変えました。AMD OS の中心は、人が入力する台帳ではなく、既にあるメール・資料・予定から**必要な文書を自動で作る**部分にあります。v0.1 はその中心を伝えられていませんでした。

---

## 1. この OS が引き受けること

> **散らばった情報を集めて回る作業を、OS が肩代わりする。**

事業化案件の管理が重くなる原因は、案件の数そのものよりも、**情報がメール・資料・打合せに散らばっていて、人が集め直さないと何も分からない**ことにあります。

```
   現状                                    導入後
─────────────────       ─────────────────
 案件A: メールの中                    ┌────────────────────────┐
 案件B: 頭の中                        │ OS が毎日、自動で作るもの         │
 案件C: 別の人のPC                    │  ・打合せの記録と次の一手         │
 案件D: 紙の予算表        ──→        │  ・締切と要対応の一覧             │
 進捗: 聞いて回らないと不明            │  ・月次の進捗報告の下書き         │
 締切: 気づいた人が覚えている          │  ・案件ごとの重要情報             │
 報告書: 毎回ゼロから書く              └────────────────────────┘
```

加えて、産連本部の立場では、集まった情報をもとに OS が各案件を同じ物差しで評価します。どの案件へ人と予算を集中するかを、印象ではなく並べて比べて決められます（第7章）。

AMD は自社で、複数のディープテック・スタートアップの事業化を同じ仕組みで横断管理しています。本提案は、その実運用中のシステム（AMD OS）を愛大の文脈に合わせて提供するものです。

## 2. OS が自動で作るもの

**ここが提案の中心です。**以下はすべて、人が入力するのではなく、既にあるメール・資料・カレンダーの予定から OS が毎日つくります。

| OS が作るもの | 中身 | 誰のどの作業が減るか |
|---|---|---|
| **打合せの記録** | 会議ごとの決定事項・進捗・次にやること・懸念点。次回の予定と、そこで要る資料も並ぶ | 議事録を書く作業。「あの打合せで何が決まったか」を思い出す作業 |
| **締切と要対応の一覧** | 公募の締切、報告書の提出期限、契約の更新、振込期日を、メールと公募要領から拾って期限順に並べる | 締切を追う作業。うっかり失念そのもの |
| **月次の進捗報告** | 案件ごとに、その月に何が動いたかの下書き。学内報告や実績報告書の素材になる | 報告書をゼロから書く作業 |
| **案件ごとの重要情報** | 決算、契約、資金調達、補助金、技術、計画、リスク、人事、期限を、資料本文から拾って1か所に集める | 「あの件の金額いくらだったか」を探す作業 |
| **マイルストーンの進捗** | 各案件の節目がどこまで進んだかを、動きから推定して更新する | 進捗率を聞いて回る作業 |
| **外部シグナル** | 政策・公募・市場・競合の動きのうち、担当案件に関係するものを拾う | ニュースを追う作業 |

いずれも AMD の実運用で毎日動いているものです。仕組みとしては、まず案件ごとの下書きを OS が作り、**先生が採否を判断してから**正式な記録になります。OS が勝手に確定させることはありません。

### 実装の状況（正直に）

| 状態 | 該当 |
|---|---|
| AMD で毎日稼働中 | 打合せの記録／月次の進捗報告／マイルストーンの進捗／外部シグナル |
| 実装中（AMD で段階運用） | 締切と要対応の一覧／案件ごとの重要情報 |

愛大への提供時点でどこまで含めるかは、この状況を踏まえて相談させてください。

## 3. そのために見せていただくもの

上の自動生成は、**元になる情報にアクセスできて初めて成立します。**逆に言えば、アクセスの範囲がそのまま、自動で作れるものの範囲になります。

| 情報源 | 何に使うか |
|---|---|
| **メール** | 締切・契約・金額・先方の反応・公募の採否 |
| **資料（ドライブ）** | 事業計画、予算書、契約書、実験記録、報告書 |
| **カレンダー** | 打合せの予定と、その前後の動き |
| Slack / Notion | 使っておられる場合のみ。日々のやり取りと議事メモ |

- **読み取りのみ**です。OS がメールを送ったり、資料を書き換えたりすることはありません。
- 対象にする範囲（アカウント・フォルダ・期間）を最初に宣言し、**その外は読みません**。
- 個人を特定する情報や本文そのものは保存せず、要点と参照先だけを残します。

**範囲を絞るほど、自動で作れるものが減ります。**たとえば産連本部の記録だけを対象にすると、公募と学内審議の管理は回りますが、研究者の方ご自身の作業（打合せの記録、実績報告の下書き）は減りません。どこまでを対象にするかは、先生方が受け入れられる範囲で決めていただくのが前提です。

## 4. 人が入力するもの

自動化が中心ですが、次だけは登録が要ります。

| 入力するもの | 頻度 |
|---|---|
| シーズの基本情報（研究者・領域・応用先） | 登録時の一度 |
| 案件の担当者 | 変わったとき |
| 予算の枠（資金種別ごとの配分） | 年度ごと |
| 自動生成された下書きの採否 | 出てきたとき |

これ以外に、日々の進捗入力や日報の類はありません。

## 5. 見る画面

| 画面 | 何が見えるか |
|---|---|
| **横断ダッシュボード** | 全シーズの現在地。止まっている案件、締切が近い案件が上に出る。朝いちばんに開く画面 |
| **案件コックピット** | 1案件の全体。進捗、直近の動き、担当、予算の消化、やること、関連資料が1画面 |
| **要対応** | 期限つきのやることを、案件をまたいで期限順に |

見える範囲は役割で分かれます（第7章）。産連本部は全案件を横断で、研究者の方はご自身の案件を見る形になります。

## 6. 予算管理

- 資金種別ごと（科研費／受託研究／共同研究／運営費交付金）に、枠・消化・残高を管理します。
- 費目別の内訳と、執行ペースが見えます。
- 学内会計システムとの直接連携は要相談です。初期は月末データの取り込みでも運用できます。

## 7. 案件の評価

OS は裏側で、各案件の事業化の見込みと、いま何が一番のボトルネックかを継続的に算出しています。AMD が自社の案件に使っている評価モデルと同じものです。

**これが誰にどう見えるかは、役割で分けます。**

| 役割 | 評価の見え方 | 理由 |
|---|---|---|
| **産連本部**（先生・URA） | 全案件のスコアと並び順、軸ごとの内訳、各案件のボトルネックが見える | 複数案件のどこへ人と予算を集中するかを決める立場。比較できる数値がそのまま判断材料になる |
| **研究者・案件メンバー** | 自分の案件の「次に手を打つべき場所」だけ。スコアの数値と他案件との並び順は出さない | 自分の案件しかない立場では並び順に意味がなく、数値だけが独り歩きしやすい |

産連本部の画面では、横断ダッシュボードの並び順が評価順になり、各案件について軸別の内訳（技術／事業化／人材・組織／規制・ガバナンス／社会受容）と、その中で最も低い軸が出ます。「どの案件にリソースを集中するか」「この案件は次に何を埋めるべきか」を、案件をまたいで同じ物差しで比べられます。

評価の値は、第2章の自動生成と同じ情報から更新されます。先生方に評価用の入力作業をお願いすることはありません。

## 8. データの取扱い

| 項目 | 内容 |
|---|---|
| 利用範囲 | 本 OS の機能提供、および AMD の事業化評価モデルの精度向上 |
| 保存するもの | 要点・参照先・日時・案件との対応。本文と個人情報は保存しない |
| 外部提供 | しない |
| 生成AIの扱い | 入力データを学習に使わない契約形態の API のみを使用。オンプレミス構成の相談も可 |
| 明文化 | 上記を契約時に条項として記載 |

評価モデルの精度向上に使わせていただく点は、契約書に明記します。

## 9. 想定スケジュール

| フェーズ | 内容 | 目安 |
|---|---|---|
| 0. 仕様確定 | 対象範囲・アクセス範囲・連携方式を確定 → 見積確定 | 〜2週 |

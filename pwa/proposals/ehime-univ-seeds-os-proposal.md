**ドキュメント種別**: 仕様すり合わせ用たたき台（v0.1）

---

## 0. このドキュメントの位置づけ

石原先生から「愛大内の多数の研究シーズの事業化を横断的にマネジメントしたいが、各案件のプロジェクトマネジメント・進捗管理・予算管理がそれぞれカオスになっている」というお話を伺いました。

本書は、**何をどこまで実装するか**を先生と一緒に決めるためのたたき台です。
「全部入り」ではなく、**梅 → 竹 → 松** の3段階で機能を並べていますので、

1. まず「これは絶対欲しい」「これは要らない」を仕分けし、
2. 採用範囲が固まったら、その範囲で開発金額をお見積りする

という進め方を想定しています。実装する内容次第で金額が変わるため、**先に仕様を固める**のが本書の目的です。

---

## 1. 何を解決する OS か（コンセプト）

> **愛大のシーズ群を「1つのポートフォリオ」として経営する OS。**

石原先生がお一人で何件もの事業化案件を抱えている現状を、

- **各シーズ＝1プロジェクト**として登録し、
- 進捗・予算・人・次の一手を**1画面で横断的に見渡せる**ようにし、
- 「いまどの案件が止まっているか」「どの案件に手を打つべきか」を**先生に代わってOSが教えてくれる**

状態にします。

```
   現状                              導入後
─────────────              ─────────────
 案件A: Excelとメール          ┌──────────────────────┐
 案件B: 頭の中                 │  愛大シーズ ポートフォリオ画面     │
 案件C: 別の人のPC      ──→   │  ・全案件の進捗が一目             │
 案件D: 紙の予算表             │  ・遅延/予算超過を自動アラート    │
 予算: 案件ごとにバラバラ      │  ・「次に打つべき一手」を提示     │
 進捗: 散在して把握不能        └──────────────────────┘
```

AMD は自社で、複数のディープテック・スタートアップの事業化を**同じ仕組みで横断管理**しています。本提案は、その実運用中のシステム（AMD OS）を愛大の文脈に合わせて提供するものです。

## 3. 機能詳細

### 🟢 梅（コア）— プロマネ・進捗・予算の基盤

#### 1. シーズ・マスタ管理
- 愛大内のシーズを**一覧で台帳管理**。研究者（PI）・所属（学部/研究室）・研究領域・応用先・成熟度・事業化ステータスを記録
- ステータスで進捗を追跡: `候補 → 調査中 → 接触済 → 商談中 → 事業化 / 見送り`
- 外部助成（科研費・JST・NEDO・AMED等）の履歴、関連ニュース・論文、接触ログも紐づけ
- フィルタ・検索で「GX領域で TRL が高いシーズ」のような絞り込みが即座にできる

#### 2. 案件コックピット（1案件1画面）
- 1つのシーズを開くと、その案件の**現在地が1画面に集約**:
  - 進捗状況・マイルストーン（Gantt表示）
  - 直近の動き・会議サマリ
  - 担当者・関与メンバー
  - 予算消化状況
  - やるべきこと（TODO）
  - 関連資料へのリンク
- 石原先生が「あの案件どうだったっけ？」を**ゼロ秒で思い出せる**

#### 3. 横断ダッシュボード（司令塔ビュー）
- 全シーズの現在地を**横断で一覧**
- 遅延している案件・予算超過の案件を**自動でハイライト**
- 「今月やること」を全案件分まとめて期限順に表示
- これが石原先生の**朝イチで開く"司令塔"画面**になる

#### 4. マイルストーン＆月次進捗
- 各シーズの事業化フェーズ（例: 申請 → 採択 → 試作 → 実証 → 法人化 → 受託）を**マイルストーン化**
- 月次で進捗 % を更新 → 案件の前進/停滞が時系列で見える
- 誰がどのマイルストーンの担当か（責任比率）も可視化

#### 5. 研究費・予算管理
- **資金種別ごと**（科研費 / 受託研究 / 共同研究 / 運営費交付金 / 自己資金）に予算枠・消化・残高を管理
- 費目別の見える化、執行ペースの可視化
- 案件横断で「いまどの資金がいくら残っているか」が一目
- ※ 学内会計システムとの連携は要相談（初期は月末データ取込でも可）

#### 6. 期限・やることアラート
- 申請締切・報告書提出・予算執行期限・契約更新を**自動で並べてアラート**
- 期限超過は赤フラグ
- 「うっかり申請期限を逃した」を構造的に防ぐ

---

### 🔵 竹（推奨）— 案件を"評価"し、意思決定を支援

#### 7. 立替精算・領収書管理
- 出張費・物品・学会参加費の立替を申請 → 承認 → 経理反映のフロー
- 領収書を写真添付で電子保管

#### 8. シーズ評価スコア（AMD Score）⭐
- AMD が実運用しているシーズ評価モデルを愛大シーズに適用
- 各案件を以下の軸で 0〜9 段階評価し、**事業化の見込みと弱点を客観化**:
  - **TRL**（技術成熟度）／**BRL**（事業化成熟度）／**HRL**（人材・組織成熟度）
  - **GRL**（規制・ガバナンス）／**SRL**（社会受容）※フル版
  - **創業者牽引力**（FRL）※フル版
- スコアの構造上、**「いま一番のボトルネックはどの軸か」=「次に手を打つべき場所」**が自動で出る
- 「どの案件にリソースを集中すべきか」の判断材料になる
- ※ この評価データは AMD のスコアモデル改善にも活用させていただきます（後述 第5章）

#### 9. 会議・議事録の自動記録
- 打合せ・面談の議事録を「**背景 → 決まったこと → 次の一手**」の構造で記録
- 案件コックピットに自動で紐づき、後から経緯を追える

#### 10. メンバー・研究者台帳
- 関与する研究者・URA・学生・外部パートナーの台帳
- 担当案件・専門領域・連絡先・接触履歴を一元管理

---

### 🟣 松（フル）— 自動化・先手提案・ポートフォリオ最適化

#### 11. 先手提案エンジン（次の一手）⭐
- AMD の「先手力ループ」を移植
- 「面談後48時間以内にフォローが必要」「先方からの催促を検知」「次回MTG3営業日前に資料準備」などを**OSが検知し、打つべき一手を提案**
- 石原先生が抱えきれない数の案件でも、**取りこぼしをOSが先回りで拾う**

#### 12. ポートフォリオ／マクロトレンド分析
- 政策・ニュース・論文の動向から、各領域の「事業化の波」を可視化
- 「いまこの領域は政策の追い風が来ている＝投入の好機」を判定
- 複数シーズ間の競合・補完関係を俯瞰し、**ポートフォリオとして最適配分**を検討

#### 13. 判断の型（プロトコル）資産化
- 「この分岐でこう判断したらこうなった」という意思決定パターンを蓄積
- 似た案件の次の分岐で**過去の型をそのまま再利用**
- 石原先生個人のノウハウを、組織の資産として継承可能にする

## 5. AMD との協働メリット（双方にとっての旨味）

本 OS は単なる業務ツールではなく、**愛大と AMD の協働基盤**になります。

### 愛大が得るもの
- 散在していたシーズ事業化を、AMD の実運用ノウハウが詰まった OS で一元管理
- 各案件の客観評価（AMD Score）による、リソース集中の意思決定支援
- AMD の事業化知見（プロトコル・先手提案）へのアクセス

### AMD が得るもの
- 各シーズの**評価スコアと AMD プロトコルの適用データ**
- これらは AMD の事業化判断モデルの**精度向上（retrofit / 検証）**に活用
- 愛大シーズ群が乗ることで AMD のモデル検証サンプルが大きく増える

> ※ データの取扱い範囲・匿名化・利用目的は、契約時に明文化します。
> 愛大側のセンシティブ情報（未公開研究内容等）は対象外とし、**事業化プロセスのメタデータ**（評価軸の値・判断履歴・進捗パターン）を中心に協働対象とする想定です。

この「**愛大はマネジメント基盤を得て、AMD はモデル精度を得る**」という相互利益構造が、本提案の核です。

## 付録: 用語

| 用語 | 意味 |

## 1. まさが決めた骨格（2026-09-11）

- ツリーの**根に到達点**（シーズン終了時にこうなっている、という状態）を置き、そこから分岐させる。PJが進むあいだも枝は増え続ける。
- 生まれた**TODOひとつひとつにポイントを割り当てる**。
- TODOが発生したら、**ガントにもMSリスト（シーズンのマイルストーン）にも入る**。
- **会議中はツリーを見ながら次々とTODOを出す。管理するときはMSリストとガントを見る。**
- **会議中にアサインしない。** 次々と発生するので、その場で担当・期限を付けさせると会議が止まる。あとでまとめてアサインできるようにする。
- **ptの配り方が要。** 配りすぎると後半にptが不足し、誰も仕事をしてくれなくなる。

出発点になった課題は、ZMPは議事録にTODOを書いているだけでプロマネが回っていない、SXは新しい論点を拾えず全体の遅れも見えない、その結果まさが巻き取ってメンバーが育たない、の3つ。2026-09-11 に数えた現在地は §12 に置く。

## 2. 3つの面

同じTODOを3つの面から見る。面ごとに見るものと、いつ誰が見るかを分ける。

| 面 | 何を見る | いつ・誰が |
|---|---|---|
| ゴールツリー | 到達点から分岐した条件・論点・TODO。どれが宙に浮いているか、どの枝が死んだか。**担当・期限・見積ptはここで付ける** | 会議中は出た人とPMが枝を足す。会議後はPMが未アサインの行を上から順に開いてアサインする |
| MSリスト | 到達点ごとに、配ったpt・検収済みpt・残pt・アサイン待ち。間に合うか | 月初合意、月次、週次。PMとまさ |
| ガント | TODOの日程と前後関係。日程が無いTODO、期限超過 | 週次。PMと担当者 |

ツリーで生まれたTODOは、親をたどれば必ずMSに属し、日程が付けばガントに現れる。3つの面のどこで直しても同じ1行が変わる。面ごとの別テーブルは作らない。

## 3. ゴールツリーの型

3-21 の3型（問い / やること / 分かったこと）は変えない。問いの種類に2つ足し、根の直下をMSに固定する。

| 層 | 型 | 内容 |
|---|---|---|
| 根 | 到達点（問いの `question_kind='goal'`） | シーズン終了時、または途中の関門で「こうなっている」という状態。期日はシーズン終了月か関門の月。1PJに1〜数本。答えは「到達した / しなかった」 |
| 根の直下 | MS（問いの `question_kind='milestone'`） | 到達点を成り立たせる条件。**ptと期間を持ち、シーズンのマイルストーン（`value_milestones`）と1対1で対応する**。対応は `project_question_milestones`（問い×MS）で持つ |
| その下 | 論点 / 仮説 / 決めること | 3-21 のまま。必須・代替の区別も同じ |
| 葉 | TODO（やること） | 3-21 の「やること」。**見積pt・確定pt・担当（複数可）・期限** を持つ |
| 横 | 分かったこと | 3-21 のまま |

- **定常業務のMS**（定例会運営、事務手続き、CEO業務のような `tag='routine'`）は到達点の枝にならない。ツリーには出さず、MSリストにだけ従来どおり置く。消化も従来の月按分のまま。
- 3-21 の判定（判断できる / 手が止まっている / 枝が死んだ / 期限超過 / 更新切れ）はそのまま効く。**MSの「判断できる」＝配下がすべて片付いた**。到達点の「判断できる」＝全MSが到達。閉じるのは人（3-21 と同じ）。
- 到達点を消しても直下のMSは消えない（3-21「親を消しても子は消さない」）。

SXなら、根「2027年4月1日にNewCoを設立し事業を開始している」、直下に 9/9 にまさが整理した4条件（NewCo体制案確定 / 出資の確約 / 愛媛大との諸手続き完了 / SIERのMOU締結）がMSとして並び、その下に既存の論点27件・やること50件がぶら下がる。ZMPなら、テーマ（KR経営改革 / 水素循環 / OkuDoor運営 / OkuDoorシステム）が到達点、現行MS10本が直下に来る。

## 4. 会議中の使い方と、会議後のアサイン

### 会議中（発生）

- 会議に出たAMD側の人がツリーを開き、「子を追加」で **種類とタイトルだけ** 入れる。担当・期限・ptは空でよい。
- 空のまま足したTODOは、その行に「未アサイン」の印が付く（3-21「上部へ抜き出さない」に従い、行の中で示す）。
- つくよみは翌日、議事録と木を照合し、記録にあって木に無いものだけを提案に置く（3-21「つくよみが拾うもの」、2026-09-11 実装済み。PJあたり1日最大5件）。全件自動起票はしない。

### 会議後（アサイン）

- **アサインはゴールツリーの中で行う**（まさ確定 2026-09-11「ptの割り振りはMSからでなくゴールツリーからやりたい」）。未アサインの印が付いたTODO行を上から順に開き、詳細モーダルで担当（人名、複数可）・期限・見積ptを付ける。ヘッダーの「未アサイン n件」を押すと最初の該当行へ移る。新しい一覧画面は作らず、MSリストやガントからは配らない。
- 担当を付けた瞬間が **委託**。本人へ届き（§7）、受託の返事を待つ。
- 議事録で主語が「まさ」だったTODOは、担当を空のまま提案に入れ、理由欄に「記録上の主語はまさ。PMが担当を決める」と添える。PMがアサインするときに、まさに戻すか他へ振るかを決める。
- PMへの通知は翌朝9:00に1通。「昨日の {PJ} の会議で TODO n件・論点 m件 が増えた。未アサイン k件」。宛先はそのPJの `is_pm`、未設定ならPL。
- 未アサインが7日を超えたTODOは、PMの週報（§5）に「アサインが止まっている」として載る。

## 5. TODOがMSリストとガントへ流れる

### MSリスト

MSの行に、配下TODOから導いた数字を並べる。人が直接書く欄ではない。

| 列 | 中身 |
|---|---|
| MSのpt | シーズン設計で配ったpt（既存） |
| 配分済みpt | 配下TODOの見積ptの合計 |
| 検収済みpt | 配下TODOの確定ptの合計。**これがMSの累積進捗になる**（§6 原則4） |
| 残pt | MSのpt − 検収済みpt |
| 予備pt | MSのpt − 配分済みpt（§6 原則2） |
| TODO | 件数。うち未アサイン / 受託待ち / 期限超過 / 検収待ち |
| 到達見込み | 間に合う / 危ない / 間に合わない（下の判定） |

**到達見込みの判定**。MSの期日までの残り月数を `R`、MSのptを `P`、検収済みptを `D`、未完了TODOの見積ptを `E` としたとき、

- 間に合う: `E ≤ P − D` かつ、直近2か月の検収ptの平均 × `R` ≥ `E`
- 危ない: `E ≤ P − D` だが、直近の検収ペースでは `R` か月で `E` を消化できない
- 間に合わない: `E > P − D`（配れるptが足りない）、または期日超過で `D < P`

記号は表示に出さず、日本語の3語だけ出す。ペースの根拠（直近2か月の検収pt）は詳細に出す。

### ガント

- 左列がゴールツリー（到達点 → MS → 論点 → TODO）、右列のバーがTODO。3-21「ガント：左列が問いの木、バーがやること（未実装）」の実装。旧構造（`project_management_tasks`）のガントは置き換える。
- 日程が無いTODOは「日程未設定」行に出す。ここでは日程だけを付ける。担当・見積ptはゴールツリーで付ける（§4）。
- 前後関係は `project_action_dependencies`（`finish_to_start` のみ、既存）。
- 表示の密度・操作は 3-16 の現行ガント（行高48px、詳細は重畳モーダル、その場編集）を引き継ぐ。

## 6. ptの配り方（配りすぎを防ぐ）

まさの懸念「配りすぎたら後半pt不足になって誰も仕事をしてくれなくなる」に、構造で答える。

### 原則1: ptはMSに配る。TODOはその内訳

- シーズン原資からMSへptを配るのは従来どおり（`/admin/ms-overview`、保存前検算つき）。**TODOのptは、そのMSのptの内訳**であり、MSのptを超えて配れない。
- TODOが増えてもMSのptは増えない。増えた分は同じMSのptを分け合う。つまり「ptの総量」はシーズン設計の時点で決まり、会議で枝が増えても総量は動かない。ここが「配りすぎ」を構造で止める1点目。
- **TODOへの割り振りはゴールツリーの上で行う**（まさ確定 2026-09-11）。MSリスト（`/admin/ms-overview`）で決めるのはMSの枠だけで、そこからTODOへは配らない。ツリーでTODOに見積ptを付けると、親をたどってそのMSの配分済みptに積み上がる。

### 原則2: MSのptの半分は予備として残す（まさ確定 2026-09-11）

- MSのptのうち、最初にTODOへ配れる上限は **50%**。残りの **50%は予備**。理由は「あとからどんどん新しいタスクが出てくる」から。
- 予備は **新しく生まれたTODOにだけ** 配る。時間が経ったからといって自動では開放しない。既存TODOの見積を膨らませるためにも使わない。新しいTODOのアサイン時に、配分可能な50%を使い切っていればPMが予備から配る。
- **シーズン終了時に余った予備は、獲得ptに比例してメンバーへ配る**（まさ確定）。余りはシーズン全体で合算し、そのシーズンで検収されたptのメンバー別の比で確定ptに上乗せする。会社側が取らない。報酬計算上は最終月の消化として入り、7-1「最終月に未払残0で閉じる」と整合する。MS単位では配らず、シーズン全体で合算する（まさ確定 2026-09-11）。
- 予備の残りはMSリストの列で見える。予備が0になったMSは赤くなる。

### 原則3: 見積ptと確定ptを分ける

- アサイン時にPMが **見積pt** を付ける。検収時に検収者が **確定pt** を付ける（見積のまま、または増減）。
- 確定ptの合計はMSのptを超えられない（DBの検査とAPIの両方）。超える検収は、先に予備の開放かシーズン設計の見直しが要る。
- 見積の合計が配分可能pt（MSのpt × 50% ＋ 新規TODOへ配った予備）を超えるアサインは、保存できる（アサインを止めると会議後の作業が止まる）が、そのMSに「配りすぎ」の警告が出て、PMの週報とまさの週報に載る。

### 原則4: 消化はTODOの検収月。MSの進捗＝確定ptの累計÷MSのpt

- TODOが検収された月に、その確定ptがMSの消化になる。MSの累積進捗率（`milestone_monthly_progress`）は、検収済みptの累計 ÷ MSのpt で書く。source は新設の `todo_acceptance`（PMの検収なので PM locked 扱い。3-10 の source 契約に1行足す）。
- **TODOが1件も登録されていないMS**（定常業務、まだ分解していないMS）は、従来の月按分（アンカー方式）のまま。両方が並ぶ移行期間を認める。
- 報酬計算（7-1）はMSの累積進捗を読むだけなので、計算式は変えない。変わるのは進捗の作り方だけ。
- これは 2026-06-15 に決めた「pt消化は必ず期間月数で按分」の考え方を、TODOが登録されたMSについて「検収の実績」へ変えることになる。按分の目的だった「特定月にまとめて達成して将来原価を跳ねさせない」は、支払上限（cap）と繰越の仕組みが残るので支払側では保たれる。**まさ確定（2026-09-11）**: TODOが登録されたMSだけ検収実績、無いMSは従来の按分。SXは切り直し後の最初の稼働月から。

### 原則5: pt単価は固定

- 本契約のpt単価 = シーズン原資 ÷（シーズン月数 × 10pt）は従来どおり。TODOのptが増減しても単価は動かない（7-1「配分pt合計が増減しても本契約pt単価は変動させない」）。

### 原則6: 小さいTODOはpt無しでよい

- ptを付けるのは、報酬に反映する大きさの仕事だけ。見積は小数1桁、最小0.5pt。
- 1時間で終わる確認や連絡はpt 0 で登録してよい。pt 0 のTODOも、期限・催促・検収の対象にはなる（やらなくてよい仕事にはならない）。
- 見積の目安として、PJごとに「1pt≒何時間」を参考表示する（pt単価 ÷ 時間単価の目安）。目安であり正本にしない。

### 原則7: 前半に配ったptを塩漬けにしない

- アサイン済みで、期限を30日過ぎても着手されていない（`running` にならない）TODOの見積ptは、**回収候補** としてPMの週報に載る。PMはTODOを取り下げる（`dropped`、理由必須）か、見積を0にして予備へ戻す。
- 後半に「ptが無い」のに前半の配分が残っている状態を作らないための弁。

### 原則8: ptが尽きたときの逃げ道

- 予備も使い切ったMSに、まだ必要なTODOが出るとき。順に、(1) 同じ到達点の他のMSの予備を融通する（PMが申請、まさが承認）、(2) シーズン設計の見直し（原資・バッファ・MS間の配分。`/admin/ms-overview`）、(3) 追加受注（別財布 `cap_extra`）。
- OSは「残pt ÷ 未完了TODOの見積合計」が1を切った時点で警告する。尽きてからではなく、尽きる前に見える。

### 原則9: 1人への集中を見張る

- PM自身のTODOの見積合計が、そのPJの配分可能ptの **50%** を超えたらまさの週報に載る（PMの抱え込み）。まさ自身のTODOの比率も同じ週報に載る（巻き取り）。閾値は暫定。

### 原則10: 支払済みMSの残作業に追加報酬は発生しない（まさ確定 2026-09-11）

- 月按分で100%消化済み（＝支払済み）のMSに、終わっていない作業が残っていても、**終わるまでやる。そこに新たなptは付けない。**
- 残作業は **pt 0 のTODO** として木にぶら下げ、担当・期限・催促・検収の対象にする（原則6）。月初合意の「担当する仕事」にも並べる（報酬欄は0）。
- 新MSのptは、まだ支払われていない新しい仕事にだけ配る。凍結したMSの残作業を新MSの配分に混ぜない。
- 凍結MSの行には、MSリストで「残作業 n件（pt 0）」を出し、支払済みなのに終わっていない仕事が見えるようにする。

### 配りすぎの検知指標（MSリストと週報に出す）

| 指標 | 読み方 |
|---|---|
| 配分済みpt ÷ MSのpt と、経過月数 ÷ MS期間 | 配分が経過を大きく上回っていたら前倒しで配りすぎ |
| 検収済みpt ÷ MSのpt と、経過月数 ÷ MS期間 | 検収が経過を下回っていたら遅れ |
| 残pt ÷ 未完了TODOの見積合計 | 1を切ったらptが足りない |

### メンバーへの配分

- TODOは複数の担当を持てる（担当ごとの割合、既定は均等）。
- 当月のMSごとのメンバー実績配分（7-1 の `actual_share`）は、**その月に検収されたTODOの確定pt × 担当割合** の比で作る。活動記録（`member_activities`）からの推定は補助に下げる。
- 月初合意の「01 あなたが担当する仕事」に、担当MSに加えて「今月受託しているTODO（見積pt付き）」を並べる。支払済みMSの残作業（pt 0）も同じ欄に並べる（原則10）。合意のhashには入れない（受託の増減で再合意を求めると月の途中で支払が止まる。3-14 の 2026-08-27 の事故と同じ形になる）。予定報酬の計算は従来どおり。

## 7. 委託の経路（アサイン → 受託 → 催促 → 検収 → 報酬）

§4 のアサインが委託にあたる。その先は次のとおり。

| 段階 | 何が起きるか | 誰が |
|---|---|---|
| 受託 | アサインされたTODOが本人へ届く。本人はワークスペースの自分の行で「受ける」か「期限を相談」。受ける＝ `accepted_at / accepted_by`。相談＝理由を1行、PMへ通知。返事が無ければ48時間で再送、96時間でPMへ | 担当者 |
| 催促 | 期限3日前 / 当日 / 超過後7日ごと、更新切れ7日。本人へは全PJぶんを1通に束ねる（朝・夕の2回、期限当日だけ即時）。PMへは毎週月曜にPJ1行（未アサイン / 受託待ち / 期限超過 / 検収待ち / 配りすぎ / 回収候補 / 到達見込み）。まさへは毎週月曜に全PJ横断1通で、PMが7日以上放置しているものと、§6 原則9の比率だけ | OS |
| 完了 | 本人が完了にする。完了証跡（リンクか一文）が空なら完了にできない | 担当者 |
| 検収 | PMが確定ptを付けて検収、または差し戻し（理由必須、`running` へ戻す）。PM本人のTODOはPL（まさ）が検収。検収待ち5日で催促、10日でまさの週報 | PM |
| 報酬 | 確定ptがMSの進捗と本人の実績配分に入る（§6 原則4、メンバーへの配分） | OS |

- 届け先は `members` にいる人だけ。クライアント側の人（こたさん等）には送らない。担当がクライアント側になっているTODOは「相手側ボール」としてPMの週報に載る。
- Slackの返信は読まない。返事は必ずOSの画面で受ける。
- 送信手段はえいみ名義のSlack（`scripts/send-eimi-slack.mjs`、宛先に個人ID可）。Slackで届けるのを既定とし、送信を開ける時期はまさが決める（まさ確定 2026-09-11）。

## 10. まさの判断（2026-09-11、すべて確定）

1. **予備は50%**。余った予備はシーズン終了時に獲得ptに比例して配る（§6 原則2）。
2. **月按分から検収実績への切り替え**は、TODOが登録されたMSだけ。無いMSは従来の按分。SXは切り直し後の最初の稼働月から（§6 原則4）。
3. **余った予備の配分単位**は、シーズン全体で合算し、シーズンの獲得pt比で配る。MS単位では配らない。
4. **アサインと期限を本人に届ける経路**は、Slackで届けるのを既定とする。本人→PM→まさの順、本人へは朝夕2回に束ねる。送信を開ける時期はまさが決める。Slackを開けるまでは、PMが定例で口頭で回す。
5. **SXの到達点直下は5本、CEO業務は定常継続、pt配分の暫定値**（8.1）は確定。支払済みMSの残作業に追加報酬は発生しない（§6 原則10）。

## 13. 検査

- 契約テスト: TODOの確定pt合計がMSのptを超えない / 証跡なしで完了にできない / 検収は `is_pm`（PM本人分は `is_pl`）だけ / 1人1日2通を超えない / 送信先が `members` 外にならない / 「いらない」にした提案を拾い直さない（既存）
- 数の突き合わせ: MSリストの検収済みptと、`milestone_monthly_progress`（source `todo_acceptance`）の累積が一致する。月初合意の予定報酬が、切り替え前後で支払済み月について1円も動かない。シーズン終了時の余りの配分が獲得ptの比になっていて、合計が予備の残りと一致する
- ドライラン: 送信を止めた状態の通知本文を design_log に1週間ぶん残し、まさが読んでから開ける
- 実データで見る: 開けてから2週間で、SX・ZMPの「未アサイン」「期限超過」「未更新」と、まさ担当比率が §12 と同じ数え方で減っているか。減っていなければ通知の間隔ではなく、到達点とMSの切り方を先に疑う
- 参照系/可変系: ツリー・TODO・MSリストの導出列は可変系。週報の集計は日次で保存して読む

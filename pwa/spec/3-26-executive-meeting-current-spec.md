# 3-26 経営会議

2026-10-23。PWA と共通DBの実装仕様。

## 入口と閲覧

- 全PJタイプのコックピット `?tab=executive-meeting` とワークスペース `#executive-meeting` の会社情報に同じ本文を置く。DDには置かない。
- 入場条件は、ユーザー本人の`is_executive=true`、当該PJのコックピットまたはワークスペースの既存閲覧権限、`project_executive_members.active=true`の本人登録の3条件。AMD管理者であっても両方の経営陣資格がなければ見られない。外部workspace accountは当該PJのactiveな直接所属も要する。社内`members`と外部`workspace_user_accounts`が独立して属性を持つ。既定値はfalse。
- ナビの非表示に加え、専用APIのGET/POSTは毎回本人・PJ・経営陣登録を照合する。認可できないときは本文もPJ存在も返さない。`no-store`。直接のDB権限は anon/authenticated に付けない。
- `project_meeting_summaries`、既存「動向・会議」、共有記録、DDの議事録、`workspace_shared` のいずれにも新しいデータを流さない。これらの既存機能には別のデータがあり、新ページの閲覧資格を代用しない。

## 管理者が登録するもの

- `/admin/executive-meetings` で管理者がユーザーごとの経営陣属性を付与・解除し、PJごとの経営陣を追加・解除する。PJ登録対象には本人属性と当該PJの既存スペース閲覧権限が必要。本人属性を外すと全PJ、PJ登録を外すとそのPJの閲覧・投票を直ちに止める。属性変更は`project_executive_attribute_events`、PJ登録変更は`project_executive_member_events`に変更者・日時・対象を残す。役員属性`is_officer`と経営陣属性は独立。
- 同画面で規程名、規程の原文全文、対応条項、定足数、可決条件、締切方法を一つの版として発行する。原文のSHA-256を保存。過去版は更新・削除せず、最新版だけが新たに始める採決へ適用される。
- 定足数は採決開始時の有権者を分母とする比率（以上/超）。可決は賛成票を、採決開始時の有権者・投票者（棄権含む）・賛否の投票者（棄権除く）のいずれかと比べる比率（以上/超）。定足数に届かなければ不成立。定足数を満たし、かつ賛成が1票以上で閾値を満たせば可決、それ以外は否決。規程原文との対応は管理者が確認する。判定条件が表現できない規程は登録せず、規則の拡張を先に行う。
- 締切は手動（経営陣全員/採決開始者/経営陣登録済み管理者）、全員投票時、開始から指定分数のいずれか。期限後の投票は受け付けず、期限に達した未確定議案は次の経営会議GETで確定する。`deadline_at` は期限、`closed_at` は確定を記録した時刻として区別する。
- 規程未登録でも議案の下書きは作れるが、採決開始は拒否する。

## 議案と採決

- 経営陣全員が議案を作り、採決を開始できる。下書きは作成者だけが編集できる。
- 開始処理はDBトランザクション内で議案行をロックし、最新版の規程版と有権者名簿を固定する。決議文・資料・開始者・規程版・有権者はその後変更できない。資料を直すときは別の議案として採決し直す。
- 一議案一有権者一票。賛成・反対・棄権のいずれかを記録し、投票後は変更できない。採決中は自分の票と投票済み人数だけ、確定後に賛否棄権数と可決/否決/定足数不足を表示する。
- `project_meeting_start_vote`、`project_meeting_cast_vote`、`project_meeting_finish_vote`、`project_meeting_cancel_vote` はservice roleだけ実行できる。議案・規程・有権者・投票は別表で、採決開始と投票は行ロックで競合を直列化する。
- 経営陣属性・PJ登録の解除やスペース資格喪失後は、採決開始時の名簿に載っていても閲覧・投票できない。全員投票による自動締切を使う場合、未投票者の資格喪失で締切不能になり得るため、経営陣登録済みの管理者が理由付きで採決を取り消し、新議案へ切り直す。取消済み採決と元の票は消さず、修正版には元議案への参照を付ける。票を自動補完・再配分しない。

## 画面内の判断順

- 初期表示は本人が未投票の議案を優先して選択する。ページ上部に本人の投票待ち件数、左に議案一覧、右に選択した議案を配置する。閲覧者の次の操作は件数と議案行の文字でも示し、色だけに依存しない。一覧は本人の投票待ち、未決議、決議済み、不成立・取消を区別する。決議済みには可決・否決だけを入れ、定足数不足や取消は含めない。
- 議案詳細は「今回決めること」→「判断材料・資料」→「あなたの対応」→「投票状況」の順に置く。資料本文中の `https://` / `http://` URLは外部リンクとして開ける。作成時は資料名・URLと判断に必要な要点の記入を促す。
- 賛成・反対・棄権は一つを選んでから「投票を確定」を押す。未選択時は確定不可。確定前に選択内容と変更不可を確認する。棄権も投票済み人数に含むことを投票欄に表示する。
- 採決の締切・取消・議案の作り直しは「議案の管理」に収め、投票操作より目立たせない。判定条件と規程原文は選択した議案に適用される版を折り畳みで参照できる。採決中の賛否内訳は表示しない。

## 将来の取締役会

DBは `meeting_kind=management|board` を区別する。現行API/UIは management だけを扱い、board の決議として表示・発行しない。取締役会の資格、招集、利害関係者、議決要件、証跡を別途実装してから同じページ内に追加する。

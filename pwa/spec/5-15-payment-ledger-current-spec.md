# 納付ページ仕様

> **状態**：実装済み（`/admin/payments`）。
> **対象画面**：`/admin/payments`。
> **画面名**：納付。
> **設計確定日**：2026-09-04。

## 目的

税務署、都道府県、市町村、年金機構、労働局へ「いつ・いくら納めるか」と「納めたかどうか」だけを一枚にまとめるadmin画面である。

`/admin/schedule`（管理カレンダー）は契約、月次報告、提出物も同じ時間軸へ並べるため、納付が他の予定に埋もれる。2026-09-04にまさから「カレンダーのとこ、月報とかに埋もれて納付が見にくい」と指摘があり、納付だけの画面を分けた。

## 固定原則

1. **手入力禁止**：この画面から金額、期日、納付済みを編集しない。正本は `company_payment_obligations` で、修正は `/admin/finance#payment-obligations` で行う。
2. **対象は公的機関への納付だけ**：`category in ('tax','social_insurance')` に限る。カード、サブスク、家賃、報酬、立替はこの画面へ出さない。
3. **行を落とさない**：期限を作れない行、金額を取得できない行、納付済みの行もすべて残し、状態で区別する。
4. **不明額を0円にしない**：`amount_status='unknown'` は「金額未取得」と表示する。
5. **freeeの照合結果を必ず書く**：納付済みかどうかを断定するだけでなく、口座を探した窓と、その窓で見つかった出金を各行に出す。未納なのか記録漏れなのかを人が判断できるようにする。

## 表示

### 上段のまとめ

| 項目 | 内容 |
|---|---|
| 期限を過ぎている・要確認 | 期限超過と、期限や金額が未確定で確認が必要な行の合計 |
| これから納める | 今日以降に期限が来る未納の合計 |
| 加算税・延滞税 | 届いた通知書の額と、未納から積み上がる見込みの額を分けて併記 |
| 納付済みとして消し込めた分 | freeeの出金と金額・日付が一致した行の合計 |

### 一覧

期限の近い順に、期限、納めるもの、納付先、金額、状態、freeeで調べた結果を並べる。期限を作れない行は最後に置く。

状態は `納付済み` / `期限超過` / `今日が期限` / `近い期限` / `これから` / `要確認` の6つで、期限超過には超過日数を添える。

`freeeで調べた結果` は次のいずれかを日本語で書く。

| 状況 | 表示 |
|---|---|
| 納付済み | `freeeの出金と一致（日付・金額）` |
| 窓に出金が無い | `<窓>に税務署あての出金は無い` |
| 同額の出金がある | `同額の出金がある（日付・金額・摘要・freeeの処理状態）。別の月の納付として使われているか、freeeで消込が済んでいない` |
| 金額が違う出金がある | `出金はあるが金額が合わない（日付・金額・摘要・freeeの処理状態）` |
| 通知書から登録した行 | `届いた通知書をもとに登録した行。口座の照合はしていない` |

摘要と処理状態はfreee公式の `wallet_txns` から取る。処理状態は 1=消込待ち、2=消込済み、3=無視、4=消込中、6=対象外 を日本語へ直す。**納めたのにfreeeで消込が済んでいない状態**をここで見分ける。

加算税・延滞税は、届いた通知書があればその額と納期限を、無ければ未納から積み上がる見込みを、元の納付の行へ添える。

### 目録

画面下部に「会社が負う税・保険料・提出の全件」を置く。仕様は `pwa/spec/5-9-admin-operating-calendar-current-spec.md` の同名節が正本で、コンポーネントは `StatutoryObligationCatalog` を共有する。

## データ

`company_payment_obligations` を `category in ('tax','social_insurance')` で読み、行数上限を跨がないようページで読む。`company_schedule_occurrences` と `company_operating_facts` は目録の突き合わせにだけ使う。

読み取りモデルは `pwa/src/lib/finance/payment-ledger.ts` の `buildPaymentLedger`（純関数）で、状態判定、加算税の親子の紐づけ、合計をここで確定する。画面は表示だけを持つ。

## freeeを見る頻度

| cron | 時刻（JST） | 納付ページに効くもの |
|---|---|---|
| `/api/cron/freee-payment-sync` | 毎日 09:10 | 入出金の同期 |
| `/api/cron/payment-obligations` | 毎日 09:20 | 給与仕訳から金額、口座明細から納付済み判定と照合の証跡 |
| `/api/cron/company-schedule` | 毎日 09:35 | 目録の突き合わせに使う予定の再生成 |
| `/api/cron/management-score-refresh` | 毎日 06:00 | 試算表と月次予実の実績 |
| `/api/cron/freee-accounting-weekly` | 毎週木曜 10:00 | 会計照合（残高差、未処理明細、役員報酬、内部振替） |

納付済みの判定に使う口座明細は毎日読む。週次なのは会計照合だけである。

## 導線

`/admin` は `/admin/schedule` のままとし、`AdminSidebar` の「納税・カレンダー」グループへ `納付` を管理カレンダーより上に置く。

管理カレンダー先頭の期限超過の警告からも納付ページへ導く。

## 検証

`npm run test:payment-obligations` が `buildPaymentLedger` の状態判定、加算税の紐づけ、合計、対象範囲（税・社会保険だけ、取消は除く）、期限が無い行の並びを検査する。

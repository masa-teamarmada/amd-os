# 3-23 PJタイプ別の標準フォーマット（現行仕様）

最終更新: 2026-10-03（§7 コスト試算タブを追加）

## 1. 目的と決定

2026-10-03 まさ確定。

> すべてのPJについて、同じフォーマットで表示する設計にして。勝手にそれを書き換えないように制限をかけてほしい。今回のSOLみたいに新たなデータが入るときには、新たなグラフを入れるんじゃなくて、フォーマットで生成されているグラフにその数値データを入れる形にしてほしい。

- PJの画面は、PJタイプごとに1つの形（フォーマット）で描く。同じタイプのPJは、同じ区画・同じ行・同じグラフを持つ。
- PJごとの違いはデータだけで出す。PJ番号で表示を分けない。
- 新しい種類の数字が来たら、標準の行・グラフのどこへ入るかを決めて、データとして流し込む。区画やグラフを足さない。
- フォーマットの定義は鍵付き。まさの明示の承認なしに変えない。

## 2. PJタイプ

`projects.project_category` から決める。正本は `src/lib/project-formats.ts` の `PROJECT_FORMAT_TYPES`。

| PJタイプ | `project_category` | 試算表タブ |
|---|---|---|
| 大学発SU | `dtsu`、`advisor` | あり |
| 新規事業 | `new_business` | あり |
| 研究機関エコシステム | `ecosystem` | なし（事業計画グループを持たない） |

顧問PJ（`advisor`）は会社の試算表を読むので、大学発SUと同じ形にする。

## 3. 試算表タブの標準フォーマット

画面は `ProjectFinanceFormat`（`src/components/cockpit/ProjectFinanceFormat.tsx`）。コックピット・PJワークスペース・DDの資金計画が同じ部品を使う。試算表タブ（`CockpitFinancialProjection`）はこの部品だけを描く。

### 3.1 区画

`FINANCE_FORMAT_SECTIONS` の順に、データの有無にかかわらず全区画を描く。データが無い区画は「未登録」と出し、区画そのものは消さない。

| 順 | 区画 | 内容 |
|---|---|---|
| 1 | 計画とケース | データにある計画の切り替え（資料から取り込んだ計画を新しい順、次に登録済みの月次試算）と、計画が持つケースの切り替え |
| 2 | 要約 | 期間・売上計・費用計・調達計（株式・融資・助成金）・最低の月末資金・期末の月末資金 |
| 3 | 時間軸 | 試算（BZM 2.2）の時間軸のイベント、会社設立、設立前DD完了期限（設立の前月、AMDの必須ゲート）、資本政策の調達イベント |
| 4 | 月次試算表 | 出所・計上主体・P/Lの行・C/Fの行・元データの内訳（折り畳み）・BZM経済CF |
| 5 | 月次の資金推移 | 月ごとの入金と出金の横並びの棒、月末資金の折れ線、手元資金の目安（データにあるとき破線） |
| 6 | 年度別の事業・資金推移 | 4月始まりの年度ごとに、売上と費用の横並びの棒、年次純C/Fの折れ線（同じ目盛り） |
| 7 | 年度別数値 | 年度ごとの売上・費用計と内訳・営業利益・株式調達・融資（実行−返済）・助成金等入金・年次純C/F・年度末資金・設立前PJ支出 |
| 8 | 前提と注記 | 計画が持つ前提の表と注記 |

時間軸・月次試算表・月次の資金推移は、月の列をそろえるため1つの横スクロールの中に描く。金額の単位は表の外に「単位：百万円」と一度だけ書く。

### 3.2 行

| 区分 | 行 |
|---|---|
| P/L | 売上・売上原価・粗利・人件費・研究開発費・販売促進費・その他販管費・設立前PJ支出・営業利益 |
| C/F | 月初資金・営業C/F・設備投資・株式調達・融資実行・融資返済・助成金等入金・月次純C/F・月末資金・月末借入残高 |
| 補助 | 出所（実績・見込・推定・計画・簡易）・計上主体（設立前PJ／会社）・BZM経済CF |

## 4. データの流し込み

変換は `src/lib/project-finance-format.ts` に集める。分けてよいのはデータの形だけで、PJ番号では分けない。

| 元データ | 入る計画 | 標準の行への入れ方 |
|---|---|---|
| `project_pl_monthly` | 登録済みの月次試算 | P/Lの各行。メモの先頭の「実績／見込／推定」を出所に出す |
| `project_monthly_cashflow` の標準の列 | 登録済みの月次試算 | 月初資金・営業C/F・設備投資（`investing_cash_flow_yen`）・株式調達・助成金等入金・月次純C/F・月末資金・月末借入残高（`bank_borrowing_balance_yen`） |
| `project_monthly_cashflow` のその他の列（収入計・SBIR/NEDO支払・FCF・財務C/Fなど） | 登録済みの月次試算 | 「元データの内訳」の行。値が1つでもある列だけ出す |
| `project_monthly_cashflow.planning_details_json`（資金計画） | 資金計画（改定日） | ケースごとに、通常支出＋融資利息→営業C/F、設備・初期費用→設備投資、シード＋ブリッジ→株式調達、借入→融資実行、元本返済→融資返済、助成金→助成金等入金。融資利息と端数調整は内訳へ。前提の表と注記は「前提と注記」へ |
| 資本政策（有効なプランの `document_json`） | 時間軸 | 会社設立、現金が入る調達（株式発行・転換社債型の発行・IPO）を時間軸へ。調達は試算側の同じ月の資金イベントより優先 |
| `project_ventures.founded_at` | 計上主体 | 設立月の正本。未登録なら資本政策の設立イベント |
| BZM 2.2 試算 | 時間軸・BZM経済CF | イベント・ゲートの通過値・経済CF。試算の対象外PJは「試算なし」 |
| `project_grants` | 助成金等入金のセル | 採択情報を◆で添える |

- 会社設立前の月のP/Lは、会社のP/Lに出さず「設立前PJ支出」へまとめる。設立前の支出は会社の資金繰りに入れない。
- C/Fの登録が無い月は、資金の計画（資本政策の調達・試算の月次前提）を持つPJに限り、会社設立後の月について、営業利益・試算の設備投資と助成金・資本政策の調達から簡易C/Fを組み立て、出所を「簡易」と出す。計画を持たないPJの実績P/Lから資金繰りを作り出さない。
- 資料から取り込んだ計画（資金計画）は画面から編集しない。数字は取り込み元で直す。
- 計画は混ぜない。資金計画と登録済みの月次試算は切り替えで別々に描く。

新しい形のデータが来たら、この表に「その形 → 標準の行」の対応を足し、変換関数で受け止める。画面の区画・グラフを足さない。

## 5. 変更の制限

`npm run test:project-format`（`scripts/check_project_format_contract.mjs`）が、本番反映（`scripts/deploy.sh`）の前に必ず走る。

1. **定義の鍵**：`src/lib/project-formats.ts` の sha256 が `scripts/project_format_lock.json` と一致しなければ止める。定義を変えてよいのは、まさが明示で承認したときだけ。承認を得たら approvals の末尾に「日付・まさ・承認の言葉・変えた内容」を足してから sha256 を更新する。
2. **PJ番号の名指しのラチェット**：コックピット・PJワークスペース・DDの部品（`src/components/cockpit`・`src/components/project-workspace`・`src/components/dd`・`src/app/(app)/project`・`src/app/workspace`）と、フォーマットの定義・変換のファイルで、PJ番号の文字列（`"p21"` など）とPJ専用の表示フラグを数える。`scripts/project_format_baseline.json` の既存分だけ許し、増えたら止める。減ったら許容数も下げさせる。
3. **試算表は標準フォーマットだけ**：試算表タブは `ProjectFinanceFormat` だけを読み込む。統合して消した部品（`CockpitFundingPlan`・`Bzm22TimeLedger`・`Bzm22TimeLedgerSection`・`CockpitPlMonthlySection`）を戻さない。DDの資金計画も同じ部品で描く。
4. **コスト試算タブは入口がデータの形で選ぶ**（§7）：入口 `CockpitCostTab` は `costFormatEngineOf(bundle)` だけで画面を選ぶ。標準フォーマット `ProjectCostFormat` は §7 の区画をすべて描き、要約の欄と前提の並べ方は定義の順に描く。コックピット・PJワークスペース・DD はどれも入口を通し、廃液の画面（`CockpitCostModel`）を直に描かない。計算の答えと式の一致は `npm run test:project-cost-model`（`scripts/check_project_cost_items_engine.mts`）が確かめる。

## 7. コスト試算タブの標準フォーマット

2026-10-03 まさ確定。

> 原価計算は、フォーマットは共通させることを前提にcxのもちゃんと入れて。

どのPJのコスト試算も、同じ区画・同じ内訳の行・同じグラフで描く。定義は `src/lib/project-formats.ts` の `COST_*`（§5 の鍵の対象）。画面は `ProjectCostFormat`（`src/components/cockpit/ProjectCostFormat.tsx`・`ProjectCostFormatSections.tsx`）。操作の形は SX の試算で 2026-09-13〜15 にまさが決めた形を全PJへ広げたもの（前提・明細・作業の数字はその場で書き換えて再計算し、保存は admin が押したときだけ。デスクトップは前提と結果を左右に並べ、スマホは結果の要約を上に固定する）。

### 7.1 区画

| 順 | 区画 | 内容 |
|---|---|---|
| 1 | 試算とケース | ケース（汎用の計算では比べる年間の量）の切り替え、保存していない変更、版 |
| 2 | 要約 | 1単位あたりの総コスト・売価・1単位あたりの利益（利益率）・成立ライン（総コスト目標）・初期投資（CAPEX）・毎年の費用（OPEX）・年間の量・作業工数 |
| 3 | 前提と作業 | 総コストの内訳（大きい順、押すと動かす場所へ移る）・作業と工数・条件／CAPEX／OPEX の3つに分けた前提・明細・作業（書き換えられる） |
| 4 | ケースの比較と原価の内訳 | ケースごとの総コストを内訳の行の色で積んだ棒（売価は破線、総コスト目標は点線）と、選んだケースの内訳の棒と割合 |
| 5 | この試算について | 要約・元にした資料・想定している系・注意して読むところ |
| 6 | ケースごとの内訳 | ケースを列にした表（内訳の行・総コスト・売価・利益・年間の数・初期投資） |
| 7 | この数字の確からしさ | 確度ごとの額と割合、精度を下げている項目 |
| 8 | 確認事項と出典 | 答えが出ると総コストが動く問い、外部ベンチマーク、この画面の見方 |
| 9 | 前提・作業・費用明細 | すべての前提（計算に使っていない前提も）・作業リスト・CAPEX と OPEX の費用明細 |
| 10 | 版の履歴と、この試算が答えていないこと | 版の履歴 |

データの無い区画も消さずに「未登録」と出す。試算が未登録のPJは、区画の一覧に「未登録」を並べる。

### 7.2 原価の内訳の行（全PJ共通）

原料・部材／運ぶ（物流）／作業（運転・保守・管理）／後処理・外注／消耗品・電力・施設／設備の償却／その他。並びと色は SX の試算で色覚の見分けを検査済みの順（`CATEGORY_COLOR`）をそのまま使う。PJごとの工程の呼び名（部材費・菌体費 など）は、行の中身としてデータが持つ。

### 7.3 データの流し込み

計算（エンジン）は、データの形（`project_cost_models.case_kind` と明細・作業の有無）だけで選ぶ（`costFormatEngineOf`、`src/lib/project-cost-format.ts`）。PJ番号では分けない。

| データの形 | 計算 | 画面 |
|---|---|---|
| `biodiesel` | 燃料の計算（`project-fuel-cost-model.ts`） | コスト試算（燃料）タブ（標準の画面への移行は §6） |
| `multi`・`dye_degradation`・`metal_recovery` | 廃液処理の二段階の計算（`project-cost-model.ts`） | 廃液の画面（標準の画面への移行は §6） |
| `other`（明細か作業がある） | 汎用の計算（`project-cost-items-engine.ts`） | 標準フォーマット |
| 試算が未登録 | — | 標準フォーマット（「未登録」） |

汎用の計算: 1単位あたりの原価 ＝ 1単位あたりの明細 ＋（年額の明細 ＋ 設備の初期投資 ÷ 耐用年数 ＋ 作業の年額）÷ 年間の量。

- 前提（`role_key`）: `sale_price`（売価、円/単位）・`business_annual_volume`（年間の量）・`labor_rate`（作業単価、円/時）・`compare_volumes`（比べる年間の量。`value_text` に「2:2028年の計画,12:2031年の計画」のように並べる。ケースの比較と切り替えになる）。これ以外の前提は「計算に使っていない前提」として読むだけ。
- 明細の `basis`: `毎m³比例`（DB の値。画面では1単位あたり）・`バッチ連動` は 数量 × 単価、`年額固定` は 数量 × 単価 × 年の回数 を年間の量で割る、CAPEX の `初期投資配賦` は 数量 × 単価 ÷ 耐用年数 を年間の量で割る。`内訳`・`参考` の行は計算に入れない。
- 作業の `count_driver`: `fixed` は年間回数、`batch` は1単位ごとに1回。年額 ＝ 年間回数 ×（1回の工数 × 作業単価 ＋ 1回の経費）。
- 内訳の行: 明細と作業の `format_row`（migration 465）。空なら CAPEX は設備の償却、作業は作業、そのほかはその他。
- 明細の行の下の「計算」は、エンジンと同じ数で式を出す（`ItemCalcLine`）。式を計算した答えが右端の額と一致することを検査で確かめる。

### 7.4 登録している試算（2026-10-03）

- CX（migration 463・465）: 製品①（TES用連続断熱消磁冷凍機・4段構成）の1台あたり。部材費・組立の作業（1台500時間）・組立工場の賃料と光熱費（月25万円）・生産設備の償却。12台/年で 28,981,105円/台（成果物3 事業計画書の2031年の売上原価 ÷ 12台と同じ）。比べる量は2・12・70台/年
- LiSTie（migration 466）: 取締役会資料の膜＋電力の部分試算（5Aケース、膜 265.3・電力 52.5 円/kg）。目標の 3 USD/kg は全工程の総コストで範囲が違うため、総コスト目標の欄には言葉で出す

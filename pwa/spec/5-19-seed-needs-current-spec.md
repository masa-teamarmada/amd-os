# 市場ニーズと関連する企業・シーズ

## 目的・画面

`/seed-needs` は社内の研究ポートフォリオ面。市場課題を企業の事業領域・強み・方針で解釈し、必要な技術と追加研究・PoCの問いを既存シーズへつなぐ。GlobalNavのシーズの隣に入口を置く。

初期表示は「市場ニーズ」。一行は市場ニーズ1件とし、企業やシーズの数では行を増やさない。タイトル・対象者、市場規模、情報の確度、関連する企業ニーズ、関連するシーズ、出典を同じ行で比較する。市場・企業・シーズ・出典名/発行元をAND検索し、確度・出典未登録で絞り込む。25件ずつページ表示。関連は直接リンク・企業経由・研究構想を集約し、同じシーズは一度だけ表示、詳細で由来を残す。企業リンクは条件・出典を読む編集dialog、シーズリンクは既存詳細、URLのある出典は原資料へ。市場タイトルで一覧の下に詳細を開く。URLのない出典も詳細で読める。

市場の詳細から企業ニーズ追加・既存台帳シーズの直接リンクを行う。企業未特定でもリンク可。関連する理由は必須、不足・検証事項は任意。企業経由の個別接続・研究構想内の候補を直接接続へ自動昇格しない。「企業ニーズ」「接続の記録」と、以下の「関係図・研究構想」は補助タブとして残す。

1. **関係図**: 市場→企業ニーズの解釈と、企業ニーズ→シーズの登録済み接続をSVG曲線で描く。同じ市場から複数企業への分岐、同じ技術への合流を表示。ノード選択で、その要素を通る経路だけを強調する。市場へ遡った後に無関係な兄弟企業へ再展開しない。企業選択時は事業領域・強みを図の上、方針・不足技術・採用条件・根拠を下の詳細へ表示。
2. **未接続から創出**: シーズのない企業ニーズを○で示し、点線で「必要な技術を、これから生み出す」構想入口へつなぐ。点線は技術が存在するという意味ではない。
3. **交点で比較**: 行は市場→企業ニーズ、列は比較するシーズ。●は記録した個別の組み合わせ、◇は同じ研究構想に含まれる組、＋は未検討。◇を個別適合へ昇格させない。交点から既存の組み合わせ編集を開き、新規時は企業とシーズを選択済みにする。右端からシーズなしの新規研究を構想できる。
4. **比較の範囲**: 初期シーズは現区分の個別接続・研究構想が参照するもの。全シーズ台帳から技術名・機関・研究者で検索し、候補を画面内の比較へ追加する。自動推薦や適合スコアはない。各層12件ずつページ切替、候補検索も12件ずつ。全文検索に合う要素とその関連経路を残す。未接続フィルターでは技術候補を残し、未知の組み合わせを考えられる。
5. **研究構想**: 図または比較表のチェックで市場・企業・シーズを複数選択。「研究仮説にする」から図の横で研究の方向、題名、不足機能、生み出す技術・仮説、実験、判定基準、次の確認を記入。応用はシーズ1件以上、組み合わせは異なる2件以上、新しいシーズの創出は0件でも保存可。市場または企業ニーズ1件以上が必要。保存済みの構想を選ぶと構成要素を強調し、本文を再編集できる。

関係図にも市場→シーズの直接リンクを表示し、起点の経路だけを強調する。

既存 `/seeds` の台帳を参照し、技術×用途の主キー `seeds.id` で結合。機関内番号 `seed_no` や研究者名で結合しない。`/seeds/[id]` へ到達可能。既存 `/poc` の案件化台帳とは別の探索面であり、案件や契約を自動生成しない。

## 市場規模・情報の確度・出典

市場規模は国内（japan）・世界（global）を別々に、対象年を添えて保存。単位は年間・億円（JPY）。下限/上限を持ち、上限空欄は下限と同額。対象となる製品・サービスの範囲、算定方法・前提・不確かさ、根拠となる出典IDが必須。広い産業全体の規模をそのままニーズの市場規模へ代入しない。外貨の場合は換算条件を算定根拠に記す。推計を作る自動処理はない。

順位は選択した同じ地域・年の推計下限の大きい順。同額は同順位、次は件数分だけ順位を進める。検索結果内で再採番しない。未調査は未評価のまま順位なし、ゼロ市場へ変換しない。対象年は登録済み年の最新を初期表示、登録ゼロなら当年。地域の初期値は国内で世界へ切替可。異なる年・地域・上限を混ぜて順位を付けない。確度順・更新順・名称順への切替も可能。

情報の確度はニーズの存在・内容の裏付けに対する手動評価。市場規模の金額・採用可能性の確定とは独立。

- A 一次情報で裏付け: 直接確認や一次資料に基づく。
- B 間接情報で裏付け: 調査・記事等に基づくが直接確認はこれから。
- C 仮説中心: 推測・検討段階。
- 未評価: まだ評価していない。

A/Bは出典1件以上、A/B/Cは評価理由・不確かさを必須にする。出典数だけで自動採点しない。記入例はC/未評価のみ。従来のevidence_status（ヒアリング確認状況）は別の属性として保持する。

市場・企業とも `sources` JSONBで出典を複数保持。id/kind/title/publisher/date/url/note。kindはprimary/report/interview/news/discussion/other、資料名・裏付ける内容は必須、URLは任意のhttp(s)。日付は発行またはヒアリング実施日。公開URLがない資料は名前・確認内容で辿る。旧source_url/evidence_note/observed_onも表示・編集し、未移行情報を消さない。

市場の `market_sizes` JSONBはscope/year/min_oku/max_oku/definition/basis/source_id。地域・年の組は一意、source_idは同じ市場のsourcesに存在必須。出典削除により推計が孤立する保存は全体拒否。DB関数valid_need_sources / valid_need_market_sizesとCHECKでネスト型、空値、負値、大小逆転、根拠欠損、重複、確度条件を検査する。本文・出典・推計・確度は同じ行の更新で原子的に保存し、updated_at一致を要求。既存クライアントが新列を送らない更新でも値を保持する。

## 正本データ・関係

| table | 単位 | 関係 |
|---|---|---|
| market_needs | 市場の課題1件 | 企業ニーズ0..N件 |
| market_need_seed_links | 市場ニーズ×シーズの直接リンク | market_need_id / dataset複合FK、seeds UUID、ペア一意、理由と不足事項 |
| company_needs | 企業視点で解釈したニーズ1件 | 市場0..1件、組み合わせ0..N件 |
| seed_need_matches | 企業ニーズ×シーズ1組 | seeds UUIDを参照、同じペアは一意 |
| seed_need_research | 研究構想1件 | 複数の市場・企業ニーズ・シーズを束ねる |
| seed_need_research_markets | 構想×市場 | research_id / market_need_id / dataset、複合FK |
| seed_need_research_companies | 構想×企業ニーズ | research_id / company_need_id / dataset、複合FK |
| seed_need_research_seeds | 構想×シーズ | research_id / seed_id / dataset、seeds UUID参照 |

同じ企業・シーズは複数のニーズへ登場できる。初版の企業ニーズは元の市場を1件指定する。異なる市場の課題から派生する場合は、企業名が同じ別ニーズとして登録する。企業法人マスタとの統合、複数市場の一括集約、自動収集、協業先への共有は初版対象外。

市場だけ、企業だけ、シーズ未接続の企業も保存できる。市場未接続の企業は「企業ニーズ」に残し、市場一覧へ架空の行を作らない。画面上の検索は行の全構成レコードを跨ぐAND検索、機関絞り込みは institution_id、未接続はmatchなし。市場・企業単独タブは各台帳内の検索。

## 記入例・確度

ニーズ・構想とも dataset=`working`（実際の蓄積）または`example`（議論用の記入例）。初期表示は記入例。関連FKは `(id,dataset)` で区分の混在を拒否。既存シーズの正本へ仮データを追加しない。

初期記入例は市場4件・企業6件・組み合わせ5件。実在シーズ4件を参照し、同じ熱電シーズのセンサーメーカー視点と設備保全会社視点、未接続の加工会社ニーズを含む。市場の存在・企業意向・性能適合・費用負担・資金提供は未確認の仮説。実際の蓄積は初期0件。研究構想の記入例は2件（熱電×導電膜の組み合わせ、加工条件から新しい技術を考えるシーズ未定の構想）。実現性・新規性も未確認。

市場・企業の確認状況は hypothesis / signal / confirmed。confirmedはヒアリングの根拠を必須にする。組み合わせの段階は hypothesis / hearing / research / poc / hold。exampleは必ずhypothesisのまま。実績・合意への自動昇格や資金額の自動推定はない。

## 認可・取得・保存

- `(app)` の認証とportfolio領域境界。DBはRLS `amd_os_is_member()` をSELECT/INSERT/UPDATE/DELETEへ適用。anon・外部アカウント・PJ限定アカウントからの直接DB取得・保存を許可しない。
- ブラウザはログイン済みSupabase client。service roleを配布せず、PostgRESTのRLSを毎リクエスト通す。新規独自APIなし。
- ニーズ・研究構想と関連は編集中の可変データとして毎回取得。参照シーズはユーザーID別 `loadReferenceData` の5分キャッシュ。専用サーバAPIを持たないためサーバキャッシュ・HTTPキャッシュは追加しない。更新ボタンで強制再取得、保存後は参照キャッシュ破棄。
- すべての表は `id` 安定順で500行ずつ終端までページ取得。失敗はエラーとして表示し、空件数へ潰さない。初期読み込みは骨組みを表示。
- 編集保存はfield whitelistのみ。DBのupdated_atと編集開始時刻を照合し、0行更新なら競合として通知。DB triggerがupdated_at/updated_byを更新。保存値をselect readbackして画面へ反映。
- 研究構想はsecurity invokerの `save_seed_need_research(p_record jsonb,p_market_ids uuid[],p_company_ids uuid[],p_seed_ids uuid[],p_expected_updated_at timestamptz)` で本文と3種の関連を一括保存。社内member判定＋各表RLS。入力はwhitelist、全参照はFK、区分混在は複合FKが拒否。更新はid/dataset/updated_atを照合し、関連の差替え失敗は本文もrollback。戻り値のid/updated_atと関連IDをreadbackする。
- 構想はkind=application/combination/new_seed。全件、探索段階の未検証仮説として扱い、seeds台帳・個別match・PoC案件へ自動登録しない。保存前の比較候補追加やチェックは画面内だけ、研究構想保存後は共有DBへ保持。
- 構想編集時は区分・親タブ・更新を無効にし、未保存文章の誤破棄を防ぐ。閉じる際は変更ありなら確認。保存失敗でフォームを維持する。
- ダイアログはnative dialogのfocus管理・Escapeと未保存確認・保存中操作抑制。検証エラーは根拠欄へフォーカス。保存失敗で入力を捨てない。

## UI・検証

ユーザーの2026-10-09指定により、市場ニーズを主画面に変更。数百件から課題・根拠・関連候補を検索し比較する。関係図は補助面として保持。目的は会議中に二人で市場課題・企業のフィルター・既存技術・不足技術を同時に辿ること。件数カードや独立した大型カードを並べず、64pxのノードを三層に配置する。企業順は市場順、シーズ順は関連企業の平均位置で交差を減らす。研究構想は複数要素の集合であり、構成要素間を勝手に全結合しない。

AMDのsky操作色、slate本文、白〜淡灰の背景を使用。点線の研究入口のみamberで未整備を示す。書体はOS共通、日本語ノード13px、補足11〜12px、4px基準の余白と控えめな境界線。閲覧はノード全体のボタン、構想への選択は別チェック。既存の一覧64px・2行省略、根拠編集の導線を維持する。

desktop 1440×900で関係図・比較・構想の横並びを確認。幅1200px以下では構想入力を図の下、700px以下は入力1列、16px入力/44px操作。図と交点比較は関係の軸を保持するため枠内スクロールを許可し、ページ全体ははみ出さない。市場一覧は25件ずつ表示し、620件の合成データで検索・並べ替え・ページ操作を検証。参照取得は500件ずつ全件取得し、数百件の用途を対象とする。補助図は各層12件。市場一覧の詳細はモバイル1列、表のみ意図した横スクロール。

- `npm run test:seed-needs`: 多対多、未接続、区分分離、検索、機関、ページ取得、競合条件、経路強調の隔離、構想の複数/ゼロシーズを検査。
- `scripts/check_seed_needs_db.sql`: transaction rollbackで正規memberの保存/readback、外部拒否、複合FK、重複、仮例の確度固定、根拠なし確認済拒否、存在しないシーズ、古い時刻での更新拒否。
- `scripts/check_seed_need_research_db.sql`: member/external/anon、複数/ゼロシーズ、区分混在・存在しないシーズ拒否、古い更新拒否、関連保存失敗時の原子性をrollback検証。
- `scripts/check_market_need_evidence_db.sql`: sources/市場規模国内・世界/直接リンクの保存読戻し、根拠削除・型・負値・地域年重複・仮例昇格・競合・FK・外部/匿名拒否をrollback検証。
- migration495/496/497/498/499/500は本番適用済み。再適用禁止。db_schemaはdump生成。
- PWA先行。iOS/macOS/Androidに専用一覧は未移植。理論・モデル・自動通知に変更なし。

# 設計書 — AMD OS の確定仕様

> **このセクションは何か**: AMD OS の「確定した実装仕様」の正本。画面 / route / API / cron / DB / 状態遷移 / 判断ロジックが**どう動き・どう作られているか**を、実装者(まさ・えいみ・Codex)が参照するために置く。OS 画面で常時見えるので、仕様が勝手に消えたら気づける。

## 3 つのドキュメント層

AMD OS のドキュメントは、読み手と目的で 3 層に分かれている。移行後はすべて OS 画面で閲覧できる `pwa/{manual,spec,bzm}/*.md` を正本とする。

| 層 | OS route | 何を書くか | 主な読み手 |
|---|---|---|---|
| **マニュアル** | `/manual` | 使い方・画面の見方・運用フロー・月次オペ・「何のため」 | AMD メンバー・運用者(全員) |
| **設計書**(ここ) | `/spec` | 確定仕様: 画面 / route / API / cron / DB / 状態遷移 / 判断ロジック | まさ・実装者(**admin 限定**) |
| **テキストブック** | `/bzm` | 理論・数式・モデル定義・rubric 導出(Before Zero Model / XRL / AMD Score / ERS) | 理論を理解したい人 |

- **数式・理論は設計書に書かない** → テキストブック(`/bzm`)へ。設計書には「結論の式・軸名・実装上の扱い」だけ置き、導出はテキストブックにリンクする。
- **使い方は設計書に書かない** → マニュアル(`/manual`)へ。設計書は「どう動くか・どう作るか」に徹する。

## なぜ OS 画面で管理するのか

仕様正本を OS 画面に出ない md(主に `pwa/design/*.md`)だけで管理していた時期は、AI が勝手に書き換えて**実装済みの仕様をなかったことにする事故**が何度も起きた。まさが画面で常時見える場所に正本を置けば、消えたら気づける。だから確定仕様は章単位でこの設計書セクションへ移していく。

# 経営スコア再設計案

> この章は `/management-score` を、会社全体の経営状態を読むための信用できる指標へ作り直すための設計メモ。個別PJの進捗ダッシュボードや根拠カード生成器ではなく、まさが「会社として今どうか」を判断するためのスコアに戻す。

## いま起きている問題

1. **材料の入口が広すぎる**
   - `p00` の内部運用MS、`points=0` のMS、廃止済みルーティン、`routine_auto` の機械按分、PJ内部riskが会社スコアへ混ざる。
   - `project_strategy_signals` には会社スコープ分類が入ったが、`milestone_monthly_progress` / `project_meeting_summaries` / `registry_diff` など他経路はまだ緩い。

2. **不明と悪化が混ざっている**
   - 先手力で `unknown` が多いだけなのに、会社が後手化したように低得点・危機判定になる。
   - 方向性で未実装テーブルの0件が、実態の悪さのように扱われる。

3. **根拠表示が実態を盛る**
   - `routine_auto` なのに `confirmed_at` が入って「確認済」と表示される。
   - evidence `impact` が固定値で、実際のスコア寄与と合わない。
   - `summary_short` や機械計算結果を、経営判断の根拠のように見せる。

4. **軸の意味が混ざっている**
   - 継続軸に、既存契約の継続確度ではなくMS進捗平均が入っている。
   - 新規軸に、同一案件の重複やOS未反映diffが入りうる。
   - 財務軸に、未同期の0円実績と本当に悪い実績が混ざりうる。

## 作り直しの原則

- **会社スコアは会社バイタルだけを見る**: 売上、入金、支払い、契約継続、営業pipeline、資金繰り、組織稼働、経営判断。
- **PJ内部情報は原則入れない**: 技術実証、PoC、知財、創業株主設計、研究論点、内部MS進捗は、会社の売上・契約・入金・資源配分へ直接効く場合だけ入れる。
- **不明は不明として扱う**: 分類不能、未実装、未同期、source不足は加点にも減点にもせず、信頼度や要点検として出す。
- **根拠カードは表示条件を満たすものだけ出す**: 重要度、会社スコープ、source品質、実寄与が揃わないものはカードにしない。
- **impactは実寄与に近づける**: 固定 `+8` / `-10` のような表示をやめ、該当軸scoreに与えた概算点にする。

## 入力を3段階に分ける

### 1. 候補材料

raw signal として保存してよい層。ここには広めに入ってよい。

例:

- MTG summary
- MS progress
- budget / actual
- billing
- project strategy signal
- registry diff
- project knowledge

### 2. スコア対象

会社スコアの計算へ入れてよい層。ここで会社スコープを厳しく見る。

必要条件:

- `applies_to_company_score=true` 相当の判定がある
- sourceが廃止済みではない
- `unknown` だけで良好/悪化を判定していない
- 会社の売上、契約、入金、資金繰り、営業、資源配分に説明可能につながる

### 3. 表示対象

根拠カードに出してよい層。

必要条件:

- 何が起きたかが自然文で説明できる
- なぜ会社スコアに効くかが説明できる
- 実際のscore寄与が小さすぎない、または経営判断上重要
- source品質が `confirmed` / `system_calculated_valid` / `reviewed` のどれか

## 軸ごとの再設計

### 財務耐久

見るもの:

- cash / runway
- 請求済み、入金済み、未回収
- 売上見込と予算差分
- 固定費、メンバー原価、支払い予定
- freee / OS内データの鮮度

直すこと:

- 実績0円を即悪化扱いしない。同期未完了なら `data_missing`。
- 収益系と費用系の好悪判定を維持しつつ、未同期と実績悪化を分ける。
- evidence impactは、finance scoreへの寄与点に近づける。

### 既存PJ継続

見るもの:

- 契約中売上と継続見込
- 更新、延長、追加契約、支援停止、解約、予算未確保
- 入金/請求/未回収
- freeze / restart
- 契約済み売上の残期間

原則外すもの:

- `p00` 内部運用
- `points=0` のMS
- `routine_auto` の機械按分MS
- 廃止済み月次ルーティン
- 技術実証や知財などPJ内部risk

例外:

- PM lockedかつ請求/契約履行に直結する納品MSは、補助材料として使ってよい。ただし根拠カードは「契約履行」文脈で出す。

### 新規案件

見るもの:

- 会社スコア対象の商談
- 案件単位の期待額、確度、契約見込月
- 重複排除済みdeal
- 見送り/失注

直すこと:

- 同一案件のsignal重複をdeal単位にまとめる。
- registry diffは「未反映候補」であって、原則スコア加点にしない。
- candidateは高確度条件を満たすものだけ入れる。

### 先手力

見るもの:

- AMD起点、共同決定、相手起点、外部起点の分類済みevent
- 分類coverage
- 高impactの受け身event
- 判定信頼度 (= 分類済みeventが十分か)

正本定義:

- 90未満は危機状態。70は警告開始点ではなく、会社としてはすでに手遅れに近い。
- ただし、危機判定に使えるのは確認済みの後手eventだけ。
- 起点不明や分類不足は、会社の後手化ではなく抽出・分類の不足として扱う。

直すこと:

- `unknown` が多い月でも、点数capで先手力を下げない。
- 分類不能は点数ではなく判定信頼度を下げ、「暫定」「要確認」と表示する。
- 分類済みeventが不足する月は前月確定値を暫定維持し、総合点への不可逆ペナルティを発動しない。
- `55 / 70 / 85` のような非合意のscore capは禁止。

### 戦略接近度

見るもの:

- ファンド設立
- 研究機関連携
- AMD OS導入
- マネタイズ仮説の前進
- 属人脱却
- 成功卒業

直すこと:

- 未実装テーブルの0件を減点扱いしない。
- 使えるsourceがない入力は `unknown` として信頼度を下げる。
- 方向性は短期スコアより、四半期単位のOKRに寄せる。

## 現状点検スクリプトの役割

点検スクリプトは、スコアを直す前に現状の危険な材料を一覧化するために使う。

検出するもの:

- `p00` / 内部運用 / 廃止済みMSがスコアや根拠に混ざっている
- `points=0` のMSが継続加点になっている
- `routine_auto` が「確認済」扱いになっている
- evidence impactが実寄与より大きく見える
- unknownが多いだけで低得点・危機判定・総合ペナルティになっている
- 未実装/未同期が悪化扱いになっている
- 同一案件らしきpipelineが重複加点されている
- 会社スコープ外のMTG/knowledge/registry diffが表示対象になっている

出力:

- `P0`: 今すぐ本番表示から外すべき根拠
- `P1`: スコア式を直すべきもの
- `P2`: 設計上あいまいで確認が必要なもの
- `info`: 状況把握用

## 実装順

### Phase 0: 危ない表示を止める

- `routine_auto` を確認済表示にしない
- `p00` / `points=0` / 廃止済みMS / 内部運用MSを継続根拠から外す
- evidence impact固定値を表示上弱めるか、実寄与へ補正
- 202606を再計算

### Phase 1: 入力契約をコード化

- sourceごとに「スコア対象」「表示対象」「除外条件」を関数化
- raw signalには `score_eligible`, `display_eligible`, `scope_reason`, `source_quality` を持たせる
- audit scriptをCI的に実行できるようにする

### Phase 2: 軸ごとの再計算

- 財務、継続、新規、先手力、方向性を順番に作り直す
- 各軸にfixtureを作る
- `unknown` / `bad` / `missing` を分ける

### Phase 3: 根拠カードを作り直す

- card summaryは「何が起きたか」「なぜ会社スコアに効くか」「実寄与」を持つ
- raw signal全文ではなく、display対象だけ出す
- review_requiredの材料は別枠に置く

### Phase 4: 過去月を再計算

- 202605 / 202606で差分を確認
- スコアが上がった/下がった理由を人間が読める形で比較
- 本番反映後に `/management-score` の表示を確認

## 完了条件

- p00内部運用MSが継続根拠に出ない
- routine_autoが確認済表示にならない
- unknownだらけの先手力が危機点にならず、判定信頼度低下として表示される
- 未実装の方向性入力が悪化扱いにならない
- 同一pipeline重複がスコアを盛らない
- evidence impactが概算寄与と大きく乖離しない
- 点検スクリプトでP0が0件になる

# コスト試算（燃料）現行仕様

> **この章は何か**: PJコックピットの「技術」タブの中にある「コスト試算（燃料）」(2026-09-14 新設) の contract。
> 燃料（バイオディーゼル、FAME）を作って売る事業の、燃料1Lあたりの総コストを試算するシミュレーター。
> 排水処理の「コスト試算」タブ（[5-13](5-13-project-cost-model-current-spec.md)）と同じテーブル・同じ操作の形で作り、計算だけを燃料用に分けた。
> **計算結果は保存しない。保存するのは前提・明細・作業だけで、数字は常に導出する。画面での書き換えも保存しない（試算）。**

## 目的

まさ 2026-09-14「OSの技術ページに、新たに『コスト試算（燃料）』を追加してほしい。そんで廃液処理のコスト試算と同様にバイオディーゼル事業のコスト試算シートを作ってほしい」。

ゴールツリーの「バイオディーゼル事業は成立するか」（`project_questions`、未回答）に数字で答えるための面。排水処理のコスト試算で積み上げた次の要件を、はじめから満たす。

1. どういう系を想定し、どう計算しているかがこの面だけで分かる
2. CAPEX と OPEX がそれぞれいくらか
3. いくら以下なら成立するか（燃料では「売価で成立する菌体の原価」を出す）
4. どの前提の確度が低いせいで精度が落ちているか
5. 前提やまだ確定できない数字は、すべて画面で変えられる
6. 切り替えや数字の変更で全体がどう変わるかを、スクロールせずに見られる（操作パネルと結果を1枠に並べる）
7. 人件費は作業リスト（1回の工数 × 共通の作業単価 ＋ 1回の経費）で持つ。作業単価は共通の1つ
8. 年に要る量は入力ではなく計算で出す。入力は事業全体の年間の量。規模はIPOできる大量生産＝売上100億円
9. 大きい数字は3桁カンマ。前提・作業・明細は「事業と製造の条件 / CAPEX / OPEX」の区分に並べる
10. 画面に DB の値「中央培養」を出さない

## 入口

| 面 | 開き方 | 権限 |
|---|---|---|
| PJコックピット | `/project/{projectId}/cockpit?tab=technology&tech=cost-fuel`（事業計画 → 技術 → タブ「コスト試算（燃料）」） | ログイン済みメンバー。試算は誰でもできる。保存は admin |
| PJワークスペース | `#technology` の同じタブ | 同上。**保存はできない**（`CockpitTechnology` に `costModelEditable={false}`）。試算はできる |

- **燃料の試算（`project_cost_models.case_kind = 'biodiesel'` の active な行）を持つPJだけにタブを出す**。いまは SX (p21) だけ。
- タブの並びは 全体像 → 技術区分 → **コスト試算（燃料）** → 未整理の断片。全体像にも、このタブを開くカードを出す。
- 技術台帳と燃料の試算の有無を並べて読み、両方そろってから技術タブを描く（タブの並びが後から変わらないように）。キャッシュ済みなら即決まる。
- 燃料の試算が無いPJで `tech=cost-fuel` を開いたときは全体像を出す。

## 何を計算するか

### 事業の置き方（2026-09 の社内資料から）

| 論点 | 置き方 | 元 |
|---|---|---|
| 製品 | FAME（脂肪酸メチルエステル）を船舶燃料向けに売る。SAF（航空燃料）までは入れない | 260818 バイオ燃料アップサイド検討資料、260903 事業概要 |
| 売価と原価目標 | 想定売価 200円/L、粗利30%を残す原価目標 140円/L（試算の `target_total_cost_per_m3`） | 同上 |
| 分担 | 培養・濃縮・脱水・油回収は SX の工場。FAMEへの転換は外部の精製事業者への委託を基本に置き、自社で行う場合と比べる | 260903 事業概要「自社工程: 培養、濃縮、脱水、油回収／外部精製: FAME転換、HEFA、水素化精製」 |
| 菌体 | 燃料のために培養した菌体だけ。**金属回収に使った菌体は原料にしない**（排水処理とは別のライン） | 260903 事業概要、技術タブ `pte_sx_bf06` |
| 株 | 自然株で考える（強化株は遺伝子組換え体で閉鎖系が要り、窒素を切ると油でなく糖を溜める） | ゴールツリー 2026-09-10 の整理 |
| 規模 | 年間の燃料の量（事業全体）5,000万 L/年（売上100億円 ÷ 200円/L）。検討資料の売上シナリオ（2033年度 80億円・2035年度 400億円）ではなく、排水処理の試算と同じ売上100億円で置いた | 排水処理のコスト試算（まさ 2026-09-14「IPOできるレベルの大量生産状態」） |
| 作業と費用 | すべて SX がやり、SX が持つ。委託するときは委託費を SX が払う（委託先の作業時間は数えない） | — |

### 二段階の計算

```
燃料1Lに要る菌体 (kg-DCW/L) = 燃料の密度 ÷ (FAMEポテンシャル × 菌体回収率 × 脂質抽出回収率 × メチル化反応率 × FAME精製回収率)
年に要る菌体 (kg/年)        = 年間の燃料の量 × 燃料1Lに要る菌体
培養設備の系列数            = 年に要る菌体 ÷ 培養設備1系列の年間生産能力         （端数も比例で数える）
燃料化設備の系列数          = 年に要る菌体 ÷ 燃料化設備1系列で処理できる菌体の量

第1段 菌体1kgの原価 (円/kg)  = Σ(1系列の初期投資 ÷ 耐用年数) ÷ 1系列の量 + Σ1系列の年額固定 ÷ 1系列の量
                              + 培養の作業の年額 ÷ 年に要る菌体 + Σ菌体1kgあたりの費用
                              （biomass_cost_per_kg_override に0以上の値があれば、それに置き換える）
第2段 燃料1Lあたりの総コスト = 菌体費 (第1段 × 燃料1Lに要る菌体)
                              + 脱水・油回収 + FAMEにする + 残渣の処理 + 品質確認・出荷 + 燃料化設備の償却
```

- 収率は **2026-09-07 の「シアノ→FAME→SAF 工程とマテバラ推定」の3ケース**（低位 / 基準 / 改善）をそのまま前提に持つ。基準は `fame_potential` など、低位・改善は `_low` / `_high` を付けた role_key。ケースの行が無ければ基準の値を使う（`fuelYieldAssumptionOf`）。値は %（0〜100）。
- 基準ケースは、乾燥菌体1tから精製FAME 81.2763 kg（92.36 L）。低位 32.49 kg、改善 182.49 kg（契約チェックで一致を確かめる）。
- 設備は系列で並べるので、**1Lあたりの原価は年間の燃料の量でほとんど変わらない**。量産でまとめて大きくする効果（規模の経済）は入れていない。
- **売価で成立する菌体の原価** `breakEvenBiomassPerKg` ＝（売価 − 燃料化の工程の1Lあたり）÷ 燃料1Lに要る菌体。負なら「菌体がタダでも赤字」。目標版 `targetBiomassPerKg` は売価の代わりに原価目標で出す。

### 切り替え（2つ）

| 切り替え | 選択肢 | 何が変わるか |
|---|---|---|
| FAME転換 | 外部に委託（開いたときの既定。事業概要の分担）/ 自社で行う | 数える明細・作業の範囲（`fuelScopesFor`） |
| 収率 | 低位 / 基準（既定）/ 改善 | 燃料1Lに要る菌体の量（年に要る菌体・系列数も） |

結果の欄には、FAME転換 × 収率 の6通りを同じ目盛りの積み上げ棒で並べる。

### 残渣の行き先

油を取ったあとの残渣は菌体の大部分（乾燥菌体1kgあたり 0.878kg、マテバラ推定）なので、どう処理するかで燃料1Lあたりの桁が変わる。明細の行ではなく前提で持ち、エンジンが計算する（`fuelResidueOf`）。

| `residue_route`（`value_text`） | 画面 | 残渣の処理（円/kg-DCW） |
|---|---|---|
| `digestion`（既定） | 発酵などで処理 | 残渣の量 × `residue_digestion_cost`（正味の費用。SX は0円＝処理費とガス・液肥の価値が相殺される前提、未確認） |
| `disposal` | 産業廃棄物として処分 | 残渣の量 × `residue_wet_factor`（5）× `residue_disposal_price`（35円/kg湿） |

SX の基準の収率で処分に切り替えると、燃料1Lあたり約1,664円上がる（契約チェック）。残渣からの有価物（フィコシアニンなど）の売上は入れていない。

## データモデル

排水処理のコスト試算と同じ `project_cost_models` / `_assumptions` / `_items` / `_tasks` / `_questions` / `_notes`。migration `411`（制約）/ `412`（SX のデータ）。

| 列 | 燃料の試算での使い方 |
|---|---|
| `project_cost_models.case_kind` | `biodiesel`（411 で制約に追加）。`unit_basis_label` は `L` |
| `scenario`（明細・作業） | `中央培養` = 培養設備（第1段）/ `共通` = 燃料化の工場（委託でも自社でも）/ `外部委託` = FAME転換を委託するときだけ / `自社精製` = 自社で行うときだけ（411 で制約に追加） |
| `basis`（明細） | `初期投資配賦` = 1系列の初期投資（系列の数だけ並べる）/ `年額固定` = 1系列の年額 / `毎kg菌体比例` = 処理する菌体1kgあたり / **`毎m³比例` = 燃料1Lあたり**（DB の値は排水処理と共通で、燃料の試算では単位 L として読む）/ `バッチ連動` = 品質確認1ロットあたり |
| `count_driver`（作業） | `fixed` / `production_line`（培養設備の系列ごと）/ **`plant_line`（燃料化設備の系列ごと、411 で追加）** / `truck_trip`（出荷の台数 = 年間の燃料の量 ÷ `truck_capacity_l`）/ `batch`（品質確認のロット数 = 年間の燃料の量 ÷ `lot_size_l`）。`plant_line` も年間回数を必ず持つ |
| `performer` / `bearer` | すべて `sx`。画面に誰がやる・誰が持つかの選択は出さない |
| `strain` / `application` | すべて null（自然株、用途なし） |
| `group_label`（作業） | 作業の流れの段: `菌体をつくる` / `脱水・油回収` / `FAMEにする` / `残渣を処理する` / `品質を確かめて出荷する` |

### 計算が読む前提（`FUEL_ROLE_KEYS`）

| 区分 | role_key |
|---|---|
| 事業の規模と売価 | `business_annual_volume`（L/年）、`sale_price`（円/L） |
| 菌体から取れる燃料（収率） | `fame_potential` / `harvest_recovery` / `extraction_recovery` / `methylation_rate` / `purification_recovery`（それぞれ `_low` / `_high`）、`fame_density`（kg/L） |
| 菌体の原価 | `biomass_cost_per_kg_override`（空欄＝計算値。0 を入れると培養の費用を持たない形） |
| 培養設備 | `culture_line_capacity_kg_year` |
| 燃料化設備 | `plant_line_capacity_kg_year` |
| 人件費 | `labor_rate` |
| 残渣の処理 | `residue_route`（選択肢）、`residue_dry_kg_per_kg_dcw`、`residue_digestion_cost`、`residue_wet_factor`、`residue_disposal_price` |
| 品質確認・出荷 | `truck_capacity_l`、`lot_size_l` |

年間の生産能力（`culture_capacity_kg_year`）は入力として持たない（契約チェック）。

## 計算エンジン

`pwa/src/lib/project-fuel-cost-model.ts`（純関数。DBアクセスも React も持たない。型は `project-cost-model.ts` と共通）

| 関数 | 役割 |
|---|---|
| `fuelYieldOf(assumptions, case)` | 収率のケースごとの FAME kg/kg-DCW・L/kg・kg/L |
| `fuelScaleOf(assumptions, yield)` | 年に要る菌体・系列数・出荷の台数・品質確認のロット数 |
| `computeFuelBiomassCost(bundle, scale)` | 第1段。行（培養設備の償却 / 年ごとの固定費 / 培養の作業 / 菌体量に比例する費用）と初期投資 |
| `fuelItemAnnual(item, scale)` / `fuelTaskAmount(task, assumptions, scale)` | 明細・作業1行の年額 |
| `fuelResidueOf(assumptions)` | 残渣の処理 |
| `computeFuelScenario(bundle, conversion, yieldCase)` / `computeFuelCostModel(bundle)` | 1通り / 6通り |
| `computeFuelTaskFlow(bundle, scenario)` | 作業の流れ（段ごとの工数・年額・円/L・未確認の数） |
| `fuelParamGroupOfRole` / `fuelParamGroupOfItem` | 操作パネルと読み物の区分（`FUEL_PARAM_BLOCKS` / `FUEL_PARAM_GROUPS`） |

- 内訳 `breakdown` は6区分（`FUEL_BREAKDOWN_ORDER`）: 菌体費（培養）/ 脱水・油回収 / FAMEにする / 残渣の処理 / 品質確認・出荷 / 燃料化設備の償却。**足すと総コストに一致する**。区分は、培養設備の行は菌体費、燃料化設備の CAPEX は償却、残りは段（`group_label`）で決める（`fuelBreakdownKeyOf`）。
- `capexPerLiter` は培養設備の償却（菌体費の中）と燃料化設備の償却の合計、`opexPerLiter` は残り。
- 確度の帯グラフは、明細・作業を行ごとに数え、培養設備の各行は「1kgあたりの額 × 燃料1Lに要る菌体」で配る。上書き値のときは上書きの前提の確度で1本。残渣の処理は効いている単価の前提の確度。
- 明細の呼び名 `fuelItemLabel`: CAPEX は中項目。OPEX は、培養設備の行（排水処理の試算からコピー）は小項目と中項目の長い方、燃料化の工場の行は「中項目（小項目）」。

### 試算中の変更

排水処理のコスト試算と同じ `pwa/src/lib/project-cost-model-draft.ts` を使う（`applyDraft` / `setDraftValue` / `draftToPatches` / `listDraftChanges` / `pruneDraft`）。残渣の行き先は `valueText`。画面から回数の決め方は変えさせない（年間回数・工数・経費だけ）。

## API とキャッシュ

- `GET /api/project-cost-model?projectId=&kind=fuel` → 燃料の試算（`case_kind = 'biodiesel'` の active な最新1件）。**`kind` が無いときは `case_kind <> 'biodiesel'` だけを読む**（コスト試算タブが燃料の試算を読まない。`loadCostModelBundle(projectId, kind)`）。`Cache-Control` と `fresh=1` は 5-13 と同じ。
- `PATCH /api/project-cost-model` は排水処理と共通（行の id で書く）。`count_driver` は `plant_line` を含む8値を受け付ける。
- 参照系。画面から素の fetch をしない。`pwa/src/lib/project-cost-model-client.ts` の `loadProjectFuelCostModel` / `peekProjectFuelCostModel` / `prefetchProjectFuelCostModel` / `invalidateProjectFuelCostModel` / `saveFuelCostPatches` を通す。キャッシュのキーは `project-cost-model:fuel:{projectId}`（コスト試算タブの `project-cost-model:{projectId}` と分ける）。
- コックピットの「技術」タブ見出しの hover で、技術台帳と一緒に燃料の試算も先読みする。

- デスクトップ（1280px以上）: 2列（`xl:grid-cols-[minmax(0,1fr)_460px]`）。枠の高さを画面の下端まで（最小520px）にし、操作パネルの中だけがスクロールする。**結果の中身は最大で約486px（書き換え中・残渣を処分にした状態）に収め、最小の枠520pxでもスクロールしない**（内訳の中身を開いたときだけスクロール）。
- スマホ幅: 1列。結果の要約（選んだ組み合わせ・総コスト・赤字などの言葉・売価との差・内訳の色の細い棒）を上に固定。表のマスは見出しを上・入力を下。ページは横にはみ出さない。
- 色: 内訳の6区分は排水処理のコスト試算と同じ6色を同じ並びで使う（`FUEL_CATEGORY_COLOR`。隣り合う色の見分けは dataviz の検査済み）。黄とピンクは色だけで伝えず、必ず区分名を並べる。
- 入力欄は排水処理と共通の `NumberField`（3桁カンマ、打っている最中もカーソルを保つ、全角を半角に）。書き換えた欄は AMD Blue の枠と面。

### 読み物（枠の下）

1. この試算について（`summary_md`、元にした資料）
2. 想定している系（`system_scope_md`）
3. 注意して読むところ（notes `caveat`）
4. 6通りの内訳（燃料1Lあたりの6区分・総コスト・CAPEX・OPEX・売価との差 / 物量と設備 / 事業全体の年間・利益率・売価で成立する菌体の原価）
5. この数字の確からしさ（選んだFAME転換の3ケースの確度別の帯と、精度を下げている項目）
6. 確認事項（確定したときに総コストが動く幅の大きい順。幅は外部に委託・収率基準で出した値）
7. 外部ベンチマークと出典（notes `benchmark`）
8. この画面の見方（notes `reading_guide`、`id="fuel-guide"`）

## 検証

`check_project_fuel_cost_model.mts`（15項目）が次を機械で止める。

2. 収率はマテバラ推定の3ケースと一致する（精製FAME 32.49 / 81.2763 / 182.49462 kg/t）
3. 年に要る菌体・系列数・出荷の台数・ロット数は年間の燃料の量から計算する。年間生産能力を入力として持たない。年間の燃料の量を2倍にすると系列数・初期投資・売上が2倍で、1Lあたりは同じ
4. 内訳は6区分で合計が総コスト、中身の合計が区分、CAPEX＋OPEX＝菌体費＋工程＝総コスト

7. 委託では自社精製の行を、自社では外部委託の行を数えない。もう一方の範囲の行を消しても総コストが変わらない
8. 残渣の行き先: 処分は 残渣の量 × 湿重量倍率 × 処分単価、基準の収率で約1,664円/L 上がる

# 支払通知書・シーズン月別収支

2026-10-28。対象は `/admin/payouts` と、同じ画面を埋め込む `/admin/kiyo?task=payouts`。管理者が全PJのシーズン報酬予算・全メンバー配分・支払原資超過・配分超過と月別入出金を確認して、今回の通知書を作成・確認・送付する。

## 画面の順番

1. 支払月、月末の支払予定日、3工程へのページ内リンク。支払月の選択肢は当月・過去月に加え先2か月を含む。稼働月と支払月が別であることを選択欄のそばに示し、合意済みの翌月支払予定を発行前に確認できるようにする。
2. `01 全PJのシーズン収支予定`。上段に振込対象者の年間支払予算・支払額・残額、選択PJの振込対象者別合計。下段にPJ・費目を行、暦月を列とする入出金表。各PJの全シーズンと、最後の入金・報酬支払月までを表示する。
3. `02 発行前の確認`。対象支払の月初合意と修正要望の本文。例外発行の確認・監査は既存経路を維持する。
4. 発行対象人数、要確認人数、PDF作成済み、送付済み、今回の通知総額（税込・立替込み）。
5. `03 メンバー別支払・作成・送付`。計算根拠、今回額、変更点、書類状態、個別作成・PDF確認・送付。一括作成はこの場所に1つ置く。
6. 再計算・確認用PDF・強制再発行は作業表のメニュー。報酬債務、上限検算、メンバー別先12か月、対象稼働月は補足欄で開く。入金確認の催促は請求・入金管理の業務とする。

## シーズン収支のデータ契約

管理者限定の `GET /api/admin/payouts/season-plan?ym=YYYYMM` が `loadPayoutSeasonPlan` を呼ぶ。`ym` は実在する月を検査する。レスポンスは `Cache-Control: private, no-store`。クライアントは支払月変更・支払データ再取得後に読み直す。月切替前の応答は破棄し、旧月の金額を新しい月の表示に混ぜない。

読取元は `projects`、`value_plan_cycles`、`billing_cycles`、`monthly_reward_payout`、`members`、`reimbursements`、`payout_notices`、`legacy_reward_payout_amount_override_events`、`company_payment_obligations`。全件を一意な列順で1000件ずつ読む。認可後にサーバーで集計し、メール・個人住所・口座・報酬要望原文はこのAPIへ返さない。

`payout-season-plan.ts` は純粋な表示用集計。既存の報酬計算、支払条件、月初合意、DBへの書込み、PDF生成、送信は変更しない。

### 対象PJと期間

- 稼働中・凍結・営業・検討中のPJを残す。終了PJは、今回の支払月に対象シーズンの支払がある場合に含める。
- 各PJは、`active/confirmed/fixed/draft` のシーズンから、支払期間が対象月を含むものを優先する。次に稼働期間が対象月を含むものを選ぶ。同期間ならdraft以外、開始月が新しいものの順。
- 対象月と無関係な終了シーズンを引き継がない。該当シーズンがないPJは「シーズン未設定」と表示し、0円の予算として集計しない。
- 全PJの表示期間の和集合を共通の月列にする。シーズン初月と、遅れて入る入金・最終支払まで保持する。

### 行と計算

| 行 | 月の意味・集計 |
|---|---|
| 入金予定・本契約 | `contractBackedClientAmount` と `clientReceiptYmForCycle`。売上は税抜 |
| 入金予定・別契約 | 対象シーズンに関係する別契約を `expandExtraRevenueCash` で一括入金月に計上。開発期間へ現金を按分しない |
| メンバー別の報酬支払（本契約＋別財布） | 保存済み `monthly_reward_payout` を優先し、未保存分は報酬キャッシュを既存 `memberPayoutYmForCycle` の支払月へ置く。通知対象外・非現金配賦メンバーを外部支払から外し、`is_officer` 単独では除外しない。旧制度の合意額eventは既存helperで表示値に適用。PJ内のメンバーを1人1行で表示し、金額のtitleに本契約・別財布を併記。保存総額とキャッシュの別財布内訳が整合しなければ月別内訳は未確認とする |
| 立替精算・実費 | 現存通知書の採用月を優先。未採用の承認済み分は既存 `selectPayableReimbursements` の締切を使い、対象月以降の最初の適格月へ一度だけ置く。消費税を再加算しない |
| 登録済み追加支出 | PJと月が明示された `additive` の支払義務。報酬・立替由来は二重計上を避けるため除く |
| 差引収支 | 本契約入金＋別契約入金−外部報酬−立替−追加支出 |
| 累計収支 | 表示期間の差引収支の累計。期首の現金残高を含まない |
| 稼働月末の未払報酬 | キャッシュの `stockYen` 等。月末残高。シーズン計の列はシーズン最終稼働月の残高 |

計算済みの `members=[]` は0円。キャッシュ欠損・対象者不明・支出額不明は `null` として「未計算」と表示し、その値を含む合計も未計算にする。予算を支払額の代用にしない。合計行は設定済みPJの計であり、未設定PJは集計外と明記する。会社共通費・期首資金は財務で確認する。

## 表の表示と操作

左からPJ104px・費目144px・合計104pxを固定し、月列88pxを横に並べる。月見出しを上へ固定。数字は円単位、等幅・右揃え、反復行は約24px。既定は入金2行、メンバーごとの報酬、立替、追加支出、差引、累計、未払残を表示する。「報酬中心にする」は全メンバーの報酬行・差引・未払残を保持し、「収支明細も表示」で全費目へ戻す。表内は縦横にスクロールし、今回の支払月を淡青で示す。「支払月へ」でその列へ移動する。固定セルの背景は不透明にする。

未払報酬の月セルから既存の月次根拠を開く。キーボードで表領域をスクロールできる。読込・失敗・再読込・0円・未計算・未設定の状態を表示する。今回の表示確認はPC Chromeのみ。スマホWeb・Swift専用画面は変更しない。

## 発行・送付との境界

正式作成・保存・月初合意の例外承認・送付確認は既存 `/api/admin/payouts` とGASを用いる。読取で再計算・採番・PDF生成・通知を行わない。PDFができている未送付分は「作成済み・未送付」、金額または宛先変更後は「再作成が必要」と表示する。送付済みの事実は維持する。報酬が0円でも立替があれば作成・確認・送付を進められる。

詳細な既存発行契約・PDF様式は [manual 6-5](../manual/6-5-admin-payouts-reward-notice-spec.md) を参照。

## 2026-10-24 メンバー別報酬行

`SeasonProjectPlan.memberPayments` は各メンバーの `memberId/memberName/cells/totals` を持ち、月セルと合計に `regularPay/extraPay` を保持する。名前はmembersのcode_name、member_name、IDの順。通知対象外・非現金配賦は月別現金支払の個人行に含めない。複数PJに参画する人はPJごとに表示し、各月の個人額合計はPJ別報酬計と一致する。PJの差引には集計額を一度だけ用いる。

計算済みキャッシュに載っていない月はその人の支払0円。キャッシュ自体が欠けた月は、支払月に対応する全既知メンバーのセル・期間合計も未計算にする。対象者不明は未確認行と未計算額を出す。計算済みmembers=[]のPJは「報酬・対象者なし」、個人を特定できない欠損のみのPJは「報酬・メンバー未計算」。欠損を架空の個人額へ割り振らない。

検証は個人別の月ずれ、本契約・別財布の保持、個人合計とPJ計の一致、通知対象外の分類、未計算の伝播、計算済み不参加月の0円を含む。

## 2026-10-27 年間報酬予算・全メンバー配分

`SeasonProjectPlan.allocation` に本契約予算・別財布予算・全メンバーの現金/内部配賦/期末未充当・配分計・残額・判定を持つ。`payout-season-allocation.ts` が読取値だけから集計する。

- 本契約原資は `value_plan_cycles.budget_yen`、別財布は期間内の `billing_cycles.extra_budget_yen` 合計。月次本契約予算の足し算や、売上からの再計算で上書きしない。販管費等に使う分を追加原資にしない。
- 各稼働月の振込対象額は `monthly_reward_payout.total_pay` を優先。未保存のメンバー分は計算済みキャッシュを使う。入金保護の有無・`reward_paid_at` の欠損によって、実績や予定の月を計上から落とさない。
- 内部配賦は `exclude_from_payout_notice` / キャッシュの非現金配賦分類に従い、メンバー別 `companyReserveYen`（互換 `officerReserveYen`）を合算する。`is_officer` は分類根拠にしない。内部配賦は配分設計の原資を使うので、配分残額の計算に保持する。現金支払・会社原価とは別分類。メンバー未帰属額があれば判定保留。
- 配分計＝全月の振込対象額＋全月の内部配賦＋シーズン最終月の外部未払・内部未充当。期末残高は1回だけ使う。配分残額＝報酬予算−配分計。負なら配分超過、非負なら配分予算内。支払対象額＝振込対象額＋期末外部未払で、これだけを報酬原資と比較して支払原資超過を確認する。欠損予算・欠損月・未解決メンバー・金額欠損は「要確認」で判定を保留する。
- PJ別一覧の名前ボタンで全メンバー表を切替。直接表示は `?seasonProject=<project_id>`。表は要素内だけ横移動し、年間表には月別表の固定3列幅を流用しない。年計は税抜、現金支払と内部配賦を別列で示す。元の月別入出金差引を報酬予算残額や会社利益と呼ばない。
- 未承認の要望・提案額は集計へ入れない。報酬登録後に読取り直す。読取でDB・計算キャッシュ・MS・通知書・PDF・送付状態を更新しない。

### 予算判定からの原因確認

PJ名または判定を押すと、そのPJの年間メンバー配分と根拠を表示する。支払原資超過PJの根拠は初めから開き、判定を押すと根拠位置へ移動する。同じ判定を押し直しても再表示できる。選択PJはURLのseasonProjectへ保持する。

`allocation.evidence` は保存済み計算のMS別pt/発生額/担当、稼働月別の原資/発生額/振込対象/内部配賦/月末未充当/累計残額、選択月のメンバー別MS明細を返す。月の初期選択は累計原資不足が初めて出る月、なければ最終月。月ボタンで内訳を切替し、既存の月次報酬根拠モーダルへ接続する。

原資基準ptは既存 `regularPointBasisForCycle`、MS配分ptはキャッシュ内訳の担当者別 `earnedPt` を合算する。複数担当者に重複する `msConsumedPt` は合算しない。別財布は分け、内訳未取得は未確認とする。MS発生額＋期首繰越＋保存支払と計算値の差＋切上げ−控除から配分計を照合し、未照合差分は隠さず出す。保護済み計算cacheの基準値は支払表示の上書き前に保持する。歴史的な固定合意との差を追加支払・返還の承認と解釈しない。

## 2026-10-27 v3.163.63 支払と非現金配分の区別

`paymentStatus` は `cashCommittedYen = cashYen + externalUnpaidYen` と登録報酬原資の比較。`within_budget / over_budget / unknown` を返す。0円なら画面は「支払なし」。`cashBudgetRemainingYen` は社内配分控除前の支払原資検算値であり、社内割当を解除した追加支払可能額として表示しない。

`status` は全メンバーの配分設計だけを示し、`within_budget / overallocated / unknown`。メンバー・年計・月別根拠には `externalUnpaidYen` と `internalUnfundedYen` を分けて返す。配分残額・配分計の既存数値は保持する。支払原資超過は赤、非現金を含む配分超過は琥珀色。会社損益は実際の原価・販管費を含む財務で確認する。分類の正本はmanual7-1。

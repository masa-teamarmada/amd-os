# PJ週次管制画面 仕様

> **目的**: 計画の再作成ではなく、既に管理されている計画・進捗から「先週からの変化」「今回決めること」「決定後の介入」を週次会議で短時間に確認する。論点・仮説を担当・期限・検証・根拠・判断へ接続し、放置を防ぐ。

## 正本境界

- 新画面は `/project/[projectId]/weekly-control`。
- 既存の `/project/[projectId]/workspace` は、計画詳細・技術証明・関係先・工数入力を扱う統合ワークスペースとして維持する。置換・redirectしない。
- 新画面はUIを先に固定する。週次差分の自動抽出が未接続の項目は、0件・変化なしと断定せず `抽出接続待ち` と表示する。
- ガントと関係先はこの画面から手動修正でき、手動で確認・保存した現在値を正本とする。将来の自動抽出は既存値を直接上書きせず、差分候補として人の確認へ回す。

## Route / Auth

| 項目 | contract |
|---|---|
| page | `src/app/(app)/project/[projectId]/weekly-control/page.tsx` |
| view | `SxWeeklyControlDashboard` |
| auth | `getCurrentMemberAccess()`。未ログインは同URLを `next` に保持してloginへ送る |
| PJ境界 | `getProjectWorkspaceBundle(projectId, access)` と `projectScopedPathAllowed()`。PJ限定ユーザーは所属PJだけ閲覧可 |
| shell | `/workspace` と同じ埋め込みshell。月初合意overlayの対象外 |
| write | portfolio/adminだけ。既存 `/api/project-workspace/[projectId]/management` を使い、clientからDBへ直接書かない |

## 画面構造

1. **週次状態帯**: 判断待ち、要フォロー、更新切れ、期限超過、今週入力を同じ帯で表示する。
2. **PJ全体の担当負荷**: 工程、タスク、必須ゲート、論点、仮説、検証、判断、action、関係先保有事項を同じ未完了作業単位へ正規化し、担当ごとに `停止 / 期限超過 / 7日内 / 期限なし / 全未完了 / 影響ゲート` を表示する。関係先だけの件数をPJ全体負荷として扱わない。
3. **週次変化レール**: `先週→今週`、`今回の会議`、`決定→介入` の3段。差分未接続はプレースホルダーのままにする。
4. **全体ガント**: `SxUnifiedTimeline` / `deriveSxUnifiedTimeline` を再利用し、事業開発・技術開発・資金調達・体制構築の工程とタスクを同じ時間軸で見る。週次管制は `dateMode="planned_only"` とし、完了見込み日・予定との差・差分線・予測ひし形・重要経路の破線接続を表示、範囲、並びの全てから外す。DBの `project_management_milestones` はこの画面では通常の工程として扱い、依存や `gate` 列があるだけでゲート・マイルストーンへ格上げしない。現時点の停止条件として表示するマイルストーンは `business-paid-poc-oral-agreement` と `funding-investment-oral-agreement` の2件だけ。上部に2行の設立前提として表示し、通常工程へひし形やゲートタグを付けない。`unassessed` は未確認、明示的未完了は未達、`completed` でも証跡不足なら未確認、`completed` かつ必要証跡ありの場合だけ充足とする。口頭合意は `先方または投資家 / 合意内容 / 確認日 / 根拠` の4項目が揃わない限り充足にしない。工程配下は `project_management_tasks` のタスク→子タスクを初期折りたたみで表示する。mobile/tabletは横ガントを主表示にせず、日付・工程・前提・担当の縦一覧へ切り替える。
5. **関係先リスト**: `SxPartnerPipeline` を唯一の一覧とし、大学・金融機関・試作先・PoC先を同じ台帳へ1社1行で表示する。初期表示は `PoC候補先` とし、暗黙の段階・要対応filterを掛けず候補全件を進捗順で表示する。`全関係先` は同じ表の表示切替であり別リストを作らない。主列は `関係先 / 共通7段階の進捗目盛り / 詰まり・PJ影響 / 次にやること / 担当・期限 / 現在地の根拠 / 履歴・保有`。進捗はpillやカードを会社名下へ置かず、全行で同じ位置に並ぶ直線目盛りと現在地の縦線で比較する。PoC表示では役割groupや保留foldで行を分断しない。ボール、行動、担当、期限、関連工程は同じ構造化保有事項から選び、別レコードの値を合成しない。構造化保有事項がない場合だけ関係先本体の現在値へフォールバックし、関連工程を推測接続せず `PJ影響 未接続` とする。上部は担当別の未完了件数・危険件数・情報不足を集計する。詳細モーダルは全やり取り履歴、未完了/完了保有事項、目標状態、合意済み/未合意、出典を表示する。メール本文、アドレス、URL、個人連絡先、内部source refは保存・表示しない。
6. **論点・仮説リスト**: `要整理 → 検証中 → 判断待ち → 決定・棄却` の4状態で一覧する。desktopは4列、tabletは2列、mobileは1列へ再配置し、ページ横スクロールを発生させない。セクション名・列名は業務上の名詞を使い、目的説明やコピーを見出しへ置かない。
7. **データ接続状況**: 週次差分、論点・仮説、工数、関係先メール接点の接続状態を示す。

## 論点・仮説の放置防止

### 段階

| 段階 | 判定 |
|---|---|
| 要整理 | 未解決で、検証中・判断待ち・完了の条件を満たさない |
| 検証中 | 論点/仮説が `validating`、または検証が `planned/running` |
| 判断待ち | `decision_needed`、未決の意思決定、または `validated` 仮説がある |
| 決定・棄却 | 論点が `closed/decided`、または全仮説が `rejected/decided` |

段階と警報は別に扱う。期限超過・更新切れは列を移動する条件ではなく、どの段階でも重ねて表示する。
決定・棄却列でも未完了の決定後actionがあれば要フォローへ残し、判断だけ記録して実行が忘れられる状態を作らない。

### 警報

- **要フォロー**: 未完了で、担当不明、次の期限なし、仮説なし、検証中なのに検証予定なし、期限超過、更新切れのいずれか。
- **次の期限**: 論点、活動中の仮説、計画/実施/停止中の検証、未決判断、未完了actionから最も近い日を採用する。
- **最終更新**: 親論点だけでなく、仮説・根拠・判断・actionの `lastVerifiedAt` の最新日を採用する。子だけを更新した論点を更新切れにしない。
- **更新切れ**: 最終更新から7日以上。日付欠損も更新切れとして扱い、0日扱いしない。
- **期限超過**: 未完了論点の次の期限が基準日より前。完了済み論点へ赤警報を残さない。

## 書き込み契約

画面から次を既存管理APIへ保存できる。

- 工程: 新規追加と、名称 / 状態 / 担当 / 計画開始・完了 / 実績完了 / 進捗 / 日程確度 / 詰まり / 完了条件 / 完了証跡の更新。
- 設立前提: 現行2マイルストーンの状態・担当・日付・証跡を値の選択から直接修正できる。接続値を選ぶと依存条件を修正できる。週次管制の依存種別は `finish_to_start` に限定する。
- タスク: 工程直下またはタスク配下へ新規追加し、計画、実績、進捗、親タスク、作業内容を更新。親子は同一PJ・同一工程内に限定し、循環参照をAPI/DBで拒否する。
- 関係先: 新規追加と現在値更新。やり取り履歴、誰が抱える具体的保有事項、役割分類を同じ画面から追加編集する。
- 論点: 新規、title / kind / status / owner / due / confidence更新。
- 仮説: 論点配下へ新規、statement / status / owner / due / confidence更新。
- 根拠・反証: 論点または仮説へ supporting / counter / missing / observation を追加。
- 検証: 仮説へ方法・担当・予定・期限・状態を追加。
- 判断: 論点または仮説を今週の判断キューへ追加。
- 決定: 判断待ちを決定済みまたは保留へ更新し、決定内容・決定者・決定日を記録。
- 決定後の行動: 決定配下へ担当・期限・完了条件・次回確認日を追加し、実行中・停止・完了と完了証跡を更新。

カードの「次の動き」は種類の固定順ではなく、`停止中 → 期限超過 → 期限が近い → 期限なし` の順で選ぶ。同順位では決定後action、判断、検証の順とし、決定後の実行が判断記録の陰に隠れないようにする。カード詳細は折りたたみ内で根拠・判断・actionを全件表示し、件数だけ見えて履歴へ到達できない状態を作らない。

保存成功後はAPIが返す最新 `SxManagementBundle` で画面を更新する。画面内で楽観的に完了へ移動させない。PATCHは `last_verified_at` と手入力由来をAPI側で更新する。

ガントは記号だけに意味を預けない。凡例は `計画期間 / 実績 / マイルストーン` の3項目だけにする。通常工程の各行は `予定 / 実績 / 前提` を文字で出し、進捗未登録は `0%` でなく `未登録` と表示する。◇とマイルストーン名は上記2件だけに使い、通常工程の終端は単純な予定日線で示す。

行の名称またはバーを選ぶと、desktopではガント横の非重畳インスペクタ、mobile/tabletでは高さ70vh以内の下部シートへ詳細を出す。ガント直下へ詳細帯を追加しない。管理者はインスペクタの名称・担当・状態・日付・進捗・内容・詰まり・完了条件そのものを選んで修正する。独立した `編集` ボタンや鉛筆アイコンを置かない。関係先も会社名・進捗目盛り・詳細値・履歴行・保有事項行を選んで修正する。

## 表示上の禁止

- 工数0、差分0、論点0を「活動なし」「変化なし」と言い換えない。
- `judgment` の全体判定を論点・仮説の放置防止件数として流用しない。
- `open` を「未着手」と表示しない。検証や根拠が進んでいる可能性があるため「未解決」とする。
- 週次管制へ完了見込み、予定との差、予測diamond、差分線、工程間の破線接続を戻さない。
- 通常工程・タスクへゲートタグやマイルストーン記号を付けない。停止条件は上記2件から推測で増やさない。
- 関係先進捗をpill、カード、会社名下の分割blockへ戻さない。PoC候補先を初期表示から隠さない。
- 既存値の修正に独立した `編集` ボタンを戻さない。値そのものを操作対象にする。
- 内部ID、raw source ref、メール本文・宛先、議事録全文を出さない。関係先台帳へ取り込む接点情報は、確認済みの要点・日付・送受信方向・以後のボールに限定する。
- 既存 `/workspace` の導線・auth・memberHomeを新URLへ置換しない。

## 受入条件

- 1440px、768px、390pxでページ本体の横あふれがない。
- 最上段だけで、抽出接続状態、最大異常、担当/期限、今週の判断候補が読める。
- 全体ガントで、4本柱の計画・実績、工程→タスク→子タスクを同じ時間軸で確認できる。設立前提は有償PoC口頭合意と出資口頭合意の2件だけを別帯で確認できる。
- 初期表示でPoC候補先が `表示N / PoC候補先N` の全件状態になり、全行の7段階目盛りが同じ列位置へ揃う。各行で進捗、具体的な詰まり、同じ保有事項に属する行動・担当・期限、止まる工程、直近の根拠を比較できる。担当別の未完了/危険/情報不足を上部で確認でき、詳細履歴を開いても本文・アドレス・URL・内部source refはDOMへ出ない。
- 任意行の計画、実績、必須条件の充足数、次の未達条件を5秒以内に説明できる。進捗未登録を0%と表示しない。
- 管理者はガントの詳細値または関係先表の値を選ぶと、独立した編集ボタンを経由せず修正面へ入れる。追加操作だけは `＋` ボタンを使う。
- 論点追加は2操作以内、既存論点への仮説追加はカードから1操作。編集・追加ボタンはアイコンだけにしない。
- 5秒で要フォロー件数、30秒で論点→仮説→根拠→検証→判断の接続を説明できる。
- `npm run lint -- <changed files>`、`npm run test:sx-weekly-control`、`npm run test:critical-ui`、`npm run build` を通す。
- `/project/[projectId]/workspace` の既存受入anchorを維持する。

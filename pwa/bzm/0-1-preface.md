# 序章 — この教科書について

> この Textbook は、Before Zero の現場で何が起き、どこが鬼門で、どう判断し、その奥にどんな BZM 理論があるかを読むための実践テキストです。BZM は後半で、現場判断を再現可能にする道具として出てきます。

## ねらい

本書は、株式会社チームアルマダ（AMD）が現場で積み上げてきた「Before 0 の経営判断」を、次の PJ で再利用できる形にするための **Before Zero 実践テキスト** です。後半には、現場知をモデル化・スコアリングする **Before Zero Model（BZM）** の理論正本を置きます。次の三つの読者を想定しています。

- **研究機関の URA・EIR**：自分の機関が抱えるシーズを、いつ・どの順序で事業化判断に乗せるべきかを判断したい人。
- **VC・連携機関・行政の担当者**：期待ベースの Valuation だけでは測れない「現実の準備度」を評価軸として欲しい人。
- **AMD のメンバーおよび AMD OS の利用者**：日々の判断、失敗、関係構築、AMD Score・σ_SU・XRL・ERS といった指標のつながりを理解したい人。

BZM は「URA 向け教科書 → AMD プロトコルの理論武装 → 学会発表」という三段のゴールを持っています。本書はその第一段、すなわち **Before Zero の現場で使える実用書** として書かれています。理論章は後半に温存し、数式・rubric・出典は将来の学会発表・論文化にも接続できるよう残します。

## 本書が解こうとしている問い

ディープテックの事業化を考えるとき、私たちは次のような問いに繰り返し直面します。

- このシーズは、**いつ**法人化すべきか。早すぎても遅すぎても失敗する。
- いま事業化の足を引っ張っている **律速要因** は何か。技術なのか、人材なのか、マクロの追い風が来ていないのか。
- ある研究機関は、ベンチャーを生み育てる **苗床** としてどれだけ整っているか。何が足りないか。

これらはいずれも「期待将来キャッシュフロー」を割り引く従来の Valuation では答えられません。BZM は、**期待ではなく現実の準備度** を連続的な尺度で測ることで、これらの問いに定量的な見通しを与えます。

## 全体の見取り図 — 現場から理論へ

本書は、まず Before Zero の現場を読み、そのあとで BZM 理論へ入る構成にします。

- **前半（第 1〜5 部）**：会社化・事業化の前に何が起きるか。研究者、大学・研究機関、企業、VC、行政、知財の間で何がズレるか。どこが鬼門で、何を見て GO / WAIT / NO_GO / HOLD を分けるか。
- **後半（第 6 部）**：前半で見た現場要素を、`σ_SU`、XRL、FRL、AMD Score、ERS としてモデル化する理論パート。
- **運用・ケース（第 7 部以降）**：AMD OS でどう使い、D-7 Textbook Insights Textbook Insights から承認済み知見をどう追記するか。

BZM の理論そのものは大きく **二つのレイヤー** から成り立っています。

- **個体レイヤー（AMD Score）**：1 つのベンチャーが IPO に向けてどれだけ育ったかを、7 つの軸を統合して測る指標。
- **苗床／土壌レイヤー（ERS）**：研究機関が「ベンチャーを生み育てる装置」としてどれだけ整備されているかを測る指標。

この二層は、マクロ環境を表す σ_SU（Triple Helix）を通じてデータ上自然に連動しますが、**計算式は別々に保ちます**（理由は ERS 章で詳述します）。

```
        ┌─────────────────────────────────────────┐
        │  苗床レイヤー：ERS（機関エコシステム整備度）   │  ← 研究機関を測る
        └─────────────────────────────────────────┘
                         │ σ_SU 経由で連動（データ上の因果）
                         ▼
        ┌─────────────────────────────────────────┐
        │  個体レイヤー：AMD Score（7 軸 Cobb-Douglas） │  ← ベンチャーを測る
        └─────────────────────────────────────────┘
```

## 各章の構成

前半の実践章は、概ね次の流れで構成します。

1. **現場で何が起きるか**：関係者、局面、ズレ、鬼門を先に描く。
2. **AMD が見るべきもの**：証拠、問い、判断ログ、赤信号を整理する。
3. **判断を間違えると何が壊れるか**：知財、関係、会社化、資源配分の破綻を明示する。
4. **理論への接続**：後半のどの変数・章で扱うかを案内する。

後半の理論部の各章は、教科書として手を動かしながら読めるよう、概ね次の流れで構成しています。

1. **本文**：概念と定義、数式とその言葉での説明。
2. **例題**：定義した式を具体的な数値で手計算する。AMD の実 PJ（ティエムファクトリ等）や典型ケースを題材にし、「式が何を意味するか」を体感できるようにする。
3. **本章のまとめ**：要点を箇条書きで再掲。復習と参照に使う。
4. **練習問題**：自分で手を動かして確認する問い。計算問題には答え・ヒントを併記し、考察問題は本文の理解を試す。

数式を読み飛ばしても文意は通じますが、**例題を一度自分の手で計算する** と、AMD Score や σ_SU が「ブラックボックスの出力」ではなく「自分で再現できる量」に変わります。可能なら電卓を片手に読み進めてください。

ケーススタディ / チェックリスト / AMD OS 運用パートは、理論章とは役割が違います。AMD OS の運用章（8-1）に加えて、現場判断、失敗からの学習、関係構築、チェックポイントを扱う既存章群（8-2〜8-5）を温存します。これらの章は、D-7 Textbook Insights Textbook Insights の承認済み候補を受けて育てるための受け皿であり、実ケース本文は根拠と承認が揃ってから追記します。

## 表記と前提

- 数式は本文中に $\TeX$ 記法で表示します。読み飛ばしても文意が通じるよう、数式の直後に必ず言葉での説明を添えています。
- 各軸の評価は原則 **0〜9 の 9 段階**（内閣府 SIP の段階定義互換）で行います。ERS だけは別ロジックで **Lv1〜5** を用います（第 7 部）。
- 本書で「SU」はスタートアップ／ベンチャー個体を、「PJ」は AMD が関与するプロジェクトを指します。

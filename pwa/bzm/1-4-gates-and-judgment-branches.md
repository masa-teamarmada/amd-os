# 鬼門と判断分岐 — 進める、待つ、止めるを分ける

> この章は何か: Before Zero の現場で判断を誤ると壊れやすい鬼門と、GO / WAIT / NO_GO / HOLD の分岐を整理します。ここでは結論を急がず、「何を見たら次へ進んでよいか」を書きます。

## 1. 判断は一度で終わらない

Before Zero の判断は、最初から `GO` か `NO_GO` を決めるものではありません。多くの場合は、次のどれかです。

| 判断 | 意味 | 典型アクション |
|---|---|---|
| GO | 次の不可逆なステップへ進む | PoC、共同研究、会社化準備、採用、資金調達 |
| WAIT | 条件が揃うまで待つ | 技術検証、知財、政策予算、CEO 探索を先に進める |
| NO_GO | この形では進めない | 仮説を閉じる、別用途へ移す、PJ 化しない |
| HOLD | 情報不足で保留 | 追加ヒアリング、資料確認、専門家レビュー |
| RESOURCE_SHIFT | 進めるが配分を変える | AMD 伴走を増やす、外部人材を入れる、大学側支援を厚くする |

重要なのは、判断名よりも「どの条件が満たされれば次へ進むか」を残すことです。

## 2. 外に出してよい情報

最初の鬼門は、外部相談の前に出してよい情報と出してはいけない情報を分けることです。

- 論文化前の新規性
- 出願前の実施例・条件・性能値
- 共同研究先との未公開情報
- 企業候補の具体用途・評価条件
- 資金調達前の資本政策・契約条件

ここを間違えると、後半でどれだけモデル上の readiness が高くても、事業化の自由度が落ちます。理論上は `GRL`、`BRL`、ERS の支援体制に接続します。

## 3. 論文化前 / 知財前 / 外部相談前

研究者にとって論文は重要です。一方で、事業化では出願・NDA・共同研究契約・顧客検証の順序が重要になります。

AMD が見るべきもの:

- 出願済みか、出願予定か、まだ発明届前か
- 論文・学会発表・プレスリリースの予定日
- 外部企業へ見せる資料の開示範囲
- 大学本部・TLO・URA / EIR の合意状況
- 顧客検証に必要な最低限の情報が何か

判断を間違えると、知財が弱くなるだけでなく、研究者との信頼、大学側との関係、企業候補との検証速度が同時に壊れます。

## 4. 会社化タイミング

会社化は、Before Zero の中でも最も不可逆性が高い判断です。早すぎる会社化は、技術・チーム・顧客が未成熟なまま固定費と期待値だけを増やします。遅すぎる会社化は、CEO 候補や企業候補、政策予算のタイミングを逃します。

見るべき問い:

- `TRL`: 会社が背負える技術課題になっているか
- `BRL`: 最初の顧客・用途・検証順序が見えているか
- `GRL`: 知財・規制・契約の最低限の地雷を踏んでいないか
- `SRL`: 社会受容や倫理論点が初期の阻害要因にならないか
- `HRL`: チームとして最低限の役割が埋まるか
- `FRL`: 創業者またはCEO候補が不確実性を引き受けられるか
- `σ_SU`: マクロの追い風が会社化を支える局面か
- ERS: 研究機関側が会社化後も支援を切らさないか

この問いは後半の [律速判定](5-1-amd-score-integration.md) に接続します。

## 5. GAPファンド、VC、CEO論がつながっているか

Before Zero では、支援施策ごとの判断がバラバラに正しくても、全体として間違うことがあります。

GAPファンドでは、研究者に「顧客は誰か」「市場はどこか」「どう成長するか」を語らせます。これは研究者を事業化へ近づけるために必要です。一方で、VCとの資金調達では、同じ研究者に対して「経営は別の人に任せた方がよい」と判断されることがあります。ここで何も整理しないまま外部CEOを入れると、研究者は自分の技術と夢を会社の外側へ押し出されたように感じます。

AMD が切るべき分岐は、「研究者CEOか、外部CEOか」という二択ではありません。

- 研究者本人が担うべき CEO 機能は何か
- 外部人材が担うべき経営実務は何か
- GAPファンドで鍛えるべき能力はどこか
- VCが本当に懸念しているのは資質か、経験か、体制か
- 会社化前に AMD が補える穴はどこか
- 研究者の夢と、資本政策上の合理性がどこでズレているか

この分岐を残さないと、支援者全員が善意で動いていても、研究者だけが孤独に意思決定を背負う構図になります。BZM ではこの論点を `FRL`、`F_character`、`F_capability`、`frl_cap_amd`、`HRL`、ERS に分けて読みます。

## 6. 分岐ログとして残す

Before Zero の判断は、後で見返せる形で残す必要があります。最小単位は次の形です。

```md
- 判断: GO / WAIT / NO_GO / HOLD / RESOURCE_SHIFT
- 判断前の問い:
- 見た根拠:
- 主な律速:
- 次に見る条件:
- 観測後の見直し予定:
```

このログが D-7 Textbook Insights Textbook Insights へ育つときは、[現場判断と分岐](8-2-field-decisions-and-branches.md) の追記対象になります。

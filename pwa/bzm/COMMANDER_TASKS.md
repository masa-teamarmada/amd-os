## 運用ルール (この盤の書き方)

- 🚨 **司令塔はタスクを直接引き受けない (まさ確定、2026-07-12 再違反→再確定・恒久ルール化)**: 執筆・変換・検算・正本反映などの実行作業は、司令塔自身の TaskList に乗せず必ず Agent tool (または spawn_task) で worker に委譲する。司令塔の TaskList に許されるのは「①全体計画管理 (この盤の更新) ②品質監督 (worker 成果物を読んで品質ゲート基準の通過/差し戻しを裁定する)」だけ。「検算」「正本反映」は品質監督ではなく実行作業 — worker に投げ、司令塔はその結果 (検算ログ・反映後 diff) をレビューして裁定するに留める。**事故**: N フェーズB' (Ch2〜8 である化) で、提案 md 生成は Agent 委譲したにもかかわらず、その後の反映前検算・反映後検証・正本反映という実行作業を司令塔が Task#1〜7 として自分で抱えて実行してしまった。同日の Changelog (2026-07-12 一つ前のエントリ) に既に同じ原則を書いていたのに本文に格上げしておらず、Changelog は読み返されないため再違反した。この教訓により運用ルール本文の先頭に固定し、次回セッション起動時に必ず目に入るようにする。**新しい実行作業が発生した瞬間、TaskCreate する前に「これは worker (Agent tool) に投げられるか」を自問し、投げられるものは全て投げる。**
- ストリームの状態が変わるたび更新する (章の done / ウェーブ完了 / まさ判断 / ブロッカー発生・解消)。
- **worker 詳細ログを貼らない**。1 行 = 「ストリーム / 状態 / 担当 / 次アクション / まさ要判断」だけ。詳細は各 L3 (`BOOK_A_CHAPTER_<n>_PROGRESS.md`) を見る。
- 状態語彙: `not-started` / `drafting` (章ワーカー起草中) / `verify` (敵対検証・機械検査中) / **`まさ確定待ち`** (品質ゲート通過済み・まさ段落確定のみ残) / `done` (まさ確定済み) / `blocked` (まさ判断・外部依存で停止)。
- **品質は「章ワーカーが出したら終わり」ではない**。司令塔の品質ゲート (下記) 通過で初めて `まさ確定待ち` に上げ、まさ確定で `done`。
- bzm md / 台帳 / handoff 系の commit + push は承認不要で即実行。**この盤への記帳は自分の変更分だけ最小行** (並走コンフリクト回避)。
- 並走章セッションが同じ main へ push する。読む前 fetch / push 前 fetch 必須、rejected なら `git pull --rebase --autostash` → push 単独実行して RC 判定 (パイプ禁止)。新規ブランチ禁止 (main 一本)。

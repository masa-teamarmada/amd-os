# 運用 — AMD OS への実装

> **ねらい**：第 7 部までに整えた BZM の理論（σ_SU・XRL・FRL・AMD Score・ERS）を、AMD OS という実際のソフトウェアにどう落とし込み、日々の経営判断にどう使うかを説明します。各軸のデータソースと自動化難度、重みスライダーと K の自動再校正、Shallow Tech モード、そして「次に手当てすべき軸」をどう画面に出すかを整理します。
>
> **前提**：第 5 部（AMD Score）、第 7 部（ERS）。

## 1. 理論を運用に落とす — 二層構造の二段階

第 5 部・第 7 部で見たように、BZM は AMD Score（動学層から出る σ_SU を含む 7 軸の判定）と ERS（苗床の整備度）の二層から成ります。AMD OS では、これをさらに **動学層 → 判定層** の二段階で扱います。

- **動学層**：観測量（政策件数・予算・VC 投資・論文数など）の時間発展から、Triple Helix の隠れ状態 μ_A・μ_I・μ_G を推定し、σ_SU を生成する（第 2 部）。
- **判定層**：任意時点の真の状態を 7 軸で評価し、AMD Score・律速軸・フェーズを出す（第 5 部）。

σ_SU は動学層が自動で更新し、TRL〜FRL は L2 抽出と UI 入力で更新する、という分担になります。

## 2. 各軸のデータソースと自動化

7 軸は、自動化のしやすさが異なります。

| 軸 | データソース | 自動化難度 |
|---|---|---|
| σ_SU | Atlas（P/B/V/R/I_R/N/C の 7 観測量） | 中（観測モデル経由で自動推定） |
| TRL | knowledge/{su}.md ベース、四半期更新 | 低（UI 入力 + L2 抽出根拠） |
| BRL | 同上 | 低 |
| GRL | 規制 DB + 手動 | 中 |
| SRL | 世論調査 + メディア言及 | 中 |
| HRL | 内部資料 + 手動 | 低 |
| FRL | ALQ 16 項目 + 主観評価 | 低（UI 入力） |

AMD OS の設計思想として、軸の評価はできるだけ **生データからの自動抽出（L2 抽出ルーティン）** に寄せ、手動入力を最小化します。σ_SU は Atlas の観測量から観測モデル（C 行列、第 2 部 §4）を通じて自動推定され、XRL の根拠は L2 抽出が四半期ごとに更新します。

## 3. UI の 3 大要素 — M × X × F

理論層では 7 軸が一つの積ですが、画面では第 5 部 §6 の **M × X × F**（マクロ × 会社の XRL × CEO の FRL）の 3 大要素で見せます。

$$S = k \cdot M \cdot X \cdot F$$

「マクロトレンドの流れがあって、会社の XRL が整っていて、それを FRL の高い CEO が牽引する」という哲学を、そのまま 3 ブロックの可視化に落とします。FRL は別格の重み（α_F=1.5）を持つため、XRL の積に呑み込ませず独立した第 3 要素として表示します。

## 4. 重みスライダーと K の自動再校正

AMD OS では、各軸の重み $\alpha_i$ を **スライダーで変更可能** にします。利用主体や状況によって軸の相対重要度は変わるためです。

- **レーン依存**：創薬では SRL を上げる、など。
- **フェーズ依存**：Before 0 では FRL/σ_SU を強調、After 0 では BRL/HRL を強調する。
- **利用主体依存**：VC・行政・大学それぞれの評価観点に合わせる。

重みを変えると重み合計 $\sum \alpha_i$ が変わるため、IPO=100,000 のスケールを保つには定数 $K$ を再校正する必要があります（第 5 部 §4）。AMD OS はこの再校正を **UI 内で自動** に行います。

$$K = \frac{100{,}000}{10^{\sum \alpha_i}}$$

これにより、重みをどう動かしても「全軸最大 = IPO 級 100,000」という基準が崩れません。

### 4.1 例題 8-1 — 重みを変えたときの K を求める

base case は $\sum\alpha = 1.5 + 1.3 + 1.1 + 1.0 + 0.6 + 0.3 + 0.2 = 6.0$ で $K = 100{,}000/10^{6.0} = 0.1$。

いま創薬レーン向けに **SRL を $0.2 \to 0.7$ に強調**したとします。新しい重み合計は $\sum\alpha = 6.5$ になり、

$$K = \frac{100{,}000}{10^{6.5}} = \frac{100{,}000}{3{,}162{,}278} \approx 0.0316$$

K が $0.1 \to 0.0316$ に下がることで、重みを増やした分だけ積が大きくなる効果が打ち消され、「全軸最大 = 100,000」が保たれます。**確認**：全軸 9（シフトで 10）なら $S = K \cdot 10^{\sum\alpha} = 0.0316 \times 10^{6.5} = 100{,}000$。スライダーをどう動かしても上限が動かないのは、この $K$ の自動追従のおかげです。

## 5. 律速軸の表示 — 次に手当てすべき軸

第 5 部 §7 の律速判定を、AMD OS では **レーダーチャート上で律速軸を赤く強調** して見せます。

$$\text{bottleneck}(t) = \arg\max_i \frac{\alpha_i}{X_i(t) + 1}$$

これにより「重みが大きいのに値が低い軸」＝投入の限界収益が最も高い軸が一目で分かり、経営アクション（次にどの軸を補強するか）に直結します。

> **実装上の教訓**：旧実装は $\arg\min$（寄与シェア）で律速判定しており、重みの小さい SRL（α=0.2）が常に律速と表示される回帰がありました。Cobb-Douglas の偏微分定義（$\arg\max \alpha_i/(X_i+1)$）に揃えて修正済みです。理論の数式と実装を一致させることが、正しい経営示唆を生みます。

## 6. Shallow Tech モード

AMD のスタジオ対象は本質的にディープテックですが、独自技術を持たないスタートアップ（Shallow Tech、例: jc）を補助的に捉えるモードがあります。

- TRL 軸を計算から除外する。
- 残り 6 軸で Cobb-Douglas を計算し、$K$ を再校正する。
- （将来案）TRL の重み（1.0）を BRL/HRL に再分配する。

これにより、After 0 で deep 化したスタートアップも同じ尺度で扱えます。

**K の再校正（例題 8-1 の続き）**：現行の Shallow Tech モードは TRL（$\alpha=1.0$）を単純に除外します。再分配しない場合、重み合計は $\sum\alpha = 6.0 - 1.0 = 5.0$ となり、

$$K_{\text{shallow}} = \frac{100{,}000}{10^{5.0}} = 1.0$$

通常 PJ（$K=0.1$）と Shallow PJ（$K=1.0$）はスケール定数が一桁違うため、両者のスコアを直接横並びで比較しないよう UI で明示します。TRL 重みを BRL/HRL に再分配する将来案を入れれば $\sum\alpha$ が 6.0 に戻り、$K$ も 0.1 に揃って通常 PJ と同一スケールで比較可能になります。

## 7. AMD Score と Valuation の併置

AMD OS では、AMD Score と Valuation を並べて表示し、第 5 部 §9 の補完関係を経営判断に使えるようにします。

- AMD Score 高 + Valuation 低 ＝ **過小評価**（買い場）。
- AMD Score 低 + Valuation 高 ＝ **過大評価**（バブル警戒）。

AMD Score の対数は log valuation と同じ単位として読めるため、両者を同一画面で比較することで「事実の準備度」と「市場の期待」のギャップが可視化されます。

## 8. ERS の運用 — ダッシュボードの下ブロック

第 7 部で定義した ERS は、ダッシュボードの **下ブロック（研究機関リスト）** として運用します。

- 各行：機関名 / タイプ / ERS 充足率 / 8 軸ミニヒートマップ / 詳細リンク。
- 機関詳細：8 軸レーダー、サブ軸 rubric の現在 Lv と根拠ノート、「この機関発の PJ」へのリンク。
- 上ブロック（SU / AMD Score）と縦に積むことで、苗床と個体を一望できる。

ERS は AMD Score とは別ロジック（加重和・充足率）なので、画面上でも「別指標」と明示し、二重計上の誤解を避けます。

## 9. データ駆動による将来校正

現状の重み $\alpha_i$・フェーズ閾値・ERS の軸重み $w_k$ は、いずれも専門家事前情報に基づく仮置きです。AMD OS にデータが蓄積するにつれ、次の校正を進めます。

- 9 PJ retrofit + 外部 SU データから、階層ベイズで $\alpha_i$ を最尤推定（第 6 部）。
- 設立判定閾値（3,500）のレーン依存校正。
- ERS の軸重み $w_k$ を等加重から実態に合わせて調整。
- σ_SU 観測モデル（C 行列の負荷量）のベイズ更新（第 2 部）。

## 10. まとめ — BZM 全体の到達点

本書は、ディープテック・スタートアップが「ゼロになる前」をモデル化する Before Zero Model を、理論の依存関係に沿って通読できる形でまとめました。

- マクロ環境 σ_SU を Triple Helix の状態空間モデルで推定し（第 2 部）、
- 会社の成熟度を XRL 群で（第 3 部）、創業者の質を FRL で（第 4 部）測り、
- これらを Cobb-Douglas で一つの AMD Score に統合し（第 5 部）、
- 過去事例の retrofit で妥当性を確かめ（第 6 部）、
- 苗床である研究機関の整備度を ERS で測り（第 7 部）、
- それらを AMD OS という運用基盤に実装する（第 8 部）。

BZM は「URA 向け教科書 → AMD プロトコルの理論武装 → 学会発表」という三段のゴールを持ちます。本書はその第一段であり、現場で使える実用書であると同時に、各部末の出典を通じて学術的な接続も確保しています。理論は今後もデータによって校正され続けますが、その校正のたびに本書と理論正本（`before-zero/theory/` および `pwa/design/`）を同じ更新で揃えていきます。

### 10.1 本章のまとめ

- AMD OS は BZM を **動学層（観測量→σ_SU を自動推定）→ 判定層（7 軸→AMD Score・律速・フェーズ）** の二段階で実装する。σ_SU は自動、XRL/FRL は L2 抽出＋UI 入力。
- 画面では 7 軸の積を **M × X × F**（マクロ × 会社 × CEO）の 3 大要素に分けて見せる。FRL は重み最大のため独立要素として表示。
- 重み $\alpha_i$ はスライダーで可変、$K=100{,}000/10^{\sum\alpha}$ を **自動再校正** して上限 100,000 を保つ。
- 律速軸は $\arg\max_i \alpha_i/(X_i+1)$ をレーダー上で赤強調。旧 $\arg\min$ 実装の回帰を偏微分定義に揃えて修正済み。
- Shallow Tech は TRL を除外し $K=1.0$ に再校正（通常 PJ の $K=0.1$ とスケールが違うので併置時は明示）。ERS は別ロジックなので別指標として下ブロックに置く。

### 10.2 練習問題

1. **K の再校正**：Before 0 強調プリセットとして σ_SU を $1.3 \to 1.8$、FRL を $1.5 \to 2.0$ に上げた。新しい $\sum\alpha$ と $K$ を求めよ。<br>（答え：$\sum\alpha = 6.0 + 0.5 + 0.5 = 7.0$、$K = 100{,}000/10^{7} = 0.01$）
2. **律速の実装バグ**：$\arg\min$（寄与シェア）で律速判定すると、なぜ重みの小さい SRL が常に律速と表示されてしまうのか。正しい $\arg\max_i \alpha_i/(X_i+1)$ との違いを説明せよ。
3. **Valuation 併置**：「AMD Score 高 + Valuation 低」の PJ を見つけたとき、経営判断としてどう動くべきか。なぜそれが「買い場」なのかを第 5 部の補完関係から説明せよ。
4. **二重計上の回避**：ERS が高い機関発の PJ について、ERS を AMD Score に足さずとも整備度が反映される経路（σ_SU）を図示し、なぜ足すと二重計上になるかを述べよ。

# PRS 9PJ判断差分レビュー

作成日: 2026-06-01
作成者: BZM理論検証worker
ステータス: BZM司令塔レビュー待ち

## 0. 結論

9PJで見ると、PRS候補を「正式スコア」へ上げるにはまだ早い。ただし、現行7軸だけでは説明が薄くなる判断差分は実在する。

特に強い差分は次の4つ。

| PJ | PRSで追加説明できる判断差分 | 重要度 |
|---|---|---|
| p03 ティエム | 「早すぎた」は7軸TRLで説明できるが、「商社+受託で食いつなぎながら本命R&Dを続けるべきだった」はP/R_netがないと扱いにくい | 高 |
| p09 JOYCLE | deep化後のTRL上昇だけではAMD関与終結を説明しにくい。目先収益が本命R&Dを毀損する負のR_netが必要 | 高 |
| p18 Yellow Duck | TRL=4のPoC進捗だけではNO_GOを出しにくい。低P/低UE/R_netなしで「技術は進むが事業として筋が悪い」を説明できる | 高 |
| p11 BWE | SIP採択・設立GOは7軸で説明できるが、初期キャッシュ自走が見えない脆さはR_netで見る必要がある | 中-高 |

一方で、CTBのようにR_netがゼロでも、創薬の外部資金・薬事プロセス・EXIT構造で生存可能性を確保するPJがある。したがって `R_net=低い -> NO_GO` のような単純rubricは危険。

現時点の推奨は、前回メモどおり `Adopt as comparison layer`。P/R_net rubric確定・DB列追加・過去score再計算はまだ行わない。次は正式rubric draftではなく、各PJの「P/R_net根拠カード」を整備して、まさ/BZM司令塔が差分だけレビューできる形にするのが安全。

## 2. レビュー基準

このレビューでは、次の3分類だけを使う。

| 分類 | 意味 |
|---|---|
| 7軸で説明できる | sigma_SU / TRL / BRL / GRL / SRL / HRL / FRL / FRL CES / alpha / bottleneckで十分に説明できる |
| PRSで追加説明 | PまたはR_netを入れると、経営判断の理由や打ち手が明確になる |
| まだ未確認 | 根拠はあるが、P/R_netの観測rubricや時点が未確定 |

ここで見るのはscore順位ではなく、判断差分。

対象にする判断語:

- 早すぎた
- GO / NO_GO
- 商社化 / 受託 / 小さく自走
- 本命毀損
- ライスワーク化
- UE不成立
- 補助金・外部資金依存の生存可能性

## 3. PJ別レビュー

### p03 ティエムファクトリ

| PRSで追加説明 | Pは大きいが、R_netが立っていなかったため「会社として死なずに本命R&Dを続ける構造」がなかった。商社化、Cabot代理店、開発受託で食いつなぎながらモノリスを続けるべきだった、という反省は7軸だけだと表現しにくい。 |

## 4. 差分の型

9PJを見ると、PRSでしか見えにくい差分は4型に分かれる。

| 型 | 説明 | 該当PJ |
|---|---|---|
| 高P・低R_net型 | 本命の天井は大きいが、そこまで生き延びる収益構造がない | ティエム、BWE |
| 負のR_net型 | 目先収益が本命R&Dを支えず、むしろ毀損する | JOYCLE |
| 低P/UE不成立型 | 技術PoCがあっても、事業の天井やユニットエコノミクスが弱い | Yellow Duck |
| R_netゼロでも成立型 | 売上ゼロでも、助成金・薬事・EXIT構造でSを確保する | CrestecBio |

このうち、正式理論化に一番効くのは「負のR_net型」と「低P/UE不成立型」。現行7軸は成熟度・準備度に強いが、目先収益と本命価値の関係、事業上限、UEの筋悪さを独立に持っていない。

## 5. PRSを入れなくても7軸で説明できるもの

次はPRS採用の根拠から除外する。

| 判断 | 7軸で説明できる理由 |
|---|---|
| ティエム設立が早すぎた | TRL=0 / TRLゲート未達で説明できる |
| JC設立時NO_GO | 自社技術なしのTRL=0で説明できる |
| CTBが創薬として普通のタイミング | 創薬専用readinessとHRL経時変化で説明するべき |
| LST/CX/SXの設立準備・GO寄り判断 | sigma_SU / TRL / BRL / HRL / FRLで大筋説明できる |
| BWEの設立GO | SIP採択、政策要請、TRL/BRL/HRLで説明できる |

PRSを採用する理由は、これらの判断を置き換えることではない。7軸の判定後に、「生存設計」「本命毀損」「小さく自走」「UEの筋悪さ」を追加で見るため。

## 6. BZM司令塔への判断事項

1. PRS候補は、正式理論ではなく比較レイヤーのまま継続する。
2. 次workerを切るなら、P/R_net rubric draftより先に、上記4型ごとの根拠カードを作る。
3. R_netは単純な売上有無ではなく、少なくとも次の3項に分ける。
   - 粗利貢献
   - 運営コスト
   - 本命PJへのリソース毀損
4. CTBのために、売上ゼロでもSを確保する外部資金・助成金・薬事/EXITプロセスをR_netと混同しない。
5. JOYCLEのために、R_netに「負の自走性」または「本命毀損」表現を入れるか判断する。

## 7. 次アクション

推奨順:

1. BZM司令塔が本レビューを `Adopt as comparison layer` の補強資料として採否判断する。
2. workerで `P/R_net evidence cards` を9PJ分作る。正式rubricではなく、根拠・未確認・反例を1PJ1枚にする。
3. その後、P/R_net rubric draftを作る。0-9値ではなく、観測項目・禁止誤判定・レーン別例外から始める。
4. DB migrationや正式score化は、少なくともCTB/JC/YD/BWEの反例処理が固まるまで保留する。

# 失敗・ピボット・仮説修正 — 消耗を学習に変える

> この章は何か: Before Zero の失敗・停滞・仮説外れを、責任追及ではなく再利用可能な判断ルールへ変換する章です。実ケース本文は捏造せず、承認済みの L2⑩ Textbook Insights が来たときだけ追記します。

## 扱う insight

この章は、うまくいかなかった事象から次の判断精度を上げる知見を扱います。

- 早すぎた設立・早すぎた採用・早すぎた資金調達
- 顧客仮説・用途仮説・価格仮説の外れ
- VC / 企業 / 大学 / 行政からの拒絶や停滞
- 制度・規制・技術検証・知財で詰まった局面
- ピボット後に残すべき仮説と捨てるべき仮説
- 複数 PJ にまたがって見えた失敗パターン

主な L2⑩ `practice_kind` は `failure_learning` と `cross_project_pattern` です。既存 schema では `insight_type='before_zero_knowhow'` または `insight_type='cross_project_pattern'` として受けます。

## 掲載基準

この章に載せる失敗・修正は、次の条件を満たすものに限ります。

- 何が仮説で、何が観測で、何が外れたのかを分けられる
- BZM のどの軸や前提が過大評価・過小評価されていたか説明できる
- 次回の判断ルール、チェック項目、赤信号に変換できる
- 個別の責任論ではなく、運用・モデル・順序の学習として書ける

載せないもの:

- 事実確認ができない反省文
- 実名・PJ名を出さないと意味が通らない内部事情
- 「失敗だった」で止まり、次の判断に変換されていないメモ
- 承認前の候補や、守秘上まだ一般化できない事例

## L2⑩ 追記ブロックの受け方

local applier が承認済み候補を追記するときは、この章では次の形を基本にします。

```md
### <学習テーマ>

<!-- textbook-insight:<candidate_id> -->

- 起きたこと: <generalized observation>
- 外れた仮説: <hypothesis>
- 見落とした信号: <missed signal>
- 修正後の判断ルール: <reusable rule>
- 次回の赤信号: <warning sign>
```

本文では、固有名詞よりも「どの仮説が、どの観測で、どう修正されたか」を優先します。ケーススタディとして扱う必要がある場合も、承認済み source refs と一般化済み文体を前提にします。

## まだ未記入 / これから集めるもの

- 早すぎた設立を避けるチェック項目
- 顧客仮説が外れたときの再検証テンプレ
- VC 拒絶を BRL / FRL / σ_SU のどれとして読むか
- 制度・技術の詰まりを WAIT / PIVOT / STOP へ分ける条件
- 横断失敗パターンを Before Zero の赤信号へ変換する表

## 読めばできること

- 失敗や停滞を、次の PJ で使える判断資産へ変換できる
- L2⑩ candidate が「単なる反省」か「掲載すべき学習」か見分けられる
- ピボット時に、残す仮説と捨てる仮説を分けられる
- 消耗を防ぐための赤信号を Before Zero の初期段階で確認できる

> **状態**：`register-open v0.2`
>
> **理論版**：`BZM 2.1 theory-open / conditional-pass`
>
> **情報締切**：2026-08-11
>
> **前向き検証**：0件
>
> **数値適用**：12PJに`estimated-v0.1`のshadow値を作成。実測版は計算不能

## 0. この台帳の目的

この台帳は、BZM 2.1の全入力と派生出力について、どこから、誰が、どの手順で取得し、欠測をどう残すかを固定する。

理論正本は`pwa/bzm/bzm-2-1-dynamic-business-value-model.md`である。

BZM 2.0の抽出台帳と値を上書きしない。

現行運用SPSの9軸入力を、BZM 2.1の確率、費用、価値へ自動変換しない。

合成テストの架空数値を実PJへ流用しない。

## 1. 抽出の共通規律

### 1.1 入力状態

| 状態 | 意味 | 計算での扱い |
|---|---|---|
| `observed` | 文書、記録、拘束力ある契約その他から直接確認した | 使用可 |
| `calculated` | 凍結入力と再現コードから算出した | コード、入力hash、版が揃えば使用可 |
| `conditional` | 条件が成立した場合だけ有効 | 条件を同じ行へ保存して使用可 |
| `estimated` | 事前登録した参照クラスまたは推定器から算出した | 手続き、母集団、版、入力hashが揃えば感度つきで使用可 |
| `partial` | 範囲の一部だけ確認した | 対応する部分出力だけ使用可 |
| `missing` | 必要だが取得できていない | 0へ変換しない |
| `not_started` | 抽出を始めていない | 0へ変換しない |
| `not_applicable` | PJ構造上存在しない | 欠測と区別して除外 |

数値が無いことと0であることを分ける。

行動が存在しないこと、存在するが使えないこと、まだ調べていないことを分ける。

### 1.2 根拠の優先順

| 優先 | 根拠 | 例 |
|---:|---|---|
| 1 | 拘束力ある契約・法定文書 | 投資契約、ライセンス、SHA、定款、補助金交付決定、購入契約 |
| 2 | 会計・銀行・発注・研究・製造の実行記録 | 残高、総勘定元帳、PO、試験成績、製造実績、CRM |
| 3 | 承認済み計画・取締役会決定 | 予算、事業計画、取締役会資料・議事録 |
| 4 | 外部一次資料 | 公的統計、規制原文、顧客の拘束力ある仕様、相手方文書 |
| 5 | 構造化ヒアリング | 担当責任者への順序、条件、反例を含む確認 |
| 6 | 再現計算 | 上記入力を使うコード、数式、集計 |

実PJの確率、費用、撤退価値、終端価値を、その場の感覚で置かない。

再現手続きが無い推測値は`missing`にする。

### 1.3 一問ずつ聞く前に行うこと

入力収集は次の順で行う。

1. 契約、計画、会計、研究・製造記録、会議資料を先に読む。
2. DBから取得できる識別、時点、既存証拠を抽出する。
3. 感度分析で判断を変えうるノードと入力を絞る。
4. そのノードの責任者へ、文書で閉じない一点だけを聞く。
5. 回答を一次文書または会議決定で確認し、版を上げる。

全PJの全行動をまさ一人へ質問して埋めない。

通常の会議・記録から維持できない入力密度が必要なら、モデルの運用可能性が反証されたものとしてノードを減らす。

## 4. 実行可能行動束

基本行動型は、続行、WAIT、再試行、ピボット、縮小、拡張、ライセンス、撤退である。

実際に比較する単位は、複数の基本行動または資金調達・交渉を束ねた行動束である。

| parameter | 意味・単位 | 一次ソースと抽出手順 | 欠測時 | 更新契機 |

各行動の遷移確率は合計1にする。

同着$T_C=T_Y$は到達失敗とする。

資本自立へ着いた後に別終端へ移っても、$T_C$を消さない。

## 6. 単一キャッシュフロー台帳

費用、便益、資金投入、補助、購入、税、残存価値を、event IDのある一つの台帳へ置く。

| field | 内容 |
|---|---|
| `cashflow_event_id` | 全版で追跡できる一意ID |
| `economic_event_group_key` | 同じ送金を複数視点の反対符号で表すとき、視点別legを一つの経済事象へ束ねるID |
| `perspective_leg` | `company` / `bzsf` / `public`。反対符号の移転では一行につき一視点だけを計算へ含める |
| `owner` | 会社、BZSF、基金、顧客その他の受取主体 |
| `counterparty` | 支払主体 |
| `scope` | 版、状態、行動、遷移、終端のどこへ帰属するか |
| `amount` / `currency` | 原通貨建ての金額と通貨 |
| `model_amount_million_jpy` | 計算で使う百万円単位の円換算額 |
| `conversion_rate_to_jpy` | 外貨1単位あたり円の換算率 |
| `conversion_rate_date` | 換算率の観測日 |
| `conversion_rate_source_ref` | 換算率の一次資料 |
| `conversion_rule_ref` | どの時点・価格を使うかの事前規則 |
| `timing` | 判断時点、遷移中、終端のどこで何か月後に発生するか |
| `nominal_or_real` | 名目・実質 |
| `price_base_date` | 実質額の価格基準日 |
| `tax_treatment` | 税前、税後、納税、非課税の区分 |
| `tax_subject_ref` | 税を負担または受領する主体 |
| `source_ref` | 契約・記録・計算への参照 |
| `information_cutoff` | 当時利用できた証拠の締切 |
| `included_in` | 即時費用、即時便益、遷移CF、終端価値、失敗損失のどこへ一度だけ入れるか |
| `perspective_attribution` | 会社、BZSF、公的の各視点で含めるか、符号、帰属理由 |
| `public_fiscal_amount` | 基金財政に帰属する符号つき金額。社会便益と分ける |
| `public_social_benefit_vector` | 便益成分、数量、単位、状態、根拠、換算規則を成分別に保存するベクトル |
| `public_social_converted_amount` | 換算規則が閉じた社会便益成分の円換算合計 |
| `public_aggregated_amount` | 最小版の事前登録規則で基金財政と換算済み社会便益を集約した額 |
| `public_aggregation_input_hash` | 上の各成分、換算、集約規則を再現する入力hash |

同じevent IDを二か所へ入れない。

会社への入金がBZSFまたは基金の支出になる移転は、同じ金額を両視点で同じ符号へ置かない。

反対符号を持つ場合は、同じ`economic_event_group_key`の視点別legへ分け、金額、通貨、換算、時点、支払主体、受取主体、出所、税対象が一致することを検査する。

groupの無い行を複製して移転を表さない。

即時費用、即時便益、遷移CF、終端価値、失敗損失の各計算区分は、根拠つきeventを少なくとも一件持つか、根拠つきの明示的な0または`not_applicable`を登録する。

eventが無い状態を0として計算しない。

異なるevent IDで同じ経済事象を重複登録する可能性はID一意性だけでは防げないため、実PJの数値計算前に支払主体、受取主体、時点、金額、出所を使った意味重複レビューを行う。

BZM 2.0の$P_o$または$SPS_{all}$をBZM 2.1の動的価値へ足さない。

会社への投資は、会社側の価値創造CFではなく資金制約と証券請求を変える金融取引として扱う。

投資家側では支出と取得証券を対にする。

補助金、税、公共調達は基金財政と社会全体で符号が違いうるため、同じ費用として二重に数えない。

各視点は`valuation_rule`で税前＋明示納税、税後込み、非課税のいずれかを固定する。

税後CFへ同じ税の納税eventを再投入せず、実質額を名目割引率へ黙って渡さない。

## 7. 三視点の価値範囲

| 視点 | 含める | 別に閉じるもの |
|---|---|---|
| 会社 | PJの営業・投資CF、税、ライセンス、撤退・転用 | 資金調達CF、負債橋、既存株主持分、全社の他資産 |
| BZSF | 初回・追加投資、証券分配、希薄化、清算優先、手数料 | 共通予算・他PJ機会費用・相関はポートフォリオ層 |
| 公的基金の財政 | 支出、回収、税収、調達対価、予算制約 | 社会全体の移転と外部便益 |
| 社会厚生 | 便益・外部不経済の各軸 | 換算規則が無ければベクトルのまま |

公的目的をスカラー化する場合、法的使命、便益境界、シャドー価格、分配ウェイト、社会的割引、集約規則を事前登録する。

登録できなければ、公的視点の方針最適化を行わない。

## 8. 支援・介入

| parameter | 抽出手順 | 禁止事項 |
|---|---|---|
| `intervention_id` | 契約・制度・AMD支援の版を一意にする | 支援一般を一つの係数にしない |
| `enabled` | 情報締切時点の成立を文書で判定 | 採択予定を成立扱いしない |
| `cost_effect` | 費用補助、利用料等の対象eventへ接続 | $q$へ直接加点しない |
| `funding_effect` | 拘束力ある資金と使途制限へ接続 | 未契約調達を現金にしない |
| `action_set_effect` | 実証場所・権利等が解放する行動を指定 | 存在しない行動を発明しない |
| `transition_effect` | 速度・品質・採用確率が変わる根拠を指定 | 手応えだけで確率を動かさない |
| `terminal_effect` | 購入保証、最低価格、数量、ロイヤルティへ接続 | 社会価値を会社価値へ直足ししない |
| `information_effect` | 審査・実証で得る観測を指定 | 情報価値だけ置き待機費用を落とさない |

支援あり・なしの二入力から得る差は`model_implied_contrast`である。

無作為化、妥当な準実験、または逐次因果仮定と感度分析が無ければ、因果効果と呼ばない。

## 9. 派生出力

次は入力せず、凍結グラフから機械計算する。

| output | 意味 | 表示条件 |
|---|---|---|
| $J_r(n,a)$ | 個別行動の視点別正味価値 | その行動の入力が閉じる |
| $E[V_r^{\mathrm{net}}\mid G,a]$ | 行動$a$の後に資本自立へ初到達した経路に条件づけた視点別正味価値 | その行動から始まる同じCF台帳と到達履歴から機械集計できる |
| $q^{\pi_0}_{plan}(H_v)$ | 固定方針の計画達成診断 | BZM 2.0凍結値を保存 |
| $V_r^{\pi_0}$ | 完全固定方針の視点別価値 | off-pathを含む$\pi_0$が完全 |
| $\pi_d^*$ | 単一権限主体の登録目的で選ぶ方針 | 閉じた行動集合、目的、権限、tieが閉じる |
| $q_G^{\pi_d^*}$ | 選択方針下の資本自立初到達確率 | 実世界確率と二時計が閉じる |
| $V_r^{\pi_d^*}$ | 同じ選択方針を各視点から評価した価値 | 各視点のCFと評価規則が閉じる |
| $E[V_r^{\mathrm{net},\pi}\mid G]$ | 方針$\pi$の下で資本自立へ初到達した経路に条件づけた視点別正味価値 | 方針全体のCF台帳とfirst-passage履歴が閉じる |
| $\Omega_d$ | 主体自身の柔軟性価値 | 同じ目的・地平で完全$\pi_0$を比較できる |
| $\Delta V_{r\mid d}$ | 主体の選択が別視点へ与える価値差 | 正負を許容し柔軟性価値と呼ばない |
| `expected_cumulative_funding` | 選択方針の経路加重累積必要資金 | 資金時点と経路が閉じる |
| `expected_failure_loss` | 非到達経路の損失 | 単一CF台帳が閉じる |
| `expected_exit_value` | 撤退・転用・ライセンス等の価値 | 相手方・権利・評価が閉じる |

未調査行動が残る場合は、`partial_action_set`または`decision_indeterminate`とする。

「最適」と表示するのは、事前登録して閉じた行動集合内に限る。

## 13. 2026-08-12の全PJ抽出試行

現行SPSを計算している12PJについて、情報締切以前のDB行と文書メタデータを読み、`estimated-v0.1`を作成した。

# ERS — 苗床（研究機関）の整備度を測る

> **ねらい**：ベンチャー個体を測る AMD Score に対し、ベンチャーを生み育てる「苗床」＝研究機関の整備度を測る **ERS（Ecosystem Readiness Score）** を導入します。なぜ AMD Score とは別ロジック（乗法ではなく加重和）にするのか、8 軸 × サブ軸 × Lv1〜5 の構造、そして二つのレイヤーをなぜ計算式上は分けて保つのかを定義します。
>
> **前提**：第 5 部（AMD Score の Cobb-Douglas 統合）、第 2 部（σ_SU）。

## 1. 動機 — ベンチャーは無から生まれない

AMD は、香川大学・KUTE・NIMS など複数の研究機関で **エコシステム構築業務** を請け負っています。現場で繰り返し直面するのは、「この機関は、ベンチャーを生み育てる装置としてどれだけ整っているか。何が足りないか」という問いです。

同じシーズでも、知財を権利化できる TLO があるか、ギャップファンドがあるか、客員起業家（EIR）制度があるかで、事業化のスピードはまるで違います。**ベンチャー個体の成熟度（AMD Score）とは別に、それを生み出す土壌の整備度を測る指標** が要る。これが ERS です。

ERS のもう一つの目的は **支援ギャップの可視化** です。機関の「何が未整備か」が見えれば、それはそのまま **AMD が次に提案できる支援メニュー** になります。

## 2. なぜ AMD Score を流用しないのか

AMD Score は Cobb-Douglas（乗法）でした。これは「一軸でもゼロに近いと全体が大きく下がる」＝**全軸が揃わないと IPO に届かない** という個体の宿命をモデル化したものです。

しかし苗床の評価で乗法を使うと、**欠けている軸が掛け算で全体を消してしまい、「何が足りないか」が見えなくなります**。ERS の目的はむしろ逆で、欠損（未整備ギャップ）をくっきり見せることです。

そこで ERS は、欠損が掛け算で消えない **加重和（充足率）** を採ります。

| | AMD Score（個体） | ERS（苗床） |
|---|---|---|
| 統合方式 | Cobb-Douglas（乗法） | 加重和（充足率） |
| 設計思想 | 全軸揃わないと IPO 死ぬ | 何が欠けているかを見せる |
| 値域 | 0〜100,000（対数スケール） | 0〜100%（充足率） |
| 評価尺度 | 各軸 0〜9 | 各サブ軸 Lv1〜5 |

## 3. ERS の構造 — 2 階層 × Lv1〜5

ERS は **2 階層構造** です。

```
capability 軸（8）  >  サブ軸 / 評価ポイント（軸ごとに複数）  >  各サブ軸 Lv1〜5
```

計算は次の手順で行います。

$$s = \frac{\mathrm{lv} - 1}{4} \quad (\mathrm{lv} \in \{1,2,3,4,5\}) \;\Rightarrow\; s \in \{0,\ 0.25,\ 0.5,\ 0.75,\ 1.0\}$$

$$A_k = \mathrm{mean}(\text{軸 } k \text{ のサブ軸 } s) \qquad \text{ERS} = 100 \cdot \sum_k w_k \cdot A_k,\quad \sum_k w_k = 1$$

- **サブ軸スコア** $s$：各サブ軸の到達 Lv（1〜5）を 0〜1 に正規化します。
- **軸スコア** $A_k$：その軸に属するサブ軸 $s$ の **平均**。サブ軸の数が軸ごとに違っても、軸どうしが歪まないよう平均を取ります。
- **ERS（充足率）**：軸スコアを軸重み $w_k$ で加重平均し、100 を掛けて 0〜100% で表します。

### 3.1 設計上の判断（2026-05-29 確定）

- **軸スコア＝サブ軸の正規化平均**：サブ軸の数のバラつきで軸が勝手に重くならないようにするためです。重みは軸レベルにだけ持たせ、サブ軸には持たせません。
- **重み $w_k$ は当面 等加重（= 1/8）**：精度が上がったら軸レベルで調整します。
- **Lv1〜5 を rubric で固定**：3 段階では差がつかないため 5 段階にし、各 Lv は「ただの 1〜5」ではなくサブ軸ごとの **到達状態の定義文（rubric）** で固定します。本書では Lv1（最低）/ Lv3（標準）/ Lv5（最高）の 3 アンカーを示し、Lv2・Lv4 はその中間補間とします。
- **機関タイプで軸セットを分けない**：研究所（NIMS）・大学（香川大）、国立・私立で性格は異なりますが、当面は共通の軸セットで評価し、精度が上がってからタイプ別チューニングを検討します。

## 4. 8 軸の概要

各軸は AMD Score の軸と **供給側で対応** します（厳密な計算連動ではなく概念マップ）。

| 軸 | 内容 | 対応 XRL |
|---|---|---|
| 軸1 | シーズ発掘・技術評価体制 | TRL |
| 軸2 | 知財・TLO 機能 | TRL→権利化 |
| 軸3 | インキュベーション・起業支援（場・伴走・教育） | BRL |
| 軸4 | 産学連携・事業会社接続窓口 | σ_SU（産業 μ_I） |
| 軸5 | 資金・ファンド接続 | FRL |
| 軸6 | 経営人材（EIR/CXO）供給 | HRL |
| 軸7 | 規程・ガバナンス整備（ゲート的） | 制度基盤 |
| 軸8 | 政府・自治体・政策連携 | σ_SU（政府 μ_G）/ GRL |

### 4.1 rubric の例 — 軸7-c（大学のエクイティ保有制度）

軸ごとに、各サブ軸を Lv1〜5 の到達状態で記述します。代表として、ガバナンスの中核である「大学のエクイティ保有・取得制度」の 5 段階フルを示します。

| Lv | 到達状態 |
|---|---|
| 1 | 制度なし。大学は株式も SO も一切保有できない |
| 2 | 認定 VB 制度はあるが、出資・保有の規程は未整備 |
| 3 | 現金出資による株式保有は可能。ただし SO/IP 対価エクイティは不可 |
| 4 | IP ライセンス対価の SO 取得まで可能。運用実績は限定的 |
| 5 | 株式・SO 保有・IP-equity・ファンド経由出資まで規程化＆運用実績あり |

他の軸（シーズ DB 化、TLO の専門性、ギャップファンドの規模、EIR 制度、国の拠点プログラム参画など）も、同じ形式で Lv1/Lv3/Lv5 のアンカーを定義します。詳細な rubric は設計正本 `pwa/design/institution_readiness.md` を参照してください。

### 4.2 軸の置き場と将来のゲート化（レビュー論点）

- **資金は軸5 に集約**：「ギャップファンド（POC〜起業前資金）」を軸3 と軸5 のどちらに置くかは論点でしたが、重複を避けるため資金は軸5 に集約し、軸3 は「場・伴走・教育」に限定しました。
- **軸7（ガバナンス）のゲート化**：軸7 は「整っていないと他軸が全部空回りする前提条件」です。当面は等加重で他軸と並べますが、将来「軸7 が低いと全体に係数で効くゲート」にする案も検討の余地があります。ただし、まずは欠損を可視化する目的を優先し、加重和のまま運用します。

### 4.3 例題 7-1 — ある研究機関の ERS を手で計算する

ある大学を 8 軸で評価した結果、各軸スコア $A_k$（サブ軸 Lv を $s=(\mathrm{lv}-1)/4$ に正規化して平均した値）が次のように得られたとします。まず軸7（ガバナンス）の作り方を詳しく示します。

**① サブ軸スコア $s$**：軸7 に 3 サブ軸があり、到達 Lv が $\{5, 3, 4\}$ だとすると、

$$s = \left\{\tfrac{5-1}{4}, \ \tfrac{3-1}{4}, \ \tfrac{4-1}{4}\right\} = \{1.0, \ 0.5, \ 0.75\}$$

**② 軸スコア $A_7$**（サブ軸の平均）：

$$A_7 = \mathrm{mean}(1.0, 0.5, 0.75) = 0.75$$

同様に全 8 軸を求めたら、次の表になったとします。

| 軸 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| $A_k$ | 0.75 | 0.50 | 0.50 | **0.25** | **0.25** | 0.50 | 0.75 | 0.50 |

**③ ERS（充足率）**：当面は等加重 $w_k = 1/8$ なので、

$$\mathrm{ERS} = 100 \cdot \frac{1}{8}\sum_k A_k = 100 \cdot \frac{1}{8}(0.75 + 0.50 + 0.50 + 0.25 + 0.25 + 0.50 + 0.75 + 0.50) = 100 \cdot \frac{4.00}{8} = \boxed{50.0\%}$$

**支援ギャップの読み方**：最も低いのは軸4（産学連携・事業会社接続）と軸5（資金・ファンド接続）の $0.25$ です。これがそのまま「この機関に AMD が次に提案できる支援メニュー」になります —— 充足率の単一値（50%）ではなく、**どの軸が凹んでいるか** が経営アクションに直結する、というのが乗法（AMD Score）ではなく加重和を採った狙いです。仮にこれを Cobb-Douglas で統合していたら、軸4・軸5 の低さが全体を強く押し下げるだけで「何が足りないか」は潰れて見えなくなります。

## 5. 二層構造の連動 — なぜ計算式は分けるのか

ERS（苗床）と AMD Score（個体）は、現実には因果でつながっています。

> 機関の整備が進む → そこ発のベンチャーの μ_I（産業）/ μ_G（政府）が上がる → σ_SU が上がる → AMD Score が上がる。

しかし重要なのは、この連動を **計算式に直接持ち込まない** ことです。

> ⚠️ **ERS を PJ の AMD Score の計算式に直接足し込まない**。機関の整備度は σ_SU（Triple Helix の μ_I / μ_G）を通じて **すでに** AMD Score に効いているため、ここで ERS を足すと **二重計上** になります。

連動は「概念的・データ上の因果」にとどめ、二つのスコアは別々のロジックで保ちます。これは第 5 部の Cobb-Douglas と本部の加重和という、設計思想の異なる二つを混ぜないという原則でもあります。

```
        ┌──────────────────────────────────────┐
        │  苗床レイヤー：ERS（加重和・充足率 0〜100%）│
        └──────────────────────────────────────┘
                  │ σ_SU 経由で AMD Score に効く（計算式は別）
                  ▼
        ┌──────────────────────────────────────┐
        │  個体レイヤー：AMD Score（Cobb-Douglas）  │
        └──────────────────────────────────────┘
```

## 6. UI 方針

AMD OS のダッシュボードでは、二層を **縦に積んで** 見せます。

- 上ブロック：SU リスト（ベンチャー個体 / AMD Score）
- 下ブロック：研究機関リスト（苗床 / ERS 充足率）

同じ画面に上下で並べることで「どの土壌からどの個体が出るか」を一望できます。研究機関リスト側には「ERS は整備度（充足率）であり AMD Score とは別指標」と明示します。機関詳細ページでは 8 軸レーダー、サブ軸 rubric の現在 Lv と根拠ノート、そして「この機関発の PJ」へのリンク（σ_SU への概念接続）を置きます。

## 7. まとめと次部への接続

これで BZM の二層がそろいました。個体レイヤー（AMD Score）が「1 つのベンチャーがどこまで育ったか」を、苗床レイヤー（ERS）が「それを生む土壌がどれだけ整っているか」を測ります。両者は σ_SU を通じて因果でつながりつつ、計算式は分けて二重計上を避けます。

最後の第 8 部では、これらの理論を AMD OS という実際のソフトウェアにどう実装し、日々の経営判断にどう落とすかを説明します。

### 7.1 本章のまとめ

- **ERS** は苗床（研究機関）の整備度を測る指標。ベンチャー個体を測る AMD Score とは目的が逆で、「何が欠けているか（支援ギャップ）」を見せる。
- だから統合方式も逆：AMD Score は乗法（Cobb-Douglas、欠損が全体を消す）、ERS は **加重和（充足率）**（欠損が消えずくっきり残る）。
- 構造は 2 階層：**8 capability 軸 × サブ軸 × Lv1〜5**。$s=(\mathrm{lv}-1)/4$、$A_k$＝サブ軸平均、$\mathrm{ERS}=100\sum_k w_k A_k$。当面 $w_k=1/8$ の等加重。
- 8 軸は AMD Score の軸と供給側で概念対応（軸2→TLO/TRL、軸5→資金/FRL、軸8→政策/μ_G 等）。Lv は rubric で固定し、本書は Lv1/3/5 をアンカーに示す。
- 二層は σ_SU を通じて因果で連動するが、**計算式には足し込まない**（足すと σ_SU 経由の効果と二重計上になる）。

### 7.2 練習問題

1. **ERS の計算**：軸スコアが全軸 $A_k = 0.5$（全サブ軸 Lv3）の機関の ERS を求めよ。<br>（答え：$100 \times \frac{1}{8}(0.5 \times 8) = 50\%$。標準状態がちょうど 50% になることを確認）
2. **サブ軸からの積み上げ**：軸5（資金）に 2 サブ軸があり到達 Lv が $\{2, 1\}$ のとき、$A_5$ を求めよ。<br>（答え：$s=\{0.25, 0\}$、$A_5 = 0.125$）
3. **乗法との対比**：例題 7-1 の 8 軸スコアを、もし $\mathrm{ERS}' = 100\prod_k A_k^{1/8}$（幾何平均）で統合したらどうなるか。軸4・軸5 の $0.25$ が結果に与える影響を、加重和（50%）と比較して論ぜよ。
4. **二重計上**：「整備の進んだ機関発の PJ は AMD Score が高く出やすい」。にもかかわらず ERS を AMD Score の式に足してはいけない理由を、σ_SU（μ_I / μ_G）の経路に触れて説明せよ。

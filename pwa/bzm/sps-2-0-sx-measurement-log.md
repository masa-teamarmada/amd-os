# SX 実測記録 — 版を追って $q$ がどう動いたか

到達見込みモデルを実際のプロジェクト 1 件（SX）に当て、v0.2 から v0.5 まで版を四つ重ねた記録。見せたいのは数字そのものではない。数字が動いたとき、その理由を毎回言えた、という過程のほうである。

> **状態**：`measurement-log v0.5`（2026-08-08 時点）
>
> **主張の地位**：`hypothesis`（未検証の仮説）。予測と結果の答え合わせ（前向き検証）は未着手。ここに出てくる $q$ の値を投資判断・GO 判定に使わない。
>
> **一次資料**：`pwa/bzm/pilot/sps-2-0-sx-inputs-v0.5.json`（凍結入力）、`pwa/bzm/pilot/sps-2-0-sx-results-v0.5.json`（結果）、`pwa/bzm/pilot/simulate-sps-2-0-sx-v0.5.mjs`（計算コード）
>
> **関連**：[到達見込みモデル](./sps-2-0-reachability-model)、[測定可能性ゲート](./sps-2-0-measurability-gate)

## 1. 何を測ったか

対象は SX（p21）。ゴールは $G_{\mathrm{self}}(12\mathrm{m})$、前提とする支援は現行 AMD 支援の継続（BZSF の追加介入なし）、期限は 2031-03-31（情報カットオフ 2026-08-07 から 55.8 か月）。

計算はモンテカルロ法で行う。入力した確率と時間の幅に従って乱数を引き、起こりうる経路を 10,000 通り作り、そのうち何本が期限内にゴールへ着いたかを数える方法である。

工程の骨組みは、設立前に技術と事業の二本のレーンが並行し、設立後に Phase 1 → Phase 2 → Phase 3 が順に続く形。各工程には成功確率と、所要時間の三点見積り（最短・いちばん起こりやすい値・最長）を置く。資金は、各フェーズの初期資金と月次の純燃焼（ひと月に出ていくお金から入ってくるお金を引いた正味）で追いかける。

## 2. 版ごとの $q$ と、動いた理由

| 版 | $q$ | 何を直したか |
|---|---|---|
| v0.2 | 0.0131 | 初回。工程を確率のつながりとして結んだ最初の形 |
| v0.3 | 0.0016 | 資金の崖（Seed 期限を過ぎた経路の打ち切り）を導入 |
| v0.4 | 0.0335 | 時間入力の読み違いを訂正。設立手続きの直列 3 か月読みが誤りと判明 |
| v0.5 | 0.0415 | 月次の資金繰りを全フェーズへ広げ、感度ケースを 8 本に整備 |

この表の要点は、**四つの変化すべてに「誰の・何の情報で・どこを直したか」のタグが残っている**ことである。v0.1 が撤回されたのは、まさにこのタグが無かったからだった。

### v0.3 で $q$ が 8 分の 1 に落ちた理由

資金の崖を入れた版で、$q$ は 0.0131 から 0.0016 へ落ちた。きっかけはまさの一言だった。

> ５月までずれ込むことで確率が上がるのが変。だって３月までしか資金がないんだから、４月に着金できないなら、愛媛大で確保しているメンバーは解雇しないといけなくなるよ。

それまでのモデルは、Seed の着金が遅れた経路を「遅れたが生きている」として扱っていた。SX では、いまの活動を支えている公的支援（PSI ステップ 2）の予算が 2027 年 3 月で尽きるため、この扱いは誤りだった。遅れた経路の打ち切りを入れると、$q$ は激減した。

### v0.4 で $q$ が 20 倍に戻った理由

しかし v0.3 の 0.0016 は、まさの手応え（Seed 成立 70%）とかけ離れていた。どちらかが間違っている。原因が確率側にあるのか時間側にあるのかを切り分けるため、成功確率をすべて 100% に固定して時間だけを動かす計算を 20,000 通り回した（`pilot/analyze-sx-v0.3-founding-delay.mjs`）。結果、確率の壁をすべて取り払っても、期限内に設立まで着く経路は 4.2% しかなかった。誤りは時間側にある。

間違えていたのは、設立手続きの読み方だった。こちらは「Seed 合意のあとに始まる直列の 3 か月」と読んでいたが、実際の設立準備は投資家による調査（DD）や条件交渉と並行して進んでおり、合意のあとに残るのは最終確認と登記だけだった。そこで、まさの段取りの発言（12 月に DD 完了 → 1〜3 月に条件交渉と投資委員会 → 4 月着金）という別の情報源から時間を引き直し、設立手続きを 1.5 か月に、各工程の最悪の見積もりを「やり直し 1 回まで」に修正した。期限内に設立まで着く割合は 4.2% から 75.5% へ動き、まさの Seed 70% という手応えと合う位置に来た。

この訂正は、手応えに合うように数字をいじった結果合わせではない。段取りという別の情報源から時間を直したら、その結果として手応えと合った。この順序だったことを記録しておく。

## 3. v0.5 の結果

### 死因の内訳（10,000 回、基準ケース）

| 結末 | 割合 |
|---|---|
| 期限内に到達（成功） | 4.15% |
| 設立前に事業レーンで停止 | 27.14% |
| 技術レーンで停止 | 9.61% |
| Phase 1 の工程で停止 | 12.86% |
| Phase 1 で資金切れ | 6.22% |
| Phase 2 の工程で停止 | 17.80% |
| Phase 3 の工程で停止 | 4.13% |
| 全工程クリアしたが期限に間に合わず | 18.09% |

$q = 0.0415$。95% 信頼区間は 0.0378〜0.0456（10,000 回という試行回数からくる計算上のブレの幅。入力そのものの不確かさは、感度分析のほうで扱う）。

いちばん大きい死因は設立前の停止（27.14%）で、有償 PoC（お金をもらって行う実証）の口頭合意と、Seed 出資合意という事業側の二つのハードルがここに効いている。次いで期限切れ（18.09%）と Phase 2 停止（17.80%）。

### 期限を無視した到達率

計画期限の制約を外すと、いつかは到達する経路が 22.24% ある。まさの累積手応え（設立 63% → Phase 1 出口 50% → Phase 2 出口 30% → 自給 25%）の最終値 25% と、2.8 ポイントしか離れていない。

この 2.8 ポイントの差は、ほぼすべて Phase 1 の資金切れ（6.22%）で説明がつく。まさの手応えは「工程を越えられるか」の見立てであり、途中でお金が尽きて越えられなかった経路は入っていない。モデルはそれを別枠で数えている。つまり手応えとモデルが食い違っているのではなく、モデルのほうが、手応えに入っていない失敗の型を一つ余分に数えている。

### 到達までにかかる時間

期限内に到達した 415 本の経路がかかった時間は、中央値で 54.0 か月。速いほうから 5% の位置で 50.5 か月、95% の位置で 55.5 か月。期限の 55.8 か月に対して、ぎりぎりのところに詰まっている。

一方、期限を無視して全工程をクリアした 2,224 本では、中央値が 59.9 か月。**期限を 4 か月超えている。** つまり現行計画は、平均的な進み方では間に合わない。間に合うのは、運よく速く進んだ側の経路だけである。

## 4. 感度分析 — 資金の崖はどう効くか

| ケース | $q$ | 期限無視の到達率 | Phase 1 資金切れ |
|---|---|---|---|
| 基準 | 0.0415 | 22.24% | 6.22% |
| 手応え累積 +10pt | 0.0570 | 30.69% | 7.33% |
| 手応え累積 −10pt | 0.0283 | 13.51% | 4.45% |
| 所要時間 −25% | 0.2558 | 25.84% | 0.08% |
| 所要時間 +25% | 0.0000 | 13.63% | 22.59% |
| 純燃焼 +30% | 0.0330 | 11.53% | 25.95% |
| 計画期限 +6 か月 | 0.1464 | 22.13% | 6.22% |

読み取れることが三つある。

**計画期限を延ばしても、到達できる経路は増えない。** 期限を 6 か月延ばすと $q$ は 0.0415 から 0.1464 へ 3.5 倍になる。しかし期限を無視した到達率は 22.24% → 22.13% でほぼ動かない。期限の延長は新しい経路を生まず、もともと着いていた経路のうち「期限内」と数えられるものを増やしているだけである。資金切れの割合も 6.22% のまま動かない。崖の位置は、期限とは無関係だからである。

**速さは効き方が違う。** 所要時間が 25% 縮むと $q$ は 6 倍以上（0.2558）になり、資金切れは 6.22% から 0.08% へほぼ消える。速く進めば、資金が尽きる前に次の調達へ届くからである。逆に 25% 延びると資金切れは 22.59% へ跳ね、$q$ はゼロになる（10,000 回で 1 回も到達しない）。

**燃焼はいちばん直接に効く。** 純燃焼が 30% 増えると、資金切れは 25.95% と全ケース中最大になる。工程の難しさを何も変えていないのに、お金の減り方だけで 4 分の 1 の経路が死ぬ。

この三つが、[到達見込みモデル](./sps-2-0-reachability-model) 4 章の「本当の締切は資金の崖だけが作る」を数値で裏づけている。

## 5. 入力の出所構成（v0.4 時点）

| 出所 | 件数 | 割合 |
|---|---|---|
| 文書・実績（document） | 16 | 36% |
| 構造化ヒアリング（hearing） | 16 | 36% |
| 仮定（assumption） | 12 | 27% |

仮定のまま残っている主な入力は、Phase 1〜3 の所要時間の幅、各フェーズの燃焼レートの幅、Phase 3 の燃焼である。次の版で優先して文書由来へ置き換える対象が、ここに並んでいる。

## 6. この記録の限界

1. 対象がまだ 1 プロジェクトしかない。SX 以外に当てていないため、PJ どうしを比べたときに差をきちんと見分けられるかは分かっていない。
2. 前向き検証がゼロ件である。$q = 0.0415$ と実際の結末の答え合わせは一度もしていない。この値はいまのところ「定義に従って計算した数」であって、「当たると確かめられた予測」ではない。
3. 戦略余力のうちお金以外の成分を測れていない。中核人材が抜ける、顧客が離れる、他社に先を越される、といった理由で止まる経路を数えていないぶん、到達率は高めに出る。
4. 工程の成功確率はヒアリング由来で、答えたのはまさ一名である。別の人に聞く測り直しをしていない。
5. 感度分析は入力を一つずつ動かしただけである。工程が遅れて燃焼も増える、というような同時に悪くなる組み合わせは見ていない。

## 7. 次に検証すること

- 戦略余力のうちお金以外の成分を、欠測のまま置くか v0.6 で復活させるかを決める。復活させるなら、「あと何か月分あるか」への換算の手順を書く必要がある。
- 仮定のまま残っている Phase 1〜3 の所要時間と燃焼レートを、まさが作る予定の月次数値計画で文書由来へ置き換える。
- 手応えを聞くときの決まり「工程ごとに、何と並行して進み、何が終わってから始まるかを確かめる」を、測定可能性ゲートの証拠パッケージ表へ追記する。
- 2 件目のプロジェクトへの適用。$q$ がどの PJ でも低く出て、比べたときの差が見分けにくくならないかを点検する。

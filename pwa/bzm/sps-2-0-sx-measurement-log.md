# SX 実測記録 — 版を追って $q$ がどう動いたか

到達見込みモデルを実際のプロジェクト 1 件（SX）に当て、v0.2 から v0.5 まで四度改訂した記録。**数字そのものより、数字が動いた理由を追跡できることを示すのが目的**の章。

> **状態**：`measurement-log v0.5`（2026-08-08 時点）
>
> **主張の地位**：`hypothesis`。前向き検証は未着手。ここに出てくる $q$ の値を投資判断・GO 判定に使わない。
>
> **一次資料**：`pwa/bzm/pilot/sps-2-0-sx-inputs-v0.5.json`（凍結入力）、`pwa/bzm/pilot/sps-2-0-sx-results-v0.5.json`（結果）、`pwa/bzm/pilot/simulate-sps-2-0-sx-v0.5.mjs`（計算コード）

## 1. 何を測ったか

対象は SX（p21）。到達目標は $G_{\mathrm{self}}(12\mathrm{m})$、政策は現行 AMD 支援の継続（BZSF の追加介入なし）、期限は 2031-03-31（情報カットオフ 2026-08-07 から 55.8 か月）。計算はモンテカルロで 10,000 回。

工程は技術レーンと事業レーンの二本が並行し、設立後に Phase 1 → Phase 2 → Phase 3 と直列に続く。各工程に成功確率と所要時間の三点見積り（最短・最頻・最長）を置き、資金は各フェーズの初期資金と月次純燃焼で追跡する。

## 2. 版ごとの $q$ と、動いた理由

| 版 | $q$ | 何を直したか |
|---|---|---|
| v0.2 | 0.0131 | 初回。工程を確率ノードで結んだ最初の形 |
| v0.3 | 0.0016 | 資金の崖（Seed 期限を過ぎた経路の打ち切り）を導入 |
| v0.4 | 0.0335 | **時間入力の誤読を訂正**。設立手続きの直列 3 か月読みが誤りと判明 |
| v0.5 | 0.0415 | 月次資金繰りを全フェーズへ拡張し、感度ケースを 8 本に整備 |

この表の要点は、**四つの変化すべてに「誰の・何の情報で・どこを直したか」のタグが残っている**ことである。v0.1 が撤回されたのは、まさにこのタグが無かったからだった。

### v0.3 で $q$ が 8 分の 1 に落ちた理由

資金の崖を入れた版で $q$ が 0.0131 から 0.0016 へ落ちた。原因はまさの一言だった。

> ５月までずれ込むことで確率が上がるのが変。だって３月までしか資金がないんだから、４月に着金できないなら、愛媛大で確保しているメンバーは解雇しないといけなくなるよ。

それまでのモデルは、Seed 着金が遅れた経路を「遅れたが生きている」として扱っていた。SX では PSI ステップ 2 の予算が 2027 年 3 月で尽きるため、この扱いは誤りだった。打ち切りを入れると $q$ は激減した。

### v0.4 で $q$ が 20 倍に戻った理由

しかし v0.3 の 0.0016 は、まさの手応え（Seed 成立 70%）と整合しなかった。そこで**確率をすべて成功に固定し、時計だけを 20,000 本回す**分解分析を行った（`pilot/analyze-sx-v0.3-founding-delay.mjs`）。すると、確率がすべて成功でも期限内に設立できる経路が 4.2% しかないと分かった。時間側に誤りがある。

誤りは設立手続きの読み方だった。こちらは Seed 合意の**後に始まる**直列 3 か月と読んでいたが、実際には DD・条件交渉と並行して進む準備であり、Seed 合意後に残るのは最終確認と登記だけだった。まさの段取り発言（12 月に DD 完了 → 1〜3 月に条件交渉と投資委員会 → 4 月着金）から独立に較正し直し、設立手続きを 1.5 か月へ、各工程の悲観側の尾を再試行 1 回までへ絞った。期限内設立率は 4.2% から 75.5% へ動き、これがまさの Seed 70% と整合した。

**この訂正は結果合わせではない。** 段取り発言という別の情報源から時間を較正し、その帰結として手応えと合った、という順序だったことを記録しておく。

## 3. v0.5 の結果

### 死因の内訳（10,000 回、基準ケース）

| 結末 | 割合 |
|---|---|
| 期限内に到達（成功） | 4.15% |
| 設立前に事業レーンで停止 | 27.14% |
| 技術レーンで停止 | 9.61% |
| Phase 1 の工程で停止 | 12.86% |
| **Phase 1 で資金切れ** | **6.22%** |
| Phase 2 の工程で停止 | 17.80% |
| Phase 3 の工程で停止 | 4.13% |
| 全工程クリアしたが期限に間に合わず | 18.09% |

$q = 0.0415$（95% 信頼区間 0.0378〜0.0456）。

いちばん大きい死因は設立前の停止（27.14%）で、有償 PoC の口頭合意と Seed 出資合意という事業側の二つのハードルがここに効いている。次いで期限切れ（18.09%）と Phase 2 停止（17.80%）。

### 期限を無視した到達率

計画期限の制約を外すと、いつかは到達する経路が 22.24% ある。まさの累積手応え（設立 63% → Phase 1 出口 50% → Phase 2 出口 30% → 自給 25%）の最終値 25% と、2.8 ポイントしか離れていない。

この差 2.8 ポイントの正体は**ほぼすべて Phase 1 の資金切れ 6.22%** で説明できる。まさの手応えは工程が越えられるかどうかについての見立てであり、途中で金が尽きて越えられなかった経路は含んでいない。モデルはそれを別枠で数えている。手応えとモデルが食い違っているのではなく、**モデルが手応えに入っていない失敗の型を一つ追加している**、という関係になっている。

### 到達までにかかる時間

期限内に到達した経路（415 本）は、中央値 54.0 か月、5 パーセンタイル 50.5、95 パーセンタイル 55.5。期限 55.8 か月に対してぎりぎり詰まっている。

一方、期限を無視して全工程をクリアした経路（2,224 本）は中央値 59.9 か月、95 パーセンタイル 67.8。**中央値が期限を 4 か月超えている。** 現行計画は、平均的な進み方では間に合わない設計になっている。間に合う経路は速い側の裾に限られる。

## 4. 感度分析 — 資金の崖はどう効くか

| ケース | $q$ | 期限無視の到達率 | Phase 1 資金切れ |
|---|---|---|---|
| 基準 | 0.0415 | 22.24% | 6.22% |
| 手応え累積 +10pt | 0.0570 | 30.69% | 7.33% |
| 手応え累積 −10pt | 0.0283 | 13.51% | 4.45% |
| 所要時間 −25% | 0.2558 | 25.84% | **0.08%** |
| 所要時間 +25% | **0.0000** | 13.63% | **22.59%** |
| 純燃焼 +30% | 0.0330 | 11.53% | **25.95%** |
| 計画期限 +6 か月 | 0.1464 | **22.13%** | 6.22% |

読み取れることが三つある。

**計画期限を延ばしても、到達率は増えない。** +6 か月で $q$ は 0.0415 → 0.1464 と 3.5 倍になるが、期限を無視した到達率は 22.24% → 22.13% でほぼ動かない。期限の延長は新しい経路を生まず、**もともと着いていた経路のうち期限内と数えられるものを増やしているだけ**である。資金切れの割合も 6.22% のまま動かない。崖の位置は期限とは無関係だからである。

**速さは効き方が違う。** 所要時間 −25% では $q$ が 6 倍以上（0.2558）になり、資金切れは 6.22% から 0.08% へ消える。速く進めば資金が尽きる前に次の調達へ届く。逆に +25% では資金切れが 22.59% へ跳ね、$q$ はゼロになる（10,000 回で 1 回も到達しない）。

**燃焼は最も直接に効く。** 純燃焼 +30% で資金切れが 25.95% と全ケース中最大になる。工程の難しさを何も変えずに、金の減り方だけで 4 分の 1 の経路が死ぬ。

この三つが、[到達見込みモデル](./sps-2-0-reachability-model) 4 章の「本当の締切は資金の崖だけが作る」を数値で裏づけている。

## 5. 入力の出所構成（v0.4 時点）

| 出所 | 件数 | 割合 |
|---|---|---|
| 文書・実績（document） | 16 | 36% |
| 構造化ヒアリング（hearing） | 16 | 36% |

仮定として残っているものの主なもの：Phase 1〜3 の所要時間幅、各フェーズの燃焼レート幅、Phase 3 の燃焼。次の版で優先的に置き換える対象がここに明示されている。

## 6. この記録の限界

1. **1 プロジェクト 1 サンプル**。SX 以外へ当てていない。プロジェクト間比較の分解能はまだ不明。
2. **前向き検証がゼロ件**。$q = 0.0415$ が現実とどう対応するかの答え合わせは一度もしていない。この値は現時点で「定義に従って計算した数」であって、「当たると確かめられた予測」ではない。
3. **戦略余力の非資金成分が欠測**。中核人材の離脱、顧客の離反、他社の先行で止まる経路が数えられていないため、到達率は過大評価側に偏る。
4. **工程確率はヒアリング由来**。評価者はまさ一名で、複数評価者での再測定をしていない。
5. **感度は一入力ずつの単独変動**。複数入力が同時に悪化する現実的な組み合わせは見ていない。

---

## 7. 次に検証すること

- 戦略余力の非資金成分を、欠測のまま置くか v0.6 で復活させるかの決定。復活させるなら「何か月分あるか」への翻訳規則を書く必要がある。
- 仮定として残っている Phase 1〜3 の所要時間とバーンレートを、月次数値計画（まさが作成予定）で文書由来へ置き換える。
- 手応えを聞く際の規律「工程ごとに何と並行し何の後に来るかを明示する」を、測定可能性ゲートの証拠パッケージ表へ追記する。
- 2 件目のプロジェクトへの適用。$q$ の分布が全体に低い側へ寄って比較の分解能が落ちないかを点検する。

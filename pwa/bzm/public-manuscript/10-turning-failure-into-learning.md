# Chapter 10: 関係を壊さず、学習に変える

投資家面談の翌週、関係者の空気は重かった。

研究者は、技術の説明を否定されたように感じていた。大学の担当者は、知財の整理が遅いと言われたように受け取っていた。支援者は、準備不足を突かれたと思っていた。外部経営人材候補は、チームが弱いという言葉を、自分への期待として聞いていた。

面談で実際に言われたのは、もっと短い言葉だった。

「顧客の切実さがまだ見えません」
「誰が会社を動かすのか、もう少し知りたいです」
「資金で何が分かるのかが曖昧です」

それだけである。

しかし、Before Zero の現場では、短い反応が大きな感情になる。

誰が悪かったのか。研究者に覚悟が足りなかったのか。大学の確認が遅かったのか。企業が本気ではなかったのか。投資家が厳しすぎたのか。支援者の進め方が悪かったのか。

責任を考えることが必要な場面もある。だが、失敗や停滞を毎回責任論だけで読むと、次の現場に何も残らない。

関係が壊れる前に、出来事を仮説更新へ戻す。

それが、Before Zero の学習である。

## 失敗を一つの言葉で片づけない

「企業に刺さらなかった」

この一言だけでは、次に何を変えればよいか分からない。

企業の課題が浅かったのか。話した相手が意思決定者ではなかったのか。検証条件が重すぎたのか。開示できる情報が少なすぎたのか。用途仮説が相手の現場とずれていたのか。価格や導入時期が合わなかったのか。相手にとっては興味深いが、いま動く理由がなかったのか。

「投資家に評価されなかった」も同じである。

市場が弱いのか。チームが弱いのか。技術が早すぎるのか。知財が不安なのか。資金使途が曖昧なのか。研究者と経営人材の役割分担が見えないのか。投資家の投資領域と合わなかっただけなのか。

失敗を一つの言葉にまとめると、感情は整理されたように見える。だが、学習は粗くなる。

Before Zero では、うまくいかなかった出来事を分解する。

何を正しいと思っていたのか。実際に何が起きたのか。どの信号を見落としたのか。どの問いへ修正するのか。

## 記入済みの学習ログ

失敗から学ぶには、空欄のテンプレートより、記入済みのログを見る方が早い。

たとえば、企業ヒアリングが止まったケースなら、次のように残せる。

| 欄 | 記入例 |
|---|---|
| 起きたこと | 大企業の探索部門は強い関心を示したが、二回目の面談後に検証条件が出てこなかった。 |
| 当初の仮説 | その企業は製造工程の検査に困っており、技術の性能を見ればPoCへ進むはずだった。 |
| 実際の観測 | 探索部門は面白いと言ったが、現場部署は同席していなかった。既存手段のどの限界が痛いのか、相手の言葉では出ていなかった。 |
| 見落とした信号 | 初回面談で、評価指標、予算主体、意思決定者を聞けていなかった。相手の「面白い」を顧客課題の証明として扱っていた。 |
| 修正した問い | 次回は、現場の困りごと、既存手段の限界、検証条件、PoC後の判断者を分けて聞く。探索部門だけでなく現場部署を入れてもらう。 |
| 次回の赤信号 | 企業名は強いが、相手が自分の課題を語らず、検証条件も出さない状態。 |

投資家面談で厳しい反応を受けたケースなら、こうなる。

| 欄 | 記入例 |
|---|---|
| 起きたこと | 投資家から「チームと資金使途がまだ弱い」と言われた。 |
| 当初の仮説 | 技術の強さと企業候補の関心が伝われば、初期資金の議論に進めるはずだった。 |
| 実際の観測 | 投資家は技術に興味を示したが、誰が顧客開拓、採用、資本政策、管理実務を持つのかを繰り返し聞いた。資金使途も費目中心だった。 |
| 見落とした信号 | 前章の責任分担表で空白だった経営実務を、面談前に埋めていなかった。資金で下げる不確実性を言語化していなかった。 |
| 修正した問い | 次の面談前に、研究者が担う機能、外部人材が担う機能、支援者が暫定で補う機能を一枚にする。資金使途を不確実性の低下として書き換える。 |
| 次回の赤信号 | 代表名だけがあり、実際に会社を動かす機能が空いている状態。 |

外部経営人材候補が合わなかったケースなら、こう残せる。

| 欄 | 記入例 |
|---|---|
| 起きたこと | 経営経験のある候補者を紹介したが、研究者との対話が深まらず、研究者が距離を取った。 |
| 当初の仮説 | 経営経験があり、資金調達にも詳しい人なら、CEO機能の空白を埋められるはずだった。 |
| 実際の観測 | 候補者は市場と資本の話は強かったが、研究者の技術観や守りたい線を十分に聞かなかった。研究者には、研究が奪われるように見えた。 |
| 見落とした信号 | 経歴だけを見て、技術理解、研究者との信頼形成、大学制約への理解を確認していなかった。 |
| 修正した問い | 経営人材候補を見るときは、時間投入、技術理解、研究者との対話姿勢、大学や研究機関の制約への尊重を先に確認する。 |
| 次回の赤信号 | 肩書きは強いが、研究者の言葉を翻訳せず、市場の言葉だけで進めようとする人。 |

こうして書くと、失敗は誰かの人格や覚悟の問題だけではなくなる。

どの仮説が外れ、どの観測を見落とし、次にどの問いを置くべきかが見える。

## 研究者との関係を守る

Before Zero の学習で、最初に守るべき関係は研究者との関係である。

研究者にとって、研究成果は単なる案件ではない。長い時間をかけて育ててきた問いであり、研究室、学生、共同研究者、論文、次の研究費にもつながっている。

事業化が停滞したとき、研究者の覚悟不足として扱うのは簡単である。

「もっと起業家らしく動いてほしい」
「顧客に会う回数が足りない」
「経営者を外から入れるしかない」

そう言いたくなる場面もある。

だが、その前に見るべきことがある。

研究者は何を守ろうとしていたのか。研究者に、担うべきではない機能まで乗せていなかったか。外部から見た会社化の期待が、研究者の研究継続や論文計画を脅かしていなかったか。支援者ごとに違う役割を求めていなかったか。

研究者との関係を守るとは、研究者の希望をすべて優先することではない。

研究者を責める前に、役割、開示、時間、経営機能、大学側の土台を一緒に見直すことである。

## 大学や研究機関との関係を守る

会社化が進まないと、大学や研究機関が遅いように見えることがある。

知財の確認に時間がかかる。契約の手続きが重い。利益相反の整理が必要になる。研究者の兼業や会社関与の条件がすぐに決まらない。

市場や投資家の時計から見ると、もどかしい。

しかし、大学や研究機関は、長期の信頼を背負っている。研究成果、学生、共同研究、公共性、研究者のキャリア、組織としての説明責任を同時に見ている。

だから、大学側を単に障害物として扱うと、関係は壊れる。

停滞を学習に変えるには、大学側の制約を早く地図に入れる。

出願の順番は何か。共同研究先との関係はどうなっているか。研究者の会社関与はどの条件なら可能か。利益相反の確認はいつ必要か。研究継続に必要な環境は何か。大学内の誰が判断者で、誰が支援者なのか。

大学の時計を読むことは、会社化を遅くするためではない。

会社化後に、研究成果が根を失わないようにするためである。

## 企業や投資家との関係を残す

企業や投資家との会話がうまくいかないときも、相手を悪者にしない方がよい。

企業が「面白い」と言ったのに進まなかった。そのとき、企業が本気ではなかったと決めつける前に、何が足りなかったかを見る。

相手の課題は本当に切実だったのか。検証条件を出せる部署だったのか。予算化までの道筋は見えていたのか。こちらの開示が少なすぎて判断できなかったのか。逆に、相手に重すぎる検証を求めていなかったか。

投資家も同じである。

投資家の質問が厳しかったとしても、それは研究成果の価値を全否定しているとは限らない。チーム、資金使途、顧客仮説、知財、タイミングのどこかが、投資可能な形にまだなっていないという信号かもしれない。

関係を残すには、相手の反応を次の設計に変える。

企業には、次回どの情報があれば検証条件を出せるかを聞く。投資家には、いま一番大きく見えている不確実性を確認する。相手の反応を、怒りや落胆ではなく、次に下げるべき不確実性として受け取る。

そうすれば、今回進まなくても、関係は次の接点として残る。

## 支援者自身も学習する

支援者は、研究者や大学や投資家を評価するだけの立場ではない。

支援者自身の仮説も外れる。

この企業なら顧客になりそうだと思ったが、実際には探索部門で止まった。研究者がピッチを磨けば進むと思ったが、実際には経営機能の空白が問題だった。会社化を待てばよいと思ったが、CEO候補や企業候補のタイミングを逃した。外部CEOを入れればよいと思ったが、研究者との信頼形成を軽く見ていた。

支援者が自分の仮説外れを認められないと、失敗は他人の問題になる。

逆に、支援者が自分の見立てを更新できれば、現場は少しずつ強くなる。

次はどの問いを早く置くべきか。どの順番を間違えたか。どの関係者を早く入れるべきだったか。どの赤信号を見逃したか。どの活動を増やしたのに、本当の低い条件へ資源が向いていなかったか。

支援者の学習は、次の研究者を守る。

## 学習ログを閉じずに残す

学習は、きれいな成功談として残す必要はない。

むしろ、次の現場で使える形にする。

- 起きたこと
- 当初の仮説
- 実際の観測
- 見落とした信号
- 修正した問い
- 次回の赤信号

この形で残すと、個別の出来事が、再利用できるレンズになる。

ただし、学習ログは個人を晒すための記録ではない。研究者や企業や投資家を評価するためのメモでもない。次に同じ構造が現れたとき、少し早く気づくための記録である。

学習を残すと、見えてくるものがある。

失敗は、技術だけで起きていない。顧客、知財、経営機能、資金、制度、社会受容、人材、マクロの追い風。さまざまな条件が少しずつずれて、停滞として現れる。

このずれを繰り返し読むためには、個別の出来事を、後半の理論で扱う要素へ少しずつ翻訳していく必要がある。

## 会議を閉じる前に残すもの

うまくいかなかった面談、停滞した会社化、壊れそうな関係があるとき、会議の最後に一つだけ選ぶ。

今日の出来事を、責任論で閉じるのか。学習ログとして残すのか。

学習ログとして残すなら、当初の仮説、実際の観測、見落とした信号、修正した問い、次回の赤信号を書く。関係者の名前を強く残すより、構造を残す。次の現場で使える問いに変える。

それだけで、失敗は少し違うものになる。

まだ残る不安もある。

学習ログを積み上げても、現場には毎回別の条件がある。ある案件では政策が先行し、別の案件では企業が先行し、また別の案件では研究だけが強い。失敗から学ぶには、目の前の関係だけでなく、外側の追い風がどの条件を支えていて、どの条件を支えていないかも読まなければならない。

だから次の章では、マクロの追い風を熱量としてではなく、政策、産業、研究、資本、社会の位相差として読む。失敗のログは、外の風を読む地図へつながっていく。

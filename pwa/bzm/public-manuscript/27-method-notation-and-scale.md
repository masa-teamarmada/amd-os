# Method Appendix M1 — 記号と尺度

この補遺では、本文で出てきた準備度や追い風を、同じ紙の上で扱えるようにするための表記を置く。

多くの軸は、0から9までの尺度で読む。0は価値がないという意味ではない。まだ現場で確認されていない、または次の判断に使えるほどには整理されていない、という意味に近い。9は完成ではない。少なくともその時点の判断に使える程度には、条件が見えているという意味である。

式の中では、軸の値に1を足すことがある。

これは、どこか一つの軸が0に近いとき、その軸を無視して全体を強く見せないための工夫である。同時に、0を掛けて全体を完全に消してしまわないための工夫でもある。

この補遺では、観測、解釈、判断を分けて読む。

観測は、会議で実際に見えたもの。予算者がいなかった、支払いが断られた、開示前の文が強すぎた、九十日メモに空欄が残った、という事実である。

解釈は、その観測がどの条件を弱く見せているかを読むこと。

判断は、その読みから、GO、WAIT、HOLD、NO_GO、RESOURCE_SHIFTのどれに近い動きを選ぶかである。

式は、この三つを混ぜないために使う。

この補遺でよく使う記号は、次のように読む。

- `X_i`: ある一つの軸の値
- `alpha_i`: その軸をどれくらい重く見るか
- `K`: 全体の尺度を整える定数
- `S`: 統合された準備度
- `s`: 研究機関側の小さな評価単位
- `A_k`: 研究機関側の一つの軸の平均

ここで気をつけたいのは、記号が増えたからといって、現場が正確になったわけではないことだ。

予算者がいないこと、開示前の文が強すぎること、外部候補が弱い事実を強く言い直してしまうこと。そういう観測を、どの軸に置くかは人間の判断である。式は、その判断を会議で検証しやすくする。

つまり、モデルに入れる前の問いが大事になる。

それは、「この値はいくつか」ではなく、「この値を置いた理由を、次の会議で誰が説明できるか」である。

## 共通の尺度

本文と補遺では、個別案件の軸を原則として0から9で読む。

| 値 | 読み方 |
|---|---|
| 0 | 未確認、未着手、または次の判断に使える証拠がない |
| 1〜3 | 初期。仮説や入口はあるが、まだ判断を支えるには弱い |
| 4〜6 | 中期。会議で使える証拠が出始めている |
| 7〜9 | 高い。少なくとも次の九十日を進める根拠として説明できる |

研究機関側のERSだけは、サブ軸をLv1からLv5で読む。Lv1は制度や導線がほぼない状態、Lv3は標準的な運用がある状態、Lv5は複数案件で再現可能な運用実績がある状態である。

## `+1` シフト

統合式では、各軸をそのまま掛けず、`X_i + 1` として扱う。

これは二つの理由がある。

一つ目は、ゼロ落ちを避けるためである。どこか一つの軸が0だからといって、研究成果の価値や他の条件まで消してはいけない。基礎研究の段階でも、学術側の勢いや政策の追い風が意味を持つことはある。

二つ目は、低い軸を隠さないためである。`+1` しても、0の軸は `1` としてしか効かない。つまり、全体を完全には消さないが、強く見せることもない。

この操作は、本文で何度も出てきた「弱い事実を弱いまま残す」態度に近い。

## よく使う記号

| 記号 | 意味 | 主な登場場所 |
|---|---|---|
| `M` | マクロ整合。`sigma_SU` から作る追い風のまとまり | M2 / M5 |
| `X` | 五つの準備度のまとまり。TRL / BRL / GRL / SRL / HRL | M3 / M5 |
| `F` | 創業者機能。F_character と F_capability の配置 | M4 / M5 |
| `S` | 統合準備度。`M×X×F` の総合地図 | M5 |
| `alpha_i` | 軸 `i` の重み、または弾力性 | M3 / M5 |
| `K` / `k` | スケールを整える定数 | M5 |
| `s` | ERSのサブ軸スコア | M7 |
| `A_k` | ERSの軸スコア | M7 |

この表は、暗記するためのものではない。

会議で「どの紙を見ているのか」を迷わないための目印である。

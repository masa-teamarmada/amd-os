# Toolkit B: 判断と開示の道具箱

この章は、本文を読み終えたあとに会議へ持ち込む道具箱である。空のテンプレートではなく、まず記入済み例を見て、必要な部分だけ自分の現場に移す。

Before Zero の会議では、結論を急ぐほど、言葉が雑になる。

「進めましょう」
「まだ早いですね」
「いったん保留で」
「投資家に聞いてみましょう」
「企業に当ててみましょう」

どれも必要な言葉である。だが、その場を閉じるには足りない。

進めるなら、何を根拠に進めるのか。待つなら、待っている間に何をするのか。保留なら、いつ戻るのか。投資家に聞くなら、どの不確実性を照らしてもらうのか。企業に当てるなら、何を開示してよいのか。

## decision record

最初の道具は、判断記録である。

会議で GO、WAIT、HOLD、NO_GO、RESOURCE_SHIFT のどれかを使うなら、必ず次の五つを書く。

| 項目 | 書くこと |
|---|---|
| 判断 | GO / WAIT / HOLD / NO_GO / RESOURCE_SHIFT |
| 根拠 | 何が確認できたから、その判断にしたか |
| 低い軸 | 技術、事業、制度、社会、人材、創業者機能、追い風のどこが低いか |
| 次の行動 | 誰が、いつまでに、何をするか |
| 戻る条件 | 何が確認できたら、判断を見直すか |

記入例はこうなる。

| 項目 | 記入例 |
|---|---|
| 判断 | WAIT |
| 根拠 | 技術は研究室内で強いが、企業の評価者と予算者が未確認。出願前資料の開示線も未整理 |
| 低い軸 | 事業、制度・ガバナンス |
| 次の行動 | 若い事業化人材が企業側の評価者を確認。産学連携担当者が資料を三層に分ける |
| 戻る条件 | 評価条件と開示範囲が揃ったら、投資家面談の準備へ進む |

WAIT は止まることではない。戻る条件を持った作業である。

もう一つ、RESOURCE_SHIFTの記入例も置く。

| 項目 | 記入例 |
|---|---|
| 判断 | RESOURCE_SHIFT |
| 根拠 | 研究、政策、公募の追い風は強いが、企業の予算者、現場負荷、開示範囲が低い |
| 低い軸 | 事業、社会受容、制度・ガバナンス |
| 次の行動 | 投資家紹介二件を延期し、企業の評価者・予算者確認、病院の技師ヒアリング、開示表更新に集中する |
| 戻る条件 | 90日後、評価枠、現場負荷、開示安全性が表になったらGO候補として再判断する |

## disclosure map

二つ目の道具は、開示地図である。

資料を外へ出す前に、ページごと、図ごと、言葉ごとに分ける。

| 区分 | 使える場 | 例 |
|---|---|---|
| 公開情報 | 発表、初回面談、一般説明 | 公開済み論文、一般的な課題、既存技術の限界 |
| 限定開示 | 相手、目的、管理条件を絞った場 | 未公開データの一部、検証条件、相手現場に合わせた仮説 |
| まだ出さない | 出願、論文、契約、研究者合意が未整理のもの | 中核図、共同研究先由来情報、強すぎる用途表現 |

大事なのは、資料そのものだけではない。

誰が話すかも決める。研究者が言う言葉、支援者が言う言葉、若い事業化人材が言う言葉、投資家向けに言う言葉は同じではない。

| 相手 | 話してよいこと | 話さないこと | 次に聞くこと |
|---|---|---|---|
| 企業探索担当 | 公開情報、課題仮説 | 出願前の中核図 | 現場評価者につなげるか |
| 企業評価者 | 検証条件の仮説 | 共同研究先由来の未整理情報 | 何が出れば検証に進むか |
| 投資家 | 不確実性と資金で下げること | 技術の詳細条件 | どの未整理が投資判断を止めるか |
| 支援制度 | 社会課題、検証計画 | 赤の情報 | 公募で下げられる不確実性は何か |

開示地図があると、外に出ることは事故ではなく設計になる。

記入済みの開示地図は、たとえばこうなる。

| ページ / 言葉 | 色 | 誰が話せるか | 話してよい相手 | 話さないこと |
|---|---|---|---|---|
| 公開済み論文の概要 | 青 | 研究者、支援者 | 初回面談、支援制度、投資家 | 出願前の中核図に踏み込まない |
| 企業の現場仮説 | 黄 | 支援者、若い事業化人材 | NDA後の評価者、限定された企業チーム | 顧客確定や導入約束のように言わない |
| 出願前データ | 赤 | 原則話さない | まだ出さない | スライド、メール、口頭説明に入れない |

## customer signal ladder

三つ目の道具は、顧客信号の階段である。

「面白いですね」を、いきなり顧客検証にしない。

| 段階 | 相手の行動 | まだ足りないこと |
|---|---|---|
| 関心 | 詳しく聞きたいと言う | 課題、予算、評価条件 |
| 課題共有 | 困りごとを自分の言葉で話す | 検証条件、責任者 |
| 評価条件 | 何を見ればよいかを出す | 予算、導入判断者 |
| 資源提供 | 現場、データ、時間、費用を出す | 契約、次の判断 |
| 継続判断 | PoC後の次アクションを決める | 導入条件、支払い、社内展開 |

顧客信号を見るときは、相手の言葉より行動を見る。

誰が時間を出したか。誰がデータを出したか。誰が評価条件を出したか。誰が社内の次の人につないだか。誰が予算の話を始めたか。

この階段があると、企業ロゴの数より、事業の準備度が見える。

記入例はこうである。

| 企業反応 | 階段上の位置 | 次の一手 |
|---|---|---|
| 探索担当が「面白い」と言った | 関心 | 評価者、予算者、現場部門へつなげるか聞く |
| 技術評価者が既存手段の限界を話した | 課題共有 | 何を満たせば検証に進むかを聞く |
| 予算者が来期評価枠の条件を出した | 評価条件 | 必要データ、費用、契約、判断日を確認する |

## role map

四つ目の道具は、役割地図である。

| 機能 | 研究者 | 若い事業化人材 | 大学・研究機関 | 外部人材 | 支援者 |
|---|---|---|---|---|---|
| 技術の意味 | 中心 | 学ぶ | 支える | 学ぶ | 言語化補助 |
| 顧客課題 | 同席 | 主担当候補 | 接続支援 | 担える | 設計補助 |
| 開示・知財 | 守る線を出す | 記録 | 主担当 | 理解必須 | 確認補助 |
| 資金で下げる不確実性 | 技術面 | 整理 | 制度資金 | 設計可能 | 翻訳 |
| 毎週の統合判断 | 持ちすぎ注意 | 補助可能 | 会議体設計 | 候補 | 暫定補助 |

空欄があること自体は悪くない。

危ないのは、空欄なのに、肩書きや熱意で埋まったことにすることである。

最後に、外部経営候補を見るときの小さな記入例を置く。

| 確認項目 | 記入例 |
|---|---|
| 補う機能 | 資金調達、企業交渉、採用、毎週の統合判断 |
| 研究者の守る線 | 出願前の中核図を投資家向けに滑らかに言い換えない |
| repeat-back | 研究者の言葉で「まだ言えないこと」を復唱できた |
| まだ未確認 | 週次の実務時間、大学手続きへの理解、悪い知らせの扱い |

## 道具は、会議の最後に使う

これらの道具は、きれいな資料を作るためにあるのではない。

会議の最後に、結論が少し強すぎると感じたときに使う。

「GOと言っていますが、低い軸はどこですか」
「WAITなら、誰が何をして戻りますか」
「この資料は、どの色で外へ出しますか」
「その企業反応は、顧客信号の何段目ですか」
「この機能は、誰が毎週持ちますか」

問いが一つ増えるだけで、研究者に流れ込む負荷は減る。支援者の善意も、企業の関心も、投資家の問いも、次の行動へ変わる。

道具箱は、答えを出すためではなく、粗い答えで止まらないためにある。

# Chapter 20: 外れた地図を、証拠ルールから直す

三か月後、会議室には前より重い空気があった。

支援制度の面接は通った。開示資料も三層に分けた。若い事業化人材は企業と病院に聞き取りを始めた。外部経営候補も、研究者との面談を重ねた。

それでも、計画どおりには進まなかった。

企業の探索担当は前向きだったが、事業部の予算者は「今年度は評価枠がない」と言った。病院の医師は協力的だったが、技師の作業負荷が想定より重かった。外部経営候補は研究者の慎重さを尊重しようとしたが、投資家向けの言葉に直すところで、また少し研究者の信頼を削った。

失敗ではない。だが、地図は外れた。

ここで必要なのは、誰が悪かったかを探すことではない。どの証拠を強く読みすぎたのか、次から証拠ルールをどう変えるのかである。

## 古い証拠ルールが失敗する

最初の地図では、いくつかの証拠を楽観的に読んでいた。

| 古い証拠ルール | 今回起きたこと | 何が足りなかったか |
|---|---|---|
| 企業の探索担当が前向きなら、事業の準備度は上がる | 予算者は評価枠を持っていなかった | 評価者、予算者、導入責任者を分けていなかった |
| 病院の医師が協力的なら、現場PoCは近い | 技師の作業負荷と倫理手続きが重かった | 医師以外の受け手を早く聞いていなかった |
| 開示資料を三層に分ければ安全に進む | 投資家向け要約で研究者の守る線が揺れた | 資料だけでなく、誰がどう話すかのルールが足りなかった |
| 経営経験者が入れば創業者機能が上がる | 研究者との信頼形成に時間がかかった | 経験より先に、技術への敬意と透明性を見ていなかった |
| 公募採択で追い風が確定する | 資金はついたが、低い軸は残った | 資金で下げる不確実性を継続管理していなかった |

この表が、retrofitの入口である。

結果が見えたあとで、当時の判断地図に戻る。何を証拠だと思い、何を見落とし、どの軸を高く読みすぎたかを確認する。

## 新しい証拠ルールを書く

地図を直すとは、「次は気をつけよう」と言うことではない。証拠ルールを書き換えることである。

| 新しい証拠ルール | 次から必要な証拠 |
|---|---|
| 企業関心は、探索担当、評価者、予算者、導入責任者を分ける | 四者のうち誰が確認済みかを表にする |
| 医療現場の受容は、医師、技師、倫理窓口、患者説明を分ける | 少なくとも技師の作業負荷と倫理審査の入口を聞く |
| 開示安全性は、資料分類だけでなく話者ルールを含める | 誰がどの相手に何を言わないかを決める |
| 外部経営候補は、実績より前に信頼形成条件を見る | 研究者の守る線を復唱できるかを確認する |
| 資金採択は、進捗証拠ではなく検証機会として扱う | 資金で下げる軸と戻る条件を毎月更新する |

後半の理論では、このように過去へ地図を当て直すことをretrofitと呼び、直した地図が次の現場で機能するかを確かめることをvalidationと呼ぶ。

だが、ここでも大事なのは言葉ではない。

大事なのは、外れたときにモデルを守るのではなく、モデルを直すことである。

## field noteを、使える問いに変える

この章で扱う学習は、失敗談を残すことではない。現場で起きたことを、次の人が使える問いに変えることである。

若い事業化人材は、次のようなfield noteを残した。

| 記録項目 | 記入内容 |
|---|---|
| 起きたこと | 企業探索担当は前向きだったが、予算者は今年度評価枠なし |
| 当時の仮説 | 企業関心があれば、PoC条件を詰められる |
| 見落とし | 探索担当と予算者を分けていなかった |
| 修正した問い | 「誰が面白いと言ったか」ではなく「誰が評価枠を持つか」を聞く |
| 公開できる形 | 企業関心は顧客検証ではない、という一般化 |
| 出さない情報 | 企業名、担当者名、具体金額、未公開資料 |

この形にすると、個別の失敗は、誰かを傷つける暴露ではなく、再利用できる問いになる。

同じことを、病院側、開示、外部経営候補についても書いた。

| 領域 | 使える問いに変えたもの |
|---|---|
| 病院PoC | 医師の賛同とは別に、誰の作業が増えるか |
| 開示 | 資料を分けたあと、誰がどの言葉で話すか |
| 創業者機能 | 経験者を入れる前に、研究者の守る線を理解しているか |
| 支援制度 | 採択された資金は、どの軸の不確実性を下げるのか |

これがvalidationの倫理である。現場から学ぶが、現場を晒さない。個別の関係を守りながら、次の判断を強くする。

## モデル修正の小さなログ

会議の最後に、支援者はモデル修正ログを残した。

| 修正対象 | 修正前 | 修正後 |
|---|---|---|
| BRLの証拠 | 企業の前向き反応を強めに読む | 評価者、予算者、導入責任者の確認を必須にする |
| SRLの証拠 | 医師の協力を社会受容の入口と見る | 技師、患者説明、倫理窓口を別項目にする |
| GRLの証拠 | 資料分類で開示安全性を見る | 話者、相手、場面ごとの禁止線を入れる |
| FRLの証拠 | 経営経験を補完力として高く読む | 研究者との信頼形成を補完条件に入れる |
| 統合判断 | RESOURCE_SHIFT後の進捗を曖昧に見る | 低い軸ごとに月次の戻る条件を置く |

このログは、理論をきれいにするためのものではない。次の案件で同じ誤読を繰り返さないためのものである。

## 次章へ残す未解決

証拠ルールは直った。

だが、個別案件の地図を直しても、同じ負荷がまた研究者に戻るなら、問題は残る。

企業の予算者を誰が探すのか。病院の技師や倫理窓口へ誰がつなぐのか。外部経営候補との信頼形成を誰が設計するのか。月次で低い軸を誰が見直すのか。

これらは、個別案件の努力だけでは持ちきれない。

次章では、個別案件の準備度と、研究機関の苗床としての準備度を分ける。unknownとnot_startedを混ぜず、機関側の行動がどう変わるかを見る。

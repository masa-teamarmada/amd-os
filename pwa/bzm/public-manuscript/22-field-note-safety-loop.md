# Toolkit A: 現場メモを、誰かを傷つけない問いに変える

ここからは本編の続きではなく、付録的な実務道具として読む章である。前章までに出てきた会議、資料、判断、失敗を、次の現場で使える形へ変換する。

会議が終わったあと、若い事業化人材は、ノートをそのまま共有フォルダに入れようとして手を止めた。

そこには、研究者が小さな声で言った不安が書かれていた。企業担当者がまだ社内で言えないと前置きした事情もあった。病院側の現場負荷について、担当者がかなり率直に話した言葉も残っていた。外部経営候補への違和感も、会議中の空気としてメモしていた。

どれも、次の判断には大切だった。

けれど、そのまま残せば、誰かを傷つける記録にもなる。

Before Zero の現場では、学びたいことほど、そのまま公開できない。研究者の本音、企業の未確定な事情、大学側の迷い、投資家の厳しい言葉、外部人材との相性。これらを捨ててしまえば、同じ失敗を繰り返す。だが、生のまま残せば、信頼を壊す。

必要なのは、現場メモを、誰かの失敗談ではなく、次に使える問いへ変える作業である。

## 生の記録と、使える問いを分ける

最初にやることは、メモを二つに分けることだ。

一つは、生の記録である。いつ、誰が、どの場で、何を言ったか。これは判断の根拠になるが、公開本文や外部共有には向かない。名前、所属、具体的な技術、契約、未公開資料、個人の評価が含まれるからである。

もう一つは、使える問いである。個別の固有情報を落としたあとでも、次の現場で再利用できる問いだ。

| 生の記録に近いもの | 使える問いに変えたもの |
|---|---|
| ある企業担当者は前向きだったが予算者ではなかった | 「面白い」と言った人は、評価者、予算者、導入責任者のどれか |
| 研究者は投資家資料の一文に違和感を持った | その表現は、研究者本人が守りたい線を越えていないか |
| 病院側は協力的だが技師の負荷を気にしていた | 医師の賛同とは別に、誰の作業が増えるか |
| 外部経営候補は実績が強いが研究者の慎重さを急かした | 経営経験より先に、技術への敬意と透明性を確認したか |

この変換ができると、現場の痛みは、誰かを責める材料ではなくなる。

たとえば、第一章から何度も戻ってきた企業反応は、次のように変換する。

| 生の記録に近いメモ | 公開しないもの | 使える問い |
|---|---|---|
| 企業探索担当は前向きだったが、予算者は今年度評価枠なしと回答 | 企業名、担当者名、年度計画の詳細 | 「面白い」と言った人は、評価枠を持つ人へつなげられるか |
| 研究者は投資家向け表現に違和感を持った | 研究者本人の言葉、未公開の図 | その一文は、研究者の守る線を越えていないか |
| 病院側は協力的だが、技師の負荷が重いと分かった | 病院名、部署名、具体手順 | 医師の賛同とは別に、誰の作業が増えるか |

## field note safety loop

現場メモを安全に使うには、次の順番を置く。

| 手順 | やること | 残すもの |
|---|---|---|
| 1. 観測する | 会議、面談、資料、感情の揺れを記録する | 生のメモ |
| 2. 分ける | 事実、仮説、解釈、未確認、約束禁止を分ける | 分類済みメモ |
| 3. 落とす | 実名、固有技術、契約、未公開条件、個人評価を落とす | 匿名化された素材 |
| 4. 問いにする | 次の現場でも使える確認文へ変える | reusable question |
| 5. 戻す | 次の会議や章で、問いとして使う | checklist / case pattern |

この順番を飛ばすと、二つの危険がある。

一つは、現場を守りすぎて学びが消えること。もう一つは、学びを急ぎすぎて現場を傷つけること。

良い実務本は、この中間に立つ。現場から逃げず、現場を晒さない。

## 使ってよい濃さを決める

本に入れるケースは、濃ければよいわけではない。

読み物としては、具体性が必要である。会議室、資料、沈黙、言い換えられた一文、誰も答えられなかった問い。こうしたものがないと、読者は自分の現場を重ねられない。

一方で、具体性が強すぎると、現実の誰かに戻ってしまう。

そこで、ケースを書く前に濃さを決める。

| 濃さ | 使い道 | 注意 |
|---|---|---|
| composite scene | 本文の冒頭や中盤に使う | 複数の現場を合成し、特定できないようにする |
| tool example | 表やチェックリストの記入例に使う | 数値、固有技術、組織名を避ける |
| abstract question | 章末や研修資料に使う | 抽象化しすぎて迫力を失わない |
| internal only | 公開本文には使わない | 生メモ、固有名、未公開条件、個人評価を含む |

この本で扱うケースは、実在の一件をそのまま書くためのものではない。何度も起きる構造を、読者が安全に見られる形へ変えるためのものだ。

## 現場メモを残す人の責任

若い事業化人材、URA、産学連携担当者、支援者は、現場のメモを持つことが多い。

そのメモは、未来の判断を強くする。だが、同時に、関係者の信頼を預かることでもある。

だから、メモを残す人には三つの責任がある。

第一に、事実と解釈を分けること。誰かが言ったことと、自分が感じたことを混ぜない。

第二に、約束していないことを、約束したように書かないこと。「関心がある」と「やる」は違う。「検討する」と「予算を出す」は違う。

第三に、次の人が使える問いへ変えること。個人の失敗として残さず、構造の確認に戻す。

現場メモは、裏話ではない。

会社になる前の判断を、次の現場へつなぐための橋である。

## 次へ渡すもの

この章で残すのは、一つの型である。

| 項目 | 書くこと |
|---|---|
| 起きたこと | 具体的に何が起きたか |
| 当時の仮説 | 何を信じて判断していたか |
| 見落とし | どの人、資料、条件、時間軸を見ていなかったか |
| 変換した問い | 次の現場で何を聞くか |
| 公開できる形 | 匿名化して残せる表現 |
| 出さないもの | 実名、固有技術、契約、未公開情報、個人評価 |

この型があると、次章の道具が効き始める。

意思決定、開示、顧客検証、資金使途、役割分担。どれも、現場メモから安全に問いへ変換されて初めて、使える道具になる。

# 19. スコアは、順位ではなく次の一手を見る

ある案件は、総合的にはとても有望に見える。

技術は強い。政策にも合っている。研究者の熱量もある。企業の関心も少し出てきた。支援者は「これは進めたい」と感じる。

けれど、次の会議で手が止まる。

最初の顧客課題は、まだ探索部門の「面白い」に留まっている。外部に出す資料には、出願前の情報が混ざっている。CEO機能は研究者本人に寄りすぎている。大学の手続きも、誰が持つか決まっていない。

総合的には良さそうなのに、次の一手が分からない。

このときスコアが必要になる。ただし、順位をつけるためではない。

## 高い低いより、どこが詰まっているか

統合準備度スコアは、複数の準備度をひとつの見取り図にする。sigma_SU、TRL、BRL、GRL、SRL、HRL、FRLのような要素を合わせ、現時点の準備度を読む。

しかし、読者がまず見るべきなのは総合点そのものではない。

見るべきなのは、低い軸と伸びしろである。

| 詰まり方 | 現場での見え方 | 次の一手 |
|---|---|---|
| TRLが律速 | 原理はあるが、試作・再現性・実環境が弱い | 技術検証の戻る条件を置く |
| BRLが律速 | 企業は好反応だが、課題と予算が浅い | 顧客課題とPoC条件を聞く |
| GRLが律速 | 開示、出願、契約、規制が未整理 | 出す情報と出さない情報を分ける |
| SRLが律速 | 現場や社会の受容が未確認 | 利用者、地域、倫理の懸念を聞く |
| HRLが律速 | 人はいるが機能が埋まらない | 役割空白と担当者を決める |
| FRLが律速 | 創業者機能が不安定 | 資質と経営実務の補完を設計する |
| sigma_SUが律速 | 個別は強いが波が来ていない | WAIT条件と観測点を置く |

スコアは「どの案件が偉いか」を決めるものではない。「次に下げる不確実性はどれか」を見つけるものだ。

## しきい値は、ゲートではなく会話の始点

ある水準を超えたら会社化、超えなければ会社化しない。そんな単純な使い方をすると、スコアは危険になる。

しきい値は、判断を自動化する壁ではない。会話を始めるための線である。

たとえば統合準備度が高く見えるのに、BRLだけが低いなら、進めるべき作業は資金調達ではなく顧客検証かもしれない。逆に総合点はまだ低くても、sigma_SUと研究の波が強く、TRLの戻る条件が明確なら、WAITとして育てる価値がある。

しきい値は「はい / いいえ」を出す機械ではない。なぜその判断になるのかを説明するための補助線である。

## 判断分岐に戻す

スコアを現場で使うときは、最後に必ず判断分岐へ戻す。

| 判断 | スコアの読み方 | 現場の言葉 |
|---|---|---|
| GO | 主要な律速が引き受け可能 | この不確実性を持って進む |
| WAIT | 律速は明確で、戻る条件が書ける | 止めるのではなく作業する |
| HOLD | 情報不足が短期で埋まる | まず確認してから決める |
| NO_GO | 会社化より研究価値を守る方がよい | 無理に会社にしない |
| RESOURCE_SHIFT | 低い軸へ資源を寄せた方がよい | いま必要なのは別の支援 |

ランキングとして読むと、総合点が高い案件に資源を寄せたくなる。律速として読むと、同じ資源の使い方が変わる。高く見える案件でも、最初の顧客が空いているならBRLへ。外に出る前ならGRLへ。創業者機能が空いているならFRLやHRLへ。

スコアは、意思決定者の責任を代替しない。むしろ、責任を取りやすくする。なぜ進むのか。なぜ待つのか。なぜ別の支援に回すのか。それを説明できるようにする。

## 今日の行動、まだ残る不安

今日できることは、いま有望に見える案件について「総合点が高そう」で止めず、律速軸と次の30〜90日の作業を書くことだ。

それでも不安は残る。現在のスコアがもっともらしく見えても、その地図が本当に現実に合っているかは、あとから確かめなければならない。

次章では、過去の判断を責任追及ではなく学習として読み直す。そこでretrofitとvalidationが必要になる。

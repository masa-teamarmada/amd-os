# Method Appendix M5 — 統合準備度と次の一手

本文のCh19では、統合地図は高期待の案件をさらに前へ押すためではなく、RESOURCE_SHIFTを選ぶために使われた。

ここでは、その地図を式として置く。

代表的な形は、次のように書ける。

`S = K * product((X_i + 1)^alpha_i)`

`X_i` は、マクロ整合、技術、事業、ガバナンス、社会受容、人材、創業者機能などの軸である。`alpha_i` は、その軸をどれくらい重く見るかを表す。`K` は全体の尺度を整えるための定数である。

もう少し分けて書くなら、次のようにも読める。

`S = k * M * X * F`

`M` はマクロの整合、`X` は五つの準備度のまとまり、`F` は創業者機能である。ここでも、どれか一つを強く見せるために分けるのではない。どこが全体を止めているかを見失わないために分ける。

この式は、案件をランキングするためのものではない。

むしろ、どの低い条件が次の一手を止めているかを見るために使う。感度は次の形で読める。

`dS/dX_i = alpha_i * S / (X_i + 1)`

これは、どの軸に仕事を置くと、統合地図がもっとも意味を持って変わるかを見るための手がかりである。

低い軸ほど、同じ一手の意味が大きくなることがある。

たとえば市場規模スライドを磨くより、予算者を一人確認するほうが地図を大きく変えることがある。投資家紹介を増やすより、開示前の一文を弱く戻すほうが、生存確率を上げることがある。短期の受託を取るより、その支払いが未来を狭めるかどうかを確認するほうが、稼げる体質の見え方を変えることがある。

だから、Ch19で選ばれたのは足し算ではなかった。

投資家紹介を増やす、市場規模スライドを磨く、短期の受託を取りにいく。そうした前向きな活動を、いったん減らす判断だった。戻った時間で、予算者、支払い拒否、開示線、九十日の見直し日を確認する。

統合準備度は、勢いを数値化するためではない。

何を減らして、何を確かめるかを決めるためにある。

重み `alpha_i` は、固定された真理ではない。

領域、時期、規制、研究機関の支援力、資金の性質によって、何を重く見るべきかは変わる。だから、重みは隠してはいけない。会議で説明し、必要なら見直す。

数値が出たあとに問うべきことは、いつも同じである。

この値が正しいかではなく、この値を置いたことで、次に減らす仕事が変わったか。

## MXFモデル

統合準備度は、本文の言葉でいえば、`M×X×F` の地図である。

`S = k * M * X * F`

それぞれは、次のように読む。

`M = (sigma_SU + 1)^alpha_sigma`

`X = product((x + 1)^alpha_x)` for `x in {TRL, BRL, GRL, SRL, HRL}`

`F = (FRL + 1)^alpha_F`

この分解を入れる理由は、会議で何が混ざっているかを見失わないためである。

追い風が強いのか。個別案件の準備が整っているのか。創業者機能の配置が見えているのか。

全部を一つの点数にしてしまうと、どこが高く、どこが低いのかが見えなくなる。`M×X×F` として分けると、同じ高期待案件でも、マクロが強いだけなのか、会社の準備が整っているのか、人の配置が効いているのかを分けて読める。

## 重みとスケール

代表的な重みは、次のように置ける。

| 軸 | `alpha` | 読み方 |
|---|---:|---|
| FRL | 1.5 | 創業者機能は、資金、人材、顧客接続を引き上げるため重く見る |
| sigma_SU | 1.3 | マクロの追い風は、同じシーズの生存確率を大きく変える |
| HRL | 1.1 | 人と組織は、九十日の実行可能性を左右する |
| TRL | 1.0 | 技術は中核。ただし単独では会社化を許可しない |
| BRL | 0.6 | 顧客、対価、予算者、導入条件を見る |
| GRL | 0.3 | 規制、知財、開示、契約の順序を見る |
| SRL | 0.2 | 使われる現場と社会受容を見る |

この重みは、永遠に固定された真理ではない。領域、規制、資金の性質、研究機関の支援力で見直す。

ただし、重みは隠さない。

重みを隠すと、数値は客観的に見える。だが実際には、何を重く見たかという判断が入っている。だから重みは会議の紙に置き、必要なら変える。

スケールを整える定数 `K` は、全軸が最大に近いときの上限をどのくらいに置くかで決める。たとえば全軸最大を100,000にそろえるなら、重み合計を使って次のように置ける。

`K = 100000 / 10^(sum(alpha_i))`

重み合計が6.0なら、`K = 0.1` になる。

## 手計算の例

ある案件で、次のように置いたとする。

`sigma_SU = 7, TRL = 0, BRL = 1, GRL = 5, SRL = 5, HRL = 1, FRL = 4`

全軸を `+1` して、上の重みを使う。

`S = 0.1 * 8^1.3 * 1^1.0 * 2^0.6 * 6^0.3 * 6^0.2 * 2^1.1 * 5^1.5`

計算すると、約133になる。

ここで読みたいのは、133という数字の大小だけではない。

`sigma_SU` と `FRL` は強く効いている。一方で、`TRL = 0` は `1^1.0` なので、全体を押し上げていない。つまり、期待と人の可能性はあるが、技術を自分たちで次へ運ぶ条件はまだ低い。

この読みが、本文でいう「高期待だがGOではない」に近い。

## 律速軸

次に手当てすべき軸は、直感だけで選ばない。

統合式を軸 `X_i` で微分すると、次の形になる。

`dS/dX_i = alpha_i * S / (X_i + 1)`

軸どうしを比べるときは、共通の `S` を外して、次だけ見ればよい。

`alpha_i / (X_i + 1)`

この値が大きい軸ほど、次の一段を上げたときの意味が大きい。つまり、次に仕事を置く候補になる。

さきほどの例では、TRLは `1.0 / (0 + 1) = 1.0` で最大になる。FRLは `1.5 / (4 + 1) = 0.3`、sigma_SUは `1.3 / (7 + 1) = 0.1625` である。

だから、この案件で次に見るべきものは、強い追い風でも、人物の期待でもなく、TRLの低さである。

本文の言葉に戻せば、会社を作る前に「誰が技術を次の実環境へ運べるのか」を見る必要がある。

律速軸は、欠点探しではない。

いま一番、仕事を置く意味が大きい場所を見つけるための道具である。

# Method Appendix M4 — 創業者機能と役割の適合

本文で外部経営候補が現れたとき、問題は「誰がCEOになるか」だけではなかった。

研究者が守りたい線を理解できるか。弱い事実を弱いまま戻せるか。企業や投資家の前で、強い言葉に滑ったときに戻ってこられるか。九十日のあいだ、誰がどの機能を持つのか。

この補遺では、そのまとまりをFRLと呼ぶ。

FRLは、人格評価ではない。研究者を創業者向きかどうかで裁くための言葉でもない。

むしろ、誰に何を背負わせると壊れるかを読むための配置設計である。

ここでは、少なくとも二つを分ける。

- `F_character`: 信頼、言い直し、弱い事実を扱う態度
- `F_capability`: 資金調達、採用、顧客開拓、交渉、実行を運ぶ力

外部経営候補が補えるものはある。若い事業化人材が拾える空白もある。研究機関が受け止めるべき責任もある。

けれど、研究者本人の保護線や技術の意味を、誰かが便利に置き換えることはできない。

FRLは、その置き換え不能なものと補完できるものを分けるための地図である。

FRLを数値として置く場合も、最初に見るべきものは面談の印象ではない。

見るべきものは、行動である。

研究者の保護線をそのまま言い返せるか。弱い支払い拒否を、強い顧客証拠に言い換えず持ち帰れるか。投資家の前で強い言葉に寄りそうになったあと、次のメールで戻れるか。採用、資金調達、顧客開拓、契約、チーム設計のうち、どれを九十日で本当に持てるか。

このため、FRLは一つの人格点ではなく、少なくとも二層で読む。

`FRL = role_fit(F_character, F_capability, context)`

ここで `context` は、その案件の技術、開示線、企業側の関心、研究機関の支援導線を含む。

つまり、同じ人でも案件が変わればFRLは変わる。ある研究成果では良い補完者になれる人が、別の研究成果では強い言葉を急がせてしまうこともある。

だから、創業者機能を見るとは、誰かを選別することではない。

その案件で、誰に何を持たせると信頼が残るかを決めることである。

## F_character と F_capability

FRLを一つの印象点にしないために、少なくとも二層へ分ける。

`F_character` は、委ねにくい中心である。

研究者の守る線を尊重できるか。弱い事実を強く言い直さないか。悪い知らせを隠さないか。反対意見を聞けるか。長い検証で折れずに進めるか。

操作上は、次のように置ける。

`F_character = 0.6 * ALQ_avg + 0.2 * Grit + 0.2 * Resilience`

`ALQ_avg` は、自己認識、関係透明性、均衡的処理、内在化された道徳観の平均である。Gritは長期目標へ向かう粘り、Resilienceは拒絶や失敗から戻る力である。

`F_capability` は、補える実務である。

資金調達、採用、顧客開拓、契約、財務、労務、交渉、事業運営。これはCEO本人だけに閉じない。外部経営候補、COO/CFO、支援側の伴走、人材ネットワークが補えることもある。

だから、経験は知識より重く見る。

本を読んでいる、講座を受けた、MBAを持っている、という知識は事故を減らすかもしれない。けれど、資金調達を主導した、事業責任を持った、採用と撤退を経験した、難しい交渉を最後まで運んだ、という経験はさらに重い。

## CESで合成する

この二つは、単純な平均にしない。

資質が高くても、経営実行力がまったくなければ壊れる。経営経験が豊富でも、弱い事実を強く言い直す人なら壊れる。

どちらか一方で完全に補える関係ではない。

そこで、補完性を持つCESで合成する。

`FRL + 1 = [a * (F_character + 1)^rho + (1 - a) * (F_capability + 1)^rho]^(1/rho)`

ここでは、初期値として `a = 0.6`、`rho = -2` のように置ける。`rho` が負であるほど、低い側に引っ張られる。

この式の意味は、面談の場面に戻すと分かりやすい。

研究者の保護線を大切にできる人でも、九十日の資金と採用と顧客確認を誰も持てなければFRLは上がりきらない。

逆に、資金調達の経験が強い人でも、支払い拒否を顧客証拠に言い換えてしまうならFRLは上がりきらない。

FRLは、良い人を探す式ではない。

壊れない配置を探す式である。

# Toolkit C: 研究機関を、苗床として点検する

この章は、研究機関向けの付録的な実務道具である。本編で扱った苗床の考え方をもう一度説明し直すのではなく、最初の九十日で使う点検表、pilot設計、unknownとnot_startedの仕分けに絞る。

研究成果の会社化は、個別案件だけでは完結しない。

ある研究者が強い。ある技術が面白い。ある企業が関心を示す。ある支援制度が使える。そうした点があっても、次の点へつながる道がなければ、毎回同じ場所で詰まる。

研究者は、どこに相談すればよいか分からない。産学連携担当者は、知財と会社化の間で毎回手探りになる。若い事業化人材は、どの権限を持ってよいか分からない。外部経営候補は、研究者との信頼形成より先に事業計画を作ろうとする。企業候補は、探索担当で止まり、予算者へ届かない。

このとき必要なのは、個別案件の努力だけではない。

研究機関そのものが、会社になる前のシーズをどう育てるかを点検することである。

## まず一つのpilotに縮める

研究機関には、すでに多くの支援メニューがあることが多い。

知財相談、共同研究、起業支援、アクセラレーター、助成金、メンター、外部人材紹介、企業マッチング、ピッチイベント。

それでも研究者が孤独になるのは、メニューが足りないからだけではない。メニューの間に、責任の導線がないからである。

| 支援メニュー | ありがちな弱さ | 苗床として見ること |
|---|---|---|
| 知財相談 | 出願後に事業側へつながらない | 開示・企業面談・論文の順番へ接続しているか |
| 起業支援 | ピッチ資料中心になる | 顧客検証、経営機能、研究者保護まで見ているか |
| 企業マッチング | 探索担当で止まる | 評価者、予算者、導入責任者へ進む道があるか |
| 外部人材紹介 | 経歴で選びがち | 研究者との信頼形成条件を見ているか |
| 助成金 | 採択が目的化する | 資金でどの不確実性を下げるかを追っているか |

この棚卸しを全学規模で一気に始めると、すぐに重くなる。最初は三つのシーズだけを選ぶ。開示前レビュー、顧客信号の階段、月次の低軸レビューを、九十日だけ回す。広げるかどうかは、そのpilotの後で決める。

## unknown と not_started を分ける

機関を点検するとき、最初に分けるべきものがある。

unknown と not_started である。

unknown は、存在するかどうか分からないもの。確認すれば見えるかもしれない。

not_started は、まだ始めていないもの。存在しない、または制度として整備されていない。

この二つを混ぜると、改善が雑になる。

| 項目 | 状態 | 次の行動 |
|---|---|---|
| EIR/CXO候補リスト | unknown | 起業支援部門、卒業生、地域企業ネットワークへ確認する |
| 開示前レビュー表 | not_started | 三層開示表を標準化する |
| 企業予算者への導線 | unknown | 既存の企業接点から、事業部接続の有無を確認する |
| 若手事業化人材の権限 | not_started | 30日単位の役割と報告先を定義する |
| 医療PoC倫理入口 | unknown | 病院側の相談窓口と標準手順を確認する |
| 月次の低軸レビュー | not_started | 個別案件の戻る条件を見る会議を置く |

unknown は調べる。not_started は作る。

この区別だけで、機関の行動はかなり変わる。

会議での記入例はこうなる。

| 発言 | その場の修正 | 次の実務 |
|---|---|---|
| EIR候補はないと思います | unknown。まだ起業支援部門と卒業生ネットワークを確認していない | 二営業日で既存候補リストを確認 |
| 企業予算者へ届く導線がありません | not_started。探索担当止まりの構造が見えている | pilot企業二社で事業部接続条件を聞く |
| 医療PoCの入口が分かりません | unknown。病院側窓口と標準手順を確認する | 倫理窓口に初回相談ルートを聞く |
| 月次レビューはありません | not_started。案件ごとの任意会議に頼っている | 三つのシーズで低軸レビューを月一回置く |

## 苗床チェックリスト

研究機関が Before Zero の苗床として機能しているかを見るなら、次の問いを置く。

| 領域 | 問い |
|---|---|
| シーズ発掘 | 研究者本人が事業化を言い出す前に、社会実装の可能性を拾う導線があるか |
| 知財・開示 | 企業面談、発表資料、投資家資料の前に開示範囲を分ける型があるか |
| 顧客検証 | 企業の探索担当で止まらず、評価者、予算者、導入責任者へ進む道があるか |
| 人材 | 研究者CEOか外部CEOかの二択ではなく、創業者機能を分解して見ているか |
| 若手育成 | 若い事業化人材が、聞く、翻訳する、記録する、戻す仕事から入れるか |
| 資金 | 助成金や投資資金が、どの不確実性を下げるかを追っているか |
| 学習 | 失敗や停滞を、責任論ではなく証拠ルールの修正へ変えているか |
| 会議体 | WAIT、HOLD、RESOURCE_SHIFTが放置にならない戻る場があるか |

このチェックリストは、研究機関を評価するためだけのものではない。

次の一手を決めるためのものである。

## 最初の九十日で作るもの

全部を一度に整える必要はない。

最初の九十日で作るなら、次の三つがよい。

第一に、開示前レビュー表。発表資料、企業面談資料、投資家資料を、公開情報、限定開示、まだ出さない情報に分ける型である。

第二に、顧客信号の階段。企業の「面白い」を、評価者、予算者、導入責任者、検証条件へ分ける型である。

第三に、月次の低軸レビュー。個別案件ごとに、技術、事業、制度、社会、人材、創業者機能、追い風のどこが低いかを確認し、戻る条件を見る場である。

この三つがあるだけで、研究者は毎回ゼロから説明しなくてよくなる。産学連携担当者も、その場で全部を抱え込まなくてよくなる。若い事業化人材も、何を持てばよいかが見える。

pilot charterとして書くなら、次の一枚で足りる。

| 項目 | 記入例 |
|---|---|
| pilot範囲 | 医療隣接、素材、AI応用の三シーズ |
| 期間 | 九十日 |
| 必ず使う道具 | 三層開示表、顧客信号の階段、低軸レビュー |
| owner | 産学連携担当者、若い事業化人材、知財担当、外部支援者 |
| stop / expand gate | 三シーズで研究者負荷が下がり、未確認が表になったら継続。会議だけ増えたら縮小 |

## この本の後に残る問い

この本は、研究成果を必ず会社にしようと言っているのではない。

会社にする前に、見落とされやすい条件を読むための本である。

会社にするべきものもある。まだ待つべきものもある。会社にしない方が研究成果を守れるものもある。会社以外の形で社会に出すべきものもある。大事なのは、熱量や制度や資本の圧に押されて、未整理のまま Zero を越えないことである。

最後に残る問いは、単純である。

この研究成果は、いま会社になるべきか。

その前に、どの不確実性を、誰が、どの順番で下げるのか。

Before Zero を読む力は、その問いを急がず、しかし逃げずに扱う力である。

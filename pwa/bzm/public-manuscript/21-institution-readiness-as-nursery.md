# Chapter 21: 個別案件と苗床を混ぜない

証拠ルールを直したあと、研究機関側の打ち合わせが開かれた。

議題は、個別案件の成否ではなかった。

この医療隣接シーズで見えた詰まりを、次のシーズでも繰り返さないために、研究機関の側で何を整えるかである。

個別案件としては、技術、事業、制度、社会、人材、創業者機能を見ればよい。だが、同じ詰まりが機関の中で何度も起きるなら、それは個別案件の低さだけではない。苗床の低さである。

この章では、個別案件の準備度と、研究機関の苗床としての準備度を混ぜずに見る。

後半の理論では、苗床の準備度をERSと呼ぶ。

## 個別案件の低さと、苗床の低さは違う

この案件で見えた低さを、個別案件と研究機関側に分けると、表はこうなった。

| 詰まり | 個別案件としての低さ | 苗床としての低さ |
|---|---|---|
| 企業の予算者が見えない | BRLが低い | 事業会社接続が探索担当に偏っている |
| 病院の技師・倫理窓口が遅れた | SRL/GRLが低い | 医療PoCの標準入口がない |
| 出願前資料の扱いが毎回揺れる | GRLが低い | 開示前レビュー導線が案件ごとに属人化している |
| 外部経営候補との信頼形成が難しい | FRL/HRLが低い | EIR/CXO候補の関係形成プロセスがない |
| 若い事業化人材の権限が弱い | HRLが低い | 事業化人材の育成と役割付与が制度化されていない |
| 月次の戻る条件が曖昧 | 統合判断が弱い | 案件を継続レビューする会議体がない |

個別案件の準備度だけを見ていると、「この案件はまだ弱い」で終わる。

苗床を見ると、「次の案件で同じ弱さを出さないには、機関側の導線をどう変えるか」に変わる。

この変化が、Ch14の繰り返しではないところである。Ch14では、研究機関を苗床として見る必要を見た。ここでは、個別案件の判断が、研究機関側の行動を実際に変える。

## unknownとnot_startedを分ける

研究機関の打ち合わせで、最初に起きた危険は、未確認を未整備と決めつけることだった。

「EIR制度はないんでしたっけ」
「医療PoCの倫理手続きは、どこかに資料がありますか」
「企業予算者につなぐ窓口は、産学連携本部にあるんですか」

誰も即答できない。だからといって、全部を「ない」と書くと間違う。

若い事業化人材が、白板に「EIR制度なし」と書きかけたところで、産学連携担当者が止めた。

「それ、なしじゃなくて、まだ確認していない、です」

別の担当者は少し反発した。

「でも、見たことがないなら、ないのと同じでは？」

ここで会議が割れた。未確認を「ない」と書けば、機関側は不当に弱く見える。逆に、本当に未整備の導線を「未確認」と置き続ければ、研究者はまた自力で探すことになる。

だから、白板の色を分けた。青は確認済み。黄はunknown。赤はnot_started。会議中に黄だったものは、次の二営業日で確認する。赤だったものは、九十日の整備計画に入れる。

そこで、unknownとnot_startedを分けた。

| 項目 | 状態 | 根拠メモ | 次の行動 |
|---|---|---|---|
| EIR/CXO候補リスト | unknown | 担当者の手元資料は未確認 | 産学連携部門と起業支援部門に確認 |
| 医療PoC倫理入口 | unknown | 病院側窓口はあるが標準手順は未確認 | 倫理窓口に初回相談ルートを聞く |
| 開示前レビュー表 | drafting | 今回の案件で三層表を作成した | 汎用テンプレにして次回から使う |
| 企業予算者への接続 | not_started | 探索担当との接点はあるが、予算者導線はない | 企業側の事業部接続を新しく設計 |
| 若手事業化人材の権限 | not_started | 役割はあるが、案件内の権限が定義されていない | 30日単位の責任範囲を制度化 |
| 月次レビュー会議 | not_started | 案件ごとに任意で集まっている | 低い軸を確認する定例を設計 |

unknownは、確認TODOである。not_startedは、整備課題である。

この二つを混ぜると、機関への提案は荒くなる。未確認なのに「制度がない」と決めつければ、信頼を失う。実際には未整備なのにunknownのまま置けば、研究者へ負荷が戻る。

## ERSは個別スコアに足さない

研究機関の準備度が高いほど、個別案件は進みやすくなる。これは直感的には正しい。

だが、苗床の準備度を、個別案件の統合スコアにそのまま足してはいけない。

なぜなら、見る層が違うからである。

個別案件では、技術、事業、制度、社会、人材、創業者機能、追い風を読む。これは、そのシーズがいまどこまで会社化前の不確実性を下げられているかを見るためのものだ。

苗床では、シーズ発掘、知財、起業支援、企業接続、資金、人材供給、規程、政策連携を見る。これは、同じような案件を生み、守り、育てる土壌があるかを見るためのものだ。

二つを混ぜると、行動がぼやける。

| 混ぜてしまう見方 | 起きる問題 | 分けた見方 |
|---|---|---|
| 機関が強いから、この案件も高く見る | 個別案件の低い軸が隠れる | 案件は案件の低さを見る |
| 案件が弱いから、機関も弱いと見る | 苗床の強みまで見えなくなる | 機関は導線と制度を見る |
| 苗床の点を個別判断に足す | 何を直すべきかが混ざる | 苗床は次案件の条件整備に使う |

ERSは、研究機関をランキングするためではない。支援ギャップを見つけるための道具である。

## 研究機関側の行動が変わる

この打ち合わせの成果は、個別案件の判断ではなく、機関側の行動計画だった。

| 苗床の課題 | 30-90日の行動 | 変わること |
|---|---|---|
| 開示前レビューが属人化 | 三層開示表を標準化する | 次の企業面談前に研究者が迷わない |
| 医療PoC入口が曖昧 | 病院の倫理窓口、技師、医師の相談順を作る | 医師の賛同だけで進めない |
| 企業予算者導線がない | 探索担当から事業部へ進む条件を聞く | 「面白い」で止まらない |
| EIR/CXO候補の信頼形成が弱い | 候補者面談に研究者の守る線を確認する項目を入れる | 経歴だけで人を置かない |
| 若手事業化人材の役割が曖昧 | 聞く、翻訳する、記録する、戻す権限を定める | 育成が名目で終わらない |
| 月次レビューがない | 低い軸と戻る条件を見る定例を置く | WAITが放置にならない |

この表ができると、研究者の負荷が少しだけ軽くなる。

次に似たシーズが出てきたとき、研究者は毎回ゼロから「どこに相談すればよいのか」を探さなくてよい。産学連携担当者も、毎回その場で開示表を作らなくてよい。若い事業化人材も、自分が何を持ってよいのかを最初から確認できる。

苗床が整うとは、個別案件が何もしなくてよくなることではない。

個別案件が、同じ罠に毎回落ちなくなることである。

## 理論パートの終わりに残すもの

ここまでで、理論語はいくつも出てきた。

TRL、BRL、GRL、SRL、HRL。FRL。sigma_SU。統合準備度。retrofit。validation。ERS。

けれど、これらは現場を置き換える言葉ではない。

同じ医療隣接シーズを見ても、章ごとに誤読は違った。期待だけで進みそうになった。準備を一語に混ぜた。追い風をGOの理由にしそうになった。創業者機能を人格評価にしそうになった。高期待を設立判断と混同しそうになった。外れた地図を人の失敗として閉じそうになった。個別案件の低さと苗床の低さを混ぜそうになった。

理論は、そのたびに地図を出すためにある。

最後に残るartifactは、次の一枚である。

| 層 | 見るもの | 次の行動 |
|---|---|---|
| 個別案件 | 低い準備度と次に下げる不確実性 | 90日計画を更新する |
| 人 | 委ねられない中心と補える実務 | 役割と信頼形成を設計する |
| 追い風 | 学・産・官・社会の位相差 | 速く行く場所と待つ場所を分ける |
| 過去学習 | 外れた証拠ルール | 次の問いに変える |
| 苗床 | unknownとnot_started、支援ギャップ | 機関側の導線を整える |

ここから先は、また現場に戻る。

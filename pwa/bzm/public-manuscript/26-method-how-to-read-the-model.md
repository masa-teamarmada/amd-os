# Method Appendix M0 — モデルをどう読むか

この補遺は、物語を読み終えたあとで開くための場所である。

本文で起きたことは、ひとつの強すぎた一文が、証拠、開示、会社化、創業者機能、WAIT、リスク資本、学習ログ、研究機関の苗床へ波及していく過程だった。ここから先では、その判断を支えていた地図を、変数と式で見えるようにする。

ただし、モデルは判定機ではない。

高い数値が出たから会社にする、低い数値が出たからあきらめる、という読み方はしない。モデルは、次に下げる不確実性を見つけるための会話の紙である。数値は、現場でまだ確認できていない条件を隠すためではなく、見落としにくくするために置く。

この補遺で扱う式は、本文の人物の判断を置き換えない。研究者、支援者、外部経営候補、企業、投資家、研究機関がそれぞれ持っていた局所的な合理性を、同じ紙の上で見比べるために使う。

だから、最初に守るべき読み方は一つだけでよい。

モデルを読むときは、「この案件は何点か」ではなく、「この案件が壊れるなら、次にどの条件が壊すのか」と問う。

## 物語と解説の読み分け

本文の物語は、現場で何が起きたかを先に見せる。強すぎた一文、支払い拒否、送信予約、九十日WAIT、RESOURCE_SHIFT、研究機関の苗床は、すべて人物の行動として出てくる。

この補遺は、そのあとで開く。

順番を逆にしない。式を先に置くと、読者は現場を点数化の材料として見てしまう。物語を先に置くと、式は人の判断を置き換えるものではなく、判断を会議で検証するための紙になる。

この本で使う基本構造は、次の三層である。

- `M`: Macro alignment。学術、産業、政策の追い風がどれだけ同じ方向を向いているか。
- `X`: Venture readiness。技術、事業、制度、社会受容、人材がどれだけ次の判断に耐えるか。
- `F`: Founder function。研究者本人、外部経営候補、若い事業化人材、研究機関のあいだで、創業者機能をどう配置できるか。

この三つを合わせたものを、ここでは `MXFモデル` と呼ぶ。

`M×X×F` は、会社化を許可する印ではない。むしろ、会社化の前にまだ低い条件がどこに残っているかを見つけるための構造である。

本文の各章を読んでから補遺に戻ると、式の位置づけはこう読める。

- Ch16で「準備できている」が五つに割れたあと、M3で `X` の軸を見る。
- Ch17で追い風の時計がずれたあと、M2で `M` を見る。
- Ch18で創業者機能が人格評価ではなく配置設計になったあと、M4で `F` を見る。
- Ch19でRESOURCE_SHIFTが起きたあと、M5で `M×X×F` の統合と律速を見る。
- Ch21で個別案件と苗床を分けたあと、M7で研究機関側のERSを見る。

つまり、解説は物語の中断ではない。

物語で見えた違和感に、もう一度名前と式を与えるための場所である。

# Method Appendix M7 — 研究機関の苗床準備度

本文の終盤で見えたのは、ひとつの案件だけの問題ではなかった。

別の研究者も、別の支援メニューPDFの前で止まった。支援制度が足りないのではなく、最初に責任を受ける人、弱い事実を戻す人、九十日後に見直す人が、毎回空きやすかった。

この補遺では、その研究機関側の準備をERSとして読む。

ERSは、支援メニューの数ではない。

見るべきものは、責任導線である。

- 最初に受ける人はいるか
- unknownとnot_startedを分けているか
- 予算者、開示、外部候補、研究者本人、支援制度の空欄が見えるか
- 九十日pilotの止める条件と広げる条件があるか

簡単な正規化は、次のように置ける。

`s = (lv - 1) / 4`

`A_k = mean(axis k sub-scores)`

`ERS = 100 * sum(w_k * A_k)`

ただし、ここでも数値は運用を置き換えない。

ERSが見せるべきものは、研究機関が「支援しています」と言えるかではない。次の案件で、同じ孤独がどこに再発するかである。

`lv` は、サブ軸ごとの到達レベルである。

それを0から1に正規化したものが `s` になる。いくつかの `s` を平均すると、その軸の `A_k` になる。さらに軸ごとに重み `w_k` を置いて足し合わせると、ERSになる。

この形は便利だが、危険もある。

支援メニューが多い研究機関ほど、点数が高く見えてしまうことがある。けれど、本文で研究者を孤独にしたのは、メニューの少なさだけではなかった。最初に受ける人がいない。悪い知らせを戻す人がいない。予算者確認が誰の仕事か決まらない。九十日後に見直す会議がない。

だから、ERSの各サブ軸には、必ず「誰が持つか」を添える。

担当が空白の高得点は、まだ高得点として扱わない。

研究機関の苗床は、制度の数ではなく、責任が流れる道で測る。

## 八つの軸

ERSでは、研究機関側の準備を八つの軸で読む。

| 軸 | 見るもの |
|---|---|
| 1 | シーズ発掘と技術評価の体制 |
| 2 | 知財、TLO、開示前レビューの機能 |
| 3 | インキュベーション、起業支援、伴走の場 |
| 4 | 産学連携と事業会社接続の窓口 |
| 5 | 資金、ギャップファンド、ファンド接続 |
| 6 | 経営人材、外部候補、EIR/CxO供給 |
| 7 | 規程、利益相反、エクイティ、ガバナンス |
| 8 | 政府、自治体、政策プログラムとの接続 |

この八軸は、個別案件の準備度とは別である。

たとえば、企業予算者が見えない案件があったとき、それはその案件のBRLが低いという話でもある。同時に、研究機関の企業接続導線が探索担当で止まりやすい、というERS上の課題でもある。

この二つを混ぜると、機関が整っているから案件もGOだ、という誤読が起きる。

だから、個別案件の地図と苗床の地図は分ける。

## 加重和を使う理由

個別案件の統合準備度は、積で読む。

一つの低い条件があると、生存確率が大きく落ちるからである。

一方、研究機関のERSでは、加重和で読む。

理由は、欠けている場所を消さずに見たいからである。もし研究機関の八軸を積でまとめると、一つ低い軸が全体を大きく押し下げるだけで、どこを改善すべきかが見えにくくなる。

ERSで大事なのは、総合点そのものより、低い軸がどこに残っているかである。

だから、式は次の形にする。

`s = (lv - 1) / 4`

`A_k = mean(axis k sub-scores)`

`ERS = 100 * sum(w_k * A_k)`

当面は、八軸の重み `w_k` を等しく置いてよい。運用データが増えたら、研究機関のタイプや支援戦略に応じて変える。

## 例

ある研究機関で、八軸のスコアが次のようだったとする。

`A = [0.75, 0.50, 0.50, 0.25, 0.25, 0.50, 0.75, 0.50]`

等加重なら、ERSは次になる。

`ERS = 100 * (0.75 + 0.50 + 0.50 + 0.25 + 0.25 + 0.50 + 0.75 + 0.50) / 8 = 50`

50という数字だけを見ると、普通に見える。

しかし、この紙で大事なのは、軸4と軸5が0.25で低いことだ。つまり、事業会社接続と資金接続が、次に機関側で手当てすべき場所になる。

このように、ERSはランキングではなく、機関の次の九十日pilotを決める紙である。

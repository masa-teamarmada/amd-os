# Chapter 15: なぜ現場をモデルにするのか

前章で、研究機関を苗床として見るところまで来た。そこから一週間後、同じ研究機関の会議室に、ひとつのシーズが持ち込まれる。

医療に近い検査技術である。研究室では、従来より早く、少ない試料で、ある状態変化を検出できる。近くの病院には協力的な医師がいる。地域の製造企業は装置化に関心を示している。政策の公募にも、よく似た言葉が並んでいる。ギャップ資金の面接も通りそうだ。

会議の空気は明るい。

「技術は強い」
「地域で実証できそうだ」
「企業も興味を持っている」
「助成金で初期検証できる」
「若い事業化人材もつけられる」

ところが、会議が終わる直前になって、次の一手が割れる。

研究者は、まず論文と出願の順番を守りたい。産学連携担当者は、企業面談の前に開示範囲を整理したい。病院側は、倫理審査と現場負荷を確認したい。企業は、装置化できるなら早く試験条件を知りたい。支援制度の担当者は、面接までに「会社化の道筋」を見せたい。若い事業化人材は、誰に何を聞きに行けばよいのか分からない。

全員が前向きなのに、次の一手が一致しない。

この瞬間に、モデルが必要になる。

## 期待だけで会議を閉じない

この案件を「有望」と呼ぶことは簡単である。けれど、その一語では、何も決まらない。

有望なのは、研究成果なのか。医療現場の課題なのか。地域の実証環境なのか。政策のタイミングなのか。企業の装置化能力なのか。研究者本人の創業意思なのか。研究機関の支援導線なのか。

会議では、これらが一つの期待に押し込められていた。

| 会議で出た前向きな言葉 | そのまま進めると起きる誤読 | 次に分けるべきこと |
|---|---|---|
| 技術は強い | 研究室の成立を、現場で使える状態と混同する | どの条件なら再現できるか |
| 病院が近い | 近さを、現場受容や倫理手続きの完了と混同する | 誰が何を試せるか |
| 企業が関心を示した | 探索部門の好反応を、顧客検証と混同する | 課題、予算、評価条件 |
| 公募に合っている | 支援制度の採択可能性を、会社化準備と混同する | 資金で何の不確実性を下げるか |
| 人をつけられる | 人名を、創業者機能の充足と混同する | 誰が責任と時間を持つか |
| 機関の支援がある | メニューの存在を、責任導線と混同する | どこで統合判断へ戻るか |

モデル化とは、この表をきれいに作ることではない。会議の熱量に混ざった誤読を、もう一度ほどくことである。

## ある日の決定メモ

その場で、支援者は会議メモを一枚だけ書き直した。

| 項目 | 記入内容 |
|---|---|
| いまの判断 | 会社化の話を進める前に、三つの未確認を分ける |
| 進めたい理由 | 研究成果、地域実証環境、政策公募、企業関心が同時に見えている |
| 止めたい理由 | 出願前情報、病院での検証条件、企業の予算経路、創業者機能が未整理 |
| 今日の誤読 | 「期待が重なっている」を「準備が整っている」と読んだ |
| 次の30日 | 開示範囲の整理、病院側の検証条件、企業側の評価者確認 |
| 戻る条件 | 三者の検証目的が衝突しない形で、一枚のPoC条件表に戻る |
| 仮判断 | GOではなくWAIT。待つのではなく、未確認を減らす |

ここで大事なのは、WAITが弱気ではないということだ。

この案件は、止めるには惜しい。だが、このまま進めるには粗い。だから、待つ。正確には、待ちながら作業する。

モデルがないと、ここで会議は二つに割れる。「せっかく追い風があるから進めよう」と「まだ危ないから止めよう」である。どちらも一部は正しい。けれど、どちらも粗い。

必要なのは、何が強く、何が未確認で、何を先に下げるべきかを分ける地図である。

## 理論語は、誤読に名前をつけるためにある

この本では、ここから理論語が出てくる。

けれど、理論語を覚えることが目的ではない。いま見た会議の誤読に、あとから名前をつけるために使う。

研究室の成立と現場で使える状態を分けるなら、技術の準備度を見る。企業の好反応と顧客検証を分けるなら、事業の準備度を見る。開示、出願、倫理、契約の順序を見るなら、制度やガバナンスの準備度を見る。病院、患者、地域、利用者の受け止めを見るなら、社会受容を見る。人がいることと機能が埋まっていることを分けるなら、人材・組織を見る。

これらは後で、TRL、BRL、GRL、SRL、HRLと呼ぶ。

研究者本人や外部経営人材が、何を委ねられず、何を補えるかを見るときには、創業者準備度という言葉が必要になる。これは後でFRLと呼ぶ。

研究機関が、個別案件を生み、守り、外へ出す土壌を持っているかを見るときには、苗床の準備度という言葉が必要になる。これは後でERSと呼ぶ。

名前は、現場より先に置かない。

現場の誤読が見えたあとで、その誤読を繰り返さないために名前を置く。

## 次章へ残す未解決

会議メモの最後には、まだ空欄が残っている。

| 空欄 | なぜ未解決か |
|---|---|
| 技術はどこまで現場条件で成立するか | 研究室の試料条件と病院の運用条件が違う |
| 企業の関心は誰の痛みか | 探索担当は前向きだが、評価者と予算者が未確認 |
| 開示してよい図はどれか | 出願前データ、共同研究情報、論文投稿予定が混ざっている |
| 病院で試すときの受け手は誰か | 医師、技師、患者、倫理審査で見る不安が違う |
| 若い事業化人材は何を持つか | 動けるが、責任範囲と権限がまだない |

この空欄を見たとき、支援者は初めて「準備できている」という言葉が危ないことに気づく。

次章では、この同じ案件を、技術、事業、制度、社会、人材の準備度に分ける。そこではじめて、準備度の軸が必要になる。

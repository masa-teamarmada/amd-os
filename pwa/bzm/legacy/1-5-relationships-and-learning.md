# 関係構築と失敗からの学習 — Before Zero を壊さず前へ進める

> この章は何か: Before Zero で必要な関係構築と、失敗・手戻りを次の判断へ変える方法を整理します。BZM は点数を出す道具である前に、関係者のズレを早く見つける道具です。

## 1. 関係構築は「誰を説得するか」ではない

Before Zero の関係構築は、相手を説得する作業ではありません。相手ごとに違う不安、制約、成功条件を見つけ、どの順序で合意すれば壊れないかを設計する作業です。

| 相手 | 先に握ること | 後回しにできること |
|---|---|---|
| 研究者 | 研究として守りたいもの、公開予定、関与可能時間 | 会社化後の細かい役職名 |
| 大学・研究機関 | 知財・共同研究・利益相反・支援体制 | 最終的な資本政策 |
| 企業候補 | 検証したい課題、使えるデータ、PoC 条件 | 将来の大型契約条件 |
| VC / CVC | チーム、なぜ今か、資金で進む仮説 | 完成後の精密な財務計画 |
| 行政 | 政策目的、地域・産業波及、制度制約 | 個別 PJ の細かい株主構成 |

関係構築の失敗は、後半の理論では `BRL`、`GRL`、`HRL`、`FRL`、ERS の低さとして現れます。

## 2. 失敗は「誰が悪いか」ではなく「どの仮説が外れたか」で読む

Before Zero の失敗は、責任論で読むと次に使えません。AMD は失敗を次の粒度へ分解します。

| 観点 | 問い |
|---|---|
| 仮説 | 何が正しいと思っていたか |
| 観測 | 実際に何が起きたか |
| 見落とし | どの信号を軽く見ていたか |
| 変数 | BZM のどの軸を過大評価・過小評価したか |
| 修正 | 次回はどの条件を見るか |

例えば「企業候補が反応しなかった」は、失敗としては粗すぎます。顧客課題が浅かったのか、検証条件が重すぎたのか、知財開示が足りなかったのか、意思決定者に届いていなかったのかで、次の打ち手は変わります。

## 3. AMD が持つべき学習ループ

Before Zero の実践テキストは、ケースを美談として載せる場所ではありません。AMD が次の PJ で判断精度を上げるため、次のループで知見を残します。

1. 現場で起きたことを L2 に残す
2. 判断・失敗・関係構築・チェックポイントへ分類する
3. 守秘と一般化を確認する
4. 承認済みの L210候補だけを Textbook へ追記する
5. 後から retrofit / AMD Score / ERS と照合する

実ケースの追記先は、内容に応じて [失敗・ピボット・仮説修正](8-3-failures-pivots-and-revisions.md) または [関係構築プレイブック](8-4-relationship-playbook.md) になります。

## 4. 関係の壊れ方を早く検知する

Before Zero では、関係が壊れる前に小さな兆候が出ます。

- 研究者が「事業化」と「研究継続」を同じものとして話している
- 大学側の知財・契約判断者がまだ入っていない
- 企業候補が「面白い」と言うが検証条件を出さない
- CEO 候補が不確実性より肩書きや条件を先に気にしている
- VC が市場よりチーム不在を繰り返し指摘している
- 行政や制度のスケジュールが PJ の意思決定より遅い

これらは Textbook 上では「赤信号」として扱い、後半の理論では readiness の低さや律速として扱います。

## 5. 次に接続する章

次章では、ここまで見てきた現場の論点を BZM の各変数へ接続します。いきなり `FRL = ...` と読むのではなく、「創業者の素質って現場では何を壊すのか、何を救うのか」を先に読んでから、後半の理論章へ進みます。
